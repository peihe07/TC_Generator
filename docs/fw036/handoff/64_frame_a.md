## 二、審查判定：**收。本輪之核心是一個否定結果，而它比一份新對清單有用。**

### 2.1 §1.1 —— **「037 之重複只能在起草時被發現」是一個結構性結論**

執行層之論證完整且其對照實驗設計得好：**同一個方法，
用在「判定對象」上精確（5 命中／4 已知／1 可區分）、用在「037 原文」上失效
（全召回需門檻 ≤0.143，而該門檻命中幾乎所有列對）。**

> **037 原文之重複，其偵測本質上需要一個「判定對象」之表示 ——
> 而那個表示是起草之產物。**

**採認，且其應立為 DR-SU3 之限度陳述**（T76c）：

```
DR-SU3 之實例清單**永遠是下界**，且**不可能有機器保證其完整**。
其成因非查核不足：037 原文之字面相似與「二列是否驗同一件事」
**是兩個不同的量**（`172`／`382` 之 Jaccard 0.143 而其判定對象相同；
`180`／`182` 之 Jaccard 0.850 而其可區分）。
故其發現只能隨起草逐對累積。
```

**其意義**：先前之狀態是「沒找到與沒有在找長得一樣」（下放包 63 §三 #5），
**現在是「找了，且證明這條路找不到」** —— **後者是可交付之結論，前者不是。**

### 2.2 §2 —— **第三次同型，而這次是自己撞見的**

「42 條」實為 `section_sha` 32 條、`body_sha` **5 條**。

**其對制度之影響經執行層自行重估**：
`frame_state` 仍該有，**惟其理由由「現行 `body_sha` 之假性不符」
改為「歷史包所引之舊式 sha8」** —— **理由換了而結論不變，且是它自己換的。**

## 三、五項裁定

### #1 掃描之候選清單 —— **准作為未起草組之注意清單，且須明標其性質**

`242`／`243`（0.927）、`233`／`234`（0.882）、`269`／`270`（0.846）等。

**其記法（避免日後被讀成發現）**：

```
`DUP_CANDIDATES.md` 檔首須載：
本清單為**字面骨架相似度**之產物，**不是重複之判定**。
其召回經回測為不足（全召回門檻 ≤0.143），**其精確度亦有反例**
（`180`／`182` 0.850、`104`／`105` 0.818 皆已判為可區分）。
**其唯一用途為起草該組時之注意提示。**
```

### #2 「42 條」之更正 —— **追認**，並立一項固定要求

**三次同型（B-36 總數對而分佈錯、B-37 欄位不相稱、本次）**，
**而三次之共同形態為：一個數被報出時，其導出方式沒有跟著出現。**

**裁定（自本包起，上繳包之固定要求）**：

```
凡於上繳包報一個**結論性數字**，須並記其**導出之欄位與比對對象**。

例：不寫「42 條之 body_sha 已與表上不同」，
    寫「32 條之 `section_sha` 與表上不同；`body_sha` 相異者 5 條
       （比對對象：`sha.tsv` 之 `body_sha` 欄 vs 現行重算值）」。

**其目的不是防錯，是使錯可被自己撞見** ——
本次之更正即因執行層在建表時被迫寫出比對對象而發生。
```

**此為 FO §5a（「數字自洽不構成正確之證據」）之操作化。**

### #3 DR-SU3 改為「四形態各一最強實例 ＋ 附件」 —— **准，全採其 (丙)(丁)**

| 形態 | **首例** |

**其餘各對置附件，並記「附件之對數為 N，其形態同上」。**

**(丁) 之理由逐字採認**：

> **同錨者其同源不需任何論證即可看出 —— 上游自己的物件編號說了它們同源。**

**併記其設計原則**（入 `REASONING.md`）：
**問一個問題（切分依據），不是問 N 個問題。**

> **F1–F3 之送裁材料，逐批列於**上繳包正文之一節**，不另開檔。**

> 訊號起點、其後之非訊號行數。

**其代價為上繳包變長，而其收益為該項不再被跳過。**
**`FRAME_F1_a.md` 之內容於下包移入正文，該檔保留不刪。**
