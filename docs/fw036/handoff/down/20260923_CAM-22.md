## §1　審計對象與判準

對象：`coverage_b.tsv` 之 197 個 PRODUCED leaf（每列對應一 TC）。
逐列以 canon §8.3 之軸檢查，每軸之判準與證據要求：

| 軸 | 判準（來源逐字為據） | 證據欄 |
|---|---|---|
| **format / type 配對** | Description 列舉「支援」之型別／模式（有線 vs 無線、有 Camera App vs 無、Backup Cam Only vs Backup and Cargo）而現有 TC 只驗其一；或有正向而無反向（§7：enumerated supported → 至少一 unsupported） | 列舉句逐字 |
| **boundary** | 含時限／數值（5 s、10 s、字數上限、相機數上限 n）而 TC 未驗 `=limit`、`limit±1` | 數值句逐字 |
| **negative / invalid** | 條文含「不得」「不可用」「灰階」「lock out」而 TC 只驗正向 | 否定句逐字 |
| **列舉** | 含 ≥ 2 個並列項（view 名稱、按鈕、狀態）而 TC 以單一 ER 概括；依 CAM-10 審閱 §一-4「查表對映每項一列」 | 並列項逐字 |
| **車型** | 前提用之 PROXI byte／CAN 訊號因 EE 而異且 ER 亦異（R-CAM3(a)–(d)）；R-CAM18 只是把缺者勾 0，若 ER 在 Atl-Hi／Atl-Mi 不同則須拆 | PROXI／DBC 命中 |
| **品牌** | hop label 帶 `*`（R-CAM5）而 TC 未分品牌 | Settings List 列號 |
| **mode / 狀態** | 同一行為在 Automatic／Manual／Off、投影中／非投影中、R1 High／R1 Low 之 ER 不同而 TC 只取一態 | 狀態句逐字 |
| **one-trigger-multi-outcome 之反向** | TC 把**不同觸發**之結果併在一列（§5.7 只允許同觸發多結果） | Procedure 步 |
