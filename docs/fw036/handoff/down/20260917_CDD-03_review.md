## 三　內容修正（併入 CDD-04，不阻斷）

**(1) I/O Control TC 之 PC-3** —— 不採「列舉封閉」讀法。
SYSAD 列舉 Write DID／Routine／DTC clearing 而漏 I/O Control，屬**漏列或刻意**不可知；
I/O Control（`0x2F`）改變 ECU 輸出，ISO 14229 實務常受 security 保護。
若實機要求 `0x27` 而 TC 未寫，測試者得 `7F 2F 33` 即 **false fail**；反之多寫一行 PC 對不需 security 之實機無害。
裁：**I/O Control TC 一律含 PC-3** `Security access 0x27 has been granted`，`pc_sources` 記
`SYSAD §4.5（保守套用；列舉未含 I/O Control）`；**FB-DIAG-k** 問 SYSAD 作者 I/O Control 是否受 `0x27` 保護。
影響：pilot `-006`～`-008`、`-013`（4 條）Revise；batch 2 起適用。

**(2) `NR1L-DIAG-043` 觸發鍵** —— 步驟 2 `Press and hold the "Power" push button`：
`Power` 為電源鍵，長按可能觸發 HU 關機或 standby，破壞診斷 session（自我干擾）。
改用無狀態副作用之鍵（建議 `"Up"`），ER 3 同步改；`-044` 若同用 Power 亦改。
通則寫入 profile：**觸發鍵不得選會改變 HU 電源／session 狀態之鍵**。
