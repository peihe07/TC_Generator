## 三、建議（乙）—— 3 項，皆不阻塞

### 乙-1　row 62 之 ER step 3「is accepted」為未經來源之斷言

```
3. PROXI Heated_Seat_Levels = 3
ER 3. PROXI Heated_Seat_Levels = 3 is accepted
```

raw 3 於 PROXI 表未定義。「未定義之值會被配置工具接受」**無來源明載** ——
若工具端拒絕寫入，該步驟根本無法執行，而 ER 卻宣告它成功（§8.4.1 之邊緣）。
row 25／44 之 `is accepted` 對象是**已定義**之 raw，性質不同。

建議改為可觀察而不預判之寫法：
`3. The result of writing PROXI Heated_Seat_Levels = 3 is recorded as Write_result`，
step 4 之比較不變。**或**維持現狀而於 Remarks 加註「若配置工具拒絕寫入，該列改判 B7」。
擇一即可，屬 Pei 裁定範圍。

### 乙-2　row 26 缺 §5.6 baseline

PENDING 解除後本列已可出貨，其 §5.6 缺口因而浮現：

```
1. Send CAN: … CmdIgnSts = 4 (RUN)          ER 1. … is sent
2. Send CAN: … CmdIgnSts = 5 (START)        ER 2. … is sent
3. Read … and check that it is greyed out
```

step 1 送 RUN 卻**未記錄該狀態下按鍵未灰階**，故「灰階」是否為 START 所致無從分辨。
