## §1　CRL vs DCL —— 術語落差，登 DR，並入矩陣

037 CertProvider-004 寫 **CRL**（`openssl verify … -untrusted CRL.r0`，非 ECU 場景用 /odm 本地 CRL）、005 寫動態下載 CRL；
CS.98 STEPS 與 SYSAD `SYSAD_IF_CP_STORAGE_IO` 寫 **DCL**（`dcl_baseline.json`／`dcl_revoked_l{0..3}.json`）；
`Cyber DIDs R&P-CS.102` 之 295D/295E 標 `CRL/DCL Header Info/UUID`，`DID CS.102` 同列標 `CRL Header`。

```text
DR-SEC-j  DCL 與 CRL 是否同一機制、同一檔案型態
  影響：CertProvider-004（注入檔為 .r0 CRL 或 .json DCL）、005（動態 CRL 之 CDP 是否亦為 DCL 路徑）、
        Cert Val CS.98 第 2/5~8 項之 TC 前提檔名。
  未裁前：TC 之注入檔名寫 `PENDING: DR-SEC-j revocation list file type`，不得二擇一。
```

任務 3 增：`trace_matrix.tsv` 對 CertProvider-004/005 之 `step_sources` 加註 `TERM:CRL|DCL`。

## §2　CS.212 之追溯為 SWE1 → CCVR 直連（跳過 SYS2）

`Secure Log CS.212` 13 項在 `Mapping detail` 全部 `Reference only → SYS-RA-SEC-671`；SYS2 CFTS084 僅以資訊引用 CS.00212，**無行為性 logging 需求**。故：

```text
R-SEC{live+4}  CS.212 之 CCVR 落點以 037 之 log 斷言直接判定，不經 SYS2
  (a) `ccvr_batch` 判定對 `Secure Log CS.212` 改用第二判準：037 列之 Verification Criteria 含
      log／Logdog／logdog／avc／logcat 斷言者，`ccvr_items` 加 `Secure Log CS.212`，`reason` 記 `SWE1-direct`。
  (b) 分析層預判命中：KeyInstall-010（`log a security violation`）、KeyInstall-012（`avc: denied` 不得出現）、
      SAM-0004（`logs an error via logdog`）、CertProvider-005（監看 log 無 CRL 寫檔）、CertProvider-006（Logdog error-level）；
      執行層 grep 全 70 列回報實數。
  (c) CS.212 第 1/7/10/11/12 項（Steven）之 GIVEN/WHEN 步驟為 R-SEC{live+3}(a)4 之合法落地來源，
      對應到 (b) 之列時可引用；其 package 未 release 前（DR-SEC-h），logcat tag／關鍵字保留佔位。
```

**新增 DR**：

```text
DR-SEC-k  CAN 金鑰佈建規格（RID 0x9001／0x9003、JSON payload 欄位、responseByte 定義）
```

**步驟落地規則補充**（R-SEC{live+3} 之 (a) 增第 6 類）：DID／RID 讀寫步驟以 §5.4 兩行式寫，指令行沿用既有交付本之診斷步驟寫法；**執行層先查既有交付本（DealerMode／SWC／power 等）是否已有 DID 讀寫之步驟前例**，有則逐字沿用其格式並回報出處；無則列 DECISIONS [PROPOSED] 等 Pei 定式，不得自創。工具側：`NR1L_UDSTool` 為 Pei 既有之 UDS 工具，指令是否以該工具語法落地，列 DECISIONS。
