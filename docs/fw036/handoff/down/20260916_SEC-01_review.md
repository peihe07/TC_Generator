## 三、裁定修正（分析層裁，於 R-SEC 範圍內；Pei 覆核）

### 三-1　R-SEC5(b) CS.212 直連之命中 —— **11 列改 7 列，batch 1 由 52 改 48**

執行層之 11 列中，**LOGENC-002／003／004／006 為誤判**：其命中詞 `log` 為受詞（`log file encryption`、`encrypt log files`、`linked by logdog daemon`），**不是 log 斷言**——R-SEC5(a) 原文為「含 log／Logdog／logdog／avc／logcat **斷言**者」，斷言指 THEN 子句宣稱「有 log 被寫出／可觀察」。LOGENC 四列之 THEN 皆為加密行為，非事件記錄；CS.212 是 secure *event* log，與 log *encryption* 無涉（SEC-01 §5 已明寫）。

判準補述（SEC-02 amend R-SEC5(a)）：**只計 THEN／`3.x`／`THEN.` 子句內之命中，且該子句須宣稱 log 之產生或觀察；主詞為 `Log Encryption`／`LogDog` 元件者不計。** 大小寫維持敏感（採 DECISIONS 6-10-d）。

重算：CertProvider-005/006/008、KeyInstall-010/012、SAM-0004/0015 = **7 列**（CP-008 之 `Confirm successful end-to-end verification through system logs (Logdog)`、SAM-0015 之 `DebugAuth prints the log about sending message` 為合格斷言）。batch 1 = 52 − 4 = **48**；與預判 45 差 3，升級門檻餘裕充足；LOGENC 四列回 batch 2。執行層重跑 `trace_matrix.tsv`／`batch_order.tsv` 回報。

### 三-2　SAM-0007 —— 人工覆寫入 batch 1

apk `samCertTestNormalFlow` 為 `Test_Items.txt` 第 04 條，可執行；CS.98 STEPS 亦引用該方法。機械判準因 `Mapping detail` 無落點而判 batch 2，屬對應者疏漏，非行為無關。**覆寫為 batch 1，`reason = manual override: apk samCertTestNormalFlow`。** batch 1 = **49**。（此為分析層建議，DECISIONS 6 之 contested 項由 Pei 定。）
