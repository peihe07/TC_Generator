## 四　「都不需要多去延伸嗎」—— 量測後之回答

**已延伸之軸（有 CFTS004／037 依據者，全部用了）**：389 列 → 544 TC（×1.40）。負向二軸（長度／值域）全數；讀寫拆二（`readable and writeable` 五 DID）；BVA 二式（`Valid values … from` 八處）；狀態軸（Antenna 3 態、Signal Strength 5 態、`$1820` 十二鍵分項）；retry 三碼各拆；常式 start／results 兩步；`-054` 分項。

**未延伸之處（分析層自查，四類）**：
1. **037 定型句之第三型「unsupported DID」** —— 至本包才由執行層發現未用（§三-1）。這是**確實漏掉的、有依據的延伸**。
2. **037 之 Verification Criteria／Verification Method 欄從未被系統性開採** —— 例：`-007` VM 書「HMI functional testing to confirm menu enable/disable states and **timeout-based fallback**」、`$2840` VM 書「**under varying antenna conditions** … known RF reception states」、`$5002`～`$5006` VC 書「valid, invalid, **boundary** value」。這些是 037 作者自己寫下的驗證意圖，屬有依據之延伸來源，但我們只在 sibling plan 偶爾引用，未逐列比對「VC/VM 提到的情境是否都有 TC」。
3. **CFTS004 各 `$XXXX` 節之 Information 列（95 列）** 只當查值用，未當斷言來源掃過 —— 其中若有「shall」句或列舉而 037 未收，依 R-DIAG8(a) 不產是對的；但若 037 已引之 FR 其鄰近 Information 列補充了該 FR 之狀態／值域（如 4940456 之 Indication Code 表），那是延伸依據，目前只在 batch 5 用到一次。
4. **canon §8.3 之環境／持久軸（reboot、power cycle、並行中斷）** 全未用 —— 因 CFTS004 對此零載；依 §8.4.1 不造值是對的，但**應明記為「刻意未延伸」而非「無」**，交付時 coverage 說明要寫。

**結論**：延伸不是「不需要」，而是**只延伸了有錨的部分，且有兩個有錨的來源（037 三型定型句、037 VC/VM 欄）沒有被系統性用完**。這兩項可量測、不造值，故 **CDD-10 先做延伸審計**（產候選清單，附錨，Pei 裁後才產 TC），交付候選延後至 CDD-11。
