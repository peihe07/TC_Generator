### 5-3　**`gen_batch2.py` 之範圍斷言迴歸（SEC-11 埋、SEC-13 炸）**

`gen_batch2.py` 之 `scope` 取「`ccvr_batch == 2` 且 `disposition != "D"`」。SEC-11 把 8 個 LOGENC 列
自 `D` 改為 `CONVERT_DOC` 後，那 8 列即落入 batch 2 之範圍，與其 `SPEC`（13 列）不符 →
本包重跑時 `AssertionError: 範圍不符：… 只在 batch_order {8 個 LOGENC}`。

- **影響面**：**v06／v07 之產物不受影響** —— 合併本以 JSON 為輸入，batch 2 之 JSON 自 v05 起未變（
  `batch2_v08` 之 sha 與 v04／v05 相同即其證）。受影響的只有「重跑 `gen_batch2.py`」這條路徑，
  而 SEC-11／SEC-12 都沒走它。
- **成因**：SEC-11 改 `batch_order.tsv` 之 `disposition` 時，只查了讀該欄的 `build_merged.py`／
  `audit_ccvr.py`，**沒查 `gen_batch2.py` 也讀它**。
- **修法**：`scope` 之排除集合改為 `("D", "CONVERT_DOC")`，並在該行加註說明
  （`CONVERT_DOC` 之列由 `gen_deferred.py` 產出 batch 3，不屬本批）。修後三支生成器皆可重跑，
  batch 2 之輸出逐字節不變。
