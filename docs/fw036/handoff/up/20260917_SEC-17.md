## 三、實作（§2 之偏離）

### 3-1　為何不照「openpyxl `PatternFill` ＋ 再存」

`openpyxl` 之 `save()` 會重建整包 —— 這正是 `backend/xlsx_surgical.py` 檔頭所載之 R16 事故
（實測 21 個 zip 成員消失、6 個 x14 DV 全失）。照 §2 之字面做，§0「zip 成員數與 DV 計數相同」
與 §5「DV／zip 計數改變即升級」必然觸發。故改以**與 `surgical_restyle` 同宗之外科法**，
新腳本 `features/security/scripts/mark_placeholder_rows.py`：

1. `xl/styles.xml` 之 `<fills>` **追加**一個 solid `FFFCE4D6`（不改既有 fill）；
2. 對目標列所用之每個來源 style id，**衍生**一個帶該 fill 之新 `<xf>` 追加於 `<cellXfs>`
   （不改既有 `<xf>`，否則會連帶重塗所有共用該 id 之格）；
3. 只把目標列 A~AH 之 `s=` 重指向新 id；該列缺格者補 `<c r="…" s="…"/>`；
4. 其餘 zip 成員**逐位元組複製**（`sharedStrings.xml` 不動 → 文字不可能變），
   最後跑 `verify_structure` ＋ 逐格文字比對。

另：下放包指名改 `build_delivery.py --mark-placeholders`，惟六本交付現由
`build_split_delivery.py` 產出（R-SEC25，SEC-15），`build_delivery.py` 只產已淘汰之單本，
故未在該檔加旗標；塗色為獨立一支（可對任何交付本重跑，冪等）。
