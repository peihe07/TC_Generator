逐條表附於 `features/diagnostics/sandbox/r_diag22_revise.tsv`（95 列，欄：`tc_id`／`batch`／`did_sid`／原觸發串／改後串／改法）。

| 改法 | 條數 |
|---|---:|

| 依批 | pilot 2／b1 9／b2 19／b3 20／b4 13／b5 13／b6 19 |

**判法**：對每條長度軸 negative，先自「ER 不含 `7F` 之列」求出該 SID＋DID 之**合法請求串**，再省去最後一個 byte。

- 讀類 `22 28 43` → 合法即自身 → `22 28`（**位元組＋描述**）
- I/O 類 `2F 50 00` → 合法為 `2F 50 00 <buzzer control tone selection>` → 省末 byte **恰等於現串**（**僅描述**）
- 寫類 `2E 28 0C` → 合法為 `2E 28 0C <Cabin EQ Curve Number byte>` → 同上（**僅描述**）
- 常式 `31 03 03 12` → `31 03 03`；`31 01 03 09 <Package Indication value>` → `31 01 03 09`

描述行一律 `… with an invalid message length` → `… with the last byte omitted`（六種句式共 95 行）。

### 2.2　值域軸之複核 —— **89 條與正向同串，且條文對讀類不可施行**

下放包 T1(a) 命「值域軸不動，但複核其資料位元組不得與正向相同」。**複核結果：89 條相同**
（SID `22` **85** 條、SID `31` 4 條；依批 b1 5／b2 1／b3 4／b4 13／b5 13／b6 19／b7 34）。

更根本的是：**R-DIAG22 之值域軸條文對 `0x22` 讀請求不可施行。** 該條書
「值域軸之請求保留完整長度，以 `<out-of-range value>` 或 CFTS004 明載之越界值填資料位元組」，
而 `22 <DID>` 請求**本無資料位元組可填** —— 讀請求的參數就是 DID 自己。

**未處置**（§2 T1(a) 明定值域軸不動；§0 只准產 batch 7）。登 `[A-DIAG52]`。

**建議（待分析層裁）**：037 negative 列之原文為
`invalid length, incorrect format, or unsupported DID` —— **第三種失效型態「unsupported DID」尚未用掉**。
讀類值域軸改寫為 `$ 22 <unsupported DID>` ＋ 描述行 `for an unsupported DID`：
ISO 14229-1 中 NRC `31 requestOutOfRange` 正是「DID 不受支援」之碼，既有 037 依據、又可執行、且與正向串不同。
SID `31` 之 4 條（常式）另依 CFTS004 有無越界值判。
