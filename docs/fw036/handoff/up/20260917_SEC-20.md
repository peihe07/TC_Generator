## 四、§4-4 逐 token 複驗與三項待裁

### 4-1　CCVR 可執行行之命中（§4-4）

| 來源 | 可執行行 | 命中 ≥1 | 命中 0 |
|---|---:|---:|---:|
| `Cert Val CS.98` items 1／2／3／5~8／10 | 60 | 58 | **2** |
| `ECU ID CS.165` items 2~6／12 | 4 | 4 | 0 |
| 合計 | **64** | **62** | **2** |

**命中 0 之兩行皆為同一字串**：`adb shell pm list instrumentation | grep melcocertprovider; if missing, run adb install -r -t CertProviderServiceManagerTest.apk`（items 2 與 5 之 GIVEN）。
成因：該「行」實為**兩個指令以英文散文相接**（`…melcocertprovider; if missing, run …`）。
兩個指令**皆已落地**於 Pre-Condition：
`The test runner is verified with adb shell pm list instrumentation | grep melcocertprovider (if missing run adb install -r -t CertProviderServiceManagerTest.apk)`。
未逐字照抄 `; if missing, run ` 之理由：`;` ＋ `, ` 會觸發 lint `R`（Pre-Condition 多條件並列）。
→ 就「指令」而言命中率 **64／64**；就「行」而言 62／64。請裁以何者為準。

### 4-2　§5 第二條之逐字自檢（**請裁**）

全庫 `$ adb`／`$ openssl` 指令 **223 行**；對本包新增之 10 TC 逐一比對 CCVR 原文，
**12 行非 CCVR 逐字子字串**，全在 ECUCert 四個新 sibling（`NR1L-ECUC-003`~`-006`）：

| 指令 | 出處與理由 |
|---|---|
| `adb shell ls -l /data/misc/ecuidentity` | CCVR item 2~6 **未給驗證指令**（其 Expected 只有 `recoveryed`）。該指令為 SEC-04 起既有之 ECUCert 步驟，用以使 push 步驟具 R-SEC7(c) 觀察手段 |

| `adb logcat -s ECU_CERT_SERVICE_FUNCTION_ID` | CCVR 之 Log pattern 欄逐字為 `MLog.i(ECU_CERT_SERVICE_FUNCTION_ID, ECU_INSTALLATION_STATUS, status.ordinal()); value : 2 -> 1`（非指令）。tag 取自該欄，指令為既有觀察式；ER 逐字引 `"ECU_INSTALLATION_STATUS value : 2 -> 1"` |

三者皆非造值（有既有 TC 或 CCVR 欄位為據），惟**確實不是 CCVR 逐字**。
若分析層要求嚴格逐字，移除三者將使該四 TC 之步驟無執行通道／無觀察手段（lint `SC` 必非 0）—— 兩者不可兼得，請裁。
