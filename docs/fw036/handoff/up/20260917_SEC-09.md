## 六、自報（§4-4）：三表以外之發現

1. **初版軸判準虛報 `AXIS_GAP` = 15**：第一版需求面關鍵詞含 `each`／`both`／`all listed` 等泛詞，
   且覆蓋面以字面比對 sibling axis 字串，導致 12 條之 gap 全為 `variant` 之假陽性
   （sibling 本就是變體拆分，只是 axis 名稱不含 `each`）。已改為 §5-1 之判準並重跑 → 5 條。
   **若以初版數字，§5 第二條（`AXIS_GAP > 10`）會誤升級**，故在此明記兩版差異與成因。
2. **`NEW-NET-01` ↔ SwdlSecureLib 之鏈結可疑**：`trace_matrix.tsv` 之 `new_test_ids` 把
   `NEW-NET-01`（Enforce TLS for external connections；`SYS-RA-SEC-088／099／208~211`）
   指到 `SWE1-SRA-SECURITY-SWDL-001／-002／-003／-005`（金鑰取得與解密）。
   兩者題域不同，疑為 SYS2 ID 清單之偶然重疊。該鏈結出自 **SEC-01 之分析層產物**（非本包推論），
   建議分析層複核；本包照現有 `trace_matrix` 分類，未自行改判。
3. **Remarks 之 CCVR 引用用詞「rows」實為「items」**：`NR1L-SWDL-005`／`-006` 之
   `CCVR Auth-Prog CS.93 evidence rows 3/5/6/7/8` —— 該 sheet 之編號在 c0 欄，
   item 3／5／6／7／8 位於**實體列 4／6／7／8／9**；若照「rows」讀作實體列，
   會誤指 item 2／4／5／6／7。內容對照可證原意為 **item**（item 7 = `do not increment the
   rollback protection version … reflash`，即 SWDL 驗證之情境）。
   建議下次 Revise 改為 `items 3/5/6/7/8`；**本包唯讀未改**。
4. **`Cert Val CS.98` 之欄位更正**：見 §4-1 之引註（`assessment` → `Mapping rationale / gaps`）。
5. **`Cert Val CS.98` 共 10 項**（非 6 項），其 case 4／9 為 `NA`（OS／bootloader 與 build-time
   環境分離，`Mapping notes` row 11 之 Component scope），故審計二之對象限 case 2／3／5~8，
   與下放包 §2 一致。
6. 本包未觸及 SEC-07 §5 之兩項殘留（Z1 之 USB／oemkeys 註解衝突、`test_can_injection.py`
   之 0x9001／0x9003／0x9004 協定），仍待裁。
