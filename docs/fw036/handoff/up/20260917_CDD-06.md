### 2.3　`PC-DIAG` 實作與一處判準校準

`lint036.py` 新增 `PC-DIAG`（每列每行）。**詞幹比對**：條文書 `press` 而實文為 `is pressed`，
僅 `\bpress\b` 會漏（自測假陰性 1 例）。

改詞幹後**反而攔下兩個合法前提**（`[A-DIAG41]`）——
`No push button on the Push Button Control Interface is pressed`、
`No hardwired steering wheel control interface button is pressed`。
二者為**靜止態**，不需執行即成立，正合 R-DIAG18 之立意（「需執行才成立者不是 Pre-Condition」）。
加否定式例外 `\bno\b[^.]*\b(?:pressed|sent|recorded|read)\b`，lint 與四個產生器同步。

### 2.4　R-DIAG17 —— `X` 豁免，**落地時揭出 lint 之實作缺陷**

`FEATURE_EXEMPT["diagnostics"] += ["X"]` 後，**290 列之合併本直接 crash**：

```
ValueError: 'X' is not in list
  at result.violations.sort(key=lambda v: (enabled.index(v.check), v.row))
```

根因（`[A-DIAG42]`）：`X` 於 **`check_row()` 內**產生，而 `FEATURE_EXEMPT` 只從
`check_order()` 移除 —— 豁免後該代號仍被產出卻已不在 `enabled`。

**更要緊的是它怎麼被發現的**：五本之 lint 我以 `grep "行計"` 取紅數，crash 時該行不存在，
於是輸出「（其餘 0）」——**crash 被讀成全綠**。是合併本那一本讓我起疑（它與其子集矛盾：
batch4 有 `H=2 U=2`，含它的合併本卻全 0），才查出五本全都 crash。

**修法**：`check_row()` 之產出一律依 `enabled` 過濾，**列級豁免（`exempt_row`）與
整項豁免（`FEATURE_EXEMPT`）在此收斂為同一道**。回歸 221 passed。
