## §5　自報錯誤

1. **`rulings_hash.py --gate` 為寫入模式，我以它試探 `--check` 之成因，把 67 列覆為全生成之 856 列**（`[A-DIAG45]`）。
   該旗標之說明只寫「有重複 id 之本體歧異時 exit 1」，未寫其仍會寫檔。
   即以 `git checkout` 還原後重附 `R-DIAG19`，`git diff` 覆核為「恰 1 列新增」。
   此舉等同在 CDD-07 期間執行 GC-16 之重生動作，而下放包首段明訂兩者**不得並行** —— 屬實質越界，幸即時發現。
   **教訓**：對會寫檔之工具，一律先 `--out <scratchpad>` 或 `--check`，不以未讀過原始碼之旗標試探。
2. **首次合併指紋時我按自訂 key 重排全檔**，`git diff` 顯示 35 增／34 刪。已還原改為純追加（1 增 0 刪）。
   **教訓**：動共用表格檔，先以 `git diff --stat` 確認變動量與預期一致再往下走。
3. **`(c) 內部代號` 自檢式無詞界而誤報**（見 §3.2 引文）。教訓：以代號做 grep 時，`DR-`／`FB-` 等前綴會包含另一代號之字串。
