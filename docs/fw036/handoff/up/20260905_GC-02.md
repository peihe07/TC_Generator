### 9-2　本輪自造之缺陷一件（已改正，具名）

首次跑對照向時以 `for f in $VAR` 之寫法搬移檔案，**zsh 不對未加引號之變數做分詞**，
於是整串路徑被當成單一檔名，`cp`／`rm`／`git stash` 全部失敗，
而我先看到的是一個「對照向 = 664 = 交付向」的數 —— 若照抄，就會得出「本包增紅 0」之偽結論。
是 `git stash` 的 `did not match any file(s)` 一行讓它露出來的。
已改以 zsh 陣列重跑，得 9-1 節之 630。
**形態**：把「指令沒報錯」讀成「指令做了事」；對照向之有效性本身未被驗證。
可測之防法（供分析層裁，本層不自立條）：對照向之量測須同時回報「被移出之檔數」，
該數為 0 而仍宣稱已建立對照向者，即未量測之斷言（R-G50 之延伸）。
