## §2　§1　修法與測試

`req_key()` 之鍵各段改為型別可比之二元組：數字段 `(0, int(seg))`、字串段 `(1, seg)`。
排序語義：**同位段數字先於字串、數字間按值、字串間按字典序**；純同型資料之相對序不變。

```diff
 def req_key(s: str) -> tuple:
-    # Numeric tokens compare as int, alphabetic tokens as str: "-10" sorts after "-2".
-    return tuple(int(t) if t.isdigit() else t
+    """（docstring：記原 TypeError 之實例與新語義）"""
+    return tuple((0, int(t)) if t.isdigit() else (1, t)
                  for t in re.findall(r"\d+|[A-Za-z]+", s))
```

`tests/test_req_key.py`（**10 項全綠**）涵蓋包內所令之各案：

| 測試 | 涵蓋 |
|---|---|
| `test_混型同位不再拋錯` | 原 TypeError 案（`6AuxSwitches` vs `AutoDoorLocks`） |
| `test_同位數字先於字串` | 新語義之方向 |
| `test_純數字段按值而非字典序` | 尾號 `002` vs `010`／`015` |
| `test_純字串段按字典序` | 字串段序 |
| `test_相同鍵相等` | 重複 D 值（相鄰列共用需求 ID）判相等而非逆序 |
| `test_較短之鍵排前` | 段數不同之既有行為不變 |
| `test_段之切分未變` | 切分規則仍為 `\d+|[A-Za-z]+` |
| `test_純同型之相對序不變`（2 例） | 包內「純同型序不得改變」之要求 |
| `test_全鍵可排序_無TypeError` | 混型集合整體可排序 |
