### 7.3　`-012` 5 s timeout（R-DIAG16 之保持步）

```text
Requirement or Design ID : SWE1-Diagnostics-012
Test Set                 : In Motion Menu Control
Priority                 : P0      Design Method : 功能測試 (Functional based ; no specific technique)

Test Item
  If the radio does not receive a diagnostic command to enable park menu options for more than
  5 seconds, the radio shall return control of in-motion menu item status to the normal disable
  conditions. ($500B, control returned after no enable command for more than 5 s)

Pre-Conditions
  1. The ECU is in the default diagnostic session
  2. The diagnostic tool is connected to the OBD-II diagnostic connector
  3. Security access 0x27 has been granted
  4. The navigation in-motion menu items are enabled by a diagnostic command

Input Test Data   NA

Test procedure
  1. Send the command to enable in-motion menu options
     $ 2F 50 0B <enable in-motion menu>
  2. Hold for 5 s
  3. Hold for 1 s

Expected Result
  1. The positive response 6F 50 0B is received, and each of the navigation in-motion menu items
     is enabled
  2. The in-motion menu items remain enabled for the 5 s during which no further enable command
     is sent
  3. Control of the in-motion menu item status is returned to the radio

Specification Reference   CFTS004-4940346
                          CFTS004-4940348
```

**說明**：`more than 5 seconds` 逐字取 CFTS004-4940348，故步驟 2 為 **5 s**（門檻內，選單應仍啟用）、
步驟 3 為 **1 s**（越過門檻，控制權應交還）。二步分立才能分別斷言「門檻內不變」與「門檻後改變」——
併為一步即無法區辨「5 秒就交還」與「超過 5 秒才交還」。
`Hold for <n> s` 依 **R-DIAG16** 成步、ER 寫該期間之可觀察結果；ER 無任何 `Listen`／`Observe`。
