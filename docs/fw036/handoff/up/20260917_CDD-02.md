## §4　拆分與未拆之理由

### 4.1　拆分（僅二處，皆依 R-DIAG1(b)）

`-002` 與 `-113` 之 negative 列各述「invalid length／incorrect format／unsupported DID」三種失效型態，
拆為**長度軸**（NRC 13）與**值域軸**（NRC 31）二條。
「incorrect format」與「invalid length」在 ISO 14229-1 同屬 `0x13`，**不另拆**（拆之即二條 ER 相同）。

### 4.2　`-001` 未拆 —— **與 §3 表之預期不符，且 TC 總數因此低 1**

§3 #1 書「CFTS004 值域 → sibling（R-DIAG8(c)）」，預估 2–3 條。
**實測：CFTS004 `$283F` 節之全部四列皆未載亮度值域** ——

| CFTS004 列 | ObjectID | Category | 原文 |
|---:|---|---|---|
| r146 | 4939791 | Heading | `$283F - Camera Level Brightness (Read/Write)` |
| r147 | 4939794 | FR | When requested by this DID, the radio shall update the brightness level of the rearview camera display using the updated level information provided. |
| r148 | 4939793 | FR | When requested by this DID, the radio shall report the brightness level of the rearview camera display. |
| r149 | 4939792 | Information | This DID reports and allows changing the brightness of the rearview camera display on the radio screen. |

037 之 Description 雖書「validate the received brightness value against the supported range」，
但依 **R-DIAG8(c)**（延伸只向 CFTS004 原文）與 **IN §8.4.1**（不造值），**無值域可拆**。
故 `-001` 為 **1 條**，值以 `<brightness byte>` 佔位（R-DIAG5(b) 條文例示之寫法），
缺件登 `DR-DIAG-5`。

### 4.3　`-272`／`-189` 未作 §6.1 分項 —— **與 §3 表之預期不符**

§3 #9 書「多子欄位 DID 之 ER 分項」。實測：

- `$2843` 節下有 **20 條** FR，各為**一個**子欄位（SXI Rev Major／Minor／Inc、RF Rev…、Module Type ID A/B/C…）。
  `-272` 所掛之 `SYS-RA-DIAG-079`（CFTS004 r80，ObjectID `4939852`）**只述 SXI Rev Major**。
- `$2841` 節同理，`-189` 所掛之 `SYS-RA-DIAG-124`（r125，`4939821`）**只述 RSErrs Terr Symbol**。

即該 DID 回報多個子欄位，但**此二 SWE1 列各自只追溯其中一個**。
依 §8.1（TC ↔ Requirement）與 R-DIAG1(a)，ER 只斷言該子欄位，**不作 a./b./c. 分項**
（分項即擴入其他 19 條 FR 之範圍，違 §8.2.1）。

§6.1 之分項用於 **`NR1L-DIAG-010`**（`-154`）—— 其來源 CFTS004-4940482 明文要求
「for each of the Video, Audio Left and Audio Right signals」，分項有據。

### 10.1　`NR1L-DIAG-001`（Camera Brightness，positive 寫，P1）

```text
Requirement or Design ID : SWE1-Diagnostics-001
Test Group               : Diagnostics
Test Set                 : Camera Brightness
Test Case Priority       : P1
Design Method            : 功能測試 (Functional based ; no specific technique)
Vehicle Model (T..Z)     : 1 1 1 0 0 1 1
Remarks                  : Harman Scope: Need Rework

Test Item
  The MDTDiagService shall interpret the received DID 0x283F request and extract the brightness level
  parameter. (write $283F, SID 2E, valid brightness)

Pre-Conditions
  1. The vehicle is in Ignition ON state
  2. The diagnostic tool is connected to the OBD-II connector
  3. PENDING: DR-DIAG-3 diagnostic session prerequisite
  4. The rearview camera display is active on the radio screen

Input Test Data
  NA

Test procedure
  1. Read the current rearview camera brightness level
     $ 22 28 3F
  2. Record the reported brightness level as Brightness_initial
  3. Write a new brightness level within the supported range
     $ 2E 28 3F <brightness byte>
  4. Read the rearview camera brightness level again
     $ 22 28 3F

Expected Result
  1. The positive response 62 28 3F <brightness byte> is received
  2. Brightness_initial is recorded
  3. The positive response 6E 28 3F is received
  4. The positive response 62 28 3F <brightness byte> is received, and the reported brightness byte is
     the value written in step 3

Specification Reference
  CFTS004-4939794
```

**設計說明**：上半取 037 Description 首句 verbatim（含 037 原拼字）；下半括號之區分 token 為
`write $283F, SID 2E`。步驟 1–2 立 baseline（canon §8.7.5(f)），步驟 3 為唯一觸發，
步驟 4 為驗證擁有者（§5.5）。`<brightness byte>` 為佔位 —— CFTS004 `$283F` 節未載值域（§4.2），
依 R-DIAG5(b) 條文例示書寫，缺件登 `DR-DIAG-5`。

### 10.2　`NR1L-DIAG-009`（AV Signal Detection，positive Routine，P0）

```text
Requirement or Design ID : SWE1-Diagnostics-151
Test Group               : Diagnostics
Test Set                 : AV Signal Detection
Test Case Priority       : P0
Design Method            : 功能測試 (Functional based ; no specific technique)
Vehicle Model (T..Z)     : 1 1 1 0 0 1 1
Remarks                  : Harman Scope: Need Rework; SID per 037 SWE1-Diagnostics-151

Test Item
  The DiagService shall interpret the received 0x31 (RoutineControl) request for DID 0x0312 and extract
  the channel input selection parameter. (routine $0312, SID 31, startRoutine)

Pre-Conditions
  1. The vehicle is in Ignition ON state
  2. The diagnostic tool is connected to the OBD-II connector
  3. PENDING: DR-DIAG-3 diagnostic session prerequisite
  4. An audio test tone of 1 kHz at 0 dB is applied to the channel input under test
  5. The video test pattern "Screen 3: 10 step" is applied to the channel input under test

Input Test Data
  NA

Test procedure
  1. Start the AV signal detection routine on the channel input under test
     $ 31 01 03 12 <AV Channel Number>
  2. Request the results of the AV signal detection routine
     $ 31 03 03 12

Expected Result
  1. The positive response 71 01 03 12 is received
  2. The positive response 71 03 03 12 <routine results> is received, and the results indicate that a
     signal was detected on the channel input under test

Specification Reference
  CFTS004-4940473
  CFTS004-4940478
  CFTS004-4940477
  CFTS004-4940474
```

**設計說明**：Pre-Condition 之 4／5 兩行**不是環境穩定性前提，是規格所載之觸發條件** ——
`1 kHz, 0 dB` 取自 CFTS004-4940477（r370），`"Screen 3: 10 step"` 取自 CFTS004-4940478（r369），
故四個錨全列（§10.7(a)：列出所驗之全部章節）。`<AV Channel Number>` 之值域見 CFTS004-4940474（r371）
—— 該條只述「其 portion 指示哪一個輸入」，未列舉通道號，故佔位。
`31 01` 為 startRoutine、`31 03` 為 requestRoutineResults，SID `0x31` 取自 037 本列
Description 明載（R-DIAG5(amend)(e)，Remarks 記 `SID per 037 …`）。
