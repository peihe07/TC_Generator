## §4　結構性回報

1. **`Body_Types` 之 raw 取自來源 label 自身之數字**（`Type 4 - DJ` → `4`、`Type 1 - D2` → `1`）。
   Atl-Hi 兩本 PROXI 之 byte 231 只載現值（`7 = Type 7`）而**無列舉**，故不以 PROXI 為 raw 之來源。
   此為「以來源之 label 文字推得 raw」，嚴格說非逐格實測；若審閱認為不足，
   `-073`／`-074` 之該行可退為 `PENDING`（需補件：Atl-Hi PROXI 之 `Body_Types` 列舉）。**歸 Pei。**
2. **`-091`（`V42-322`）之來源僅 3 token 且無等式** —— 逐字即
   `Gear_Box_Type to vehicleUpdate_1.VC_Trans_Equipped`。PROXI 值 ↔ LVDS 值之對照表於 SYS2 查無，
   故 ER 只驗「該 LVDS 訊號反映該 PROXI 值」而不寫具體對映（§8.4.1 不自造）。
   其可判性偏弱，於此具名。
3. **`-088`（`V2-538`）為清單完整性之驗證點** —— 十四個 LVDS 訊號之「都在」，
   各訊號之值語意由其各自之來源承接（已於 reasoning 逐一指名去處）。
   若審閱認為應逐訊號拆列，本列可擴為 14 列，**歸 Pei**（現計 1 列）。
4. **`-080`／`-082` 之 ER 項數依來源而異** —— `V2-519`／`V2-520` 列 CAN ＋ LVDS 兩項，
   `V4-125` **只列 `TELEMATIC_FD_14` 一項**（逐字如此），故 `-082` 之 ER 只兩項。
   非遺漏，為 §8.4.1 不補來源未載者。
