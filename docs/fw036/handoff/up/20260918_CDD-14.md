## §3　T2 —— `SID-WORD`

### 3.1　實作與自測

`FEATURE_CHECKS["diagnostics"]` 新增 `SID-WORD`。母體＝「編號描述行 ＋ 其下之 `$` 位元組行」配對；
`<unsupported SID>` 起首者不判（其服務位元組非具體 SID）。

**判準（校準後）**：描述行**指名了某服務**（`read`→`22`／`write`→`2E`／`InputOutputControlByIdentifier`・`I/O control`→`2F`／`routine`→`31`）
而其下位元組行之 SID 為**另一服務** = FAIL。未指名服務者不判。

| # | 案 | 判 |
|---:|---|:-:|
| 正 1 | `Activate a buzzer control tone…` ＋ `$ 2F` | PASS |
| 正 2 | `Send a request for DID $2843 with the last byte omitted` ＋ `$ 22 28` | PASS |
| 正 3 | `Select the 7 kHz Tool controlled tone in the Buzzer Control DID` ＋ `$ 2F` | PASS |
| 正 4 | `Start the package select routine` ＋ `$ 31 01` | PASS |
| 反 1 | `Send a write request for DID $5100…` ＋ `$ 2F` | PASS（攔） |
| 反 2 | `Read the setting` ＋ `$ 2E` | PASS（攔） |

**6/6 PASS**（下放包命 3 項，實作 6 項）。

1. **`[A-DIAG75]` `SID-WORD` 首版判準誤讀 —— 101 行假陽性。**
   我把 R-DIAG32 讀成「每個 SID 只准一組動詞白名單」，於是把 `Activate`／`Select`／`Send the command to set` 這類

   已校準，十一本由 103 → 2。
   **教訓**：條文說「不符」時，要先問「不符的是什麼」—— 是**服務身分**不符，不是用詞不在白名單。
