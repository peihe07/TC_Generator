## 二、五項裁定

### #1 `RULINGS.sha.tsv` 之提交方式 —— **取 (甲)，照提交並記明**

**不等平行線落定。** 理由：

> **等待期間 `sha.tsv` 是過期的，而過期之 `sha.tsv` 使 R-G13 之引用比對失效** ——
> 下放包所引之 `sha8` 對不上，執行層依 R-G13 須停下回報，
> **於是每一包都會產生一次假性不符**。
> **「純 commit」之價值不值這個代價。**

**照 §6.2 之指令提交**，惟 commit 訊息須改為含其實情：

```bash
git add docs/fw036/RULINGS.sha.tsv
git commit -m "docs(fw036): regenerate RULINGS.sha.tsv after R-G28

New anchors: 53 (R-G28 x1; ics_management x43; driver_distraction x9).
No existing sha256 changed; 44 rows differ in line number only.
Parallel-session rows are included by necessity: the tsv is a single
global file and cannot be regenerated per line." \
  -- docs/fw036/RULINGS.sha.tsv
```

**`RULINGS.sha.tsv` 之「不可能純」是其結構性質，不是本次之瑕疵** ——
須記入其檔首註（T68a），免得日後有人以為某次提交夾帶了無關變更。

### #2 `R-G28` 是否登 `IN §9` 自查表 —— **不登**

**其射程不合**：

| | `IN §9` 自查表 | `R-G28` |
|---|---|---|
| 執行時機 | **每個 TC 出手前** | **feature 開案時一次** |
| 執行者 | TC 撰寫者 | intake 執行者 |

登進去會使自查表被**逐 TC 勾檢一件與該 TC 無關之事** ——
R-G21 之「人工項」機制針對之對象為 `IN §9` 之項，**本條不在其射程**。

**其正確落點即現處**：`FO §0 Tier 0` 之 intake 清單（已在）＋ `FO §9.2` 條文。
**`GATES.tsv` 不登之判定亦追認**（該簿 46 列無一為人工項，且「連續 10 輪命中 0」
之除役判準對人工項無意義）。

### #3 追溯適用 —— **准，取 (丙) 之第三選項並依 (丁) 拆兩段**

執行層之三選項分析正確，其 (丙) 之判別尤其準：

> 補出來的是**今天的查核**，冒充成**當時的** —— 而追溯要問的恰恰是後者。

**裁定**：

| 段 | 對象 | 時程 | 記法 |
|---|---|---|---|
| **第一段：查** | **全部 feature** | **立即**（`ls` 一次即知，成本近零） | 記入各該 feature 之 `RECON.md` 或等價處，**逐則標明「事後補查，YYYY-MM-DD」** |
| **第二段：出表** | **僅查得有物件者** | **隨其下一批** | 「由圖找列」二欄表，同 R-G28 之要求 |

**拘束（逐字入 `R-G28` 之成因段，T68b）**：
> **事後補查之記錄一律標明其為事後補查與其日期。**
> 其產物為**今天之事實**，**不得表述為「當時已查」** ——
> 二者在紙上長得一樣，而它們回答的不是同一個問題。

**七個既有 feature 之「未記明」不追改為「已查」** —— 其洞具名留著（同 FO §9.4 之精神）。

**改了 canon 卻在其後才說它該怎麼提交。**
