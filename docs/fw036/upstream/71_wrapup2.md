## 5. 獨立自評

### 5.1 §六-5：審閱者之第一個問題，現行交付說明答得了嗎

**答：其第一個問題最可能是「這 195 個 PENDING，哪些是你們的問題、哪些是我們的？」——
而現行結構答不了它，因為 `PENDING_LIST` 依 DR 與型別編排，不依責任歸屬編排。**

**(甲) 為何是這個問題。** 一份 317 個 TC 之簿，其中 195 個帶佔位 ——
**審閱者之風險不是「測試寫得對不對」，是「這批東西還要多久才能用」。**
**而那取決於「誰欠誰」。**

**(乙) 現行結構之缺口。** `PENDING_LIST.md` 有 DR 欄與型別欄，**而二者都不是責任**：

| 現有欄 | 其所答 |
|---|---|
| DR 欄 | 「這個佔位在等哪一封信」 |
| 型別欄 | 「這個佔位缺的是觀測／觸發／判準」 |
| **（缺）** | **「這個缺件該由誰補」** |

**(丙) 而責任其實可由現有資料導出，只是沒有被寫出來**：

| 歸屬 | 其形態 | 概估 |
|---|---|---|
| **上游之欠件** | 規格未載（值、判準、清單） | DR-SU1／SU4／SU6 之多數 |
| **台架能力之欠缺** | 觀測或觸發手段不存在於現行環境 | DR-SU2 (a)(b)(d)／DR-SU7 |
| **上游之切分決定** | 需求該不該合併 | DR-SU3 全部 |
| **外部系統之可及性** | 伺服器側／他 ECU | DR-SU2 (e) 與其子形態 |

**(丁) 故建議 T84 之交付說明加一節「Who owns each gap」** ——
**四類，各給其 TC 數與一個最強實例。**
**其成本為一張表；其收益是審閱者第一個問題有地方可答。**
