# 改善案效果量尺（27 包 §六）

**立此表之理由**（26 上繳 §十三-3 第 4 項）：改善案之立案理由是
「往返太多、規則不遵守」，而**全案未定義任何量測該二者之指標** ——
往返數與違規數皆為**事後點數，非事前立的量尺**。
一個以「往返太多」立案而不量往返數的案子，**其成效只能用感覺主張**。

資料檔：`docs/fw036/IMPROVEMENT_METRICS.tsv`（每案結案輪追一列）。

## 三指標之定義（量測條件；未載條件者不予採認，FO §5a）

| 指標 | 定義 | 量法 |
|---|---|---|
| `roundtrips_per_workorder` | 下放包數 **＋** 重複包數 | 下放包數 = 該案 `docs/fw036/handoff/` 之 NN 序數；重複包 = 同輪多份且經 [SUPERSEDED] 標記者 |
| `violations_caught` | 被閘或覆核攔下之規則違反，**逐型列舉不加總** | 只計「攔下」者；未被攔而事後發現者不入本欄（其屬遺留清單）|
| `gate_first_red` | 結案輪 `gate_all.py` **首跑**之紅支數 | 首跑 = 該案最後一包上繳前之第一次執行 |

## 本表自身之限制（先寫下來，免得下一案讀成保證）

1. **三指標皆為過程指標，不是產物品質指標。** 往返變少、違規攔得多、
   閘首跑全綠，**都不直接等於 TC 更好**。本表量的是流程，不是交付物。
2. **`violations_caught` 之增加可能是好事也可能是壞事** —— 攔得多可能
   表示閘變強，也可能表示違反變多。**單獨看這一欄無法判斷方向**，
   須與 `gate_first_red` 併讀。
3. **`roundtrips_per_workorder` 之下降可以用「把工單做大」買到** ——
   一包做完等於一次往返。**故下一案須同時記其工單之範圍**，
   否則此欄可被無意識地優化。
4. **本案之基線是回溯建立的**（事後自上繳包點出），而**下一案起
   應於各輪即時記錄** —— 回溯點數正是本表要終結的作法。
