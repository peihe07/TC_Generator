決策矩陣 — 這個情境該用哪一邊？
情境 預設模式 原因
第一次跑一個標準 TC 產生 GUI 每個欄位看得到、每步可預期、符合 ASPICE 稽核
跑熟的重複任務（第 10 次同類型） AGENT 一句「跑這份」比點 5 個 module 快
逐筆 accept / reject / edit Expected Result GUI Review Module 的 memo 編輯 + side-by-side 比 chat 直觀
增量補生成（某幾個 REQ） AGENT 「補 REQ-045 到 052」一句解決；GUI 要手動勾選
跨 job 比較 / 查詢歷史 AGENT GUI 沒有這個功能；Agent 呼 list_jobs 就能做
手動調整 grouping（拖曳） GUI 拖曳互動非語言能描述；Configure Module 原生支援
validator 出 warning 不確定怎麼修 AGENT Agent 能診斷並建議 retry / 升級 / 改 prompt
批次匯出 / 排程 AGENT GUI 未支援；Agent loop 或 cron 皆可
正式交付 / 客戶送審的最後一版 GUI Export 前人工走一遍 Review，責任鏈清楚
探索性：「這批品質如何？哪幾筆最弱？」 AGENT 對話式分析 + Agent 能直接讀 validator 結果
三個典型劇本 — 實際切換時機
劇本 A — 純 GUI（日常 SOP，佔 60% 使用量）
開啟 Upload Module → 拖檔
Configure Module → 確認 grouping
Generate Module → 跑
Review Module → 逐筆 accept
Export Module → 匯出
→ Agent 完全沒登場。QA 照 SOP 做事，合規安全。
劇本 B — 混用（中段求助 Agent，佔 30% 使用量）
GUI Upload + Configure，照往常開始
Generate 跑完後 Review 看到 2 筆 validator warning，不確定要 regenerate 還是手改
切換點 → 點 taskbar [AI] 按鈕，問 Agent：「這 2 筆該怎麼處理？」
Agent 分析後建議「升級 gpt-5 重跑這 2 筆」，使用者按下選項
Agent 呼叫 regenerate tool，完成後 tool card 顯示「[Open in Review]」
切換點 → 點 Open in Review，回到 Review Module 確認結果
Review 完成 → Export Module 匯出
劇本 C — 純 Agent（跨 job 查詢或批次，佔 10% 使用量）
只開 ChatModule，問：「過去一個月哪些 job match rate < 80%？」
Agent 呼叫 list_jobs + get_job_detail 批次查，列出 3 個 job
使用者：「幫這 3 個都補掛 SYS1 spec 重跑」
Agent 逐個 regenerate，回報每個 job 的新 match rate
要正式交付時 → 點某個 job 的 [Open in Review] 轉 GUI 做最後檢查
→ 這類工作 GUI 原本做不到，現在變成一句話。
該切換的信號（給使用者的判斷提示）

GUI → Agent 的信號

  • 發現 UI 上沒有這個操作（比如批次、跨 job）
  • 要重複做同一件事 超過 3 次
  • 不確定該選哪個模型 / batch size
  • Validator 警告看不懂，不知下一步
  • 要「問資料」而不是「改資料」
  • 指令像人話（「上週那個」「差不多就好」）

Agent → GUI 的信號

  • 要 逐筆對內容做決策（accept / reject / edit）
  • 需要 視覺化操作（拖曳分組、side-by-side diff）
  • 正式交付 / 送審前的最後檢查
  • Agent 連問 2 次以上確認細節，不如自己點
  • 需要完整 audit trail 存檔的「正式動作」
  • Agent 成本超過預算（降模式節省）
