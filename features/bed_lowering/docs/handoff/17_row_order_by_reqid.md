## 一、要做的事

交付本 151 列依 `Requirement or Design ID`（D 欄）**升冪重排**，
TC ID 隨列重新指派 `newR1L-BLM-001` ~ `-151`。

### 1.1 排序鍵

`SWE1-HMI-BLM-{nnn}-{mm}` —— **`nnn` 與 `mm` 皆按數值排序，不按字串排序**。
（字串排序會把 `-10` 排在 `-2` 前面。三位數與兩位數之零填充使字串排序
在本案恰好等價，**但仍以數值排序實作並於上繳具名此點已驗**。）

### 1.2 允許之作法

**不得**以 `patch_cells.py` 逐格搬移（151 列 × 16 欄 = 2,416 格，
搬移過程中任一步錯位皆難察覺）。

採：自 `bed_lowering_11.xlsx` **讀出 151 列全欄** → 依排序鍵重排 →
以 XML 外科式寫回**同一份母本副本**（即自 `00 起建` 之 R-G1 母本重新
FILL 一次），產出 `bed_lowering_12.xlsx`。

**來源為工作簿實檔，不是 batch json** —— batch json 缺 B 類修正
（022 群入口、027-03 前置、四處文法），自 json 重建會把已修正的內容
倒退回未修正版。**此點為本包最大風險，請於上繳具名如何確保。**

### 1.3 重排後之驗證（全數必做）

1. **內容不變性**：重排前後,以 `req_id` 為鍵配對 151 列，
   逐列比較除 TC ID 與列號外之**全部 15 欄**，差異須為 **0**
2. **排序正確性**：D 欄逐列與前一列比較，`(nnn, mm)` 嚴格遞增
3. **TC ID 連續性**：`001` ~ `151` 無跳號、無重複
4. **計數**：151 列、母體對帳不變
5. **保全計數**：`11` vs `12` 全等（legacy DV 與 x14 分開計）
6. **全簿 lint**：151 列 clean
7. **round-trip**：讀回實檔與重排後之期望值比對，**期望值須來自
   §1.3-1 之配對表，不得來自產生寫入的同一支函式**（上繳 07 之教訓）
