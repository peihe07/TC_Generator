R33-1  P-6 —— -005 維持讀法 (i)，TC2 改寫
  裁：
  (a) TC2 之 design_method 由 `負向測試 (Negative / Invalid)` 改為
      `功能測試 (Functional based ; no specific technique)`。
      理由：其程序未注入任何非法輸入，只觀察輸出集合之封閉性，
      不合 §12 第一列 `Invalid input / illegal op` 之條件。
  (b) TC2 之 tc_title 與 test_item 改寫為**輸出集合封閉性**，

  (c) 真正之負向（向 AMP 注入集合外之值、驗 AMP 不動作）

      並列入 RD-1。
  (d) **先例（本裁決之主要產物）**：
      **§7 之負向配對要求，當本 ECU 不具備構成該負向之位置時，

      成因（逐字收錄執行層之自我歸因，較分析層之原判更準確）：
      「§7 談的是 TC 的配對，§8.4.2 談的是行為的歸屬 —— 兩者在這片
        葉子上相衝突，而我只套了前者。reasoning 裡已寫出 outcome
        主詞是 AMP，卻沒把那個認知接回設計方法的選擇上。」
      §5a：**已寫入 reasoning 之認知，必須回頭檢查它是否改變了
        其他欄位的選擇**；reasoning 不是傾倒觀察的地方，是推導的一環。

      請指出其 CFTS022 出處或補充條文
  理由：不對稱錯誤代價指向補測（擴範圍）而非不測（縮範圍），

      據以生成 TC 會對合規實作產生誤判（§7 FF）。故先問後補。

**逐葉範圍指示：**

  兩對皆須各自成 TC，**不得合併**（framework Part VI 注 1）。
  但兩對之間**不得互相補齊措辭** —— -006/-007 是自動調整側，
  -009/-010 是使用者調整側。
- **AMP present 與否之建立方式**：`Acustic_Configuration` /
  `Audio_System_Type` PROXI 參數（VF651_V6_R2，HDCC28 版
  `e20ba7a4…`，現已 citable）。**PROXI 參數之具體值若條文未給，
  依 §8.4.1 不得自行填**。
- **-008 之 outcome 主詞為 AMP** —— 與 -005 同型。
  **依 R33-1(d) 先判注入點／觀察點是否落在本 ECU**：
  若該行為之可觀察面全在 AMP 側，依 §8.4.2 排除並指名歸屬，
  **不得**以觀察 HU 側行為冒充。**此葉之判定結果須單獨回報**，
  不得逕行產出後才說明。

  （R24-2 / R28-2）。VF651 之引用形式須於本批首次使用時回報，

## 3. 停手條件

1. 2.4 之 lint 對 B1 回跑 findings ≠ 0 → **停止 2.5（B2 生成）**，
   續行回報 findings 逐條。不得為使 B1 通過而放寬 gate
2. 2.4 之陽性對照有任一 gate 無法被觸發（即該 gate 不可能失敗）→
   停止該 gate 之入庫，標「未實測」而非 PASS，續行其餘
3. **-008 之 ECU 判定落在「可觀察面全在 AMP 側」** → 停止該葉之生成，
   續行其餘四葉，回報判定依據
4. 任一葉需要 §2.5 表以外之 artifact id → 停止該葉，續行其餘，回報
   （id 一律查得，不得推算 —— R30-1）
5. 台帳任一條指令 FAILED → 停止全部，回報
