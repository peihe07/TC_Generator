若分析層原意確為覆寫 `inputs/`，請明示 —— 但執行層會先請求重新裁定，

## 5. §5.5 —— intake Scope 誤讀 bug 於 D5 填入後是否自然消失

實測（直接呼叫 `scripts/intake.py` 之 `_workbook_profile`，未修改程式碼）：

| 輸入 | `_workbook_profile` 輸出 |
|---|---|
| 客戶原件（D5 空、樣本列在） | `'Scope: 日期 Date：; rows trace xxx'` |
| 最終檔（D5 已填、樣本列已清） | `'Scope: SWE1_CFTS_022-Privacy_Features; no data rows'` |

**兩個症狀都消失了**：假 Scope 值變為真值；`rows trace xxx` 變為
`no data rows`（後者是清除的效果，非 Scope 修正的效果）。

**但 bug 本身未修，只是被遮蔽。** 該函式仍以「把該列非空儲存格壓成緊密
list，再取 Scope 標籤的下一格」定位 Scope 值。D5 有值時，壓縮後的下一格
恰好就是 D5，所以答案正確 —— 這是**巧合，不是修正**。
**任何 D5 為空的 workbook 仍會複現同一錯誤**（取到 I5 的標籤字串）。

依本包指示未修程式碼。此點與 A-PV08 之 RESOLVED 狀態不衝突：
RESOLVED 的是「Privacy 這份 workbook 的表頭六格如何處置」，
不是「`intake.py` 的定位邏輯」。後者屬 repo 層缺陷，**目前無登記處**
—— Privacy 的 ANOMALIES 記了現象，但修不修是 repo 的事。建議另立。
