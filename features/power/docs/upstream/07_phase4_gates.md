### 2.1 特徵字串之抽取方式（執行層自裁，下放包要求說明並舉例）

對每個黑名單錨點取其內文，以 `(?<=[.;:])\s+|\n+` 切句，
保留長度 ≥ **40 字元**之句子，再**扣除任何也出現於被引用錨點內文中的句子**。

**扣除這一步是必要的**，否則會誤判合法 TC。兩個錨點常共用樣板句 ——
例如「In the following "Ignition Working Conditions": Ignition Pre Off, Ignition Off,」
同時出現於 §1.6.2.1.10 之 `4941431`（被引用）與 §1.6.2.1.11 之 `4941434`（被引用），
若不扣除，任何合法引用其一之 TC 都會因「命中另一個」而 FAIL。

實測：814 個黑名單錨點中 **733 個具獨有特徵字串**，共 **1398 句**。
其餘 81 個之內文全為共用樣板或短於 40 字元，故無特徵字串 ——
這 81 個只受閘門 (a) 保護，(b) 無法涵蓋，**已知限制**。

**舉例**（自 `4941009`，CFTS009 §1.1 Revision Notes）：

```
Initial Release based on SR25 CFTS009 extracted on Mar 26, 2025.
```

### 2.3 fixture 首次執行即抓到一個真 bug

**首次執行時 (a) 完全不觸發。** 原因：`ANCHOR_ID_RE = r"\b\d{6,8}\b"` ——

### 100% 歸屬率之成因（R-P53 要求說明）

每一處參照都**緊接在其錨點的後一段**（距離 1 或 2），而下一個錨點最近也在其後兩段。
此非規則過度擬合，而是 Polarion 匯出之結構必然：
錨點行是 metadata（`[Artifact Type:…]`），其後緊接該需求之內文，參照即嵌於該內文中。

3 個前後等距者（前距 2、後距 2）仍取前者 —— 此 tie-break 與 §C rule 2
（需求錨點歸屬於其前最近之章節錨點）同一慣例，**非本包新創**。
