## 二、B2 —— `input_test_data` 排除界線（R-P205 / G139）

**排除已實作，且能區分二型。判別方式（保守白名單，非一律排除）**：

1. 僅 `input_test_data` 之**純數字** token 適用
2. 該數字所在**行**若含**規格參數之跡象**（含底線之識別子、`PROXI`、
   `Timeout*`、`$…$`）→ **不排除，仍觸發**
3. 否則須逐字命中「測試選用量」之措詞（`events` / `interval` /
   `volume level` / `starting volume` / `measurement window` / `burst` /
   `iterations` / `cycles of injection`）方排除；
   **其餘一律觸發並入待裁類**（本條明令「不能區分時寧可觸發」）

**fixture 四案如期**：

| 案 | 期望 | 實際 |
|---|---|---|
| `Event burst: 20 events injected at 100 ms intervals` | 不觸發 | 不觸發 |
| `Starting volume level: 25` | 不觸發 | 不觸發 |
| **`Switch_Off_Time: 20 minutes`（規格參數值）** | **觸發** | **觸發** |
| **`Timeout1: 30 minutes, measurement window per events`** | **觸發** | **觸發** |

末案即本條所慮之情形 —— 同一行兼有測試量措詞與規格參數名時**不得排除**，
已由規則第 2 條攔下。

**一項須明說**：本條舉 `20` 為規格閾值之例，而語料中 `20` 亦出現於
`20 events injected`（測試選用）—— **同一數字得為二者之一，端視上下文**，
純詞彙規則無法可靠區分，故採白名單而非黑名單。
