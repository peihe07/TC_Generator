```
[R-P210] R-P204 未涵蓋 §8.4.1 之造值；(a) 型之狀態值須有依據。
         28 §1.1 第 13–14 項：`SWE-PM-094` 之 `187` 前提為
         `The HU is in STANDBY MODE`，
         **而該 leaf 之 clause 完全未提任何模式**。
         執行層依 R-P204(a) 判為合法環境設定並註記，
         其自陳「那個模式是誰選的、為什麼是 STANDBY，規格沒說，
         我也沒有來源。**通過判準不代表前提是對的**」。

         **該自陳成立。R-P204 只處理 §8.4.2 之依據越界，
         未處理 §8.4.1 之造值。**
         §8.4.1 之禁止清單逐字含 `default states` ——
         選定一個 clause 未載之起始狀態，即為造一個 default state。

         風險為實：若待驗行為僅於某些狀態下發生，
         將起始狀態定為 `STANDBY` 可能使測試根本未觸及該行為。

         判準（補 R-P204 之不足）：
         （a）該狀態值**逐字見於本 leaf 之 clause**
              → 合法，無須額外說明（即第 1–12 項之情形）
         （b）該狀態值**未見於 clause**
              → 須於 `reasoning` 載明二事：
                （i）該狀態之選擇依據為何（測試可執行性／他 leaf 之定義／
                     規格他處之明文，逐一指出）
                （ii）待驗行為是否隨該狀態而異；若是，
                     其他狀態是否需另立 TC
              二者無法說明者，**標為待查並列入 DR 候選**，
              不得以「已通過 R-P204」結案

         處置：以本判準重掃全部 264 條之 `pre_conditions`，
         逐項分 (a)/(b) 並回報；(b) 型逐條依上開二事處置。
         R-P204 依 R-P36 原文不改，於其下加註指向本條。
         裁決者 Pei，逐字依據：「上繳」。
```

```
[R-P211] `$Day_Night_Mode$` 二項之裁定。
         28 §四：`SWE-PM-091` / `SWE-PM-092` 之
         `$Day_Night_Mode$` 係執行層為驗「設定覆蓋訊號」而注入，
         **而其 clause 未載該訊號**；執行層列為真陽性候選、未自行處置。

         裁定，依 clause 之實際內容分二情形：
         （a）該 leaf 之 clause **載有某種「設定覆蓋訊號」之機制**
              （不論其所舉之訊號為何）
              → 該機制在範圍內，惟**所用之訊號須為 clause 所載者**；
                以 `$Day_Night_Mode$` 代之為造值，
                須改用 clause 所載之訊號
         （b）該 leaf 之 clause **未載任何覆蓋機制**
              → **真陽性**（§8.4.2）：該 TC 測試本 spec 未擁有之行為，
                須移除該注入，或改寫為僅驗 clause 所載之行為

         處置：先引該二 leaf 之 clause 逐字，判其屬 (a) 或 (b)，
         再依上開處置；**不得以「為驗證需要」為由保留無依據之注入**。
         裁決者 Pei，逐字依據：「上繳」。
```
