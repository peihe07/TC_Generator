## 五、須先裁之三事（施作前）

### 1. R-P356 之前提在現行 corpus 上不存在

現行 corpus 之 `specification_reference` 為 `{spec_filename}_{section_id}`
（feature.yaml `spec_reference_template`，如
`…CFTS_009_Wake-up and Power-up_SR26_20250909-1658_1.6.2.1.2`），
**全 283 條無任何一個 ObjectID**。H 家族 = 0。

R-P356 條文為「每列僅保留其 `test_item` 括號下半所對應之 ObjectID」，
其標的（整段共用之 6–11 個 ObjectID）在現行 corpus 上無一實例。
**請裁**：(i) R-P356 於本包無標的，記明後略過；或
(ii) 其意旨改適用於 `section_id` 之收斂（則須另給判準，本層不自行推定）。

### 2. R-P357 之四欄鍵在現行 corpus 上會誤刪

現行 corpus 25 對四欄（Test Item / Pre / Procedure / ER）逐字相同者，拆為二類：

- **14 對為誤判**：其 Procedure 寫 `… the event listed in Input Test Data …`，
  區辨內容落在 **Input Test Data** 欄。例：
  `-039` ITD `Ignition working condition: "Ignition Off"` 對
  `-042` ITD `"Ignition Pre Off"`；
  `-166/-167/-168` 分別為 FOTA update available for the Radio / TBM / ROV。
  此為 pm_29 所無之型別（44 包之後才出現）。依 R-P357 逐字施作會刪掉真實測項。
- **11 對為真重複**（ITD 亦逐字相同），惟其 `req_id` **全數不同**
  （如 `-149` `SWE-PM-054` 對 `-192` `SWE-PM-101`）。

**故依 R-P357(a)（同 Req ID 刪後者）在現行 corpus 上之可刪列為 0；
11 對全部落入 (b)，二列皆保留，僅於 Remarks 互註。**
連帶：**B6 三代對照表本包無異動**（無刪列）。

**請裁**：R-P357 之比對鍵是否加入 `Input Test Data`（五欄）。
本層建議加入，但此為判準變更，不自行為之。

### 3. R-P358(c) 之 `#325` 在 pm_29 上即不成立

附件註明「列號 = 工作簿 `No.#`」。pm_29 `No.# 325` 為 `SWE-PM-089` 之
**R-P141 留白列**（req_id 有值，其餘全空），非「Test Item 缺括號下半」。
若改讀為 tc_id `-325`（= `No.# 326`），該列 Test Item 括號下半完整
（`(read the applied theme -> The HU shows the Day theme)`）且 Procedure 有 2 步。

**二種讀法皆與描述不符。** 依 R-P358(c) 逐字施作於留白列，將違反 R-P141。
**請裁**：指明所指之列，或撤回本項。
