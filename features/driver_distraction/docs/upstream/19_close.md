## 五、T28b —— 空集合之出口

### 5.1 改法：自結構導出，不繫於「組 6 恆存在」

```python
def _oos_sources():
    """回傳 {來源名: (有無範圍外之標記, 解析所得之 leaf 集合)}。"""
# (i) 標記之有無須二來源一致 —— 一有一無與名單不一致同級
# (ii) 有標記而解析為空 → 停；**無標記而為空 → 合法，通過**
# (iii) 再比名單相等
```

**次序不變**（先自洽、後相等），且輸出加註標記狀態：
`範圍外（…；標記 有）4：[…]` ／ 無標記時印 `標記 **無** —— 合法為空`。

### 5.2 ⚠ 明命之「期待為綠」注入 X —— **實跑是紅的**

| # | 注入 | 期待 | 實測 |
|---|---|---|---|
| **X** | 二來源**同時**移除 `OUT OF SCOPE`／「範圍外」標記 | **綠**（下放包 22 §五 明命）| **exit 1** |

**分解其紅之來源**：

```
範圍外（profile §5 ∩ framework Part II，二來源一致；標記 **無** —— 合法為空）0：[]
閉合：可出貨 24 ＋ 不得出貨 0 ＋ 範圍外 0 ＝ 24　對 28 leaf：❌ **不閉合**

```

**即：空集合閘本身通過了**（印出「合法為空」，未停）。
**紅來自閉合總數與第三項覆核** —— 而**下放包 22 §五 之裁定文自己就這樣寫**：

> 若…無任何列標…→ 範圍外名單合法為空，通過（**閉合另由總數對 leaf 數攔**）

**故該注入在現況下不可能綠**：四個 leaf 未生成，把它們的「範圍外」身分拿掉之後，

「範圍外名單**合法**為空」之情境是：**28 leaf 全部在案且全部產出**。
