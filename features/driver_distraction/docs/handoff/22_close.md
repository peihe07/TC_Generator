## 二、R-DD26 v2（全文；v1 留存）

```
R-DD26 v2（跨包引用之前提須為已量測之狀態；前提之搬運為雙向）

分析層於下放包中引用之數字、狀態、清單，若其成立繫於**前一包之執行與否**，
則該引用為**前提之搬運**，非事實之陳述。

(a) 凡書「應為 X」「現況為 X」者，X 須為**本庫可量測之現況**，
    或明標其前提（例：「補包 19 後應為 X；現況為 Y」）。
(b) 跨包之效果**不得預先計入** —— 包 N+1 不得以包 N 之預期效果為基線。
(c) 執行層遇下放包所書之期待值與實測不符時：**照實回報實測值，
    不調整產物或判準去湊期待值**；並回查該期待值所繫之前提是否成立。
    「數字不對 → 先查自己剛改的地方」之直覺有一個盲點 ——
    **它假設上一個已知良好狀態真的存在**。
    **查錯之前，要先確認基線是量出來的，不是讀來的。**
(d) 本條與 §2.4（改一處狀態陳述須全帳 grep）互補：
    §2.4 治**同一時點之跨檔不一致**；本條治**跨時點之前提失效**。
(e) **前提之搬運為雙向**（v2 新增）。二個方向皆為本條所治：
      正向 —— 假定上一包**已**執行而其未執行（包 20 之誤：期待 24，實得 23）
      反向 —— 假定上一包**未**執行而其已執行（包 21 之誤：派工成為 no-op）
    前者使執行層查錯，後者若照做即**二次編輯**（無所得或有損）。
(f) **執行層於執行前先驗前提**（v2 新增）。下放包所書之前提不符現況時：
    **驗而不做，並把驗法逐列寫出**供分析層覆核；不逕自重做，亦不逕自略過。
(g) 分析層書前提時，應標明其**量測時點**（例：「依上繳 17 之實測」），
    使跨時點之失效可被辨識。
（分析層裁；v2 2026-08-29，下放包 22 §二）
```

## 三、R-DD27（反向注入 ＋ 臨時驗法；T-抄）

執行層 §9.4 之發現落條 —— **本輪最具一般性之一項**。

```
R-DD27（注入須含期待為綠之組；臨時驗法之結論須附驗法）

(a) 注入表最易騙人之處，在於它只收「**該紅的有沒有紅**」。
    **該綠的有沒有綠，同樣須注入。** 凡新立或改版之檢查項，
    其注入組須至少含**一組期待為綠者**（證 carve-out 未關太緊、
    或證改法未引入偽陽性）。
    先例二：上繳 15 之注入 Q（`reasoning` 用中文須綠）—— 下放包明命；
    上繳 18 之注入 U（二式混用須綠）—— **無人命而執行層自為**，
    且其為該改法之淨新增價值所在。
(b) 一組注入之價值，須以「**新舊之別**」陳述，非以「有沒有紅」陳述。
    舊版亦會紅者，其所得為**訊息之準確**，不得書為「攔下了」。
    陳述改法所得時，須實跑**舊版**取其行為，不得由裁定文之敘述推定
    （下放包 21 §四 10-5 即為推定之誤，見下放包 22 §1.1）。
(c) **一次性核對腳本不受任何拘束，而其結論會被寫入上繳包。**
    凡臨時驗法之結論入包者，**須同時寫出其驗法**（可為一行程式或其判準），
    使覆核者能判其是否量到了它宣稱之物。
    先例：上繳 18 §2.1 之 `ovr.count('"R-DD20') == 3` ——
    該字串在鍵與值中共 6 次，**驗法錯而檔案是對的**。
（分析層裁，下放包 22 §三）
```

## 四、11-3 —— 「以位置代副本」之全帳清查（T28a）

執行層 §3.2 之實測：前版所指之 `docs/handoff/02_…` §三 存者為**最初稿**
（1149 字元、無 SYSAD 引文段），**非被替換之稿**（2020 字元、含引文段）。

> **裁定假設之風險是「他檔會被移動」；實況是該檔從一開始就不是那一份。**
> **指標之風險不只在目標會消失，更在指標本身可能一開始就指錯。**

**裁定：全帳清查，範圍限三檔**（`DATA_REQUESTS.md`／`ANOMALIES.md`／
`COVERAGE_GAPS.md`）。**判準**：條目之內容以「見某某包某節」代替實體副本者
即為命中。逐項處置：

- **已被取代之文稿**（如 DR 舊稿）→ 依 10-4 體例留摺疊副本
- **仍現行之內容**（如條文之出處註）→ **不必複製**，惟須驗其指標所指與所述相符
  （**取一驗一**，不得只驗其存在）
- 命中而無法取得原件者 → 記入 `COVERAGE_GAPS.md` 或該條目，
  **不得以「指標仍在」充作已保存**

## 五、11-4 —— 空集合之出口（T28b）

現行判準「framework 組 6 恆存在」為**外部事實假設**，日後範圍外名單合法為空時會誤停。

**裁定：改為自結構導出，不繫於特定組。**

```
若 framework Part II 無任何列標 `OUT OF SCOPE`
   且 profile §5 無任何列標「範圍外」
→ 範圍外名單合法為空，通過（閉合另由總數對 leaf 數攔）

若二來源之一有該標記而其解析結果為空
→ 停（解析失敗之徵候）

若二來源之標記有無不一致（一有一無）
→ 停（與名單不一致同級）
```

**次序不變**：先各自驗「標記有無 vs 解析結果」之自洽，**再**比相等。
**附一組注入**：二來源同時移除 `OUT OF SCOPE` 標記 → **須綠**（R-DD27(a)）。
