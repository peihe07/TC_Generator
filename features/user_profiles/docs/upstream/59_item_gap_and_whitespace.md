### 2.1 兩處「看似多餘」者 —— 查過，都是刻意的

**(1) `design_method` 之分號前空格（189 列全部）**

```
功能測試 (Functional based ; no specific technique)
```

那個空格**出自母本「下拉選單」工作表之逐字值**（實測 9 條全部如此，
另有 `組合測試 (Combinatorial Testing ; Pairwise / t-wise)` 同形）。
**它是客戶的枚舉字串，不是我方的排版** —— 改了即與 R 欄之 DV 不符，
`audit_enums` 會紅，而在客戶的表單裡那格會變成非法值。

**(2) `M` 欄 23 行之三格縮排**（`TC-039`／`TC-013`／`TC-076`）

```
2. The row list shows only:
   a. Personalization (Presets, Menu Bar Order, App Drawer Favorites, and more)
   b. App Store Download
```

那是 §6.1 之**子層列舉**，且 `K-3` 之判準
`SUBLIST = re.compile(r"^\s+[a-z]\.\s", re.M)` **以該縮排為抑制條件** ——
拿掉縮排有兩個後果：**層級在交付件裡消失**（`2.` 與 `a.` 變成同一層），
且 `TC-039`／`013`／`076` 三條會被 K-3 判紅（「指代一張表而未列舉」）。

**兩處都可以改，但都不該由我逕行改** ——
一處是客戶的字串，一處會使三條轉紅並失去層級。
**若仍要改，請指定哪一處**：

- (1) 需連同 `feature.yaml` 之 DV 對照與 `audit_enums` 之詞表一併處理
- (2) 需同時改 `K-3` 之 `SUBLIST` 判準（否則是「改了資料去迎合閘」的反面 ——
  閘會叫，而叫得對）

## 4. 獨立判斷

1. **這一輪最值得記的是「掃了沒有可去的」也要附輸出。**
   若只回「已檢查，無多餘空格」，那句話與「我沒檢查」在紙上長得一樣（G-D 之形）。
   附上七類各自的 0，讀的人才知道我查的是哪七類 ——
   **也才看得出我沒查哪些**（例如我沒查字型層級的空白，那不是字串問題）。

2. **兩處「看似多餘」的空白，恰好各代表一種不該動的理由。**
   一處是**別人的值**（客戶的下拉選單），一處是**我們自己的閘所依賴的形態**。
   前者改了會壞掉交付件的合法性，後者改了會壞掉三條 TC 的判定。
   **「多餘」是視覺判斷，而視覺判斷在有 DV 與有閘的欄位上不成立。**

3. **空行這件事暴露了一個小缺口**：呈現層的規格（兩段之間空一行）
   **沒有任何閘保護**，因為它對所有既有判準都是無差別的。
   我加的那條綠向案例只是把它記下來，**不能防止它被改掉** ——
   要真的防住，得有一支「`test_item` 須恰為 `<行>\n\n(<行>)`」之形態閘。
   本輪未立，**具名為已知未查**（canon §9.5 之同類）。
