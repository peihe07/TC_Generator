## 3. 異議兩項（09b：草案為分析層所擬，非不可質疑）

### 3.1 異議一 —— **C 類之三條只有一部分被取代，整條標記會誤傷**

| 條 | 被取代者 | **仍然生效、且正在被使用者** |
|---|---|---|
| **`R-U3`** | 「證據＝內文完整」之解讀（R-U25 拆為兩面）| **spec 基線之檔名、`spec_mode = A`** —— `R-U1` 之 `specification_reference` 格式即依此，framework §1 每天在用 |
| **`R-U15`** | 阻斷範圍（R-U27 收窄）| 「非 Phase 1 阻斷」「**不得以鄰近 PU id 推定內容**」「不是版本不對，是這一版沒有這兩列」—— **R-U27 自己就引用了最後那句判讀** |
| **`R-U22`** | 引用範圍之限縮（R-U39(2) 改可測判準）| 「先驗可讀性不逕列阻斷」「**037 沒引用不等於 spec 沒寫**」「據此重估 A-UP02」—— **R-U28 整條建於其上** |

**問題之形狀**：一條裁決包了數件事，日後就只能整條取代或整條保留，**兩者皆失真**。

- 標整條 `[SUPERSEDED]` → 讀者會以為 `spec_mode = A` 也失效了
- 不標 → 那個被取代的部分繼續生效

**本輪之處置**：依 09b 明文照辦（加 `[SUPERSEDED by R-xxx]`、原文不改），
**並於 `RULINGS.md` 之同段附一張「仍然生效者」對照表**，逐條寫明範圍。

**請裁**：是否改為 `[PARTIALLY SUPERSEDED by X — <哪一項>]`。
本層傾向改 —— 理由是**現在的標記與事實不符**，而對照表只是補救，
下一個讀者未必會讀到它。

**已升格為通則**（canon §9.1 第 11 項、§9.3）：**一條裁決只管一件事。**

### 3.2 異議二 —— **`R-U6` 等條「整條升 A」會把 feature 事實一起升上去**

草案 A 類列 `R-U6`（BLANK 之 style authority），而該條同時含：

| 通則 | feature 事實 |
|---|---|
| 不得取本管線自身之產出 | style authority = Home 之 **144 列**；不採 AMFM 之理由；BLANK 綁定之四項 |

同樣情形在 `R-U25`（含本 feature 之 BASELINE 細節）、`R-U16`（含 037 之 SHA）、
`R-U14`（含 `A-UP09` 之編號）。

**本輪之處置**：升格單位改為**原則**，canon §9.1 之來源欄逐條標
「**僅其原則；某某未升**」，feature 側之對照表同樣標明。

**這一項我逕行調整了**（未先請裁），理由：09b 作業 2 寫「逐條寫入**通則**」——
「通則」二字已排除 feature 事實，故本層讀為草案本意如此，非擴權。
**若讀錯請指正。**
