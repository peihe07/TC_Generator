## 1. AD-1 之病灶 —— TI-2 的比對是字面的

`TI-2` 驗「第二段非僅重複第一段」，判準為
`" ".join(part2.lower().split()) == " ".join(head.lower().split())`
—— **逐字相同才紅**。而

```
New Profile Setup starts from the All Profiles tab
(Verifies that the New Profile Setup starts from the All Profiles tab)
```

逐字不同，故 189／189 全綠。**它不知道「換句話說」也是重複。**

## 2. 代理判準與門檻

### 2.1 門檻之選定依據（**先寫下，再跑** —— Q-1 之教訓）

去除 `Verifies that` 與停用詞後，取「**第二段帶進之新實詞數**」為量。
**門檻：新實詞 < 2 者列待判。** 依據三項，皆為 a priori：

1. **一個新實詞可能只是語法產物** —— 複數（`popup`／`popups`）、同一詞之另一形態
   （`activate`／`activation`）、或冠詞級的名詞。
   **兩個彼此獨立的新實詞，是能承載一件「標題沒說的事」之最小量。**
2. **取計數而非比率** —— 實詞數在本語料為 4–15，比率門檻會**懲罰長句**
   （同一個新事實，句子越長比率越低）。計數與長度無關。
3. **列待判而非轉紅** —— 「有沒有帶進新資訊」是語意判斷，與 AB-1 同類，
   機械判不了（55 輪 §7-3 已具名此類）。

**被否決之另一選項**：`第二段實詞 ⊆ 第一段實詞`（純子集）。其太嚴 ——
只抓得到「一個新詞都沒有」者，而 `173`（`more`／`one`）與 `166`（`same`／`way`）
各帶了新詞卻仍是改寫。**這一段寫在跑之前，見該檔 docstring 之版本。**

### 2.2 G-K —— 報命中數之前，先證明它對點名之三條會叫

```

      └ ORIG-168 新實詞 0 個 []

      └ ORIG-173 新實詞 0 個 []
  PASS — **56 包所點名之 `166` 之原文 → 須命中**: 命中，期望 命中
```

**三條之原文以字面固定於自我測試中，不讀語料。**
若讀現況，改寫一落地 G-K 之證明就跟著消失 ——
**判準是否抓得到該病，與該病是否已被治好，是兩件事。**
另加三條「改寫後不得再命中」之回歸，共 13 案例全綠。

### 2.3 盲區（R-G11）

1. **以同義詞改寫而實詞不重疊者抓不到**（56 包已點名）。
   `Welcome popup shown at ignition on` ↔
   `Verifies that a greeting message appears when the key turns` ——
   零重疊，本判準判它「帶進 5 個新實詞」，而它其實什麼也沒帶。
   自我測試以 `F-4` **明寫此案為「不命中」**，使盲區在輸出裡看得見。
2. **不判新實詞之重要性** —— 帶進兩個無關緊要的詞亦會過關。
3. **數字不是實詞** —— 分詞之首字元須為英文字母，故 `12-character` 只留下
   `character`。`176` 之第二段唯一帶進之新東西正是那個 `12`，
   於是它被判為待判（**偽陽**，見 §3.3）。方向是保守的（多叫，不漏叫），
   但這一條是本輪實際踩到的，**在此具名**。
4. 詞形還原為**去尾 s** 之粗略作法，不處理不規則變化。

### 3.2 殘餘 3 條 —— **不改，具名**

`036`／`041`／`060`。三條之**驗證目標句已由第一段完整承載，且其 ER 亦無
第一段未載之斷言**：

| tc_id | 第一段 | 其 ER 全文 |
|---|---|---|
| `036` | Edit Profile tab shows at most six lines per page | 1. 分頁顯示 2. 每頁至多六行 |

| `060` | Non-interactable items greyed out in Valet Mode | 1. 含鎖定項之畫面顯示 2. 所有不可互動項變灰 |

**要讓這三條之第二段帶進新東西，只能自行構思** —— 那超出本包授權

**把它寫進第二段是可行的**，但那是把「本條在測什麼」換成「本條在什麼條件下測」
—— **屬規格變更，交 Pei 判**，本輪不自行擴張。

### 3.3 偽陽 1 條

`176`：第二段為 `Verifies that a space is accepted in a username and counts
toward the 12-character limit`。**它確實帶進了新資訊**（空格被接受 ＋ 上限為 12），
而判準只算得出 `accepted` 一個新實詞 —— **數字被分詞規則吃掉了**（§2.3-3）。
**維持原樣**，並以此為「列待判 ≠ 轉紅」之實證。

## 5. 獨立判斷

1. **本輪最該記下的不是判準，是「G-K 的證明會被自己的修好殺掉」。**
   首版自我測試讀語料取 `168`／`173`／`166` 之現況，
   於是 31 條一改寫，10/10 立刻變成 7/10 —— **不是判準壞了，是證明沒了**。
   把三條原文以字面釘進測試才對：**判準抓不抓得到該病，
   與該病治好了沒有，是兩個獨立的問題，測試要分開問。**

2. **殘餘 3 條是這個判準最誠實的輸出。**
   它們不是「判準抓錯」，而是「該病確實存在，而在授權範圍內無藥可下」——
   第二段之來源被限定為 `reasoning` 與 ER，而這三條的 `reasoning` 與 ER
   都不比標題多說一句。**能修的都修了，修不動的說清楚為什麼，
   比湊三句話讓判準閉嘴誠實。**

3. **35 條裡有 31 條可修，代表 55 輪那一批第二段的問題比 56 包估的大。**
   56 包舉了三條，實際是 31 條 —— 即**六分之一的語料**。
   成因不是疏忽：55 輪之規則是「取 `reasoning` 之驗證目標句改寫為英文」，
   而**當該句與 `tc_title` 說的是同一件事時，忠實地改寫就會產生同義反覆**。
   規則本身沒有要求「第二段要比第一段多」——`TI-2` 也只驗了字面。
   **這是規則的缺口，不是執行的缺口。**

4. **對 `TI-2` 的建議（不自行實施）**：本輪之代理判準可作為 `TI-4` 併入
   `audit_delivery_fields`，但**它只能是黃燈**。
   現行 `TI-2` 是紅燈閘，把語意判斷塞進紅燈會逼出湊字數的第二段 ——
   **那比同義反覆更糟，因為它看起來像資訊。**
