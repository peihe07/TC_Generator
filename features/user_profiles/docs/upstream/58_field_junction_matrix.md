## 1. G-N —— 自我測試不得讀當前語料

### 1.1 條文

> **自我測試若以當前語料為案例，缺陷修好之後測試即失去證明力 ——
> 而它表現為分數下降，看起來像判準退化，實際上是證明消失。**
>
> **正解**：把缺陷之原文**以字面釘進測試**，
> 另加一組「**修正後不得再命中**」之回歸。

### 1.2 成因（56 輪之實測）

`audit_second_segment` 之 G-K 段首版自語料取 `168`／`173`／`166` 三條，
斷言其命中 —— 當時 **10/10**，證明成立。
AD-1 之 31 條改寫一落地，同一支測試立刻 **7/10**。

**那三個 FAIL 不是判準壞了，是判準的證明沒了。**
若當時把它讀成「判準退化」而回頭放寬門檻，
就會**為了讓測試變綠而弄壞判準** —— 這是本條真正要防的失誤。

### 1.3 兩個問題要分開問

| 問題 | 案例之來源 | 修好之後 |
|---|---|---|
| 判準抓不抓得到該病？ | **字面釘住之原文** | 永遠不變 |
| 該病治好了沒有？ | **當前語料** | 由紅轉綠 |

合成一個案例，兩個答案就分不開；**而分不開的時候，通常會誤讀成第一個。**

### 1.4 與 G-D／G-K 並列 —— 三者皆為「證據本身之有效性」

| # | 它防的是 |
|---|---|
| G-D | 空清單與壞清單**輸出相同** |
| G-K | 報 0 命中而**從未證明它會叫** |
| G-N | 證明**隨著修好而消失**，且消失時看起來像退化 |

**與 `audit_pending` 之 digest 不衝突**：digest 要求「語料一改就回列**重判**」，
G-N 要求「語料一改而**判準之證明**不得跟著失效」——
一個管**判定**，一個管**證明**。

## 6. 獨立判斷

1. **矩陣之價值不在「已查 14 組」那一欄，在輪次那一欄。**
   若只列已查，它讀起來像成果清單。
   加上輪次之後它揭露的是：**三組最基本的接合，五十五輪都沒有人問過。**
   下一個 feature 若只抄 14 組去實作，會複製這個 feature 的覆蓋率；
   **要抄的是「開工時先把接合關係列成表」這個動作** —— 那才是 §9.5 的用法。

2. **「不補做九組」這個決定本身需要被檢驗，我把它的依據寫進 canon 而非只寫進上繳。**
   理由：讀上繳的人是 Pei，而讀 canon 的是下一個 feature。
   下一個 feature 需要知道的不是「User Profiles 沒做」，
   而是**「在什麼條件下可以不做」** —— 語料定稿、交付件已出、
   每支新閘之首跑紅都要付四份 pack 加一次重寫回。
   **同樣的九組，在一個還在 P5 的 feature 身上，答案應該是相反的。**

3. **G-N 是這五十八輪裡唯一一條「從自己的錯誤裡長出來、而該錯誤差一點就沒被發現」的常規。**
   `10/10 → 7/10` 出現的那一刻，最省事的反應是回去調門檻。
   會停下來的原因只有一個：**三個 FAIL 全部落在剛剛被我改寫過的那三條上**——
   這個巧合太整齊了。
   若當初改寫的是三十一條裡的其他二十八條，這條常規不會存在。
   **它被抓到有運氣成分，而運氣不該是機制的一部分** —— 故立為條文。

4. **本 feature 分析層無未結項。** 餘 5 項皆屬 Pei：
   交付、git、`R-U17`、Tutorials PDF、RD v2 ＋ #8 ＋ A-UP14 之寄出。
