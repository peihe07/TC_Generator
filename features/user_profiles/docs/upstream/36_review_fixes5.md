## 1. Y-1 —— **採 (a)**，並說明其為何足夠

### 1.1 所擇與理由

**採 (a)。** 於 `TC-117`（`022`，5.3）之 ER3 加
`and the “Edit Profile” tab is not opened`，procedure 步驟 3 相應改為
`Read the screen and check that Driver Profile B is highlighted and no
editing screen opened`。

**§5.7 之併入在此成立**：「選取另一個 profile」是**一個觸發**，
其必然結果有二 —— 切換發生、且不進入編輯。
**兩者同一觸發，故併於同一條之 ER3，不必另造 TC。**

（若採 (b) 另立負向 TC，其 procedure 會與 `TC-117` 逐字相同、
只有 ER 不同 —— **那是把同一次操作寫成兩條**，
與 4.5.2／5.7 之配對不同：那兩處之正反兩條**操作本身就不同**
（互換 vs 再連一個、自 Edit Profile 連 vs 自他處連）。）

### 1.2 `TC-121` 之 remarks 隨之改述

> 其反向由 `SWE1-HMI-PROF-022` 之 **ER3 後半**承擔 ——
> 該句逐字為 `the “Edit Profile” tab is not opened`（36 包 Y-1 所補）。
> **在該句補上之前，該 `only` 無人驗** —— `SWE1-HMI-PROF-022` 原本只斷言切換發生。

**委派指到了 ER 行號**，而非只指 leaf —— 使日後複核不必重讀整條。

### 2.3 **落為掃描：配對之兩條須屬同一 leaf 群**

「被指者之 ER 有沒有那句反向斷言」是語意，機械判不了。

故其 `req_id` 之**基號**應相同（`030-01` ↔ `030-01-neg`、`010-01` ↔ `010-02`）。

**該判準抓得到本輪之兩處指錯**（`009`→`016`、`030-01`→`034-03`），
而跨 leaf 群之配對**不一定是錯的**（`121` → `022` 即為跨節之正當委派），
故列**待判**而非紅。

現行語料命中 **1 處**（即 `121` → `022`，已於 §1 處置）。
