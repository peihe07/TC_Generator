## 1. 作業 2 — R-U36：**本條之前提有誤，我在 07 輪歸錯邊**

R-U36 之立條依據為 07 包 §7 第 1 項，該項寫：

> `8.7` 之字內斷字（`spa ces`）—— **PDF 文字層**有此形態…

**那句是錯的。** 全量掃兩側之結果：

| 側 | 字內斷字之相異形態 |
|---|---|
| **xlsx（169 節 Description）** | **4** —— `aft er`／`know n`／`program med`／`spa ces` |
| **PDF（21 頁文字層）** | **0** |

`8.7` 之對照：

```
xlsx: Username can be alphanumeric with spa ces (spaces count toward…)
PDF : Username can be alphanumeric with spaces (spaces count toward…)
```

**是 xlsx export 插入了詞內空白，不是 PDF 抽取造成的。**
07 輪我在「對照向未命中」的清單裡看到那一行，**沒有分辨它印的是哪一側的字串**。

### 1.1 量測條件與偽陽性風險（08b 明文要求）

**判準**：`\b([A-Za-z]{2,})\s([a-z]{1,4})\b`，且

- 合併後之字（`ab`）**在詞庫內**，且
- 前半（`a`）**不在詞庫內** → **強證據**（`spa` 不是詞，`spaces` 是）
- 兩半皆在詞庫內 → 弱證據，另計

**詞庫**：以 **PDF 側語料自身**之相異詞（長度 ≥ 3）為據，**不引外部詞典** ——
理由是這份 spec 有大量專有名詞（`SPAAK`、`PROXI`、`TBM`），外部詞典會把它們
判為非詞而製造偽陽性。

**偽陽性風險，逐項列**：

| 風險 | 說明 | 本輪之實測 |
|---|---|---|
| **正常詞序被誤判** | `keep changes`、`save and` 之類，兩半皆為詞且合併後恰巧也是詞 | 弱證據組 **0 命中**，故未實際發生 |
| **詞庫不完整** | 詞庫取自語料自身；若某個真詞只以斷字形態出現過，合併後之字不在詞庫 → **漏抓** | **無法排除**。這是本判準之下界性質 |
| **跨行連字** | PDF 之 `deacti-vation` 型斷字 | 本 PDF 之文字層未見連字號斷行，未觸發 |
| **短尾詞** | `b` 限 ≤ 4 字元；更長之斷裂（如 `progra mmed`）抓不到 | 本輪之四例皆 ≤ 4；**更長者未量** |

### 1.2 C 組重報 —— **維持 3.6%／2.1%**

四個形態所在之節為 `4.4`／`5.5`／`5.6`／`8.7`，
其現行分類**全部為「標點/空白差異（不算掉句）」**，delta 各 −1。

**成因**：`classify()` 之 `strip_punct` 為 `re.sub(r"[^\w]+", "", s)` ——
**連空白一併去除**，故 `spa ces` 與 `spaces` 正規化後相等。

| 組 | 分子之定義 | 節數比 | 字元比 |
|---|---|---|---|
| A | 無頁界切段之相異者 | 24 / 140 = 17.1% | 16.3% |
| B | 加頁界之相異者 | 13 / 140 = 9.3% | 6.2% |
| **C（終值）** | 該節 PDF 側有、而**全 169 節 xlsx 皆無**之片段 | **5 / 140 = 3.6%** | **651 / 31,630 = 2.1%** |

**四個形態落在 C 組者：0。** 故 **C 之終值不變**，
且 R-U36 所擔心之「3.6% 仍偏低」**在此成因上不成立**
（其他成因見 §7）。

### 1.3 補句表是否還有遺漏

C 組未變 → **補句表七條不增不減**。

## 2. 作業 3 — R-U37：**注入抓到判準之缺陷**

腳本：`scripts/verify_locator.py`（8 個向，可重跑）。

### 2.1 第一版判準錯在哪

```python
best = max(cands, key=lambda c: SequenceMatcher(
    None, want[:300], norm(corpus[c:c+600])[:300]).ratio())
```

**兩個候選拿到的窗口長度不同。** 落在段落**前面**之候選，其 600 字元窗口
會把**後面那個候選的文字一起吃進去**；`SequenceMatcher` 之 ratio 為 `2M/T`，
T 被撐大 → **正確候選之分數反而低**。

**兩個注入向因此 FAIL**：

| 向 | 結果 |
|---|---|
| 正確者在**後** → 須選後者 | PASS（第一版也對，因為它剛好偏好短窗口）|
| **正確者在前** → 須選前者 | **FAIL** —— 選了後面的 decoy |
| **三候選，正確者在中間** | **FAIL** —— 選了最後一個 |

### 2.2 依 R-U37 **改判準，不改案例**

改為**等長窗口**：`corpus[c : c+len(want)]`。兩候選拿到一樣長的窗口，
稀釋效應消失。**改後 8/8 PASS**，且 `audit_xlsx_vs_pdf.py` 之判準同步修正。

**稽核表逐位元組未變** —— 真實語料剛好不踩這個缺陷
（`PRACC7.` 之兩處相鄰且長度相近）。

> **這正是它非得用注入才驗得出來的原因。** 07 輪之「人讀過認為正確」是對的
> ——**在那兩個案例上**。而判準錯的地方，語料裡剛好沒有。

### 2.3 對照向與範圍向（R-G7／R-G7-1）

| 類 | 向 | 結果 |
|---|---|---|
| 對照 | 唯一命中 → 不觸發消歧 | PASS |
| 對照 | 語料原樣 → 選中同一 offset | PASS |
| 真實 | `4.7` → 選前者；`5.1` → 選後者 | PASS ×2 |
| 注入 | 正確者在後／在前／三候選在中 | PASS ×3 |
| 行首 | `Table CPA2.)` 之內含不得被選中 | PASS |

**未標 PASS 之界線（canon：不可能失敗者不標 PASS）**：
兩候選僅差一個字（`deactivation` vs `deactivating`）時，本機制選中前者（正確），
**惟其正確與否取決於該字之權重，非本機制所能保證**。語料中無此形態
（重複標籤僅 3 處且內容迥異），故不作閘。
