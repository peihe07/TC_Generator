## 2. K-2 —— TC-039 之兩列：**採 (b)**，逐列標適用條件

**所擇：(b)。** 理由：spec 自身即以 `(if applicable)` 逐列標之，(b) 貼近條文；
(a) 會把「這台車有沒有該配備」寫成 TC 之前提，**使該 TC 只能在特定配備之車上跑**。

修正後之 ER 列（節錄）：

```
i. Rear Steering Wheel Controls — Audio Control Selections
   (shown only if the vehicle has rear steering wheel controls)
j–l. Navigation — …（shown, as the vehicle has Navigation）
m. Connected Account — …（shown only if the vehicle supports a Connected Account）
o. Electric Vehicle — Creep Selection          ← **未標任何適用條件**
```

### 2.1 第 o 列 —— **保留歧義**

`Electric Vehicle — Creep Selection` 在 Table PIP1 中**未標 `(if applicable)`**，
而其餘條件式列項都標了。其在非電動車上是否顯示，**條文未述**。

**處置**：ER 不標其適用條件，**亦不推定其不顯示**（§8.4.1）。
remarks 具名該歧義。

**這與 j–l 之寫法刻意不同**：Navigation 三列寫「shown, as the vehicle has
Navigation」（pre-condition 已固定），第 o 列什麼都不寫 ——
**空白本身就是記載**，讀者看得出這一列的條件沒人知道。

## 3. K-3 —— 指代掃描

### 3.1 可測部分：**命中 0**

判準：ER 出現指代詞（`the rows of`／`the items in`／`described in`／
`listed in`／`the chart`／`the table` …）而其後無列舉。

首跑命中 **2 處，皆為 TC-017**，逐條判為**判準之偽陽性**：

> `The options are **listed in** the Table EDPR1 order: Resume Setup
> (only if not complete), Edit Name, Edit Avatar, …`

—— 它**已經列舉了**，只是用**行內逗號**而非 `a./b./c.` 子層。
**改判準，不改案例**（v2：≥3 個逗號分隔項亦視為已列舉）。修正後 0 處。

### 3.2 盲區之人工補足（**下放包已先聲明，本輪照辦**）

判準抓指代詞；**C-1 之原句 `followed by the applicable examples` 沒有指代詞** ——
它用的是複數名詞。故另建 `--plural` 掃描（複數名詞 + 無列舉）。

**先證它抓得到 C-1 之原句**（否則只是換個地方漏）：

```
對 C-1 原句：命中 2 處 —— 「the applicable examples」「Navigation examples」
對現行 TC-039：命中 0 處（已有子層列舉）
```

**全批 `--plural` 掃描：命中 2 處，逐條判皆非缺陷**：

| tc_id | 命中 | 判 |
|---|---|---|
| 017 | `The options` | 其後即行內列舉十項 → 非指代 |
| 021 | `The options recorded in step 1` | 指**步驟 1 所記錄者**，且 ER3 已逐項列出六個受限項 → 非指代 |

**結論：D-3／C-1 之同型在現行語料中無第三例。**
惟此為**兩個判準之聯集**所得，**非窮盡**（見 §6 第 2 項）。

### 4.2 K-4b：`priority` ↔ `priority_basis`

首跑 **13 處** —— **判準本身測錯了東西，13 處全部不是缺陷**。

v1 驗「該級之 basis 是否含**該級之關鍵詞**」，於是
`啟用之 PIN —— Valet Mode 之防護本身`（P0）因為我的詞表寫「防線」而非「防護」轉紅。
**詞表不全不等於記載矛盾。**

C-5 要抓的是**相斥** —— basis 用了**別級**之措辭
（P1 之 basis 寫「非主路徑分支」而條文說 `will always be displayed`）。
v2 改為：只在 basis 出現**低於本級**之定性詞（呈現層／回饋／輔助功能／細節）時轉紅。
修正後 **0 處**。

### 4.3 兩項判準各改過一次 —— 故補方向性案例（`--self-test` **18 / 18**）

K-3 與 K-4a／K-4b 之判準本輪各改一次，**改的都是判準不是案例**。
改完之後三項全部歸零 —— 而**一個永遠 0 處的掃描與一個壞掉的掃描，輸出相同**。
故補 `--self-test`，比照本 feature 其餘各 lint 之慣例（R-G7 對照向）：

| 掃描 | 紅向（真實出現過之形狀）| 綠向（**曾被誤判為紅者**）|
|---|---|---|
| K-3 | ER 指代一張表而未列舉（D-3／C-1 之同型）| **TC-017 之行內逗號列舉** |
| K-3 `--plural` | **C-1 之原句**（無指代詞，k3 抓不到）| 同句已補子層 |
| K-4a | TC-036（BVA 無 limit±1）、**TC-047**（無非法操作）、狀態轉換無 A→B、情境 2 步、故障注入無故障 | **TC-022**（非法性在 ER 而非 procedure）、TC-008、TC-021 |
| K-4b | **C-5 之形狀**（P1 basis 寫「呈現層」）、P0 寫「輔助功能」、P2 寫「核心五類」| **P0 basis 寫「防護本身」**（v1 因詞表不全而誤紅）|

**綠向之選法是刻意的**：取的全是**判準修正前會轉紅的那幾條**。
若日後有人把判準改回 v1，紅向仍全過，**綠向會倒** —— 這才是這組案例要守的東西。
