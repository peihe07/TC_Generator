## 停手門檻（自裁，取代現行之逐項停手慣例）

執行層須停手上報者，**限於三類**：

- **(a)** 不可逆操作（刪除、git 歷史改寫、交付送出）
- **(b)** 跨 feature 影響
- **(c)** 影響超過語料 10% 之判準

**其餘一律採預設值續行並記錄**，分析層事後覆核得推翻；
推翻之成本由重生成承擔 —— **重生成比停等便宜**。

立此門檻之理由（自陳）：10–12 輪為 **3.3% 之語料**（180 leaf 中 6 個）
停了三輪，而該判準之錯誤代價僅為事後十分鐘之修改。
分析層以對付不可逆事項之規格處理了可逆之技術決定。
