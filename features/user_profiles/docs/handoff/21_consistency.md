## 判讀

### K-1 —— R-U5 之核心五類為**例示，非窮盡**

R-U5 所列五類（profile 建立／切換／偏好之儲存與回復／Valet Mode 進出／
資料遺失風險）為**本 feature 之具體化**，不排除 canon §10.2 之其他 P0 條件。

§10.2 之 P0 逐字含 **safety**、**vehicle-critical CAN signal**、
boot/recovery、connection、audio output、data-loss risk。
故：

- `089`（9.3，行車中禁用編輯項目）—— 其存在理由為**行車分心之防止**，
  落 §10.2 之 safety → **P0**
- `116`／`135`（Valet PIN 與其繞過）—— 落 §10.2 之 safety 與
  D-UP16-01 之「核心能力被繞過」→ **P0**

**判別問法**：該條失效時，壞掉的是使用體驗，還是**車輛或其資產的防線**？
後者不需要 R-U5 列它才成立。

寫入 `DECISIONS.md`（併 D-UP16-01 之附二），並於 `RULINGS.md` 之 R-U5
下加註（**條文本身不改**，同 F-3 之先例）。

### K-3（作業）「以指代詞引用表格內容」須全量掃描

D-3（Table CPA2，14 輪）與 C-1（Table PIP1，20 輪）為同型之第一、二例。
**第三例無人掃過**，而現行 G18 只查字面值，查不到「這句 ER 在指代一張表」。

**掃描判準**（可測）：ER 中出現指代詞
（`the rows of`／`the items in`／`the info in`／`the list of`／
`described in`／`specified in`／`chart`／`table`／`listed`／`as above`）
而**其後無 §6.1 子層列舉**者，逐條列出。

命中者逐條判：屬指代表格內容 → 以 `render_spec_region.py` 補列；
屬指向另一條可觀察之陳述（如 9.3.2 之 `the message specified above`，
其內容已由 9.3.1 之逐字引用補上）→ 具名說明其已補。

**聲明盲區（R-G11）**：本掃描抓不到「以自然語句概括表格內容而未用指代詞」者
（例：`the applicable examples are shown`）—— **C-1 原句正屬此型**。
故掃描結果為下界，須另以人工複讀 ER 之「複數名詞無列舉」形態補足。

   與條文之 `will always be displayed` 不符）
