## 發現

### U-1（defect）`TC-082` 之 ER3 對兩個分支皆通過

spec 4.1.1 逐字有**兩句**都指向 `PU1088`：

> `PU1088 is displayed when settings have been **successfully restored** to
> default.`
> `PU1088 is displayed **if HU or TBM do not confirm** complete default
> restoring.`

**同一個 popup，成功與未確認都會出現。**

而 `TC-082` 之 ER3 為 `PU1088 is displayed` —— 一個**根本沒回復成功**、
只是 HU/TBM 未確認而顯示 PU1088 之實作，**本 TC 一樣通過**（§7 false pass）。

leaf `002-02` 之 description 為 `PU1088 shows when restore completes`，
即其單位是**成功分支**；ER 卻寫成兩個分支共有的觀察。

**改**：ER3 併驗「回復確已完成」以綁定成功分支，例如
`PU1088 is displayed and the setting under test is back to its default value`。
pre-condition 已有「至少一項設定偏離預設」，該觀察點取得到。

**與 `TC-081` 之分野不變**：`081` 驗回復之**範圍**（只及現用 profile、
不刪 username／avatar），`082` 驗**流程提示**；本次只是在 `082` 加一個
**綁定分支用**的觀察點，不是把 `081` 的驗證搬過來。

**連帶自檢**：全批凡 ER 斷言某 popup／訊息顯示，而該 popup 在條文中
**有一個以上之觸發條件**者，逐條列出並判其 ER 是否綁得住所要之分支。
命中 0 亦回報。

### U-2（作業）30 輪 §3.1 之反向形態，本輪掃

執行層自陳：T-1 之閘抓「ER 引用步驟而該步驟未建立基準線」，
**抓不到反向 —— 步驟建立了基準線而 ER 從未用它**（多餘的記錄步驟），
且**本輪未查語料是否有該形態**。

**掃**：procedure 含 `record`／`and record` 之步驟，其所記之物是否在任一 ER
被引用。命中者逐條判 —— **可能是多餘步驟，也可能是 ER 漏了斷言**，
兩者處置不同，須分開講。

盲區沿 30 輪 §3 第 2 項（字面比對，同物換詞會假紅），具名即可，不加同義詞表。

## 已讀 8 條中值得記下的三處

1. **`TC-079` 之「中間切至 Profile B 是必要的」** ——
   不切走，「回復」與「值本來就在畫面上」無從分辨。
2. **`TC-080` 之 ER 併驗「不報錯」** ——
   條文說的是 `ignore`；只驗「該項不在」，一個略過卻拋錯之實作會通過。
3. **`TC-084` 把 `key cycle` 標為 R-U21（裁決）而非 spec** ——
   與 `TC-051` 之相反判定（12.3.2 條文自身寫 `at the next key on`，
   故其權威為 spec）並存而不衝突。**同一個觀察點，來源類別逐條判**，
   這正是 J-4 要分的。
