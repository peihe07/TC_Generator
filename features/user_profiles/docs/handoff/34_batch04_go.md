## 二、S-1 之「紅 0」證明得漂亮

**「0」須先證明它不是「沒掃到」** —— 逐一列出實際母體 10 個字面值及其溯源，
故紅 0 為實質結果。這一步不做，`--self-test` 全綠與掃描壞掉的輸出完全相同。

其中 `TC-100` 正是 28 輪**出處對照抓到、而當時 G18 結構上看不見**的那一個。
**同型缺陷自此由閘承擔，不再倚賴人工。**

另一項值得記：本次**只擴引號內字面值，未擴未加引號之數值**，
理由是 pre-condition 之數字多為測試設置，貿然擴會產生
「**一批只為轉綠而生的登記**」—— 那種登記表比不設閘更糟。
**克制得有理由，不是偷懶。**

## 三、四輪四種對應關係 —— 記入 profile

33 輪 §3.1 之整理成立，記入 profile 之方法節：

| 對應關係 | 掃描 | 型態 |
|---|---|---|
| 步驟 ↔ ER | T-1 | 紅 |
| 步驟 ↔ ER（反向）| U-2 | 紅 |

**四支中三支為「待判」而非「紅」**，其自陳之理由成立：
它們要判的是**語意關係**，硬判會誤殺正確者。

> 可測的是「有沒有」，不可測的是「指的是不是同一件事」。

該句記為本 feature 之方法結論。**其形態顯為 feature-agnostic**，
惟升為全域通則屬 Pei（同 R-U56 之處理），**分析層不自推**。
