## 發現

### X-1（defect）`TC-128` 與 5.10.1 衝突，且其執行結果不確定

`TC-128`（`030-02`，5.7 末句）之情境：

| | |
|---|---|
| pre | A 為現用且**無**座椅；**座椅連結者為 B** |
| 步驟 2 | `Save the position to the memory seat linked to Driver Profile B` |
| ER3 | `No memory seat is linked to Driver Profile A` |

**但這正是 5.10.1 之觸發條件** —— 存到「非現用 profile 所連之座椅」時，
**PU0588 會跳出來問**（`TC-131` 即驗此）。而依 `TC-132`，
若使用者選 **Yes**，該座椅**就會**連到 A —— **與 ER3 相反**。

`TC-128` 之 procedure **完全沒有提到 PU0588**。測試者執行到步驟 2 會撞上
一個未預期之 popup，**而結果取決於他按了什麼** —— §2 要求之確定性與可重現性不成立。

**兩條條文並不衝突**：5.7 之 `not **automatically**` 意為「不經詢問即發生」，
5.10.1 則是「問過且答 Yes 才發生」。**衝突的是 TC 之寫法，不是 spec。**

**改**：`TC-128` 之 procedure 須處理 PU0588 —— 於步驟 2 後加
「於 PU0588 選 No（或關閉）」，ER 隨之斷言 A 仍無座椅。
如此「不自動」才是**被觀察到的**，而非碰運氣。

**連帶自檢**：全批凡 procedure 之動作會觸發他節所定義之 popup 者，
逐條確認該 popup 已被 procedure 處理。
判準可用：TC 之動作字串與 `spec_popup_ids.tsv` 之觸發條件比對，
命中者列待判。**命中 0 亦回報。**

### X-2（style-divergence）`TC-134` 之步驟 2 未指名受測途徑

`Attempt to link the unlinked memory seat position **from outside the
“Edit Profile” screen**` —— 「outside」不是一個測試者能執行的位置。

**同型之 `TC-047`（12.2「只能自 All Profiles 啟用」）做對了**：
逐一指名兩個受檢位置（Edit Profile 分頁、車輛設定），
並於 reasoning 具名其為抽樣。

**改**：步驟 2 指名實際受檢之畫面（步驟 1 已開 “All Profiles” 分頁，
即為其一），reasoning 具名「窮舉不可行，此為抽樣」。

## 已讀 11 條中值得記下的三處

1. **`TC-126` 判 P0 且其理由寫在 ER 之位置上** ——
   「變灰本身不是防線，防線是按下不生效」，故 ER3 前半之斷言不可省。
   **P-1 之分野已被正確套用於新批次**，不是只改了當初那兩條。
2. **`TC-124`／`TC-134` 之 ER 皆斷言「一個都沒有」而非「這一次沒成功」** ——
   後者容許實作改連到別的座椅位置。**全稱限制之反向，其 ER 要斷言限制本身。**
3. **`TC-129` 之 popup 不寫 PU 編號** —— 5.8 未給該 popup 之 id，
   故 ER 只述其內容要旨（§8.4.1 不推定）。
