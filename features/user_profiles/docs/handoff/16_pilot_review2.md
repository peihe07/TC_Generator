## 新發現

### F-1（defect）TC-013 之 `specification_reference` 併列 11.5，應移除

多節掛回解的是 **context 注入**（哪一節之 prompt 拿得到那些列項）；
`specification_reference` 記的是 **追溯**（本 TC 直接驗證或倚為 setup 之節）。
**兩者是不同的欄位，不同的問題。**

TC-013 驗的是 11.4（CPA2）之說明畫面內容；Table CPA2 亦屬 11.4。
11.5（CPA3）講的是 App Store app 之刪除／更新／安裝範圍，
**本 TC 一句都沒驗到**。其併列之唯一理由是「該表印在 p17，
而 p17 也掛 11.5」—— 那是**頁面共置**，不是章節歸屬（§10.7）。

**改**：TC-013 之 `specification_reference` 移除 11.5，保留 11.4。
`p17 → ["11.4", "11.5"]` 之 must_carry 掛回**不動**（該處是對的）。
並自檢全批：凡 `specification_reference` 之某節係因 must_carry 多節掛回
而入者，逐條複核其是否真被該 TC 驗證或倚為 setup。

### F-2（作業，非永久限制）Table CPA2 之欄別須讀圖

在 PDF 側可抽（R-U23 之結論即「不是缺件，是缺讀取能力」）。
**能讀而未讀，不是限制。**

且欄別正是該表的意義所在：CPA2 要說的就是**哪些能力屬 Connected
Account、哪些屬 Local Profile**。ER 只列列名而不宣稱欄別，
測試者無從判斷畫面呈現是否正確 —— §6「完整之 Test Item outcome」未達。

### F-3（採納並明文）P0 之 tie-break

§8 第 1 項自立之「以失效後果分」**採納**，並寫成明文：

> 一條 TC 同時落在 R-U5 之核心五類與「邊界／非主路徑」兩帶時，
> 以**失效後果**決定：後果為核心能力失效或被繞過 → **P0**；
> 後果為輸入體驗或呈現降級 → **P1**。

據此 TC-015／TC-016 維持 P0（Valet Mode 可被繞過）、
TC-003／TC-009 維持 P1（輸入體驗降級），現狀不變。
**本條屬 R-U5 之適用釐清，非新政策**；記入 `DECISIONS.md`，
於 `RULINGS.md` 之 R-U5 下加註指向。
