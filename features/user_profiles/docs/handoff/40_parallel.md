# 40 下放包 — 並行化：生成、覆核、DV gate 同輪推進

**本包無裁決條文。** 以下皆屬分析層自裁（批次排序與分批邊界、
gate 條件、下放包之作業指示）。

## 為何改

30–39 輪共十輪，**新增 TC 零條**。該十輪找到九個真缺陷，
但其節奏為「一輪一缺陷」，且**每批生成都等覆核結束才開** ——
**該等待是分析層加的，不是流程要求的**。

覆核與生成之間**沒有依賴**：系統性缺陷之修正一律以重生成落地
（每次重生成全批，實際變動 1–5 條），**與下一批是否已生成無關**。

## 一、三批併為兩批（自裁：分批邊界）

| 批 | 範圍 | leaf | 估條數 |
|---|---|---|---|
| **第五批** | 5.12–5.16（`ALLPR`）13 ＋ **ch6 Defaults 9** | **22** | ≈ 24 |

而其條款家族界線（`ALLPR` / `NOPR` / `PRWEL` / `PRSU`）於批內仍逐節具名。

## 二、生成與覆核同輪並行（自裁：批次排序）

自本輪起：

- **第五批生成** 與 **第四批之 Z-1 修正／R-U56 自檢** 同輪
- **第六批生成** 與 **第五批覆核** 同輪
- 覆核所生之修正，於其後最近一次重生成一併落地

**唯一之例外**：若覆核發現**系統性**缺陷（影響 ≥ 3 條或跨批者），
下一批生成暫停一輪待修 —— 那是真依賴，其餘不是。

它是 Phase 6 之唯一硬阻擋，且**可完全並行**。分析層將其排在最後，是排程之誤。

**本輪起與生成並行推進**，作業如下（R-U14 逐字要求：
「機器檢查存在且實跑」，非文字修補）：

1. **建 `scripts/verify_dv_integrity.py`**
   - 對產出檔驗 `x14:dataValidation` **節點數**與 **zip member 集合**，
     比對來源母本（`forms/…_SWQT_20260817_ext.xlsx`）
   - 借 Comfort `write_back` §3.3 之同型 assertion；**先查其實作再寫**
2. **反向驗證（R-G7）**
