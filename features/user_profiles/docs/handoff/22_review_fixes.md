## 發現

### L-1（defect）TC-018 之 `[username]` —— §11 之方括號禁令未經例外裁定

ER2 寫 `the username appears in the Edit Username line as
“Edit username: [username]”`。

§11 逐字：**方括號 `[...]` 保留給本文件之 placeholder 語法與 sibling row
標記，不得出現在 TC 輸出欄位**。其 profile-scoped 例外（逐字引自來源者
得保留原記法）**須由 feature profile 明定** —— 先例為 Home A-H10
（Pop Up List 之 `<OK>`／`[OK, X]`）。

**本 feature 尚無此例外條款**，故現況為：spec 原文確有 `[username]`，
而我方無授權保留它。且 lint 全綠 —— **表示連方括號閘都沒有**。

**處置（擇一，具名）**：
- (a) 立 profile 例外（比照 Home A-H10），並要求 lint **對照來源列驗證**
  該 token 確為引用而非自擬
- (b) 改寫為不含方括號之等效敘述（如 `as “Edit username:” followed by
  the username`）

**(a) 較貼近 §8.4.1**（逐字不改寫），惟須連同 lint 閘一併立，
否則等於開一個沒有邊界的例外。
**無論擇何者，補一個方括號閘**：無授權之方括號須轉紅。

### L-2（defect）TC-020 之委派對象可能不成立 —— 9.2 第二條件恐無覆蓋

9.2 有兩個獨立條件：
1. `for regions without the <Brand> app`
2. `if the vehicle **does not support the connected profile feature**`

TC-020 取條件 1，reasoning 將條件 2 委派給 **11.3（CPA1）之 leaf**。

**但 11.3 之文為 `if the vehicle is equipped with connectivity`** ——
**連網能力**與**支援 connected profile 功能**不是同一件事：
一台有連網能力之車，仍可能不支援該功能。

若兩者確為不同條件，則 9.2 之條件 2 **無任何 TC 覆蓋**，
而 reasoning 卻聲稱它已被承擔 —— §8.2.1 要求委派須指名確實承擔者，
指錯比不指更糟：**它讓覆蓋稽核看起來是滿的**。

**作業**：核對 11.3 與 9.2 條件 2 之語意是否同一。
- 同一 → reasoning 補述其同一性之依據
- 不同 → 條件 2 為覆蓋缺口，登記並於本批或下批補一條 TC

### L-3（finding）變體配對之標準不一致

| 節 | 變體 | 正向 | 反向 |
|---|---|---|---|
| 11.4 | R1 High | TC-013（非 R1 High）| **TC-044（R1 High）已生成** |
| 9.1 | R1 High | TC-017（**以 R1 High 為前提**）| **未生成**（非 R1 High 之對照）|

兩處同為 R1 High 之變體差異，**一處配了對造，一處沒有**，
而 TC-017 之理由為「取樣單位為 leaf」—— 該理由對 11.4 同樣成立，
卻在那裡沒有阻止配對。

更值得注意的是**方向**：TC-017 把**變體**設為前提，
於是 **base variant（非 R1 High）之清單順序反而未被測** ——
而那是多數車輛之情形。

**作業**：立一致之判準並回報 ——
凡 ER 含**變體覆寫之字面值**者，須配其對造；
不配者於 reasoning 具名其理由（且該理由須不適用於已配者）。
依此判準，TC-017 之對造應補；全批同型者一併掃出。
