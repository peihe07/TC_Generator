**其中三個注入向確實轉紅**（openpyxl save / 範圍縮小 / 掉 member），

**執行層不逕行改判是對的** —— 「把封鎖之解除與封鎖之啟用者放在同一個人手上，
正是 R-U14 當初要避免的事」。該分辨成立，記入 `DECISIONS.md`。

**解除之範圍**：本 feature 之**寫回實作**得開工。

## 二、寫回實作之硬約束（承 40 輪 §4.3）

`surgical_save()` 之 `diff_cells()` 對 `Test Case Specification`
（1411 × 34，B 欄 shared formula）**逾 100 秒未完成**。

**寫回實作一律走「直接給定 edits → `patch_sheet_xml`」之封裝路徑**
（實測 0.04 秒），**不得呼叫 `diff_cells()` 求變動格**。
我方本就知道要寫哪些格 —— 求差異是在解一個我們沒有的問題。

寫回後**必跑 `verify_dv_integrity.py`**，DV-1／DV-2 兩向皆須綠。

## 三、X-1 詞表：十六條修正 ＋ 常規化

`Activate` 未入觸發詞表，致十六條真陽性在四個批次裡躺了六輪，
**而每一輪的閘都是全綠的**。

執行層之獨立判斷第 1 項成立，**立為本 feature 之常規**：

> 凡以**動詞**為觸發條件之掃描，須另立同義動詞對照表；
> **每批生成後，以該批 procedure 實際用過的動詞回頭比對詞表一次**，
> 新動詞未入表者，掃描結果不予採認。

理由：`--self-test` 驗的是「給它一條該紅的它會不會紅」，
**驗不到「它根本不看的那一類輸入」** —— 那是 R-G11 之盲區聲明落在詞表上。

**十六條之修正**：於各該 pre-condition 加「該 profile 之 Welcome popup
設定為關閉」，或於 ER 具名該 popup（依該條之驗證目標擇一，逐條具名所擇）。
**於本輪之重生成一併落地。**
