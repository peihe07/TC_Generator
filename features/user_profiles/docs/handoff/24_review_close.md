## 發現

### P-1（defect）TC-062／TC-063 之判級與 §8.7.4 相衝，且方向相反

| tc_id | 驗什麼 | 現判 |
|---|---|---|
| `062`（126-02）| 手套箱鎖按鈕**變灰**（外觀）| **P0** —「變灰即該防線之執行手段」|
| `063`（126-03）| ER1 **鎖定狀態未變** ＋ ER2 PU0833 | **P1** —「兩者各半，取中」|
| `060`（125-04）| 不可互動項**變灰**（外觀）| **P2** |

三處合看有兩個問題：

1. **與 canon §8.7.4 相衝** —— 該節逐字：視覺狀態（greyed-out）**不蘊含**
   不可操作。`062` 之判級理由「變灰即防線之執行手段」正是 §8.7.4 所否定者：
   **變灰是指示，不是機制**。一個變灰但按下仍解鎖之實作，`062` 會通過。
2. **與 D-UP16-01 附二之自訂分野相衝** —— 該分野為「防線成立本身 → P0；
   防線之回饋或呈現 → P2」。`062` 驗的是呈現、`063` 之 ER1 驗的才是防線，
   而判級恰好相反。且 `060` 同為變灰外觀判 P2 —— **同形不同級**。

**建議**：`062` → **P2**（同 `060`）；`063` → **P0**（其 ER1 為防線本身）。
若欲保留 `062` 之 P0，則須為其補一條驗「按下不生效」之 ER ——
但那即 `063`，會造成重複。

### P-2（defect）TC-070 之 ER3 為全稱斷言，超出 procedure 所能證

ER3：`Valet Mode is still active and **any popup that would allow an exit
is blocked**`。

procedure 只走兩個入口（狀態列圖示、All Profiles 分頁），
而 reasoning 已自陳「入口之窮舉不可能完備 —— 取兩個最可能者」。
**自陳是抽樣，ER 卻寫全稱** —— 測試者無法據此判定通過與否（§6）。

**建議**：ER3 收斂為已走過之入口，並具名 spec 所點之 `PU0934`
（`the PU0934 exit popup is not shown`）；
「所有入口皆被阻擋」之全稱留在 reasoning，不入 ER。

### P-3（defect）TC-072 之 remarks 與 `specification_reference` 不一致

remarks 寫「複位後為 **12.3.1**（同一 PIN 退出）與 **12.6**（停用詢問），
故**併列該二節**」，而 `specification_reference` 只有 `14.1` 與 `12.3.1` ——
**12.6 未列**。

同一條 TC 內兩處記載互相矛盾（同 C-2 之形狀）。
**補列 12.6，或改 remarks 為只複位到 12.3.1 並說明 12.6 為何不列。**

### P-4（升級）A-UP11 之實際影響面為 6 條 TC，非記載瑕疵

`TC-057`／`058`／`059`／`060`（125-01～04）與 `TC-061`／`062`（126-01～02）
之 reasoning 皆標「**該 leaf 之標題與描述錯位，見 A-UP11**」，
而六條**全部依 description 生成**。

A-UP11 自 19 輪起列為「未做全量掃描」，其分類一直是**記載問題**。
但若 037 之 title 才是需求單位，**這六條驗的東西就可能不是該 leaf 所指者** ——
它不是記載瑕疵，是**六條 TC 之驗證目標可能錯置**。

**M-6（180 leaf 全量掃）之優先級升為阻塞第三批**：
掃描結果須先回報 title／description 何者為需求單位之判準，
再定這六條是否重生成。

## 值得記下的三處（非缺陷）

1. **`TC-051` 之來源標示分得極準** —— `key on` 與 R-U21 之
   「設定→key cycle→讀回」同形，但 12.3.2 條文自身即寫 `at the next key on`，
   **故其權威為 spec 而非裁決**。同一個觀察點，來源類別不同 —— 這正是 J-4 要分的。
2. **`TC-045` 之 §5.7 例外具名** —— 進入與退出為兩個觸發，
   但條文以「像建立／像刪除」成對定義，只驗一半則另一半之語意不成立。
   例外有理由、有具名，可接受。
3. **`TC-055` 照錄 popup 原文「含其未加問號之原樣」** —— §8.4.1 之正確實踐。
