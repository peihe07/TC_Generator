## 2. §1.2 根因已獨立復現

執行層所述之首版 regex，分析層以其字面重跑：

```python
pat = re.compile(r'(?<![\w-])(\d{2,3})\s*[\u2013-]\s*(\d{2,3})')
'SYS-RA-TIME&DATE-029–033, 046, 047, 080, 081'   → []                  # 範圍未觸發
'SYS-RA-TIME&DATE-076–077, 083–085, 154'         → [('083', '085')]    # 僅後者觸發
```

與其說明逐項相符，且解釋了為何**恰好**是 3 筆而非 4 筆：`076–077` 之範圍
同樣被擋，但其兩端點各由完整-id 與裸數字規則撿回，展開值與端點值同為 2 筆，
故無損失；`083–085` 前為逗號空白，後查通過而正常展開。**唯一實際損失落在
`029–033` 之內部三筆 030/031/032。**

根因定性採納：負向後查所防護之對象（id 尾碼前之連字號）與範圍起點前之
字元同形，防護規則自我抵銷，且失敗靜默。

執行層未逕採 00R 之數字而先獨立重跑再對差 —— **此作法正確，記錄於此以為
往後之常態**：上游給的更正數字同樣受查證義務拘束（canon §5a「接受更正時之
查證義務，與提出陳述時相同」）。
