## 4. 常數表 v3 —— **生成時以佔位處理，不等過目**

v3 之 19 條中 14 條無爭議、5 條為 `PENDING: DR-8/9/10`。
Pei 尚未過目。

**分析層裁定：B1 生成不等待該過目**，作法為：

- **不建 `tm_constants.py`**（仍待過目）
- **B1 生成時，步驟措辭由生成端依 canon §5.1–5.3 逐 TC 撰寫**，
  不引用常數表
- **pilot 覆核時，以 v3 為對照**，檢查生成之措辭與 v3 是否收斂 ——
  **若生成端自然寫出與 v3 相近之措辭，即為 v3 之獨立佐證；
  若大幅分歧，則 v3 或生成端有一方需修正**

**此作法之理由**：常數表之價值在跨 TC 之一致性，而 B1 只有七片、
且分屬七個不同 Test Set —— **重複步驟本就少，常數化之收益在 B1 最低、
在 B2–B4 才顯現**。以 pilot 產出反過來驗證常數表，比先鎖定常數表再生成
更能發現措辭問題。

**UI 標籤之限制仍在**：`11` T4 之 HMI Settings List 查證未回。
生成時凡涉 UI 標籤者，**若該標籤未見於 CFTS015 或 HMI Settings List，
一律寫 `PENDING: DR-12 UI 標籤正式名稱`**，不得沿用 v3 之推測值
（`"Time and Date" settings` 實測於 CFTS015 出現 0 次）。
