## 1. A-TM22 定級為理論風險 —— 受理，三項依據成立

`sheet_members()` 走 OOXML 標準之 `r:id` → rels `Target`，且
**錯誤形態為缺漏而非誤指**（解析失敗使 key 不存在 → 下游
`surgical_save:295-296` 必 raise）。此一區辨是定級之關鍵：

> 這與 A-TM21(a) 之情形根本不同 —— 後者是「字母宣告錯了就寫進錯欄」，
> 錯誤會被**執行**而非被攔。

**「錯了會被攔」與「錯了會被執行」是兩種盲區，不可同級處理。** 採納。

DV 交叉驗證（rels 解析與 DV 內容特徵同指 `sheet6.xml`）為兩條獨立路徑，
證據充分。定級之兩項附帶條件（(i) 針對當前母本結構、(ii) 依據是現行實作
走 rels 而非母本測試通過）**逐字保留**。

### 1.1 §3.1(4) 之發現 —— 立為條文

> 母本九分頁之顯示序 1–9 與 `sheetN.xml` 之 N 逐項相同 …… 若日後有人以
> 索引推算替換此函式，母本測試會全綠。

**這是一個「受測物本身沒有鑑別力」之案例**，與 R-TM28 之
`sxm` signed=True（已簽核者測不出 A-TM15 修法）同型，但更隱蔽 ——
前者可由 `signoff.signed` 一眼看出，後者要把九個分頁的顯示序與檔名序
逐一對過才知道。

```
R-TM42（分析層自裁，2026-08-21）—— 受測物之鑑別力須先於測試本身確認

以某一資料或檔案作為某項實作之驗證受測物前，須先確認
**該受測物能區分正確實作與已知的錯誤實作**。

具體作法：列出該項最可能之錯誤實作（如以索引推算取代 rels 解析），
判斷受測物在該錯誤實作下會通過或失敗。若會通過，該受測物對此項
無鑑別力，須另尋或另加判準。

依據：
- 036 母本之分頁顯示序與 sheetN.xml 檔名序恰好全部一致，故
  「憑索引推算」之錯誤實作在母本上會全綠（04Z-A3 上繳 §3.1(4)）
- sxm 之 signoff.signed=True 使 A-TM15 修法前後行為相同（R-TM28）

兩例之共同點：受測物看似合格（檔案齊全、可跑通），但對**該特定項**
無鑑別力。R-TM21 問「本工作沒做判準會不會通過」，本條問
「錯誤實作會不會通過」—— 兩者互補。
```

## 3. §4.5 之共同點 —— 併入 R-TM38 之註記，不另立條文

> 三者之共同點是「保留了容易保留的那半，丟掉了需要動手的那半」。
> docstring 保留承諾丟掉實作、讀者保留「找到了」丟掉「驗過了」、

> 地方停下。

**定性精準，且比三條分立之條文更有用。** 但不另立新條 —— 現有
R-TM38 / R-TM39 / 全集 5 已各自涵蓋其一，再加一條通則只會增加條文
總數而不增加可操作性（現行 `## R-TM` 已 42 條）。

**改以註記併入 R-TM38**（T1(b)），使日後讀該條者看得到三者同源。
