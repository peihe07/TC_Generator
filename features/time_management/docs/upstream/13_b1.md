## 1. T4 —— arch 之編碼（R-TM63 第 5 項：單一來源）

### 1.1 判準置於 `tm_rulings`，兩層共用

新增 `load_ee_arch()`、`atl_hi_placeholder()` 於 `tm_rulings.py` ——
**context 層與 lint 層由同一函式供給**，本檔不複寫 tsv 內容。
複寫即製造第二個來源，正是 R-TM59 / R-TM61 所記之漂移形態。

**缺檔即 raise，不靜默略過**。理由寫在 docstring 裡：靜默略過會使每一個
Atl-Mid 物件都被當成 Atl-Hi 而寫入真值 —— 錯誤方向正是「產出看起來正常
的錯值」（A-TM26 同族）。三種缺陷皆已紅向驗證：

```
PASS 缺檔     → FileNotFoundError: …不得以「全部視為 Atl-Hi」續行
PASS 表頭錯   → ValueError: 表頭為 ['leaf','object_id']，應為 [...]
PASS 空表     → ValueError: 無資料列
```

### 1.2 context 之 `arch` 段（綠向：003 = 1 真值 + 5 佔位）

```json
"arch": {
  "atl_hi": ["4813923"],
  "atl_mid": ["4814088","4814089","4814096","4814097","4814099"],
  "not_in_tsv": [],
  "placeholders": [
    "PENDING: DR-11 Atl-H 對應需求（CFTS015-4814088 標為 Atlantis Mid）", …
```

**與下放包 T4 之綠向預期完全一致。** `rendered` 只含真值，佔位另列 ——
使「哪些是真的引用」與「哪些是待補」在資料結構上就分得開。

另加 `not_in_tsv` 欄：物件不在 tsv 內時**不得預設為 Atl-Hi**，

## 5. 生成過程中發現的兩個問題

### 5.1 **鍵名不一致：`specification_reference` vs `spec_reference`**

```
feature.yaml columns / write_back  →  spec_reference
lint_tcs（B7、arch）               →  specification_reference
```

**後果不對稱**：
- TC 只用 `spec_reference` → lint 之 B7 對每條報「為空」，其餘 B7 檢查
  （SYS2 全集、docx 存在性、§10.7 排列）**完全跑不到**
- TC 只用 `specification_reference` → `write_back` 之
  `for key, idx in cols.items(): tc.get(key)` 取不到值，
  **該欄靜默留空寫入工作簿**

**後者是靜默的** —— 這正是本 feature 一路在防的形態。

**本包之處置**：19 條 TC **兩個鍵都寫**，使 lint 之 B7 能實際運作
（見 §4 之發現即由此而來）。**這是權宜，不是解法** ——
兩個鍵長期並存本身就是雙來源。**提請裁定統一為哪一個**
（執行層傾向 `spec_reference`，因其為 `feature.yaml` 之權威宣告）。

**本項未由任何既有閘門攔下**：lint 不知道 write_back 用什麼鍵，
write_back 不跑 lint。**建議 write_back 增一項啟動檢查**：
`cols` 之每個 key 是否都在 TC 內出現過，否則報「該欄將全空」。

### 5.2 **DR 號誤用：我把注入無效訊號掛在 DR-9**

010 之三條 TC 需要「使訊號變成無效／恢復有效」之操作。
首版我寫 `PENDING: DR-9`，**而 DR-9 之定義是「CAN sleep 之可觀察終止
條件」** —— 意義不同。

**已更正為 DR-20 並登記**（`10` §1.2 之缺口 G2，影響 009/010/022 三片）。

**此錯之性質**：佔位之 DR 號若指向不相干的缺件，答覆回來時無法對應。
與 `DATA_REQUESTS` 既有之「同一缺件不得有兩個 DR」為一體兩面 ——
前者是**一號多義**，後者是一義多號。已寫入 DR-20 之登記段。

### 5.3 一項自查發現並更正者：A-TM26 之強制記錄漏了 8 條

生成後自檢發現：訊號出現 30 處，而 reasoning 記了 `ArchColumn` 者
**只有 2 條**。A-TM26 明訂「無此記錄之取值一律視為未驗」。

已補至**含訊號之 10 條全數記錄**（並清除補寫過程中產生的重複註記）。
**此非 lint 發現**（lint 無此閘），故不受「不預先修正」之拘束。

**順帶說明一個缺口**：A-TM26 之強制判準目前**沒有對應的 lint 閘** ——
「reasoning 是否記了 ArchColumn」無人檢查，本次靠自檢發現。
列入未驗清單 A 區。
