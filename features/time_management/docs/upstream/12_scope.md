### 1.2 **核心主張不受影響**

R-TM63 所依賴者為五項事實，逐項與逐 leaf 表相符：

**更正只及於總數與百分比，不及於任何處置。**

### 1.3 為何查清後續行而非停在原地

停止條件之目的是防止「數字不符卻照用」。本次**差異已完全歸因**
（下放包兩表互相矛盾，而重測與其中較細者全符），且**受影響者為
不參與任何判定之總數與百分比** —— R-TM63 之五項依據全部相符。
若此時停下，B1 將因一個純敘述性數字而卡住。**已於本節與 A-TM27
完整記錄，供分析層覆核；若認為應停，請下放。**

### 1.4 **執行層自身之一個量測錯誤（已自行發現並更正）**

首次重測我得 **84** 而非 88，差在 009（少 3）與 015（少 1）。

```
009: 'SYS-RA-TIME&DATE-029–033, 046, 047, 080, 081'   ← 029–033 為五筆
015: 'SYS-RA-TIME&DATE-076–077, 083–085, 154'
```

037 之來源需求欄使用 **en dash（U+2013）範圍**，我的 regex 只抓三位數字，
把 `029–033` 讀成兩個端點而漏掉中間三筆。

**與 A-TM09 之首版錯誤同族**：皆為 regex 未涵蓋來源之實際書寫形態。
已改為 `expand()` 並附兩向自驗（範圍展開／單列舉），
且對 `b - a` 加合理性上限，以免一個誤配吞掉整段編號。

**能自行發現，是因為逐 leaf 比對而非只比總數** —— 只比總數會得到
「84 vs 78，差 6」，方向與成因都看不出來；逐 leaf 比對直接指出
009 與 015 兩片，成因一眼可見。

## 2. T3 產出

`data/ee_architecture_by_leaf.tsv`，**88 資料列 × 6 欄**：

```
leaf | sys_ra | object_id | ee_architecture | is_atl_hi | section
```

`is_atl_hi` 判準逐字：標籤含 `Atlantis High`（**不分大小寫**）或等於 `All`。

**大小寫不敏感是必要的**：SYS2 之 EE Architecture 欄實測有 `ATL-Hi`(101)
與 `Atl-Hi`(10) 兩種寫法。我首版比對用大小寫敏感之 `in`，
**結果恰好相同（0 不一致）純屬運氣** —— 該 10 筆小寫變體都不在可比集內。
已改為不分大小寫並複測。

### 2.1 一項下放包未提及的交叉驗證：**SYS2 有第二個 EE 欄**

`SYS2 Basic Report` 之第 7 欄為 `SYS2 EE Architecture (All, ...)`，
值為 `ATL-Hi` / `All` / `ATL-Mid` —— **這是與 CFTS015 docx 標籤並行的
第二個獨立來源**，下放包只用了 docx。

執行層以之交叉驗證：

```
兩來源比對：一致 138 | 不一致 0 | docx 無此物件 89
```

**138 筆可比者零不一致。** 這使 A-TM27 之量測基礎多一層佐證 ——
不是單一來源的解讀，而是兩份文件同向。

（89 筆「docx 無此物件」為 SYS2 之來源物件不在 docx 帶標籤集內者，
含 A-TM13 之兩筆；未逐筆追查，列入未驗清單。）
