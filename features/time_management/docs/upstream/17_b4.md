判準由逐 TC 改為 leaf 聯集後，本閘須看該 leaf 之**全部** TC，

### 2.3 三項舊紅向已移除，非改期望值

**移除而非改期望值** —— 改期望值會使其變成「驗證一個已不存在的行為」，
那比刪掉更糟：它會在往後每次重跑時都顯示 PASS。

已由 R-TM72 之四項 leaf 層案例取代。**自驗 56 → 57**（淨 +1：新增 4、移除 3）。

## 3. R-TM73 —— 執行層自加一項：**欄位清單同源，非只同值**

條文要求「臨時判準之掃描範圍須與 lint 對應閘門一致」。

**執行層另立 `AUTHORED_FIELDS` 常數並使兩處共讀**：

```python
AUTHORED_FIELDS = ("pre_conditions", "input_test_data",
                   "test_procedure", "expected_result")

def authored_text(tc: dict) -> str:
    """作者所撰之全文 —— test_item 下半 + AUTHORED_FIELDS。"""
```

`lint_boundary` 改用 `authored_text(tc)`；本包之 B4 自檢 `import` 同一函式。

**理由**：條文只要求「一致」，未要求「同源」。**一致靠人維持會漂移** ——
這正是本 feature 一路在記的形態（`tm_rulings` 之單一來源、
`tc_id_format` 之三來源、B3 閘之靜默失效皆屬此族）。

## 5. T3 —— B4 三片

### 5.1 013 DST Handling（單一 Atl-Hi 物件）

spec 錨僅 4813995（`The daylight saving time shall be adjusted
automatically.`）。**依 R-TM60 無手動 DST 開關**，觸發為時間跨越切換點
（`PENDING: DR-10`）。

**寫成兩條 —— 進入與退出各一**。理由同 018 之 reset/battery 二觸發：
自動調整的兩個方向是不同的狀態轉換，以其一代替另一會使覆蓋只有一半，
而 lint 無從發現。

### 5.2 015 Manual Date（5 Hi + 4 Mid，001 為對照）

四條涵蓋：手動輸入、送上匯流排、**年份之四數位訊號**、內部計數之更新。

**`$DateTmYear$` 在 Atl-H 為四個 4-bit 數位**（LID 表 Format 欄：
`4 bits each / 0 to 9 (digit 1) … (digit 4)`），與時/分/日/月之兩數位不同 ——
單獨寫一條，因該形態差異只在年份出現。

**UI 標籤**：`Set Date Day` / `Set Date Month` / `Set Date Year`
取自 HMI Settings List 第 7 節（`11` T4），**有正式來源故不寫 DR-12 佔位**。

### 5.3 022 SNA Handling —— B-2 界線之另一側

**得涵蓋 SNA 送出規則（屬 022），不得涵蓋 GPS 值之送出正確性（屬 014）。**

實測：022 兩條之作者所撰內容對 `GPSDateTm` **零命中**。
**受測訊號刻意取時間訊號（`$DateTmHour$` / `$DateTmDay$`）而非 GPS 訊號** ——
使「驗 SNA 規則」與「驗 GPS 值」在受測物上就分開，不靠措辭迴避。

第二條驗 4813905 之第二子句（`if no SNA value is defined, it shall be set
to the default value. The default values are specified in the CAN database`）——
**期望值指向 CAN database 而不自擬**，因 `$DateTmDay$` 之 SNA 欄在 LID 表
為空（`11` §3.3.2：19 個 LID 中僅 `$DateTmFormat$` 有 SNA 值）。
