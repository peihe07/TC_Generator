### 2.1 **「五條」之計數本身不精確 —— 提請下一包統一**

上表為**六組鄰接**。R-TM23 增列兩條時，原三條中之 `018↔011` 與新增之
`011↔008` 在 011 這一片上部分重疊 —— 從 011 之角度看是「格式歸我、
時間值不歸我」一件事，從 018 與 008 之角度看是兩件事。

故「五條」是**以條為單位數**而非以鄰接對數，兩種數法各自成立但混用時
不精確。`06R` §1 之訂正解決了「三條自動判準 vs 五條界線」之混淆，
**但未及計數本身**。

**執行層未逕改**（屬條文本體之命名與計數）。**提請下一包統一** ——
建議以「鄰接對」為單位重新編號（如 `B-1` … `B-6`），使
「哪幾對有自動判準」可逐對對照，不再需要在敘述中解釋。

**這同時是 R-TM24（來源隔離）之機械化**：來源隔離若只靠產生器讀對檔案，
仍可能在後續處理中被改寫；綠向逐字比對來源，使該隔離可驗。

### 3.2 **退化紅向 C-2 首次失敗 —— R-TM42 再次應驗**

首次執行為 **12/13**，失敗者為「退化紅向 C-2：抽空後仍綠」。

**成因**：B1 之七片為 `001, 003, 006, 007, 008, 010, 012`，**不含
A-TM13 兩片**（002 / 005 在 B2）。故 B1 之 context 無任何 `gap`，
退化操作無物可抽，而原判準之 `if not gaps: return c["batch"] != "B2"`
使其恆真。

**即受測物（B1）對該項無鑑別力** —— R-TM42 之判準：「列出該項最可能之
錯誤實作，判斷受測物在該錯誤實作下會通過或失敗。若會通過，該受測物對
此項無鑑別力。」

**修正兩處**：

1. `chk_c2` 改為 `bool(gaps) and all(...)` —— **要求 gaps 非空**，
   不再以「無 gap 即通過」為滿足條件
2. self-test 對 C-2 之綠向與退化紅向**自動取含 A-TM13 之批次**
   （`next(b for b, ns in BATCHES.items() if any(n in SPEC_GAP for n in ns))`），
   並印出該切換：

```
（C-2 之受測物改用 B2 —— B1 不含 A-TM13 兩片，對該項無鑑別力，R-TM42）
```

**故不論以哪一批次跑 self-test，C-2 皆被真正測到。** 已驗 B1 與 B2
兩者皆 13/13。
