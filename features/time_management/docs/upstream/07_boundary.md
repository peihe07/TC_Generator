## 1. 對駁回依據之訂正 —— 結論不變且更強

下放包 §2.2 舉 CFTS015 物件 `4814105` 為「022 對 `$GPSDateTm*` 有正當
管轄」之依據。**逐字引文正確，但該物件不在 022 之引用鏈內。**

實測：

```
022 之引用鏈物件：4813905、4814056
  4813905 / 4814056 逐字（同文）：
    "If the ECU can not send reliable data, the ECU (including gateway)
     shall send SNA (Signal Not available) values in the destination
     signal..."
  022 引用鏈之全部訊號：（無）
  其中 GPSDateTm 類：無

4814105 之歸屬：014 之引用鏈
```

**故正確之駁回依據為**：022 之管轄來自對「每一個 destination signal」之
**通則涵蓋**，而非對某組訊號之**具名擁有**。022 自身之 spec 依據
不指名任何訊號 —— 通則涵蓋本就無訊號名可作判準。

這比原依據**更強**：原依據若成立，022 尚有一組具名訊號可考慮列入
`not_ours` 之反面；而實情是 022 連一個具名訊號都沒有，訊號名判準
在此原理上不成立。

**裁定本身照辦，未動**：022 不入 `BOUNDARY_SIGNALS`。訂正只記於
`RULINGS.md` R-TM53 回報段末與 R-TM55 回報段，不改條文區塊之逐字內容。

## 3. T3 —— 空 `owns` 之處理與五案例

### 3.1 實作

`lint_boundary` **本即只讀 `not_ours`，不讀 `owns`**。故空 `owns` 不需
新增分支，但需要兩件事：

1. `if not rule` 改為 `if rule is None` —— 前者對「規則存在但為空 dict」
   與「規則不存在」不可分；雖現行無空 dict，語意上判準應是「表內有無此片」
2. docstring 明寫「本閘只讀 not_ours，不讀 owns」，使日後修改者不會
   誤加 `owns` 前提而把該二片再排除出射程

### 3.2 五案例（實跑輸出）

```
PASS 紅向 boundary (B4 R-TM55：018 命中 011 之 $DateTmFormat$，owns 為空):
      SWE-RA-TIME&DATE-018 之內文命中 `$DateTmFormat$`，該訊號屬鄰片。
PASS 紅向 boundary (B4 R-TM55：017 命中 014 之 $GPSDateTm，owns 為空):
      SWE-RA-TIME&DATE-017 之內文命中 `$GPSDateTm`，該訊號屬鄰片。
PASS 綠向 3 (018 提 $DateTmHour$ —— 非其 not_ours): 未誤報 boundary
PASS 綠向 4 (017 提 $DateTmMinute$ —— 非其 not_ours): 未誤報 boundary
PASS 負控   (022 提 $GPSDateTm —— R-TM55 駁回列入，須仍不叫): 未誤報 boundary
```

**綠向之構造與下放包所擬不同，且是刻意的**：下放包擬以
「017 之正常 TC 提 `TELEMATIC_TIME_DATE`」為綠向。該構造**不能證明
本閘不誤報** —— `TELEMATIC_TIME_DATE` 不在任何 `not_ours` 內，換成任何
一段無關文字都會過，該綠向對「閘是否過寬」零鑑別力。

改用之構造為 **017 提 `$DateTmMinute$`**：該訊號是 008 所 owns 之
真實訊號、形式與 `$GPSDateTm` 完全同族，但不在 017 之 `not_ours` 內。
若本閘誤以「命中任一他片訊號」為判準（而非「命中本片 not_ours」），
此案例會轉紅。018 之綠向同理（提 008 owns 之 `$DateTmHour$`）。

**陰性對照為必做項，已做且通過。** 它使 R-TM55 之駁回持續受檢：
日後若有人把 022 補入 `BOUNDARY_SIGNALS`，此案例立即轉紅。

### 4.1 兩處落檔之逐字相同 —— 及一次自身之取樣錯誤

首次比對報 **DIFF**。成因不是內容不一致，而是**比對器取樣錯**：
`RULINGS.md` 內現有 12 列 `B-x`（增列前之舊表 6 列 ＋ 本次重測 6 列，
舊表依 R-TM13 保留不刪），比對器抓到前 6 列即舊表。

改以**共同段落標題**定位後再比對：

```
兩檔皆有同一段落標題: True
列數: 6 6
SAME ['B-1','004 ↔ 010','無','無訊號可測','無訊號可測']
SAME ['B-2','014 ↔ 022','無','無訊號可測','抓不到（依 R-TM55 刻意不補）']
SAME ['B-3','018 ↔ 011','單向','抓到','無訊號可測']
SAME ['B-4','014 ↔ 008','雙向有','抓到','抓到']
SAME ['B-5','014 ↔ 017','單向','無訊號可測','抓到']
SAME ['B-6','011 ↔ 008','雙向有','抓到','抓到']
逐格相同: True
兩檔皆含「**六對中四對有自動判準…」: True
兩檔皆含「B-2 為何維持「無」—— 供日後讀者，勿重提補入」: True
```

**此事本身值得記**：一份文件內同一張表存在新舊兩版時，
「抓第一個符合樣式者」之比對會沉默地比錯版本，且失敗方向是**假 DIFF**
（尚屬安全）——但同樣的取樣錯若方向相反（新表在前、舊表在後），
就會變成**假 SAME**。定位錨點須是唯一的段落標題，不是樣式。
未另立條文，僅記於此供分析層裁量。
