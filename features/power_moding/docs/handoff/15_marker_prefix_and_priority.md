## 三、priority 重判之覆核（§8 第 3、4 項）—— **發現一處內部矛盾**

執行層請求覆核，並自陳 `-006` 改 P2 之動機不純。**逐條看過，其中七條可，
一條不可。**

### 3.1 不可者：`-003` 之 P0 依據與 `-004` 相矛盾

| tc | 級 | 其 reasoning 所載之依據 |
|---|---|---|
| `-003` | **P0** | 逾時為被動路徑；**其失效使無人操作之車輛永遠停在免責畫面** |
| `-004` | P1 | Maserati **設計上就沒有逾時**；其失效使畫面提前消失，而 **Accept 路徑仍在** |

**兩者不能同時成立。**

`-004` 已載明：**Maserati 之正常設計即為「無逾時，使用者須按 Accept」**，
而該情形被判為**可接受**（P1）。

則 `-003` 之逾時失效，其結果**恰好等同 Maserati 之正常運作** ——
使用者按 Accept 即可離開。**「永遠停在免責畫面」不成立**，
除非同時主張 Maserati 之正常設計亦為 P0 級之缺陷。

### 3.2 處置：二者須同級，或其依據須改寫

**不指定何者為正解** —— 兩條路皆可，須擇一並使依據互不矛盾：

| 案 | 內容 |
|---|---|
| （甲） | `-003` 降 P1，與 `-004` 同級。依據改為「逾時失效使自動離開路徑失效，惟 Accept 路徑仍在（`-002` 已驗），開機仍可完成」 |
| （乙） | `-004` 升 P0，與 `-003` 同級。須說明為何 Maserati 之正常設計不構成同一風險（例如：Maserati 使用者被告知須按 Accept，而非 Maserati 使用者不被告知） |

**分析層傾向（甲）** —— 其與 `-002`（Accept 路徑，P0）之分工清楚：
主動路徑失效才阻斷開機，被動路徑失效只是不便。
**惟此為 priority 之實質判斷，執行層得依 §10.2 rubric 自行擇定並載其依據。**

### 3.3 可者：其餘七條

- `-001`／`-002`／`-008` 之 P0 **依據成立** —— 三者皆為「其失效使開機無法完成」
  或「以未取得確認之狀態進入 last mode」。
- `-005` P1／`-006` P2 之分級**可接受**：`-005` 驗能力之存在（其失效 = 功能缺失），
  `-006` 驗其抑制（其失效 = 多顯示一組重複控制）。
  **後果之量級確實不同，非為求分布而拆。**
- `-007` P1 成立。

### 3.4 對執行層 §8 第 4 項之自陳（動機不純）之回應

其自陳為
「**我無法排除自己是因為『八條同值看起來不對』而去找理由拆開**」。

**該自陳本身正確且必要，但其結論可以更確定**：`-006` 之 P2 依據
（失效後果為「多顯示一組重複控制」）**可獨立於分布而成立** ——
即使全批仍為八條同值，該依據仍站得住。**故動機雖可疑，判斷不受污染。**

**真正受污染者是 `-003`**（§3.1）—— 其 P0 依據需要一個「永遠停住」之
嚴重後果，而該後果與 `-004` 之既有判斷衝突。**這才是「找理由」之痕跡。**

## 四、裁決條文（逐條抄入 `RULINGS.md`）

```
R-PMH57（marker 前綴清單須由反向掃描產生）
marker 枚舉法（R-PMH54）所用之前綴清單，**不得人工列舉**，
須以反向掃描產生：對規格全文掃 `\b([A-Za-z][A-Za-z_ ]{0,8}?)\s?
(\d+(?:\.\d+)?)\s?([.):])`，取其前綴分布，逐一判定為
「需求 marker」或「交叉參照／偽命中」，判定結果逐項具名留檔。

實測（分析層 15 包 §2.1）：人工列舉之六個前綴遺漏 **`DS`**
（`DS4.1)`，PDF 行 306，對應 outline 7.5.1）。
**PDF marker 全集為 31 而非 14 包所報之 30。**
缺漏數不變（`DS4.1)` 於 SYS1 內），**故結論不變而分母錯**。

**此錯為分析層與執行層獨立計算而得之同一值** —— 二者用了同一份人工清單。
**先算後比只能抓「算法不同而結果不同」，抓不到「前提相同而前提本身錯」**；
故前提本身須另有反向驗證，不得倚賴對照。
```

```
R-PMH58（COVERED 須自檢查點自動產生）
`lint_batch.py` 之 `COVERED`（已涵蓋之 canon 節號集合）**不得手寫**。

實施：每一檢查點於其註冊處附其所檢查之 canon 節號，
`COVERED` 由該等註冊自動彙集；`canon_coverage.py` 匯入之。

依據：14 包 §3.2 —— `COVERED` 先宣告 `5.2` 而該檢查尚未實作，
致未涵蓋清單稱其「已涵蓋」而實際沒有。**宣告與實作分離即會分岔**
（A-PMH12 之同型）。手寫之集合無法防此。
```

```
R-PMH59（priority 之依據須批內互不矛盾）
同一批內各 TC 之 `priority` 依據**須互不矛盾**：若某條以「後果 X 嚴重」
判為高級，而另一條以「X 為正常設計且可接受」判為低級，二者不得並存。

檢查方式：批內成對之 TC（同一軸之兩側、變體對、正負對）其級別若不同，
須於 `reasoning` 說明**該差異之來源**，且該說明不得與對側之 reasoning
相衝突。此項不可機械判定，屬人讀覆核之必查項。

依據：batch 1 第三輪之 `-003`（P0，依據為「逾時失效使車輛永遠停在
免責畫面」）與 `-004`（P1，依據為「Maserati 設計上即無逾時，
Accept 路徑仍在」）—— 二者不能同時成立（15 包 §3.1）。
```
