## 三、§12 第 4 項 —— 我做了反向掃描，**查出一處規格內部之牴觸**

執行層自陳：`-007` 之限定只排除了**矩陣**之 pop-up，
**規格自身是否另有會在免責畫面期間產生 pop-up 之敘述，未反向掃過。**

**量測條件**：`pm.txt`（PDF 全文 11 頁）以 `pop-up`／`popup`／`pop up`
不分大小寫掃描，逐處判其是否可與免責畫面期間共存。

### 3.1 全 25 處之歸類

| 處 | 內容 | 與 `SU3.)` 之關係 |
|---|---|---|
| 行 131／147／155／263 | `Geolocation + SOS Popup (refer to TBM Geolocation L&F…)` | **印證** —— 其位置在流程圖之免責畫面**之後** |
| 行 144 | `If disclaimer screen is skipped go directly to last mode screen, showing GDPR/SOS popup first` | **印證** —— 明載其條件為**免責畫面被跳過**，二者互斥 |
| 行 164 | `Note: do not show popup again if popup was shown at Radio Off.` | 未對照（不同謂詞：是否重複顯示） |
| **行 341／357** | **`HVAC Knobs: Fully functional. Pop-ups still shown.`** | **⚠ 牴觸 —— 見 §3.2** |
| 行 416–439 | `PM1)` 之 IGN OFF popup 群（FOTA／Wi-Fi／Charge Now） | 未對照 —— 其相位為 IGN OFF，非開機序列 |
| 行 453／455／460 | `PITA6`／`PITA6.1`／`PITA9` | 未對照 —— 其狀態為 Power Button Off；`PITA6.1` 明載「按電源鍵至 On **後**顯示免責畫面」，**為先後而非同時** |

### 3.2 **行 341／357 為規格自身之 p9 能力矩陣 —— 它自己說 pop-ups 仍會顯示**

`HVAC Knobs: Fully functional. `**`Pop-ups still shown.`** 於 p9 出現**兩次**
（`KEY OFF (ACC)` 與 `KEY OFF (No ACC)` 兩列之 `HEADUNIT POWER OFF` 欄）。

**與 `SU3.)` 之關係**：

- 共同謂詞：**pop-up 是否顯示**。`SU3.)` 取「不顯示」（免責畫面移除前），
  p9 取「顯示」；
- 條件互斥？**未證** —— 免責畫面出現於開機序列，而 p9 之列為電源狀態，
  二者之軸不同，**無任何依據證明其不重疊**。

**依 R-PMH84，此為牴觸。**

### 3.3 這一處與先前所有牴觸不同 —— **它在規格內部**

先前之 `10.3`（R-PMH80）與 `r48`（R-PMH87）皆為**規格 vs 素材**；
**本處為規格 vs 規格**（`SU3.)` 在 p8、p9 之矩陣在同一份 PDF 內）。

**其後果有二**：

1. **不能以「以規格為權威」解之** —— 兩造皆是規格；
2. **它加強了 `DR-PMH5`** —— p9 之能力矩陣不只是「無來源」，
   **它自身之內容與 p8 之 `SU3.)` 相衝**。該 DR 之問題全文須增此一項。

### 3.4 對 `-007` 之影響 —— **限定已足，但其依據須擴充**

`Pop-ups still shown` 之情境為 **HVAC Knobs 之操作**，
而 `-007` 之限定已含「不操作 HVAC 硬控」（R-PMH87）。
**故限定不必增加**，惟其 `reasoning` 之依據須自「矩陣之 17 格」
擴為「矩陣之 17 格 ＋ 規格 p9 之兩處」。

**其餘 24 處皆不落在免責畫面期間**（印證 5／未對照 19），
故四項事件限定**經反向掃描後仍為充分**。

## 四、裁決條文（逐條抄入 `RULINGS.md`）

```
R-PMH88（條文優先於步驟）
下放包之**作業步驟**若與**裁決條文**（同包或既有）相衝突，
**以條文為準**；執行層依條文執行，並於上繳具名該衝突與其選擇。

**執行層不因此承擔判斷之責任** —— 條文為已裁定者，步驟為其實施之描述；
描述與被描述者相衝時，錯在描述。

依據：22 包 §2.2 —— 下放包步驟 2 令五格全改「牴觸」，
而 R-PMH85(c) 令「凡以該術語為據之對照判定一律標『待定義』」；
執行層依條文只改 `r48`。**該選擇正確。**
其成因為分析層於 R-PMH85 之但書中**以一列之證據（`r48` 未用 `VP`）
寫了涵蓋五列之結論**，其後之步驟 2 沿用該過寬之結論。
```

```
R-PMH89（規格內部之牴觸）
牴觸之兩造若**同屬規格文件本身**（非規格 vs 素材），
其處置與 R-PMH80 相同（限縮 ＋ 揭露，不裁權威），
**惟須另立 anomaly 並於其中明記「不得以『以規格為權威』解之」** ——
兩造皆是規格，該原則在此無分辨力。

現行適用：`SU3.)`（p8，`No pop-ups will appear until the disclaimer screen
has been removed`）與 p9 能力矩陣之
`HVAC Knobs: Fully functional. Pop-ups still shown.`（p9 出現兩次，
`KEY OFF (ACC)` 與 `KEY OFF (No ACC)` 兩列之 `HEADUNIT POWER OFF` 欄）。
共同謂詞為 pop-up 是否顯示；條件互斥未證（免責畫面之相位為開機序列，
p9 之軸為電源狀態，二軸不同而無依據證明不重疊）。

**連帶**：`DR-PMH5` 之問題全文須增列此項 ——
p9 之能力矩陣不只「無來源」，**其自身之內容與 p8 之 `SU3.)` 相衝**。
```

```
R-PMH90（斷言類之反向掃描）
凡以「限定排除某類斷言」為據之 TC（如 `-007` 以四項事件限定排除 pop-up），
其限定之充分性**須經規格全文之反向掃描**，不得只掃素材。

方法：以該類斷言之關鍵詞（`pop-up`／`popup`／`pop up` 等，含大小寫變體）
掃規格全文，逐處判其與該 TC 之情境是否可共存，
並將結果分為印證／牴觸／未對照三類（R-PMH79）。

**掃描之結果須寫入該 TC 之 `reasoning`** —— 只寫素材側之依據而未寫
規格側者，其「限定為充分」之主張未經完整檢驗。

依據：22 包 §12 第 4 項（執行層自陳只排除矩陣之 pop-up 而未反向掃規格）；
分析層 23 包 §3.1 之掃描查出 25 處，其中 **2 處為牴觸**（p9 之
`Pop-ups still shown`），其餘 23 處為印證 5／未對照 18。
```
