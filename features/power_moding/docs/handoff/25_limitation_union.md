## 三、`r45` × `-007` ER4(b) —— **處置：擴充限定，且不依賴歧義之判讀**

### 3.1 牴觸成立

| | 逐字 | 謂詞 |
|---|---|---|
| `-007` ER4(b) | `The announcement is heard in the background` | 音訊是否可聞 |
| 矩陣 `r45`（`Mute Button Pressed`，`Key On, Gear != Reverse`） | `Mute --> Active` | 同上，取相反值 |

條件互斥未證（`Key On` 與免責畫面之相位重疊；四項限定不含 Mute 鍵）→ **牴觸**。

### 3.2 其形態與 `r48` 完全相同，**故其解法亦相同**

`r45` 之觸發為**按 Mute 鍵** —— 又一個測試員可控之事件。
依 R-PMH87 已建立之機制（**排除事件即排除該格**），
**加入「不按 Mute 鍵」即解**。

### 3.3 ⚠ 但同時要解掉 §10 第 1 項之歧義 —— **用涵蓋兩讀之限定，而非判讀它**

執行層自陳：`r46`／`r47` 之 `Else: Mute Active` 判為「維持」而非「使之靜音」，
其依據為箭頭之有無，**而矩陣未定義其記法**；若該詞意為「使之靜音」，
**牴觸由 1 增為 3**。

**不必判讀該歧義。** `r46`／`r47` 之觸發為
`Headunit Mode Button Pressed` 與 `Headunit Mode Change via VR`
—— **同樣是測試員可控之事件**。

**將該二事件一併納入限定，則無論 `Else: Mute Active` 作何解，該二列皆不適用。**

**這比判讀歧義更強**：判讀可能判錯，而涵蓋兩讀之限定不會。
→ R-PMH95。

### 3.4 擴充後之限定（**七項**）

| # | 限定 | 其所排除之格 | 對應斷言 |
|---|---|---|---|
| 1 | 不按 ON/OFF 鍵 | `r6`／`r24` | pop-up |
| 2 | 不轉 key-off | `r15` | pop-up |
| 3 | 不開啟車門 | `r25` | pop-up |
| 4 | 不操作 HVAC 硬控 | `r48` ＋ **p9 之 `Pop-ups still shown`**（已由 §二證為未對照，惟限定仍涵蓋之） | pop-up |
| **5** | **不按 Mute 鍵** | **`r45`** | **audio** |
| **6** | **不按 Headunit Mode 鍵** | **`r46`**（無論 `Else: Mute Active` 作何解） | **audio** |
| **7** | **不以 VR 變更 headunit mode** | **`r47`**（同上） | **audio** |

**四項變七項，其增加全部來自 audio 斷言之掃描。**

## 四、由此得出之通則 —— **限定須逐斷言導出，其總集為聯集**

R-PMH87 之四項限定係自 **pop-up 一個斷言**導出。
**其導出過程正確，其結果對該斷言充分** ——
**而它被當成了整條 TC 之限定。**

`-007` 之 ER 有 5 條、斷言更多；**每一斷言各有其相關之矩陣列**，
**故每一斷言各需其限定，TC 之限定為各斷言所需之聯集。**

→ R-PMH94。

**且執行層 §10 第 3 項已指出**：`-007` 之 ER1／2／3／5 之斷言**完全未反向掃**。
依 R-PMH94，**限定之充分性在該掃描完成前無法主張** ——
現行七項只涵蓋 ER4 之兩個斷言。列為步驟 4。

## 五、裁決條文（逐條抄入 `RULINGS.md`）

```
R-PMH94（限定須逐斷言導出，其總集為聯集）
TC 之事件層限定，其導出單位為**斷言**（R-PMH93 之單位），非 TC。

每一斷言各須：
(a) 以其自身之關鍵詞反向掃描規格與素材（R-PMH90／R-PMH93）；
(b) 列出與其取相反值之格／行；
(c) 導出使該等格／行不適用所需之限定。

**TC 之限定為各斷言所需限定之聯集**；
**在其全部斷言皆完成 (a)~(c) 前，不得主張該 TC 之限定為充分。**

依據：R-PMH87 之四項限定係自 pop-up 一個斷言導出，其對該斷言充分，
**而被當成整條 TC 之限定**；24 包對 audio 斷言之掃描查出 `r45` 之牴觸
（`Mute Button Pressed` → `Mute --> Active` × `The announcement is heard
in the background`），**該格不為原四項所排除**。
`-007` 之限定因而由四項增為七項（25 包 §3.4），
**而其 ER1／2／3／5 之斷言仍未掃**（24 包 §10 第 3 項）。
```

```
R-PMH95（歧義以涵蓋兩讀之限定處置，不以判讀處置）
素材之記法有歧義而其兩讀導致不同判定時，
**若存在一個涵蓋兩讀之處置，取該處置，不判讀該歧義**。

理由：判讀可能判錯，而涵蓋兩讀之處置不會；
且判讀須寫入依據而該依據無來源（素材未定義其記法），
即為以無來源之推論支撐判定。

現行適用：矩陣 `r46`／`r47` 之 `Else: Mute Active` 可讀為「維持靜音」
或「使之靜音」，執行層以「箭頭之有無」判為前者而自陳矩陣未定義其記法
（24 包 §4.3／§10 第 1 項）。
**其觸發（`Headunit Mode Button Pressed`／`Headunit Mode Change via VR`）
為測試員可控之事件，故納入限定即涵蓋兩讀** —— 不判讀。

**本條不使該歧義消失** —— `Else: Mute Active` 之語意仍未定，
其登記（A-PMH22）保留；本條只使**本 TC 之判定不再倚賴它**。
```

```
R-PMH96（互斥之依據優先取規格逐字）
條件互斥之證明（R-PMH84），其依據**優先取規格之逐字**；
無逐字可取時方得取素材之結構；**常識與通念不得作為依據**。

依據：A-PMH21 之互斥證明，執行層原繫於「免責畫面必為 head unit 開機中
所顯示」並自陳「它是常識而非引文」（24 包 §10 第 4 項）。
**引文存在** —— `PITA6.1`（outline 10.4）逐字為
`Upon pressing power button to On state disclaimer screen shall be displayed
(see SU6.) unless certain phone call scenarios have occurred.`
免責畫面之顯示條件即 head unit 轉為 On，
**故其不可能出現於 `HEADUNIT POWER OFF` 欄所述之狀態**（25 包 §2.2）。
```
