## 二、`-002` —— **我判錯了，執行層是對的**

15 包 §4.2 逐字：「分析層 §3.3 判 `-002` 之 P0『依據成立』。**本層不同意，
據實回報。**」

**其指認完全成立，我接受。**

`-002` 原依據為「Accept 為離開免責畫面之**唯一主動路徑**，其失效即無法
進入 last mode screen」——**該句於非 Maserati 不成立**：逾時路徑仍在
（正是 `-003` 所驗者），Accept 失效後車輛仍會自行離開。

**而這與 `-003` 犯的是同一個錯的鏡像**：

| tc | 錯誤形態 |
|---|---|
| `-003` | 論證逾時之重要性時，**把 Accept 路徑當作不存在** |
| `-002` | 論證 Accept 之重要性時，**把逾時路徑當作不存在** |

**我在 15 包 §3.1 抓到了前者，卻在同一份文件之 §3.3 放行了後者** ——
兩者相距三段。我用了「其失效使開機無法完成」這個判準去驗 `-003`，
卻沒有把同一個判準回頭套到 `-002` 上。

**R-PMH59 是我立的條**（priority 依據須批內互不矛盾），
**而我自己執行該條時只做了單向** —— 檢查了被質疑者，沒檢查支持質疑之依據
所倚賴的那一條。**這是 R-PMH51「單向比對看不見漏句」在推理層之同型。**

執行層之改寫（`-002` 之 P0 結論維持，依據換為「Accept **於 Maserati 為
唯一路徑**」）**正確且更強** —— 其級差之來源可一句說完：

> Accept 之失效**有無替代路徑視變體而定**（Maserati 無）；
> 逾時之失效則**恆有 Accept 可替**。

三條之依據自此互不矛盾，**且不再依賴任何一條把另一條的路徑當作不存在**。

## 四、`sandbox/spec.txt` 與 PDF 之等同性（15 §10 第 3 項）—— **判準錯了，不是證據不足**

執行層擔憂：全部 marker 量測建於 `spec.txt`，而其字元數（15,167）與
分析層之 15,751 差 584，**「極可能來自空白正規化，但我沒有證明它是」**。

**該擔憂之處置不是去證明那 584 字元** —— **R-PMH21 已裁定「規格 PDF 之
抽取字元數不得作為規格完整性、抽取正確性或版本一致性之判準」**，
而「兩份萃取是否為同一份文件」正是版本一致性之問題。
**用一個已被明文禁用之量作為擔憂之依據，是判準之誤用。**

**正確之等同性判準已經存在且已經通過**：

| 項 | 分析層（`pymupdf`，`pm.txt`） | 執行層（`spec.txt`） |
|---|---|---|
| marker 全集 | **31** | **31** |
| 章 7 | 13（含 `DS4.1)`） | 13（含 `DS4.1)`） |
| 章 8／9／10／11／12 | 6／1／7／1／3 | 6／1／7／1／3 |
| 缺漏 | `SU9.)`、`SU9.1)` | `SU9.)`、`SU9.1)` |

**兩份獨立萃取之 marker 集合逐項相等** —— 而 marker 是需求單位之標記，
其集合相等即證二者為同一份規格之同一版本。**這比字元數強，
且它不受任何正規化策略影響。**

→ R-PMH60。

## 五、`VERDICT` 之殘餘盲區（15 §10 第 1 項）—— **採納其自提之下一步**

執行層指出：反向掃描保證「沒有候選被漏看」，但每一候選是 `req` 還是
`noise` 仍由人判；**誤判為 `noise` 者，該章一樣靜默消失，
且 must-hit C 抓不到**（它只抓「未判定」，不抓「判錯」）。

其自提之下一步為：對判為 `noise`／`xref` 者，檢查其鄰近文句是否具需求語氣
（`shall`／`should`／祈使句），有者升為須人讀。

**採納**，並補一項使其可驗：**該檢查須有 must-hit** —— 把 `SU` 之判定
由 `req` 改為 `noise`（測試替身），其鄰近文句必含需求語氣，
故須被升為須人讀並攔下。**若攔不下，該檢查對真正的誤判亦無效。**

→ R-PMH61。

## 六、裁決條文（逐條抄入 `RULINGS.md`）

```
R-PMH60（兩份萃取之等同性判準）
同一規格文件之兩份獨立萃取（不同工具、不同正規化策略），其等同性
以 **marker 集合是否逐項相等**驗之，**不以字元數、行數或位元組數**。

理由：R-PMH21 已裁定抽取字元數不得作為完整性、正確性或版本一致性之判準；
「兩份萃取是否為同一份文件」即版本一致性之問題，
故以字元數之差異為據提出或消解該疑慮，皆為判準之誤用。

marker 集合為需求單位之標記，**不受正規化策略影響**；其逐項相等
即證二者為同一份規格之同一版本。

實測（16 包 §四）：分析層之 `pymupdf` 萃取與執行層之 `spec.txt`，
marker 全集皆 31、逐章計數皆同、缺漏皆為 `SU9.)`／`SU9.1)` ——
**等同性成立**，字元數之 584 差額不予採認為疑點。
```

```
R-PMH61（VERDICT 誤判之偵測）
marker 前綴之 `VERDICT` 判定（R-PMH57）中，判為 `noise` 或 `xref` 者，
須另行檢查其鄰近文句是否具**需求語氣**（`shall`／`should`／`will`／
祈使句起首），命中者升為「須人讀確認」並於輸出具名。

must-hit（缺之則本條無效）：將一個已知為 `req` 之前綴（如 `SU`）之判定
改為 `noise`（測試替身），其鄰近文句必含需求語氣，
**故須被升為須人讀並攔下**；攔不下者，本檢查對真正之誤判亦無效。

依據：15 包 §10 第 1 項 —— 反向掃描保證「沒有候選被漏看」，
但 must-hit C 只攔「未判定」，不攔「判錯」；
誤判為 `noise` 者，該章一樣靜默消失。
```

```
R-PMH62（自訂判準須雙向自套）
提出某一判準以質疑某項結論時，須將同一判準**回頭套用於支持該質疑之
其他項**，並記其結果。

單向套用會產生一種特定形態之錯誤：**被質疑者被修正，而質疑所倚賴之
另一項帶著同型缺陷通過**。

依據：分析層於 15 包 §3.1 以「其失效使開機無法完成」之判準抓出 `-003`
之 P0 依據不成立，卻於同一份文件 §3.3 放行 `-002` ——
而 `-002` 之依據犯的是同一個錯之鏡像（論證 Accept 之重要性時把逾時路徑
當作不存在）。由執行層於 15 包 §4.2 查出（16 包 §二）。

此為 R-PMH51「單向比對看不見漏句」在推理層之同型。
```
