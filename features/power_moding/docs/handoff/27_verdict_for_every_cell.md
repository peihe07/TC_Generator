## 二、§12 第 1 項 —— **你做到的比你以為的多，差的是一個名字**

執行層自評其未達成「關鍵詞只排序」。**逐項看其輸出後，我認為差距只有一步。**

### 2.1 那 126 格已經有判定了，只是不叫判定

`audio` 之落選 126 格，其輸出為：

```
41 格  該格之謂詞域為 ['state']，與 `audio` 不交
28 格  該格之謂詞域為 ['power']，與 `audio` 不交
 9 格  該格無任何謂詞域之詞
```

**「其謂詞域與 audio 不交」就是一個 `未對照` 之判定，且其依據已具名。**
R-PMH79 之 `未對照` 定義即「無共同謂詞」——
**這些格所得到的，正是那個記法。**

**故現況與 R-PMH98 之要求，其差別不在有無判定，而在**：

| | 現況 | 應為 |
|---|---|---|
| 那 126 格 | 列於「落選」欄，**不在 `VERDICT` 表內** | **以 `未對照` 入 `VERDICT` 表**，與入選之 48 格並列 |
| 關鍵詞 | 決定「入選 vs 落選」兩個**不同待遇** | 決定**人讀之先後**（皆已有判定，只是誰先被人看） |
| `verdict_form.py` 之母體 | 48 | **174** |

**「落選」這個類別一旦消滅，關鍵詞就自動降為排序** ——
因為它不再決定任何格之待遇，只決定順序。

### 2.2 而偽陰隨之改變性質

| | 現況之偽陰 | 改造後之偽陰 |
|---|---|---|
| 形態 | 某格因用詞未被想到而**不存在於輸出** | 某格因**謂詞域分類錯誤**而得 `未對照` |
| 可否檢查 | **否**（不在輸出裡） | **是** —— 可構造 must-hit：一格含 audio 用詞而被分為 `state` → 須 FAIL |

**這才是 R-PMH98 之實質** —— 不是消滅列舉，是**使列舉之錯誤變成可檢查的**。

→ R-PMH100。

## 三、§12 第 3 項 —— 斷言之切分不該由連接詞決定

執行層自陳：切分以 ` and ` 為之而該規則未經驗證，
並舉 `-002` ER1 `The disclaimer screen is displayed with the "Accept" button`
—— **含兩個可分之斷言（畫面顯示／按鈕顯示）而其連接詞為 `with`，未被切開**。
**「23 這個數字是該規則之產物。」**

**成立。** 斷言之單位應為**謂詞**：一個獨立之謂詞即一個斷言。
`with` 之例中，`is displayed`（畫面）與其受詞所隱含之（按鈕之呈現）
為兩個可各自為真為假之命題。

**惟謂詞之切分不可機械化到底** —— 故其規則為：
機器以連接詞（` and `／` with `／` while `／分號／逗號）**產生候選切分**，
**人讀複核其是否各自可獨立為真為假**，複核結果寫入常數。

→ R-PMH101。

## 四、§12 第 6 項 —— Pre-Condition 之斷言該入母體

執行層自陳只掃 `expected_result` 之斷言，
`pre_conditions` 與 `test_procedure` 不入任何掃描母體。

**依 R-PMH97 之二分**：

| 欄 | 其斷言之類 | 是否入母體 |
|---|---|---|
| `expected_result` | 多為 SUT 行為斷言 | **是**（現行） |
| **`pre_conditions`** | **SUT 之狀態斷言**（`The system has reported ready`／`A traffic announcement is available`） | **是 —— 現行漏了** |
| `test_procedure` | 測試員之操作 | **否**（R-PMH97 之測試執行斷言） |

**Pre-Condition 描述的是 SUT 之狀態，其主語為 SUT** ——
依 R-PMH97 之判別法，**它屬 SUT 行為斷言，本就該掃**。

**其風險非零**：若矩陣某格斷言「在該情境下 SUT 不可能處於該狀態」，
則該 TC 之 Pre-Condition **無法被建立**，其整條 TC 不可執行。
**這比 ER 之牴觸更早失效。**

→ R-PMH102。

## 五、裁決條文（逐條抄入 `RULINGS.md`）

```
R-PMH100（落選即判定 —— 消滅「落選」類別）
斷言掃描（R-PMH98）之粗篩，**其落選項須以四詞記法（R-PMH91）
入判定表**，不得另列於「落選」欄。

落選之常見記法為 `未對照`，其依據即粗篩所憑之理由
（如「該格之謂詞域與本斷言不交」）。

**「落選」這個類別消滅後，關鍵詞即自動降為排序輔助** ——
其不再決定任何格之待遇，只決定人讀之先後。R-PMH98 之要求於此達成。

**本條同時改變偽陰之性質**：
  改造前 —— 某格因其用詞未被想到而**不存在於輸出**，**不可檢查**；
  改造後 —— 某格因其**謂詞域分類錯誤**而得 `未對照`，**可構造 must-hit**
            （一格含該斷言之用詞而被分入他域 → 須 FAIL）。

**R-PMH98 之實質不是消滅列舉，是使列舉之錯誤變成可檢查的。**

依據：26 包 §4 之 `audio` 落選 126 格，其輸出已含具名理由
（「其謂詞域為 `['state']`，與 `audio` 不交」）—— **該理由即一個
`未對照` 之判定**，只是不在 `VERDICT` 表內（26 包 §12 第 1 項自陳）。
```

```
R-PMH101（斷言之切分以謂詞為準，非以連接詞）
斷言之單位為**謂詞**：一個可各自為真為假之命題即一個斷言。

切分之作法為兩層：
(a) 機器以連接詞（` and `／` with `／` while `／`;`／`,`）**產生候選切分**；
(b) **人讀複核**其各切片是否各自可獨立為真為假，
    複核結果寫入常數（非只在上繳包）。

**不得以任一連接詞之有無單獨決定切分。**

依據：26 包以 ` and ` 切分得 23 個斷言，而
`-002` ER1 `The disclaimer screen is displayed with the "Accept" button`
含兩個可分之命題（畫面之顯示／按鈕之呈現）而其連接詞為 `with`，
**未被切開**；執行層自陳「**23 這個數字是該規則之產物**」
（26 包 §12 第 3 項）。
```

```
R-PMH102（掃描母體及於 Pre-Condition）
斷言掃描之母體及於 `pre_conditions`。

依 R-PMH97 之判別法（主語是否為 SUT）：
  `expected_result` —— 多為 SUT 行為斷言，**入母體**；
  `pre_conditions`  —— **SUT 之狀態斷言**（`The system has reported ready`），
                      **入母體**；
  `test_procedure`  —— 測試員之操作，屬測試執行斷言，**不入母體**。

**Pre-Condition 之牴觸比 ER 之牴觸更早失效**：若素材某格斷言
「在該情境下 SUT 不可能處於該狀態」，則該 TC 之前提無法建立，
**整條 TC 不可執行**，而其 ER 是否牴觸已無意義。

依據：26 包 §12 第 6 項（執行層自陳只掃 `expected_result`）。
```
