## 三、資料檔註解行（A-DM23）—— 裁定

執行層自陳：`data/` 下五個 TSV 之 `#` 註解行會使
`csv.DictReader` 把註解讀成表頭，**失敗形態為「空資料」而非報錯**。
兩個處置方向皆影響此後所有 feature，故未自行擇一。**正確。**

### 3.1 裁定：出處移出資料檔，改為同名 sidecar

`data/` 下之 `.tsv` **第一行必須是表頭列**，不得有任何前置行。
出處、量測條件、廢止註記等移入同 stem 之
`<name>.tsv.meta.json`，欄位至少：

```json
{
  "generated_by": "features/display/scripts/coverage_map.py",
  "generated_at": "2026-08-25T…",
  "inputs": [{"file": "…", "sha256": "…"}],
  "measurement_conditions": "…",
  "rulings": ["R-DM13", "R-DM22", "R-DM25", "R-DM26"],
  "notes": "…"
}
```

**不採「保留註解行並明定慣例」之方向。** 理由與 R-G16(a) 同型：
那需要每一個未來的讀取者都記得略過 `#`，而失敗形態是靜默的空資料 ——
正是「靠紀律維持、且壞掉時不出聲」的那一類。sidecar 之失敗形態是
**檔案不存在**，會出聲。

sidecar 與資料檔分離之風險（被搬走一個）以兩項緩解：
(a) 兩檔同 stem，`ls` 即見成對；
(b) 產生腳本一律同時寫兩檔，缺一即為腳本缺陷。

### 3.2 適用範圍

本條**自本輪起適用**，並回溯處理 Display `data/` 下現有全部 `.tsv`。
其他 feature 之既有資料檔不回頭修改（同 R-G1 之慣例），
惟新產出者一律適用。

執行層須全 repo 清查 `features/*/data/*.tsv` 之第一行是否為表頭列，
**清查結果登記，不代其他 feature 修改**。
