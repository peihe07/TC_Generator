## 二、B11 之處置 —— 把判斷改成資料

執行層自陳（B11）：R-G33(c) 之三個「指名 token」
（`warning popup`／`protective shutdown`／`multi-stage`）
是**它從中文 deferred 項自行對譯**的，條文未規定對照方式。

> 本批三項皆單純，但若 deferred 項之措辭較抽象，該對譯即成判斷而非量測。

**這是 B9（停止條件 58 之自訂詞表）之第二例，且可結構性解決。**

**裁定**：`deferred` 陣列之每一項改為物件，明載其英文 token。
即由

```
"SWE1-DM-004 之 warning popup（PU0517）—— DR-DM10(a) 未結。…"
```

改為

```json
{
  "leaf_id": "SWE1-DM-004",
  "token": "warning popup",
  "reason": "DR-DM10(a) 未結。組 B {4820289} 於越過門檻時即關背光，…",
  "blocking_dr": "DR-DM10"
}
```

`token` 為**寫 deferred 項時就決定**之值，非事後對譯。
R-G33(c) 之檢查改為「括號下半是否含該項之 `token` 逐字」——
**檢查成為純字串比對，無判斷成分**。

`token` 之選定仍是人的決定，但它落在**寫 deferred 之時**、
由**寫的人**負責，且會被上繳包看見；不再是檢查時另一個人的事後推論。

## 三、裁決條文

```
R-G34（抄錄之置放以順序驗證通過為準 —— 全域）
條文抄錄之**置放位置**，以 `transcribe_rulings.py` 之順序驗證
能維持 exit 0 為準；不得為了條文之字面相鄰而使該驗證失效。

理由：順序驗證是抄錄鏈唯一之機器保證，「累計 N 條、逐字元全數相符」
一語自 09 輪起每包引用。相鄰性是導覽之便利，可由指標達成；
順序驗證失效則整條保證失效。**兩者代價不對等。**

補充條文（對既有條之補充、修正、加註）一律置於其**所屬下放包**之節，
非其所補充之條之下。其導覽以二者達成：
(a) 被補充之條下留一則指標（非 fence，不入核對表母體），
    指向補充所在之節，並記其置於別處之理由；
(b) 檔末之「廢止與取代之對照」表增一列，記其關係。

**分析層之指示若與本條衝突，以本條為準，執行層具名回報即可，
不待重裁。**

實例（上繳 23 §1.1）：下放包 23 指示「R-DM48 之補充追加於 R-DM48
條下」。執行層先照做並實測 —— 該置放使順序驗證由「全數相符」轉為
「有不符」並 exit 1（`display_source_blocks()` 依下放包檔名重建應有
順序，而 R-DM48 出自 20 包、其補充出自 23 包）。改採檔末置放後
exit 0。**指示有誤，偏離正確。**
```

```
R-G33(d)（揭露句之時效 —— R-G33 之補充）
R-G33(a)(b)(c) 規制**揭露之寫入**。本項規制其**解除**。

`deferred` 項一旦解除（DR 答覆到達、缺件補齊、範圍重裁），
其對應之揭露句**須同步自各 TC 之 `test_item` 括號下半移除**。

理由：揭露句之誤讀風險是**雙向**的。
  寫入時不揭露 → 部分覆蓋被讀成完整覆蓋（R-G33 所防）
  解除後不移除 → **完整覆蓋被讀成部分覆蓋**（本項所防）
兩者皆為工作簿上之不實陳述，皆使交付面失真。

三項細則：
(1) R-G33(c) 之檢查**須於兩個時點各執行一次**：TC 寫入時、
    交付前（release gate）。只在寫入時檢查者，其保證於
    `deferred` 陣列變動之後即失效。
(2) 交付前之檢查為**雙向**：陣列有而括號無 → 違反 R-G33(b)；
    **陣列無而括號有 → 違反本項**。
(3) `deferred` 項之解除須連同其揭露句之移除一併記於該輪之上繳包，
    不得只記解除。

實例（上繳 23 §三末列，執行層增列）：Display pilot-01 之三條
現各含一句 `… is deferred`，其正確性有時效。DR-DM10 答覆而
deferred 解除後若無人回頭刪除，工作簿會宣告一個已被測之面向未被測。
**立條者（分析層）只想到一個方向。**
```

```
R-DM53（`deferred` 項改為物件，明載其英文 token）
`batch_context.md` 與 `generated/*.json` 之 `deferred` 陣列，
其每一項改為物件，必含四鍵：

  leaf_id      該 deferred 項所屬之 leaf
  token        R-G33(c) 檢查所用之英文 token，**逐字**
  reason       其被 deferred 之理由（中文可）
  blocking_dr  阻斷之 DR 編號；無則 null

`token` 為**寫 deferred 項時**決定之值，由寫的人負責，
並於上繳包中可見。R-G33(c) 之檢查改為「括號下半是否含該項之 `token`
逐字」—— 檢查成為純字串比對，**無判斷成分**。

理由（上繳 23 之 B11）：原陣列為自由文句，檢查者須自中文標的
對譯英文 token 方能比對。本批三項標的具體（popup／shutdown／
multi-stage）故對譯無爭議，**而「對譯無爭議」本身是檢查者之判斷，
無第二來源核對**。措辭較抽象時，該對譯即成判斷而非量測。

本條與 B9（停止條件 58 之自訂詞表）同類：
**一個看起來是機器判準之檢查，其詞表是人給的。**
差別在本條可結構性解決 —— 把詞從檢查端移到宣告端。

現行三項之 `token` 依上繳 23 §2.1 之對譯落定，
**不重新決定**（其已通過複驗且三條之揭露句已依其補寫）。
```
