## 三、裁決條文

```
R-G35（素材之可及性須於下放包內聲明 —— 全域）
下放包若以某素材為依據下指令，須聲明該素材**於執行層側之可及性**：

  (a) 已在 repo → 記其路徑
  (b) 在 `forms/` 或他 feature → 記其路徑與取得方式
  (c) **僅存在於分析層（Project 附件、對話上傳）→ 須逐字寫明
      「該檔須由 Pei 置入 <路徑>，在此之前步驟 X 不可執行」**

分析層之量測得自附件複本者，其數字仍可寫入下放包作為比對基準
（canon §5a 之界線宣告），**但不得據以下達需要該檔在手方能執行之步驟，
除非同時聲明 (c)。**

理由：分析層與執行層之可視範圍不同。分析層看得到的東西，
執行層未必拿得到；而下放包之語氣不區分兩者時，
執行層只能以「找不到」回報，一輪往返即耗於此。

本條補 R-G32 之未涵蓋向：R-G32 規制「前置**狀態**須為已查證之事實」，
本條規制「所依**素材**之可及性須被聲明」。

實例（下放包 24）：其全部量測取自 Project 附件之
`SYS2_CFTS013_…xlsx`，而該檔從未進入 repo。24 包步驟 5 寫
「檔案置入 `features/display/inputs/`」，未寫其須由 Pei 先行置入，
致步驟 4／5／6 與停止條件 61／62 皆無從執行。**錯在下放包。**
```

```
R-G36（規格內容一律機器抽取，不得自下放包轉抄 —— 全域）
凡寫入 `data/*.tsv`、`generated/*.json`、或任何交付所依之資料檔者，
其**規格本體之內容**（逐字引文、條號、值域、門檻）一律由執行層
**自素材機器抽取**，不得自下放包之文字轉抄。

理由：下放包之數字與引文為分析層之量測結果，其地位是**比對基準**
（canon §5a），不是資料來源。轉抄會使資料檔之 `generated_by`
落為「人工登記自下放包 N」——而該欄之全部意義是可重跑。
**一份不可重跑的資料檔，其可信度即等於當初抄的人的注意力。**

三項細則：
(a) 素材不在手上時，該筆**登記為待辦，不寫入**；不得以
    「來源＝下放包 N、未經重算」之形態先行寫入
(b) 分析層之下放包若要求轉抄，執行層具名回報即可，不待重裁
    （同 R-G34 之分寸）
(c) 例外僅一：分析層之**裁決條文本身**（`R-*` fence 區塊）
    為逐字抄錄之標的，其抄錄機制另有核對表保證

實例（上繳 25 §5.3）：下放包 24 步驟 4 要求把 `{CFTS013-937}` 之
逐字引用寫入 `popup_priority.tsv`。執行層拒絕並指出
「**這是全案唯一一次我被要求把沒見過的規格文字寫進資料檔**」。
其判斷正確；分析層不採其所提之「未經重算形態先登記」替代方案 ——
一份標著未經驗證的來源登記，於動工時仍須重查，先寫只是把重查
的必要藏起來。
```
