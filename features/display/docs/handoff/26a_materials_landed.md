## 二、【待裁】`inputs/` 出現一份 SYS2 之重複檔

同時出現：

```
inputs/SYS2_CFTS_020_DISP_TCH_ICS_20260616_All_HW_System_Accepted & Released.xlsx
inputs/SYS2_CFTS_020_DISP_TCH_ICS_20260616_All_HW_System_Accepted & Released copy.xlsx
                                                                          ^^^^^
```

分析層實測（`Filesystem:get_file_info`）：

| 檔 | size | mtime |
|---|---|---|
| 原檔 | **193,683** | 2026-08-16 06:30:00 |
| `copy` | **193,683** | **2026-08-25 21:15:49** |

**大小相同、mtime 為今日。** 形態上像是置入 CFTS013 時附帶產生之副本，
**但分析層不推定其成因**。

### 2.1 為何這件事不能放著

| 面向 | 影響 |
|---|---|
| `reference:` 綁定 | `sys2_export` 綁**確切路徑**（不含 `copy`），故 `verify_reference_binding.py` 仍會回 MATCH ——**它不會發現多出一份** |
| `paths.sys1_export` | 亦為確切路徑，`recon.py` 取原檔 —— **不受影響** |
| 任何掃 `inputs/` 之作業 | **會看到兩份**。素材台帳、覆蓋重算、日後之人 |
| git | `inputs/` 由 `.gitignore` 排除（R-G12），**此重複不會出現在任何 diff** |

即：**現有的每一道機器檢查都會放過它，而它會誤導人。**
這正是 R-G23 所指之「宣告不等於保護」之另一面 ——
綁定保護的是「這一份是不是原來那一份」，不保護「旁邊有沒有第二份」。

### 2.2 待 Pei 裁示（檔案刪除屬 Pei）

| 選項 | 適用情形 |
|---|---|
| **甲** | 誤複製 → **刪除 `copy` 檔**。分析層建議此項，若其確為誤複製 |
| **乙** | 有意置入且為不同版本 → 須說明其與原檔之關係，並裁定何者為準；若為新版，`sys2_export` 之 sha256 須重裁（**不得靜默更新**，R-G23） |
| **丙** | 有意保留為備份 → 移出 `inputs/`（該目錄之語意為「本 feature 之受裁素材」，備份不屬之） |

**裁示前，執行層不得刪除、不得移動、不得改名**（檔案動作屬 Pei），
亦**不得將 `copy` 檔納入任何量測母體**。
