## 一、上繳包 13 之覆核

**核可。停止條件 34 之觸發正確，該項不得由執行層擇一。** 四項具名。

### 1.1 A-DM30 —— 綠燈檢查了錯的東西

四個新 `reference:` 鍵首次插入時落成 `lint:` 之子鍵。
**YAML 解析無誤、無警告、檢查照常輸出 `5 of 5 match.`**

執行層之定性採認：

> 這與 A-DM28 同族而不同型：A-DM28 是**訊息說謊**，
> 本條是**對象錯了而結果仍是綠的**。

其後續觀察更重要：

> `entries: N` 那一行是唯一能察覺此錯的線索（5 vs 9）。
> 引用綁定結果時應連同該行，**不得只引「N of N match」** ——
> 「5 of 5」與「9 of 9」都是全綠。

升為全域條文（§四 R-G26）。

### 1.2 A-DM29 —— 用子字串判斷「兩個概念是不是同一個」

上輪判「`Header row index`：recon 有測」，依據是子字串 `"header"`
命中 —— 而實際命中的是 `column mapping: 15 fields resolved from
header text`。以確切詞組 `"header row"` 重掃：**0 命中**。

執行層之自評採認並升為全域條文（§四 R-G27）：

> 我在判斷「兩個概念是不是同一個」時**用了非逐字之方法**（子字串），
> 而那正是 R-DM13 對 bag-of-words 之禁令所針對的思路，
> 只是換了一個對象。

**這條的影響比它看起來大**，見 §三。

### 1.3 §5 之量測形狀

守衛絕對成本 0.04 s，佔最慢腳本 0.9%、佔最快腳本 **46.4%**。
執行層之判定「現況可接受，不優化」正確，且記明其形狀：

> 成本隨**呼叫次數**線性成長，而非隨資料量。

只報「0.9%」會讓人以為它便宜；只報「46.4%」會讓人以為它昂貴。
兩個都報，並指出成本的自變數是什麼 —— 這才是可用於日後決策的量測。

### 1.4 分析層之一項獨立複驗

`sys2_export` 之綁定值為 `421c8eef3f5cb01a…`。該值與上繳 08 §2.1
所載之「冒名檔雜湊」相同，形式上可疑。

分析層對沙箱內之 SYS2 複本實算：

```
421c8eef3f5cb01a2d4d4768b41d38897009c53cdfdff2ff1b6ab80ba72adb1d
```

**逐字相符，非錯置。** 08 輪之冒名測試正是以 SYS2 之 xlsx 頂替 037

## 二、§3.2 之裁定 —— 同名異量，拆為兩個名字

`Missing referenced specs` 一名之下並存兩個量：

| 側 | 定義 | 值 |
|---|---|---|
| recon | leaf 所引之 **outline 章節**不在受裁匯出中者 | 0 |
| 自測 | CFTS_020 **本文**以 `{CFTSnnn-mmm}` 引用之**外部文件** | CFTS_009、CFTS_013，另 6 份未評估 |

**兩者皆保留，改名以區分**（§四 R-DM40）。

且執行層之附註是本項之關鍵：**recon 之 0 是空的 0** ——
本 feature 之 `citation column: NOT FOUND`、`sections: 0`，
故「所引章節不在匯出中」者必然為 0。依 canon §5a，
不可能失敗之檢查不標 PASS，標「未實測」。

**若不拆名，`DECISIONS.md` 會出現一個看起來是 0 的缺口。**
而實際上一個是「查不到缺口，因為根本沒有東西可查」，
另一個是「查到兩份缺件並已開 DR」。

## 三、R-G27 之回溯適用 —— 交叉檢查之涵蓋面須自我審查

A-DM29 揭露之問題不止於一項偽陽性。**上繳 09 §4 之 17 項交叉檢查
是本 feature 唯一一次獨立驗證，而其項目對應同樣是人工手動建立的**
（執行層 §6 第 2 項自陳）。

該表之每一列都是一個「recon 之某項 == 自測之某項」之主張，
而那些主張**未經任何逐字檢驗**。其中若另有偽陽性，
則「16/17 相符」之結論本身就有洞。

本包要求回頭審查該表（步驟 3）。**這不是重做交叉檢查，
是檢查交叉檢查的映射。**

## 四、裁決條文

```
R-G26（綠燈須連同其母體一併引用 —— 全域）
凡「N 項全部通過」形態之檢查結果，其引用一律須連同**母體大小**
（`entries: N`／`checked: N`／母體列數）。

**禁止單獨引用「N of N match」「0 failed」「全部相符」等表述** ——
「5 of 5」與「9 of 9」在字面上同樣是全綠，而其中一個檢查的
可能是錯的對象。

實例（上繳 13 §4.1，A-DM30）：四個 `reference:` 鍵因 YAML 縮排
落成 `lint:` 之子鍵。解析無誤、無警告，檢查輸出 `5 of 5 match.` ——
一個通過的檢查，檢查的卻不是預期之對象。`entries: 5` 是唯一線索。

一般化：**綠燈之意義由其母體界定。** 母體錯了，綠燈只證明
「錯的那組東西彼此一致」。
```

```
R-G27（概念映射須以確切詞組或欄位鍵為據 —— 全域）
判斷「兩份產出中的兩個項目是不是在講同一件事」時，**不得以子字串、
詞幹、token 重疊或任何近似比對為據**，須以確切詞組、完整欄位鍵、
或 JSON 之鍵路徑為之。無法以逐字建立映射者，判為「無對應」，
不得以「看起來像」補足。

理由：R-DM13 禁止以 bag-of-words 建立**資料列之間**的對應；
本條將同一禁令延伸至**產出項目之間**的對應。後者更隱蔽 ——
它產生的不是一筆錯誤的資料，而是一個錯誤的「已比對過」。

實例（上繳 13 §3.3，A-DM29）：以子字串 `"header"` 判定
`Header row index` 為「recon 有測」，實際命中者為
`column mapping: 15 fields resolved from header text`。
以確切詞組 `"header row"` 重掃得 0 命中 —— recon 不報表頭列號。

**本條回溯適用**：凡既有之對照表其項目映射為人工建立者，
須以本條之判準重新審查一次，偽陽性逐項更正。
```

```
R-DM40（`Missing referenced specs` 拆為兩名）
本 feature 之 `DECISIONS.md` 中，`Missing referenced specs` 一名之下
並存兩個不同的量，拆分如下：

(a) **`Cited outline sections absent from the ruled export`**
    —— `recon.py` 之 `outline_misses`。本 feature 之值為 **0**，
    且該 0 為**空的 0**：`citation column: NOT FOUND`、`sections: 0`，
    故此檢查在本 feature 不可能失敗。
    依 canon §5a **標「未實測」，不標 PASS 亦不標 0**。

(b) **`External CFTS documents cited by the body`**
    —— CFTS_020 本文以 `{CFTSnnn-mmm}` 引用之外部文件。
    已評估者二：CFTS_009（`{CFTS009-722}`，→ DR-DM1）、
    CFTS_013（→ DR-DM4）；**另 6 份未評估**（A-DM13）。

兩者皆為有效之量，皆保留。**不得合併、不得擇一** ——
一個是「查不到缺口，因為沒有東西可查」，另一個是
「查到兩份缺件並已開 DR」，合併會使後者被前者的 0 蓋掉。
```
