## 三、Q2 之第三種框架（提交 Pei，與 A／B 並列）

briefing 依下放包之要求只列 A、B 兩個選項且不含偏好。分析層另提一項
**A、B 皆未涵蓋之框架**，一併提交裁定：

**選項 C —— 範圍取 8 leaves，SYS2 取為內容來源而非範圍母體**

其依據為 briefing 中已量測之一項不對稱：

- 037 八條：數值 **0/8**、訊號 **0/8**、外部引用 **0/8**
  （A-DM18／R-DM27）
- SYS2 八十列：相異訊號 **15** 個、值 token **13** 個，
  其中 r31–r34 為 Display Hot 之完整狀態機

即：**037 界定「測什麼」，SYS2 供給「怎麼測」。** 兩者不是競爭之母體，
而是同一件事的兩個層級 —— 這一點在下放包 03 §4.2 已量測到
（037 之 `Hot Algorithm` 與 SYS2 r30 之 `Display Hot Algorithm` 逐字同名），
但當時被表述為「Q2 之前提垮了」，未被整理成一個可裁定之選項。

選項 C 之交付形態與代價：

- `req_id` 為 `SWE-DM-nnn`（8 個），與選項 A 同
- TC 之內容（訊號、值、狀態轉換）自 SYS2 相應列取得，
  依 R-DM14／R-DM17 之三段解析鏈
- **已知代價**：64 列無候選者之處置與選項 A 相同（未查證），
  且**新增一項揭露義務** —— 交付時須附「037 leaf ↔ SYS2 列」之
  對照表，使審查者看得見哪些 leaf 之內容有 SYS2 支撐、哪些沒有
  （現況：004／005 有 4 列、007／008 有 12 列、其餘四個 leaf **無**）
- **後者是選項 C 的真問題**：001／002／003／006 四個 leaf 在
  037 中無值、在 SYS2 中無逐字錨可連 —— 其 TC 之具體值**目前無來源**，
  須靠 CFTS_020 逐條查（DR-DM1／DR-DM4 已開）或全數以
  `PENDING: DR-{n}` 佔位（§8.4.3）

**分析層不代 Pei 擇一。** 提出選項 C 之理由是：A 與 B 之對立
（8 vs 80）預設了兩者為競爭母體，而已量測之事實不支持該預設。

## 四、裁決條文

```
R-G23（綁定須被檢查，宣告不等於保護 —— 全域）
R-G15 要求 `feature.yaml` 之 `reference:` 節逐項綁定參考資料庫之
檔名與 sha256。**本條補其執行面**：綁定須有一支檢查程式實際比對，
且該比對須在每次使用參考資料庫之產出前執行。

理由：一份宣告了 sha256 而從未被比對之綁定，其失效形態與「沒有綁定」
相同 —— 差別只在它讀起來像已經受到保護。R-DM19 之承載範圍
（26 列訊號解析、2 筆查無、此後所有 TC 之訊號欄）全部掛在該綁定上。

檢查失敗時之行為：**停並回報實際值與宣告值**，不得自行更新宣告值。
更新宣告值等同接受一份未經裁定之新版資料庫。

本條適用於 `reference:` 節之全部項目（dbc_b／dbc_fd／lid／proxi），
以及此後任何以 sha256 綁定之素材。
```

```
R-DM35（`DECISIONS.new.md` 之地位與失效）
`DECISIONS.new.md` 為 `recon.py` 某一次執行之產出，其地位為
**帶時間戳之證據**，非待處理之草稿。

三項規定：
(a) 合併完成後，檔首須加註「已於 <日期> 併入 `DECISIONS.md`，
    分歧處置見 <上繳包>」；原文依 R-TM13 保留
(b) 下次 `recon.py` 重跑產生新的 `DECISIONS.new.md` 時，
    舊者改名為 `DECISIONS.new.<日期>.md` 保留，不刪除、不覆寫
(c) `DECISIONS.md` 恆為權威（R-DM32）。任何一份 `.new.md` 皆不得
    被當作簽核標的

理由：檔名 `.new` 讀起來像「較新且待採用」，而其實際地位是
「較舊之一次量測」。名稱與地位相反之檔案會被誤用。
```
