## 二、它答了什麼、沒答什麼

### 2.1 【關鍵】它講的是 Associated Display，我們的 004／005 是 DCSD

檔名逐字為 `Radio_Error_Management-**Associated**_Display`。
而 `{CFTS013-930}` 逐字定義該區分：

> 那些觸控螢幕整合於 HU 模組者稱為 Associated variants；
> 那些介接外部觸控螢幕模組（**DCSD**）者稱為 Disassociated variants。
> 以 `_ADspl` 與 `_DDspl` 之後綴區分。

而本 feature 之 004／005 追溯至 CFTS_020 `1.11.2.2 DCSD Display Hot
Behavior` —— **DCSD 即 Dis**associated。

逐字佐證：

| 查詢 | 本檔命中 |
|---|---|
| `85 degree` / `85 deg` | **0 / 0** |
| `DISP_HOT` | **0** |
| `DCSD` | 94（皆在說明性段落與元件定義，**非需求本體之門檻**） |

本檔之門檻為 **50／51–55／56–<60／>=60 degrees C**（HU 顯示器），
CFTS_020 之門檻為 **85 degrees C**（DCSD）。**兩組不同，不得互相代入。**

### 2.2 DR-DM4 —— **不結案**

DR-DM4 求 `{CFTS013-629}`、`{CFTS013-633}`、`{CFTS013-952}` 三條之內容。

逐字搜尋結果：三者**各出現 1／1／2 次，全部落在 `r8`
（`CFTS013-752`，Category = Information）之修訂履歷自由文字內**，
**無一為 `Document ID` 欄之值**。即：**三條需求本體不在本檔內。**

本檔之 `Document ID` 全集（32 個）：
602, 751, 752, 0, 660, 603, 1192, 604, 930, 931, 605, 1196, 1197, 1194,
606, 609, 610, 611, 612, 613, 932, 950, 975, 951, 933, 934, 935, 937,
938, 939, 942, 947。

**本檔為 CFTS013 之部分分析（32 列），非全文。**

### 2.3 但它給了一個結構性事實 —— DR-DM10(b) 之問法須改

DR-DM10(b) 問「`{4820283}` 之警示階段時長／終止準據」，
其預設是**時間**。本檔顯示 HU 側之同型流程**以溫度分段，不以時間**：

| Document ID | 門檻 | 行為 |
|---|---|---|
| `CFTS013-975` | — | 開機後每分鐘量測一次顯示器溫度 |
| `CFTS013-951` | `>= 51` 且 `<= 55` | 每高於 50 一度，背光降 5%（51 → 5%、55 → 25%） |
| `CFTS013-933` | `>= 56` 且 `< 60` | 不再降低亮度，顯示 `"Screen is Hot"` 警示 |
| `CFTS013-938` | `>= 60` | 螢幕關閉（輸出 blank，背光強度 0） |
| `CFTS013-942` | `> 50` → `<= 50` | 恢復 `'Normal Screen Operation'` |

即：**warning → off 之轉換由「溫度到達下一級門檻」觸發，不由時長觸發。**

**這是 HU 側之事實，不是 DCSD 側之事實。** 但它使 DR-DM10(b) 之問法
應由「時長為何」改為「**DCSD 側之 warning → off 是否亦為溫度分段？
若是，其第二門檻為何？**」——見 §四步驟 3。

### 2.4 006（Pop Up Handling）之需求側業主已逐字取得

`{CFTS013-937}` 逐字含：

> the 'Screen is Hot' popup (**Popup PU0130**, a.k.a. 'Display is Hot')

**這是首次有需求本體逐字指名 `PU0130`。** 此前 `PU0130` 與需求之連結
只來自 Pop Up List 之 Description 相符（上繳 21 §6），屬語意相符；
現有逐字之需求側出處。

同條另載其優先序行為：警示顯示中若有更高優先序畫面
（Rear/Surround View Camera、SOS、Emergency Calls）須切換 ——
**此即 DR-DM2 所求之「popup 仲裁順序」之一部分**（HU 側）。

### 2.5 DR-DM1 之指標確認（內容仍缺）

`{CFTS013-612}` 逐字含 `See {CFTS009-722} for the Splash Screen,
Disclaimer Screen and Rear Camera Screen sequencing`。

**指標確認，內容仍不在手上。DR-DM1 維持 OPEN。**

### 2.6 一項不得誤用之數值

`{CFTS013-951}` 給了亮度降低之具體規則（每度 5%）。
上繳 22 之 B4 記「亮度降低之數值未給」——**該記載對 DCSD 側仍然成立**。
`CFTS013-951` 是 **HU 顯示器**之規則，且其門檻為 51–55°C，
與 DCSD 之 85°C 無關。**不得代入。**

## 三、裁決條文

```
R-DM51（Associated Display 與 DCSD 為不同標的，其值不得互相代入）
CFTS013（`Radio Error Management - Associated Display`）之需求標的為
**Associated Display**（觸控螢幕整合於 HU 模組者）；
CFTS_020 `1.11.2.2` 之需求標的為 **DCSD**
（Disassociated Center Stack Display，外部觸控螢幕模組）。

`{CFTS013-930}` 逐字定義該區分（`_ADspl` vs `_DDspl`）。

三項拘束：
(a) CFTS013 之門檻（50／51–55／56–<60／>=60 degrees C）與
    CFTS_020 之門檻（85 degrees C）**分屬兩個標的**，
    不得互相代入、不得以其一補其二之缺（§8.4.1）。
(b) `{CFTS013-951}` 之亮度規則（每高於 50 一度降 5%）為 Associated
    Display 之規則。**DCSD 側之亮度降低數值仍屬未給**
    （上繳 22 之 B4 對 DCSD 仍成立）。
(c) 引用 CFTS013 之任一值時，須於 `reasoning` 逐字記其標的為
    Associated Display，並記其與本 TC 標的之關係。

本條為本 feature 第四個命名近似陷阱（前三：037 檔名連字號 R-DM11、
CFTS043 為 HVAC A-DM31、SYS3 無 `SYS-RA-DISP`）。
**其形態最隱蔽** —— 檔名、章節名、門檻語彙、popup id 全部相似，
差別只在 `Associated` 與 `Dis`associated 一字。
```

```
R-DM52（本檔為 CFTS013 之部分分析，不得視為全文）
`SYS2_CFTS013_…xlsx` 之 `Document ID` 為 32 個值，
**不含 DR-DM4 所求之 `629`／`633`／`952`** ——
三者僅出現於 `r8`（`CFTS013-752`，Category = Information）之
修訂履歷自由文字內，非 `Document ID` 欄之值。

即：**「該 id 之字串出現於檔內」不等於「該需求存在於檔內」。**
凡查證某條號是否到手，須查 `Document ID` 欄，
不得以全檔子字串命中為據（R-G27 之逐字原則於本處之應用）。

DR-DM4 **維持 OPEN**，其標的不變（CFTS013 之 `629`／`633`／`952`）。
```
