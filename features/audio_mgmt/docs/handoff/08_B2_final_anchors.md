## 二、逐案處置（裁定明細）

### 二.1 SWE1_AMM_030 — 部分覆蓋
錨 4866054 涵蓋「依既定優先權與使用者請求進行 ENT／INFO1／INFO2 來源選擇」。
葉尚含「衝突時套用設定之 duck／mute／reject／pause 動作集」——全文檢索
`duck` 與 `reject|mute` 同現 0 筆，CFTS019 正文無對應。
**處置**：TC 範圍限縮至 4866054 字面（IN §8.2.1 存疑從窄），**不寫動作集**。
reasoning 明寫：本錨僅覆蓋優先權仲裁部分；動作集無 CFTS019 正文對應，
疑出自 1.3.4 條件表 {4866981} 或 `{CFTS019-5129}` 跨文件參照，併入 DR-AM1。

### 二.2 SWE1_AMM_031／032 — 共錨（R-AM16）
1.3.2.5 Source Selection {4866053} 全章僅 4866054／4866055 兩物件（雙路確認）。
來源 ID 178／179 連號，形態為上游將一條 CFTS 需求分解為兩個 SWE 葉。
**共錨允許**：兩個不同 SWE ID 指向同一 CFTS 物件係上游分解之結果，
非造 ID，R-AM6 不適用。
**條件（硬性）**：兩條 TC 之 test_item 括號下半必須寫出各自側重，不得逐字相同——
- 031：INFO2 取得優先權、衝突之 ENT/INFO1 串流轉入 interrupted 狀態
- 032：具 pause/stop 能力之使用者來源暫停至 INFO2 全部非作用
**032 併列雙錨**：其葉首句「INFO2 優先於 ENT 與 INFO1」屬 4866054 範圍，
故 spec_reference 併列 `CFTS019-4866054` ⏎ `CFTS019-4866055`
（IN §10.7 一行一 ID、同文件內升冪）。此較切給 030 乾淨。

### 二.3 SWE1_AMM_061 — DR-AM6
錨 4866123 正確（`$ICSPowerButton$` = [pressed] 為葉之觸發），但行為本體
明文推給 `{CFTS020}`，該件不在 `inputs/`。
**處置**：TC 只寫可驗證部分（收到訊號、進入靜音狀態）；靜音邏輯細節填
`PENDING: DR-AM6 mute logic defined in CFTS020, document not available`。
**嚴禁依 IN §8.4.1 推測 CFTS020 內容。**

### 二.4 SWE1_AMM_233 — 部分覆蓋
錨 4866916 僅述「signal source shall be mixed with all output channels」。
葉尚含「對 Information 來源套用設定之 ducking level」，錨文無對應。
**處置**：TC 不寫 ducking level，reasoning 註明部分覆蓋。

### 二.5 SWE1_AMM_309 — C→A，錨 4866484（池外）
第二路尋得，分析層複核成立。錨文直述「具 stop/pause 能力之使用者啟動
播放裝置應於 HFP 期間暫停」，即葉之全部內容，**無推論一跳**，R-13 疑慮不存在。
**取 4866484 不取 4866485 之二重依據**：
1. 變體 — 4866484 之 Radio 清單含 `R1L-R` 與 `R1L`（本案 R1LR_Atl-H）；4866485 無。
2. 本文 — 葉僅言 HFP；4866484 亦僅言 HFP，4866485 尚含 E-Call/R-Call，寬於葉。
原先第一路對 4866055 之「不採」判斷正確且維持——該否決針對 4866055，非針對本葉。

### 二.6 SWE1_AMM_076 — 維持 4866155，部分覆蓋
4866154 係 `$VolumeINFO1/2$` 靜音狀態指示，與葉之 Mute Routing Configuration
不同題旨，不取。4866155 雖為前提句，但正是「靜音條件依 HU HMI Specification
與 Routing_Table 啟用」，即葉之題旨。
Routing_Table 屬外部件（`{Component Technical Specification - VP1 and VP2 System}`），
併入 DR-AM1。TC 不寫 Routing_Table 之具體對應。

### 二.7 SWE1_AMM_086 — 改錨 4866442
原候選 4866220 之適用情境限「至少兩個 information 來源作用中」，
較葉為窄。4866442（Entertainment ∧ Information ∧ Signal 於任一
Ignition Working Conditions 下有效）涵蓋面與葉相符。
**判準是涵蓋面，非相似度**（兩者相似度差 0.01，無區辨力）。

## 四、A-AM07 / DR-AM7：EE Architecture 適用性疑點（不阻塞）

分析層複核錨表時發現：**B2 之 47 個錨中 24 個標記為 `EE Architecture:
Atlantis Mid` 而不含 `Atlantis High`**，本案為 R1LR **Atlantis-H**。
集中於 TA/VR 仲裁段（4866926–4866933）、TLM 靜音段（4866129–4866134）、
VSIM 段（4866689–4866695）。

**與先前假設之關係**：執行層曾測試「EE Architecture 過濾」作為
**池籍**（匯出缺漏）之解釋並推翻之（純 Mid 之 491 個中有 229 個在池內）。
本件問的是**適用性**，非匯出，兩者為不同命題，不衝突。

**不阻塞之理由**：SWE.1 上游確為這些需求產出了葉；依 IN §8.2.1，
上游分解為權威，TC 作者不得改判範圍。

**DR-AM7（已裁發）**：請上游確認 `EE Architecture: Atlantis Mid` 標記之
需求是否適用於 R1LR Atlantis-H；若不適用，SWE.1 對應葉需重新界定範圍。
B2 照現行錨表出貨，回件後統一處置。
