使「表是否完備」可被逐輪機器檢查，不靠人記。

**正規化步驟（完整、逐項）**

1. 空白類 → 半形空格：`U+00A0`、`U+2007`、`U+2009`、`U+202F`
2. 零寬類 → 刪除：`U+200B`、`U+200C`、`U+200D`、`U+FEFF`、`U+00AD`
3. 引號類 → ASCII：`U+2018`／`U+2019` → `'`；`U+201C`／`U+201D` → `"`
4. 破折類 → `-`：`U+2013`、`U+2014`、`U+2212`
5. 項目符號 → 空格：`U+25AA`、`U+2022`
6. `\t` → 空格；`\r` → `\n`
7. 折疊連續半形空格（不跨行）：`[ ]{2,}` → 單一空格

第 7 步為必要 —— docx 中多處為 `$…$\xa0\xa0and`（**雙** NBSP），
只換不折會留下 `$…$  and`，`\bICS (?:shall|…)` 這類含**單一字面空格**之
主詞正則仍對不上。此即 A-ICS66 之根因在「空格數」而不只在「空格種類」。

### §1-2 為何 09 之覆蓋清點不受 NBSP 影響（機制層之解釋）

`s118_gap_09.py` 之 token 抽取與比對**結構性地免疫於空白差異**，
與 `s118_compare_08.py` 之主詞正則不同：

| | 09（覆蓋清點） | 08（節層對比） |
|---|---|---|
| 抽取單位 | `$…$`／`[A-Z][A-Z0-9_]{4,}`／`"…"`／`T…` —— **四者皆為不含空白之單一 token** | `\bICS (?:shall|will|…)` —— **跨空白之片語** |
| 比對前處理 | `norm()` 去**全部非英數字元**（含 NBSP）後轉小寫 | 無正規化，直接 `re.search` |
| NBSP 之後果 | 無 —— token 內不含空白，`norm()` 又已剝除 | **主詞比對失敗 → 標籤集為空** |

實測佐證：29 個判適用物件中，正規化前後 **token 集合改變者 0 個、全中集合改變者 0 個**。

**故：A-ICS66 之影響面小於下放包所述。**
下放包 11 之背景段寫「後果：`4821702` 的標籤集為空 —— 而 09 §1 正是用它判
b04-06／b05-01／b05-02 為『有覆蓋』」。實測顯示此為**二個不同函式之混同**：

- 「標籤集為空」是 **08 之 `tags()`**（行為面標籤）在 `4821702` 上之結果 —— **確為空**，本輪複驗屬實（見 §2-1）；
- 但 09 §1 判 b04-06／b05-01／b05-02 覆蓋 `4821702`，用的是 **09 之 `tokens()`／`hits()`**，
  該路徑**從未依賴 `tags()`**，也不受 NBSP 影響。

即：A-ICS66 之缺陷**真實存在且已複驗**，但其後果落在**錨層對應集合**（08 §5），
**不落在 09 之覆蓋清點**。R-ICS39(d)「對應集合本身須重測後方得加錨」之顧慮
指向的正是前者，**該顧慮成立**；而「09 之覆蓋判可能被污染」之顧慮，**實測不成立**。
