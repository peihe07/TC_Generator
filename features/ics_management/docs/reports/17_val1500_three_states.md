逐項拆解：

| 項 | 值 | 出處 |
|---|---|---|
| 起始位元 | **55** | `SG_` 之 `55\|8@0+` |
| 長度 | **8** bit | 同上 |
| 位元組序 | **`@0` ＝ Motorola／big-endian**；`+` ＝ unsigned | 同上 |
| factor | **0.5** | `(0.5,0)` |
| offset | **0** | `(0.5,0)` |
| 值域（min\|max） | **`[0\|100]`**（物理量） | `[0\|100]` |
| 單位 | **`"%"`** | `"%"` |
| 發方 | **`ETM`**（`BO_` 行之節點）；`BO_TX_BU_ 1283 : ETM,LTM;` **列 `ETM` 與 `LTM` 二發方** —— 本 DUT（`LTM`）為追加發送方 | `BO_ ` 行＋`BO_TX_BU_` |
| 收方 | **`SGW`** | `SG_` 行末之接收節點清單 |
| `VAL_` 列舉 | **全部僅 1 筆**：`255 "SNA"` | `VAL_ 1283 RQ_DISP_INTS 255 "SNA";` |
| 節點清單（全檔） | `BU_: ETM FPDM LTM SGW` | `BU_:` 行 |

**推得之數量關係（自上列數字算出，非手估）**：8 bit unsigned → raw 域 `0..255`；
factor 0.5、offset 0 → 物理量 `= raw × 0.5`；宣告物理值域 `[0|100]` → **有效 raw 域 `0..200`**；
`raw 255` 由 `VAL_` 指派為 `SNA`；**`raw 201..254` 既不在物理值域內、亦無 `VAL_` 標籤 —— 無定義**。

## §10 作業 D-3 — 核心問題：R-17(a) 對連續量如何適用

### §10.1 條文逐字

`docs/fw036/RULINGS_LEDGER.md` 之 R-17(a)：

```text
(a) 規格（CFTS／SWRA／HMI L&F）所載之訊號名與值名，視為**概略之指涉**；
    若於 DBC 有可測定之**同一物**對應，`test_procedure` 與 `expected_result`
    一律採 **DBC 實名與實值**，不以規格寫法覆蓋。
    值之語意標籤逐字取自 `VAL_`（R-7 不變）。
```

其所指之 R-7 落檔於 `docs/runtime/ASPICE_SWE6_AI_Instruction.md` §8.7.5(a)（R-1 v3）：

```text
(a) 訊號一律以 `$<MESSAGE>.<Signal>$` 全名書寫，`$` 包覆全名；
    值採 `= <raw> (<label>)`，`<label>` 逐字取自 DBC `VAL_` 列舉（R-7）。
```

以及 §8.7.5(b)：

```text
(b) Procedure 之觀察步驟須寫出應觀察之值（R-11(b)）：
    `Read the signal $MESSAGE.Signal$ and check that it is <raw> (<label>)`
```

### §10.2 條文與現況之對位

| 條文要素 | 現行 `0 (0 %)` 之對應 | 是否相容 |
|---|---|---|
| `<raw>` = `0` | `0` | ✅ 相符 |
| `(<label>)` 之括號形制 | `(0 %)` | ✅ 形制相符 |
| `<label>` **逐字取自 `VAL_`** | `VAL_ 1283 RQ_DISP_INTS` 只有 `255 "SNA"` 一筆；**無 raw 0 之標籤** | ❌ **不相符** |

**結論（判定，非建議）**：現行 `0 (0 %)` 之括號內容 `0 %` 是
**「raw 0 × factor 0.5 ＝ 0，附 `SG_` 之單位 `"%"`」之換算結果**，
**不是**、也**不可能是**逐字取自 `VAL_` 之標籤 —— 因為該 `VAL_` 根本沒有 raw 0 之項。
故現行書寫**與 R-17(a) 之字面不相容**。

### §10.3 條文之射程缺口（本題之真正形狀）

R-17(a)／R-7 之語法 `= <raw> (<label>)` 隱含一個**未言明之前提：該訊號是枚舉量，
其每一個會被寫進 TC 之 raw 值都在 `VAL_` 內有標籤**。

`RQ_DISP_INTS` 打破此前提：它是連續量，256 個 raw 值中**只有 1 個（255）有 `VAL_` 標籤**，
**覆蓋率 1/256**。對其餘 255 個 raw 值，R-17(a) 之 `(<label>)` **無物可填**。

這不是「執行層寫錯了」，而是**條文對這一類訊號沒有規定**。
現行 `0 (0 %)` 是執行層在條文缺口上所作之**未具名之補充**（A-ICS112 即指此）。

**且該缺口目前被一個巧合遮蔽**：raw `0` × factor `0.5` ＝ 物理量 `0`，
**二數恰好同為 0，看不出 `0 (0 %)` 之左右兩個 `0` 意義不同**。
若日後有一條 TC 需寫非零強度（例如 50 %），同一寫法會成 `100 (50 %)` ——
屆時「raw 與括號內數字不同」才會浮現。**現行三條之正確性是巧合，不是遵循。**

## §11 作業 D-4 — 四種可能之書寫方案

改動量之計數基準統一為 **§8 之 6 行交付欄**（3 條 TC × 2 欄）。
`test_item` 上半之 verbatim 依 R-17(b) 一律不動，四案皆 0 行。

### 方案 ①：**維持現行換算式**（`= 0 (0 %)`），並以 R-17 補款追認之

- 形制：`<raw> (<物理量><空格><單位>)`，物理量 = `raw × factor + offset`，單位取 `SG_` 之單位欄。
- **與 R-17(a) 字面相容**：❌ **否**（括號內非 `VAL_` 標籤）。**須補款方合式** —— 補款內容即「連續量之 `<label>` 位置改置物理量與單位」。
- 可讀性：**高**。測試執行者在 CAN trace 工具上讀到的是 raw，而規格語言（`[0% Intensity]`）講的是百分比；此式**同時給出二者**，不需執行者心算 factor。
- 改動量：**0 行**（現況即此形制）。
- 風險：在補款落檔之前，此式在 lint 或審查上是一個**無條文依據之寫法**；且 `0 (0 %)` 之巧合會持續遮蔽問題（§10.3）。

### 方案 ②：**改為純 raw**（`= 0`）

- 形制：`<raw>`，不加括號。
- **與 R-17(a) 字面相容**：**部分**。R-7 之語法 `= <raw> (<label>)` 把括號寫成語法之一部分，省略括號同樣是偏離；惟其偏離方式是「不填一個填不出來的欄」，比「填入非 `VAL_` 之內容」保守。仍**須補款明文允許省略**。
- 可讀性：**低**。執行者看到 `= 0` 無從知道單位；且 `RQ_DISP_INTS` 之語意（顯示亮度百分比）在交付簿上完全消失，與 §8.4.1「不得使規格語意流失」之精神相悖。
- 改動量：**6 行**（6 處 `0 (0 %)` → `0`）。
- 風險：非零值時尤劣 —— `= 100` 完全看不出是 50 %。

### 方案 ③：**raw ＋ 單位，不加括號標籤**（`= 0 %`）

- 形制：`<物理量><空格><單位>`（**注意此式丟棄 raw**）或 `<raw> <單位>`（**此式單位與 raw 不匹配，錯誤**）。可行者只有前者。
- **與 R-17(a) 字面相容**：❌ **否**，且更遠 —— 它連 `<raw>` 都不寫，而 R-17(a) 之立法本旨正是「採 DBC 實值」。
- 可讀性：**中**。對讀規格的人友善，對讀 CAN trace 的人不友善（trace 上顯示的是 raw `0`，不是 `0 %`；非零時 trace 顯示 `100` 而 TC 寫 `50 %`，**執行者需自行心算 factor** 才能核對）。
- 改動量：**6 行**。
- 風險：**最高**。丟棄 raw 等於丟棄 R-17 之核心（以 DBC 實值為準），且引入執行者心算 → 誤判空間。

### 方案 ④：**分流** —— 枚舉值用 `VAL_` 標籤、連續量用物理量，並於 R-17 明文分流

- 形制（補款草案之形狀，**非條文，僅示意**）：
  - 若該 raw 值在 `VAL_` 有項 → `= <raw> (<VAL_ 標籤>)`，**不變**（含 `RQ_DISP_INTS` 之 `255 (SNA)`）；
  - 若該 raw 值在 `VAL_` 無項，而 `SG_` 有非 1 之 factor 或非空單位 → `= <raw> (<raw×factor+offset><空格><單位>)`；
  - 若二者皆無（無 `VAL_` 項、factor=1 且單位空）→ `= <raw>`。
- **與 R-17(a) 字面相容**：❌ 現行字面不相容，**但本案即是把字面補完整**，補款後三種情形皆有明文，不再有「條文沒規定」之欄位。
- 可讀性：**最高**。同一份交付簿內，枚舉量與連續量各以其最自然之形式呈現，且**同一訊號之 SNA 值仍走 `VAL_` 標籤**（`255 (SNA)`），不會出現「同一訊號兩套寫法無規則」。
- 改動量：**0 行**。現行 6 行恰好已符合本案之第二條分支。
- 風險：補款之射程是**全案面**（`RQ_DISP_INTS` 只是第一個撞上的訊號；任何有 factor 而 `VAL_` 不全之訊號皆適用），故其落檔須經分析層／Pei，**不是執行層可自為**。

### §11.1 四案對照表

| 方案 | 書寫 | R-17(a) 字面相容 | 可讀性 | 改動行數 | 補款必要 |
|---|---|---|---|---|---|
| ① 維持現行換算式 | `0 (0 %)` | 否 | 高 | **0** | 是（追認） |
| ② 純 raw | `0` | 部分（省略括號） | 低 | **6** | 是（允許省略） |
| ③ 物理量＋單位 | `0 %` | 否（且丟棄 raw） | 中 | **6** | 是 |
| ④ 分流（枚舉／連續） | `0 (0 %)`；`255 (SNA)` | 否→補款後是 | 最高 | **0** | 是（全案面補款） |

## §12 作業 D-5 — 建議（**建議，不改**）

**建議採方案 ④（分流），並以 R-17 之補款形式落檔。**

理由（四點，逐點可駁）：

1. **改動量為 0 行**。現行 6 行之寫法恰好已是方案 ④ 之第二分支之產物 ——
   問題從來不是「寫錯了」，而是「寫對了但沒有條文依據」。以補款追認之，
   等於**用零改動換一個明文依據**；②③ 則要動 6 行去換一個更差之可讀性。
2. **它同時保住 R-17 之本旨與 R-7 之形制**。R-17 之本旨是「以 DBC 實值為準」——
   方案 ④ 之 `<raw>` 永遠是 DBC raw，未讓步；R-7 之形制是 `= <raw> (<label>)` ——
   方案 ④ 保留括號，只是明定「連續量之括號內填什麼」。③ 破壞前者，② 破壞後者。
3. **它是唯一處理得了同一訊號內混合情形者**。`RQ_DISP_INTS` 之 `255` 有 `VAL_` 標籤而其餘沒有。
   ①②③ 三案都只講「這個訊號怎麼寫」，答不出「同一訊號之 255 怎麼寫」。
   方案 ④ 之判準下沉到**逐值**（該 raw 在 `VAL_` 有無項），故 `255 (SNA)` 與 `0 (0 %)` 可並存而不衝突。
4. **它預先關掉 §10.3 之巧合**。明文寫出括號內是「`raw×factor+offset` 加單位」，
   則日後之 `100 (50 %)` 一望即知其構成，不會被誤讀為筆誤。

**但本包不改任何一行。** 理由逐字引 R-ICS50(e)：
