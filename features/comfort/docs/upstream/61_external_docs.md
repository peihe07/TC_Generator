### 2.1 三項作法上之選擇，各有其理由

**(a) 五條取後號（430–434）而非插入原位**：插入會使其後之 tc_id 全部後移，
且 `batch12` 若自表產出兩列，其後號會與 `batch13` 之 `START_N = 237` 相撞。
**號碼寫死而非自 `max(tc_id)` 導出**（R-C43：字面是身分，`max+1` 是邊界）。

**(b) PC 之標籤另立 `[ext-verbatim]`**：CFTS043 那句是**外部文件之原話**，
標成 `[spec-verbatim]` 會使 `source-class-truthful` 拿本 spec 該節去查一句
不在那裡的話 —— 更糟的是**讀者會以為它出自本 spec**。
新標籤已入 `SOURCE_CLASSES`。

**(c) `spec-ref-stem` 放行外部出處之清單自 `external_docs.py` 匯入**，
不在 lint 內另抄一份：兩份清單會分岔，一份不會（R-C43 同理）。

### 2.2 `11.5` 與 `12.6` 自此分道

兩節之條文只差一個文件名。R-C40 曾據「逐字相同」使兩側同進退，
**今其前件已不成立**：`HMI Settings List` 存在且載有選項，`HMI Notes` 不存在。
故 `-382` 移出 marker 白名單（R-C26：移除亦是裁定，81 §2.3 即其裁定），
`-383` 維持 `[BLOCKED-SPEC]` 與 `Owner: HMI Notes` ——
**擁有者由條文決定，不由我方能否取得決定**（81 §3）。
