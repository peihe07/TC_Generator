## 1. §5 之三者不一致 —— 立條文，統一處置

執行層自陳：`11.11` 用了「條文自帶觸發條件」而 ch9 未用，
**「這是作業邊界之理由，不是原則之理由」**。該自陳正確，故補原則。

```
R-C42  條文自帶觸發條件者，該條件即為 PC 之明文來源

某節之條文自身載有其適用條件（`In some vehicles …`／`when configured with …`
／`If the vehicle is equipped with …`），則：

一、**該條件即滿足 R-C28 第一問**（明文對應在其本節），PC 得以該條文逐字
    表述並標 `spec-verbatim`。**該 leaf 可生成，不因該條件尚未登記為軸而停下。**

二、**是否登記為軸，另依既有三條件判**，與可生成性無關。
    軸之作用為跨 TC 之一致性與否定式之涵蓋，不是生成之許可。

三、未登記為軸者，該條件登記為「待軸化候選」。
    **同一條件於兩處以上之節出現而仍未登記為軸者 → gate FAIL** ——
    屆時不一致之風險由潛在轉為實在，登記即成必要。

理由：停下之正當理由是「無法陳述」（R-C28 第一問失敗）。
條文自帶條件者可以陳述，其所缺者只是跨節之統一名稱 ——
**以缺一個名字為由不產出一條可陳述的 TC，是把管理手段當成了前提。**
```

**連帶處置（本輪執行）**：以 R-C42 重新檢視**全部 48 個停下之 leaf**，
逐一回報其停下之依據屬下列何者：

| 依據 | 處置 |
|---|---|
| 條文自帶條件而僅缺軸 | **解封，生成** |
| 條文未載該條件（R-C28 第一問失敗）| 維持停下 |
| 對照未定義／委派未決／白名單未裁 | 維持停下，與本條無關 |

**預期解封者**：ch9 之 7 leaf（§5 已判可生成）、`17.5`、`013-04`，
以及 DR #38 所涉之 `2.3.1`／`2.5.1` 若其條文自帶條件。
**逐一以證據判，不以本包之預期為準。**

## 2. §2.3 `autojunk` —— 系統性重測，並立為量測規約

**同一缺陷第三次出現**（下放包 05 §7 為分析層之首例，本輪為執行層），
且本次之位置最尖銳：**一道用來檢查「有沒有做過量測」的 gate，自己的量測
是錯的。**

執行層自陳只重測了「我記得的三個數」，其餘未逐一重測，
**且已知其誤差方向為低估**。

低估之後果須寫明：**相似度被低估 → 判為「非鏡射」→ 不加排除式 PC
→ 該 TC 之適用範圍過寬**。這是我們最在意的方向。

指示：

1. 對 41 份上繳包 grep 出所有**用作判定依據**之相似度數字，
   以 `autojunk=False` 逐一重測，回報原值／新值／該判定是否因此改變
2. 立為量測規約（寫入 profile §3.7）：

```
相似度之量測一律 `autojunk=False`；長文比對**須同時報共同子字串之長度**，
不得只報比值。比值為代理，長度為實質（§5a）。
```
