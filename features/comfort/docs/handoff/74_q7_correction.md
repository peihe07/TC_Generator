## 2. Q7（§8.2.2）之判準 —— **錯，須全面重判**

執行層之判準為「**多個獨立之可觀察量**落在同一 fail 上」。
**該判準不是 §8.2.2 之判準，亦與既有裁定相反。**

### 2.1 canon 之判準是「觸發」，不是「觀察量」

§5.7 明文：

> **One trigger → multiple consequential outcomes belong in ONE TC, not split.**
> The trigger is the verification unit; outcomes that necessarily follow from
> the same trigger are facts to be checked, **not separate TCs**.
> Split criterion remains: different **triggers**, different **inputs**,
> different **scopes** — **not different outcomes of the same trigger**.

而 30 §2 已就本 feature 裁過同一形態：`-019`（MAX DEF 一次按壓 → 七項連動）
**維持一條**；`-024`（四個不同控制各自破壞 MAX DEF）**拆為四條**。
**兩者外觀相近而方向相反，判準只有一條：trigger 是一個還是四個。**

### 2.2 逐項改判

| 執行層之判定 | 正解 | 依據 |
|---|---|---|
| `055-01`…／`068-01`…／`075-01`… **8 條**：層級＋高亮＋指示 → 應拆 | **維持不拆** | 一次按壓之三個連動後果（§5.7） |
| **按壓循環類 19 條**（11.1／11.2／11.8／12.1／12.2／12.8／12.9）→ 19 → 57 | **維持不拆** | 同上。**+38 條之擴充不成立** |
| `024-02`：一次按壓 → 七個參數 → **「本輪最該拆的一條」** | **維持不拆** | **此即 `-019` 之同型**；30 §2 已裁 |
| `024-04`／`024-03`：MAX DEF 沒關掉 vs 回復錯了 | **維持不拆** | 同一次關閉之兩個連動後果 |
| `110-05`：slider／status bar／popup 三處呈現 | **維持不拆** | 同一次調整之三處顯示 |
| `107-06`：MAX A/C 與 MAX DEF 兩個觸發 | **拆** ✅ | 不同 trigger |
| `112-04`：鍵／觸碰／滑動／硬控四種調整途徑 | **拆** ✅ | 不同 trigger（操作面／輸入方式）|
| `110-01`：English 與 Metric 兩個值域 | **拆** ✅ | 不同 input（同 `002-05` 之前例，39 §1.2）|
| `023-01`／`101-01`／`017-01`／`023-02`／`023-03` | 維持不拆 ✅ | 判定與正解相同 |

**淨效果：15 條擬改判者中，3 條應拆、12 條不拆。**
原估之 `19 → 57`（+38 條）**不成立**。

### 2.3 重判之指示

以**下列判準**重跑 Q7 之全部 373 leaf，取代現行之「多個獨立可觀察量」：

```
Q7 之問：本 leaf 之 TC 是否涵蓋**一個以上之 trigger、input 或 scope**？

  是 → 應拆，逐一具名其 trigger／input／scope
  否（多個後果同出一個 trigger）→ **不拆**，§5.7 明文

**判準不是「有幾個可觀察量」，是「有幾個觸發」。**
一次按壓造成七件事，是七個要檢查的事實，不是七條 TC。
```

**ER 末行之限制隨之消失** —— 新判準讀的是 procedure 之觸發步驟，不是 ER。

### 2.4 這是我的疏漏

30 §2 之裁定已寫下該判準，而**下放包 73 §3 之第 7 問我寫成
「兩個獨立之部分失效是否都落在同一個 fail 上」** ——
該措辭來自 §8.3，未帶上 §5.7 之限制，故執行層據以實作出一個**會把連動後果
判成獨立失效**的判準。

**與 R-C35 同型**：我給的前件（獨立部分失效）與所欲判之事（獨立 trigger）
不同一。**第三次由我造成同型錯誤。**
