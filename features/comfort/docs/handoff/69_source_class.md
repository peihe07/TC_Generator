## 1. §4.3 —— **採 (甲)：改標 `spec-derived`，並立 gate 使標籤為真**

123 條標 `[spec-verbatim]` 而僅 5 條真正逐字。**這不是措辭問題，是標籤問題**：
source class 是一項**關於出處之主張**，而 R-C41 之精神即「陳述須與其取得方式
相符」。一個標成逐字而實為改述之 PC，其讀者無從知道該句是條文說的還是我們寫的。

### 1.1 處置

- **非逐字者改標 `spec-derived`**。該標籤仍滿足 R-C28 第一問 ——
  第一問要的是**明文對應**，不是逐字；改述若確有對應即通過
- **R-C42 解封之 21 條維持 `spec-verbatim`**，因 R-C42 一明文要求逐字；
  其中若有不合者，**改的是文字不是標籤**（回頭逐字化）

### 1.2 立 gate —— 與 68 §4 之「不立 gate」不衝突

68 §4 我裁「不逕立 gate」，其對象是**「PC 須逐字引用」這項義務**，
理由為該義務不適用於全 corpus。

**本項不同**：所立者為**標籤與事實相符**之檢查，非逐字之義務。

```
gate `source-class-truthful`：

凡首行以外亦含 source class 標註之每一行 PC，
標 `spec-verbatim` 者，其所引片段須為其所標出處節 `full_text` 之
**連續子字串**（空白正規化後比對）；否則 FAIL。

標 `spec-derived`／`test-setup` 者不受此檢查。

**此為標籤之真值檢查，不是逐字之要求** —— 作者得自由選擇改述，
但選了改述就不得標逐字。
```

反向驗證：取一條 `spec-verbatim` 之 PC 改動一字 → 必 FAIL。

### 1.3 量測範圍擴及**全部 PC 行**

現量測只涵蓋首行。**標籤是逐行的，檢查亦須逐行** —— 否則第二行以後之
`spec-verbatim` 永不受檢。

## 3. §6.2／§6.3 —— 兩種掃描之範圍，分別定

| 掃描 | 範圍 | 理由 |
|---|---|---|
| **逐字化量測**（最長共同子字串）| **僅 PC 各行** | 其意義繫於 source class 標籤，而只有 PC 帶該標籤。`test_item` 依 profile §3.1 本即為**濃縮之需求陳述且允許 modal**，其為改述是設計而非缺陷 |
| **字元訛誤掃描** | **全部欄位** | `-361` 之誤正在 `test_item`，**是字元掃描抓到的，不是逐字化量測抓到的** —— 兩者所抓之物不同，範圍不應相同 |

### 3.1 字元掃描改為一般化，不用手列對照表

現行六對為手列，其自陳「命中為零不代表不存在」正確。

改法：**對每條 TC，取其所標出處節之 `full_text` 中出現之非 ASCII 與
排版類字元集合**（`«»`／`’`／`“”`／en dash／em dash／不斷行空格／`′`／`″` 等），
**與該條各欄位中出現者比對**，回報差集兩側：

- **節有而 TC 無** → 可能為漏錄（如 `«»` 未照錄）
- **TC 有而節無** → 可能為誤用（如以 `"` 代 `'`）

**不預先列舉字元對** —— 以「該節實際出現什麼」為基準，其涵蓋範圍隨語料自動擴張。

## 5. 通過、無須處置者

- **「最短的一批不是問題，`spec-verbatim` 那一批才是」** ——
  該判讀即本輪之主要發現；量測之設計意在找短的，**而真正的缺陷在標籤與
  事實之落差，不在長度**
- **`-081` 之措辭不轉指**，且其理由寫明：「若寫成『由他處涵蓋』即與 marker
  自相矛盾」
- **對帳片語逐列具名後之 mutation 訊息**：
  「a shared fragment only checks that the sentence exists, never that it is
  about this row」
- **注入式 mutation 以 `2.11` 之無限定語句構造 miss**，
  **不依賴語料存在** —— 該向現為此 gate 唯一不會隨語料歸零而失效者
- **68 §1「範圍窄不是理由」已被執行層引用並落實**
