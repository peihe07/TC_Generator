## 2. §7.5 / DR #32 —— 第四類，但不是 BLOCKED

`122-02` 之內容委派予**本 spec 之另一節**。三類 marker 皆不合，
而**「不合」的理由不是漏了一類，是它根本不是同一件事**：

前三類皆為「**本交付件不涵蓋**」；`122-02` 是「**本交付件涵蓋，但在別的
列上**」。把它標成任何一種 BLOCKED，等於向評閱方宣告一個實際上已被涵蓋
的缺口。

```
R-C39  內部委派之 leaf —— [COVERED-BY]

某 leaf 之內容全部委派予**同一 spec 之另一節**，而該節之 leaf 已於本交付件
產出 TC 者：產出一列 `[COVERED-BY]`，**不計為 coverage gap**。

Remarks 依 R-C27：首 60 字元內須含
  `[COVERED-BY] <涵蓋之 req_id>` 之意。

使用條件（五項全備，缺一即回報停下）：
  一、委派之對象為**本 spec 之節**（外部文件者屬 [BLOCKED-SPEC]）
  二、該對象節之 leaf **已產出 TC**，具名其 tc_id
  三、該 TC 之 expected_result **確實涵蓋**本 leaf 之內容 —— 須逐句比對
      並具名，不得以「兩者述及同一事」代替
  四、本 leaf 扣除委派後無獨立餘留（同 R-C24 之餘留分析）
  五、tc_id 經白名單增列（R-C26）

第二項未滿足時（對象節尚未生成）：**不得先標 [COVERED-BY]**，
該 leaf 標 `deferred`，於對象節生成後再判。

`test_procedure`／`expected_result` 為空，豁免同 BLOCKED row，
但**其具名回報行須與 BLOCKED 分列** —— 兩者於統計上意義相反。
```

profile §5.3 之判別次序增出口：

> …「條文有無委派字面」—— **有 → 再問「委派對象是外部文件抑或本 spec 之節」**：
> 外部 → `[BLOCKED-SPEC]`；本 spec → `[COVERED-BY]`。無委派字面 → 續問可觀察端。

## 4. §2.1 `FRONT DEF → DEFROST` —— **不以裁定補入，改為組合**

以裁定手動補入等於以推論建表，與「變體來源為實測」相牴觸。

**正解是使階層與等價可組合**：若 `DEF` 與 `DEFROST` 同屬一個等價組，
則 `FRONT DEF → DEF ≡ DEFROST` 之路徑本已存在，只是產生器未將等價正規化
套用於階層之輸出。

指示：
1. 實測 `DEF`／`DEFROST` 是否已在同一等價組；未在則以實測補入等價組
2. 產生器改為：階層之輸出**再過一次等價正規化**
3. 回報組合後新增之對數

若實測顯示 `DEF` 與 `DEFROST` 在語料中並非同指，則**不補** —— 那是內容
問題，登 DR。

## 6. §10.5 —— 其餘四軸之窮盡實測：**做**

`axis-values` gate 之判準為值數，而值數若未經窮盡實測，
**該 gate 之基準本身未經證明** —— 它只能偵測「有人改了清單」，
不能偵測「清單本來就漏了一個值」。

四軸各做與第三軸同等強度之全語料掃描（129 節），回報：
每軸之命中節、相異值、以及**是否存在未列之值**。
若查出未列之值，`axis-values` 應於該軸 FAIL —— 那是它的設計目的。

`value-count` 之語意隨之由「已知之值數」改為「經 129 節掃描未見第 N+1 值」，
並於 profile 具名其掃描日期與 pattern（R-C30）。
