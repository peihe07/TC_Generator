## 1. §1.3 觸發時點 —— **改，且錯在我**

執行層之量測是決定性的：632 列到期，**兩側皆已生成者為 0**。

我 42 §1 寫「某 Test Set 全數生成之日，凡涉及該組節次且 `provisional == true`
之列一律 FAIL」。**`provisional` 之成因是「某一側未生成」，而會觸發的那一側
正是已經生成的那一側 —— 缺的那一側仍然缺。**

**此為 R-C35 之形態，且犯者是我**：gate 之前件（「任一側之組完成」）
是關於該列之一般事實，而所欲觸發之事是「缺的那一側補上了」。
前件為真而所欲之事為假，在此**恆常成立**而非偶然成立。

```
修正（本包裁定）：

`provisional-sibling` 之觸發條件改為：
  該列中**原本未生成之那一側**，其所屬 Test Set 全數生成之日。

判定依據：`provisional == true` 且兩側皆已生成 ⇔ 缺的那側已補上。

改後本輪 632 → 0；`Climate Modes`／`Rear Climate` 等組完成時按對造逐批到期。
```

**執行層未自行改而如實留紅燈，處置正確** —— 改觸發條件是改裁定，不是落實
裁定。其「能寫下的只有一個橡皮圖章」一句，即拒絕清旗之理由，
**寫入 `RUNBOOK.md`**。

其兩項偏離字面之設計（類級恆為 true、`false` 單向不可逆）**皆採納**：
前者維持 41 §4 之效力，後者使人工複核不被重建抹除。第二項尤其重要 ——
**若複核之結果會被下一次重建覆蓋，該複核等於沒發生。**

## 2. §2.2 `AUTO ECO` → `AUTO` —— **加，但標為階層而非等價**

`AUTO ECO` 與 `AUTO` 不是同義異寫，是**特化與泛化**。等價組會使兩者互換，
那是錯的；但完全不連結，則「只寫 AUTO ECO 之節」與「寫 AUTO 之節」永遠
配不成對，而它們確實述及相關行為。

指示：產生器增**階層表**（與等價組並列而不混用）：
`AUTO ECO → AUTO`、`MAX A/C → A/C`、其餘以實測補（掃 129 節，
列出「X Y」形態且 `Y` 亦單獨出現為控制名者）。

- 由階層導出之對，`source` 欄標 **`via-hierarchy`**，與等價組導出者可分辨
- 其判定沿用高頻詞之類級處置（`AUTO` 已為類），**不逐對**
- 依 R-C37，階層表之來源須為實測，且其輸出須明示不完備

## 3. §3.2 第三軸 —— **換軸**，條件三項，影響須同輪評估

執行層之發現正確：`C13.0` 之「5 states」是「非 tri-mode」之**細分**，
不是與之並列之第三值。故現行二值軸（tri-mode 有無）**模型錯了**，
應為三值之**氣流模式集合**軸。

**授權換軸**，惟三項條件齊備方得執行（客觀條件，非判斷）：

1. 三值（4 模式／5 模式／tri-mode）皆在條文中**逐字出現**，具名節次與句
2. 三者**互斥且窮盡**，或條文明示其為三種並列情形
3. 無任何值由推論補齊

**影響評估須於同輪完成並回報，不得先改後評**：

- `-015`／`-016`／`-017` 之**肯定式** PC 是否需改寫（現以二值軸表述）
- `2.12`／`2.12.1`／`2.12.2` 生成時之 PC 形態
- 換軸後之值數變化對 `axis-values` 機制之影響

三項不齊 → 不換，回報缺哪一項。

## 4. §3.3 `axis-values` 之推廣 —— **是**

執行層指出該機制只接了 15 條軸中的 1 條（軸 13），而 EMEA（40 條否定式）、
軸 9（9 條）、軸 2（2 條）皆無保護。

**推廣至全部使用否定式 PC 之軸。** 其理由與 34 §4 立該 gate 時完全相同：
否定式之涵蓋範圍隨軸值增減而變，且變動是靜默的。**該理由不因軸之編號而異。**

### 4.1 我的預測錯了，記之

我 42 §3 稱「`axis-value-count` 屆時將 FAIL，那是本輪最值得看的一次 gate
動作」。執行層實測：**該 gate 盯的是軸 13，而擬改者為軸 3，而軸 3 無任何
否定式 PC —— 預期之 FAIL 不可能發生。**

我把「機制存在」讀成「機制涵蓋此案」，未查其實際接線。
**與本輪 §1 同源：對機制之陳述未經實測。**

## 5. DR #29 —— **不維持現狀，補排除式 PC**

`-019` 之 ER 硬寫 `(7/7)`，而 `C6.1` 之 `Off, 1-8` 使該 ER 於該類車輛為假。

**「維持 `(7/7)` 並等 DR 解答」不可接受** —— 那是明知一條已產出之 ER 在
某配置下為假而不處理。§7 之 FP／FF 不因問題已登記而消失。

**但改寫 ER 亦不可**（改 8/8 或「最高設定」皆為造值或弱於條文，
執行層判斷正確）。

**第三條路**：既有之**第十四軸**（前排 HVAC 風速範圍：`Off, 1-7`／`Off, 1-8`）
正是此事之配置變數。補排除式 PC：

- `-019` 增一行 PC：前排 HVAC 風速範圍為 `Off, 1-7`，出處標 **`(2.7)`**
  （`C6.` 之逐字），`2.7` 併入 `specification_reference`（R-C29）
- ER 之 `(7/7)` **不動** —— 加上該 PC 後它為真
- `reasoning` 具名 DR #29 之缺口：`Off, 1-8` 之車輛其 MAX DEF 所設之風速
  未經條文界定，本 TC 不涵蓋

**此非迴避 DR，是使已產出之 TC 在其可陳述之範圍內為真**；
`Off, 1-8` 側之涵蓋缺口由 DR #29 追。
