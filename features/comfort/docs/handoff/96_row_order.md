# 96 — Comfort HMI / 列序與缺列之規則（訂正）

- 產出層：分析層｜2026-08-17｜對象：執行層／規則存續
- 裁定：Pei，2026-08-17
- 性質：**既有規則之訂正記載**，同 95。

---

## 1. 規則

```
一、**列序依 `Requirement or Design ID`（即 037 之 leaf id）遞增**，
    不依批次順序、不依 Test Set 順序。

二、**未產出 TC 之 leaf 仍佔一列** —— 其 `Requirement or Design ID` 照填，
    其餘欄留空。
```

工作簿由上而下即為 037 之 leaf 全集，**其順序與 037 一致，其缺漏一眼可見**。

---

## 2. Comfort 之誤實作

### 2.1 列序 —— 依批次而非依 req_id

現行 434 列之順序為**生成批次之順序**：
batch 1 `Seat Control Tab`（13.x）→ batch 2 `Tri-Mode`（3.x）→
batch 3 `Front Climate Anatomy`（2.1／2.2／6.3／2.14）→ …

故 `Requirement or Design ID` 欄自 `076` 跳至 `023` 再跳至 `002`，
**評閱方無法以該欄對照 037**。

分析層之疏漏：**批次順序是我方之作業順序，不是交付物之組織原則。**
Test Set 之分組功能由 Test Set 欄承擔（§4.1），**不需要也不應該由列序承擔**。

### 2.2 缺列 —— 20 個 leaf 完全不存在於工作簿

20 個未產出 TC 之 leaf，現行處置為**不產任何列**（R-C16 等之裁定）。

**而規則要求它們佔一列。**

---

## 3. 第 2 項解掉了一個我繞道處理的問題

分析層自 79 §2.2 起，為「20 個 leaf 在工作簿內不可見」建立了一整套機制：
交付說明逐項列出、25 / 22 兩數之標示與互指、`047` 與 `072` 之特別說明。

**而既有規則本來就解了它** —— 缺列留空，缺漏在工作簿本身即可見，
不需要一份外部文件去說明它。

**其代價具體**：BLOCKED row 之三類 marker（R-C24／R-C38／R-C39）之設計理由
為「使缺口可見而非無聲」，**而那個目的在列序正確時已由留空列達成**。
四列 marker row 仍有其獨立價值（它們載明**擁有者**，留空列不載），
但「使缺口可見」不再是其唯一理由。

## 4. 連帶之後果

### 4.1 `tc_id` 須重新編號

§10.3 定 `tc_id` 於同一 `{project}-{abbr}` 群組內**單調遞增**。

現行 001–434 依批次順序指派；**列序改依 req_id 後，tc_id 於列上即非遞增**。
故 434 條之 tc_id 須依新列序重新指派。

**其影響**：既有文件中凡以 tc_id 引用者全部失效。
惟本 pipeline 已於 60 §1 立「散文欄位不得以 tc_id 具名他條，一律用 req_id」
並加 `no-tcid-in-prose` gate，**故該影響限於 `DELIVERY.sha256` 之台帳記載
與往返包之敘述**，語料內部不受影響。

### 4.2 B 欄之自動編號

B 欄公式為 `=IF(ISBLANK($D10),"",ROW()-9)`。留空列之 D 欄為空，
**故其自動不編號** —— 有編號者為 TC，無編號者為缺列。

**該行為與規則相容且無須調整**，惟其連帶：B 欄之編號自此**不等於列數**，
而等於 TC 數。

### 4.3 總列數

434 條 TC ＋ 20 條留空列 = **454 列**（row 10–463）。

範本已擴充至 row 601，容量足夠。

## 6. 檢查

新增 gate：

- `row-order-by-reqid`：`Requirement or Design ID` 欄自上而下須為 037 之
  leaf 序（以 `layer3_map.tsv` 之 leaf 全集為準），不符即 FAIL 並指名首個
  逆序之列
- `all-leaves-present`：037 之 403 個 leaf **每一個**皆須於該欄出現至少一次；
  缺者 FAIL 並具名
- `blank-row-shape`：留空列除 `Requirement or Design ID` 外各欄皆須為空

三者皆須反向驗證。

**`all-leaves-present` 之必要性**：現行語料 383 / 403，而**無任何檢查問過
「403 個是不是都在表上」** —— 覆蓋率之計算來自我方之統計，不來自交付物本身。
