## 1. DR #45 —— R-C42 三**修訂**，採執行層之實作

R-C42 三原文要求「同一條件於兩處以上出現而仍未登記為軸者 → FAIL」。
執行層指出：四個候選之**否定值於條文無字面**，逕行登記即為條文造一個值
（§8.4.1）—— **三之字面與 §8.4.1 相衝**。

其實作（`axis-candidate-registered`：每一 ≥2 節之候選須有**具名之處置**，
`registered:` 或 `deferred: DR #x`，**沉默即 FAIL**）**保住了三之目的
而不觸及 §8.4.1**。

```
R-C42-1  R-C42 三之修訂

R-C42 三改為：

  同一條件於兩處以上之節出現者，須有一個**具名之處置**：
    `registered: 第 N 軸`   —— 三條件齊備而登記
    `deferred: DR #x`       —— 條件不齊，具名其所待之 DR
  **沉默即 FAIL。**

原文之「未登記為軸即 FAIL」不再適用 —— 當某軸之值於條文無字面時，
登記本身即違反 §8.4.1。**本條所防者為「不一致之風險無人認領」，
不是「軸未登記」。**

R-C42 一、二不變；三之原文保留於條文旁，標其修訂出處。
```

**其 gate 之涵蓋範圍亦採納**：量測**已寫入之 pre_conditions** 而非節之全文
—— 理由「該條所防之風險為兩條 TC 把同一條件寫成兩種樣子，
**只有寫出來的 PC 能做到這件事**」正確；且首版量測節全文時，
四個候選中三個之節次宣告即與實測不符，**gate 首次執行就抓到**。

## 2. §8.3 `14.12` 三條 —— **改回逐字引用，不以措辭消解歧義**

執行層將 ER 之主詞寫成「該功能之硬控」以迴避 DR #37，並自陳
**「這是措辭上的迴避，不是答案」**。

**該自陳正確，而處置須改**：「該功能之硬控」**已經選了一個答案**
（逐控制之讀法），而那正是 DR #37 之待答項。§8.4.1：來源歧義者保留歧義。

處置：

- **PC 逐字引用條文**（`If the hard controls are knobs that turn` /
  `If the hard controls are UP/DOWN toggles`），不改寫、不加限定
- **ER 之主詞回到條文自身之措辭**，不寫「該功能之」
- `reasoning` 具名 DR #37 之歧義，並明記：**混合型態之車輛上，
  本條依 14.12 之字面無法判定其適用**

**如此，歧義留在條文所在之處** —— 測試員於混合型態車輛上會撞到它，
而那正是 DR #37 該被回答的證據。**以措辭把它藏起來，等於替上游作答。**

## 3. §8.2 「條文自帶條件」之判斷 —— 立可查之判準

該判斷現為 `[manual]` 且無機器判準；其自陳「若我把某句讀成條件而它其實是
陳述，該 leaf 就被錯誤解封」成立。

**但 §2.1 之表已提供判準**：21 條所引之句**全部以限定語起首**
（`Some vehicles`／`On some vehicles`／`If`／`For`）。

指示：加 gate `rc42-condition-marker` —— 凡以 R-C42 解封之 TC，
其首行 PC 所引之條文片段須以具名之限定語集合起首；
不符即 FAIL 並具名。**限定語集合寫入 profile，其增列須經裁定。**

此不使判斷變成機械，但**使「我讀成條件」與「它以條件之語法出現」
兩者之落差可見**。

**對照組**：§2.2 甲類之 `015-04`／`015-05`（「Adjusting … will alter the
Front and Rear passengers」）**正是無限定語之陳述句** ——
該分野於本輪已有兩側實例，判準有據。

## 4. §8.6 `MOVED_TO_BATCH16` —— 加身分檢查

現有計數不變式（`emitted + withheld + moved = framework.md`）**只驗數**。
缺者為身分：某 leaf 宣稱 moved 而 batch16 未產出它，數仍相符。

加 gate：四份生成器之 `MOVED_TO_BATCH16` 之**聯集**須**恰等於**
batch16 所產出之 leaf 集合。反向驗證含「移走一個而 batch16 未產」與
「batch16 多產一個而無人宣稱移出」兩向。

**「移走的 leaf 不可長得像消失的 leaf」一句已對，本項使其可驗。**

## 7. 通過、無須處置者

- **「R-C42 解封的是『條文說了條件，只是沒人給它取名字』；解不開的是
  『條文根本沒說』。前者缺的是管理，後者缺的是內容。」** —— 該分野正確且
  應保留
- **`001-01`／`001-02` 之判定**：「條件之存在有明文，條件之內容沒有」
  —— R-C42 一要求可逐字表述者，此處無可逐字者
- **`039`（9.1）之停下理由不是軸，是沒有 ER** —— 其停下依據與其餘甲類不同，
  分開記正確
- **既有 360 條 tc_id 一律不動**，且理由為「為兩條新增而重寫 250 列交付件
  是 churn 而非資訊」；同時指出「**位移現在是安全的**（散文已改 req_id）」
  —— **可以做與值得做，分開判**
- **相似度重測判定無一改變，而其原因（受影響者只有長文）一併記出** ——
  「無變化」附其成因方為有效結論
- **`11.5`／`12.6` 之 R-C40 前件不成立**（委派對象不同），未逕以同標籤類推
