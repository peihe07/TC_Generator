## 1. R-C44 —— 列舉之三問

執行層問：「值域之列舉 vs 觸發之列舉」是否升為條文。**是**，
且應與既有二問合併 —— 三者同族而各管一軸，散落三處會被逐一遺忘。

```
R-C44  列舉之三問（拆分前逐一回答，任一答「否」即不拆）

一、**誰列的？**
    條文列舉 → 得為拆分之維度
    條文泛稱而由我方挑樣 → **不拆**，所選之樣本為 interaction data（§4.5）
    自查：能不能把這 N 個項逐字引出來？

二、**列的是什麼？**
    **觸發**之列舉（各項各自可被操作而產生後果）→ 拆
    **值域**之列舉（同一觸發之可能取值）→ **不拆**，由該值域之 TC 涵蓋
    自查：這 N 個項，是 N 種按法，還是同一種按法的 N 個結果？

三、**窮舉還是舉例？**
    窮舉 → 得逐項
    `e.g.`／`such as`／`including` → **舉例，不逐項驗**（§8.4.1）
    自查：條文自己有沒有說它只是舉例？

三問之外觀相同而處置相反 —— 一份列舉可以同時通過第一問而卡在第二問
（`033-01` 之 `Off／1-7／15h`），或通過前二問而卡在第三問
（`14.3` 之 `e.g.`）。**故須逐問答，不得憑「這看起來是個列舉」一次判定。**
```

**溯源**：一 = 75 §1；二 = 本包（`033-01` 之判定）；三 = 76 §3
（其前例為 29 §2 之 `such as JL/JT`）。三者原文各留其處，本條為其合併。

## 2. `splits.py` 之 `FIRST_N = 386` —— **追認不改**，且理由較其所述更強

執行層之判定（配置起點而非成員界定；其失效會出聲）**成立**。

**另有一項理由未被提及，而它更關鍵**：改為「自現有 corpus 之最大 tc_id 導出」
會使 tc_id **依生成順序而變** —— 先跑 A 再跑 B 與先跑 B 再跑 A 產生不同編號。
**tc_id 應為確定性之產物**，而固定起點加上大聲之碰撞檢查，其確定性優於
自語料導出。

R-C43 所防者為**靜默之失效**；本例之失效由 `tc-id-sequence` 立即報錯，
不在其射程。

**其自陳（「在寫下 R-C43 的同一輪自己新引入一個邊界值」）之記錄正確** ——
一條規則之作者在同一輪違反其字面而未違反其目的，該情形值得留在紀錄裡，
免得後人只讀字面。
