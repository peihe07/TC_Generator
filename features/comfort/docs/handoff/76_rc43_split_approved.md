## 1. R-C43 —— 以範圍界定成員者，須改以身分界定

`rc42-condition-marker` 以「tc 編號 ≥ 361」判定成員，而 65 §4 稱該界線為
「corpus 之事實而非手記清單」。**該句是我寫的，而它錯了。**

執行層之訂正一針見血：

> **它是事實，直到下一次追加為止。**

**本 pipeline 之第三例**（`MOVED_TO_BATCH16` 之計數 vs 身分、
等價對之 `req_id:tc_id`、本次之編號界線），故立條文。

```
R-C43  以「當下之範圍」界定成員者，須改以「成員之身分」界定

凡檢查、清單或不變式之成員由**區間、計數或當下之邊界值**界定者
（`id ≥ N`、`共 M 筆`、`最後一批之後`），一律改以**可自來源導出之身分**
界定（自生成器讀出之集合、具名之 id 清單、可重算之查詢）。

理由：範圍式界定在**界定當下為真**，而其為真之條件是「不再增長」——
而語料會增長。**其失效不報錯**：新成員落在範圍外，檢查靜靜地不涵蓋它；
或落在範圍內而不該被涵蓋，檢查靜靜地誤報。

自查：**若明天多了一筆，這個界定還對嗎？**
```

### 2.3 `033-01` 之第三值（`Off`）—— 生成前先答一問

`Off／1-7／15h` 三值中 `Off` 未被現行 TC 觸及，而 `2.7`／`7.5` 另有
「不可自畫面關閉風扇」之條文。

**先答**：條文中是否存在**可將風速置於 `Off` 之觸發**？

- **無** → `Off／1-7／15h` 為**值域之列舉而非觸發之列舉**，
  依 §1 之判準不拆為三條；該 leaf 之現有 TC 已涵蓋其可達之值域

**此區分須寫入該條之 `reasoning`** —— 值域之列舉與觸發之列舉外觀相同

## 3. `14.3`／`14.13` 之 `e.g.` —— **不逐項驗**

`e.g.` 於條文中明示其為**舉例而非窮舉**。

依 75 §1 之判準：**條文以泛稱表述而由我方挑選樣本者 → 一條 TC**。
`e.g.` 之情形更強一層 —— **是條文自己在挑樣本**。逐項驗即把條文之例示
讀成窮舉，屬 §8.4.1 之反向造值（29 §2 之 soft top 前例：
`such as JL/JT` 不得寫成 JL/JT）。

**維持一條**，其所引之例為 interaction data（§4.5），
`reasoning` 具名該列舉為 `e.g.` 而非窮舉。

## 5. §1 之三條推翻 —— **接受**，且其方向正確

`013-03`／`021-02`／`121-02` 之條文為
`Rear defrost is independent of **any other climate functions**` ——
**泛稱**，AUTO 與 FRONT DEF 係執行層自選。依 §1 之判準不拆，
**推翻其自身上包之判定**。

`023-01` 之 `there are 3 airflow mode buttons (Windshield, Face, Feet) …
**Each** Mode button can be pressed to individually toggle` ——
逐字列舉三項且明寫 `Each … individually`，**拆 3**，
**推翻我 74 §2.2 之「維持不拆」**。

**兩個方向各三條，皆依同一判準得出** —— 該判準之可用性由此獲證：
它不是只會把答案往一個方向推。

其 §8.4 之提醒正確：**若該判準本身再被修訂，這六條會再翻一次。**
故 `split_reason` 之引句尤須逐字，使日後之複判有據可依。
