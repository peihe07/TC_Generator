## 2. §3.1 `HMI Settings List` 之版本 —— 不代選項，給判準

本層未讀 §3 之三選項全文，**故不逕選**。判準如下，執行層據以定並回報依據：

```
一、**引用發生在哪一版，依據即是哪一版。** `-382` 之內容取自客戶目錄之
    SR24 Post 2A (June 15 2023)。

二、欲改以 `inputs/` 現放之 SR25 R1L-R (Feb 13 2026) 為依據者，
    **先比對兩版之 30／31 節**：
      - **內容相同** → 改引 SR25 版、更新 profile §1.1、
        `-382` 之 `reasoning` 記其換版依據為「兩版該節內容相同（實測）」。
        **語料不需重跑** —— 依據換了而所依據之文字未變
      - **內容不同** → **不得逕換**。該條之內容係自 SR24 版寫成，
        換版即換依據，須重驗其 TC 是否仍成立；
        若確須用 SR25 版，重跑該條並記其變動

三、無論何者，`inputs/` 內須存放**被引用的那一版** ——
    受 `BASELINE.sha256` 保護者必須是可複驗依據的那一份（同 §4 之理）。
```

**不以「新版比較好」為理由換版** —— 我方之基線為 SR24（R-C1），
外部文件之版本選擇同理：**與所引之時點一致，而非與最新一致。**

## 3. §3.2 SYS2 技術安全需求分析報告 —— **不得引，入「未認可」表**

執行層之判定成立。其所引之 `SYS-RA-HVAC-007` 尤其有力：

> In the case of conflict between this document and the HMI requirements,
> **the HMI requirements shall have precedence**.

**該文件自己說了它不是行為之依據。** 入「未認可」表並記此句為其理由 ——
**列出不可引者，是為了讓「沒引」與「漏查」可以分辨**（上繳 61 §1）。

其得作「唯讀之對照與導覽」，同 R-C18 對 `layer3_map` 之處置：可看，不可據以判讀。

## 4. §3.3 引用路徑改指 `inputs/` —— **准**

理由正確且應保留：**受 `BASELINE.sha256` 保護之副本才是可複驗的那一份。**

客戶目錄不在本 pipeline 控制下，其被替換時無人出聲；`inputs/` 之副本
每輪受 `shasum -c`。**引用之路徑應指向那一份會被檢查的位元組。**

`external_docs.py` 與 profile §1.1 之路徑一併改指 `inputs/`，
並保留其客戶目錄之原始出處為附註（**來源可考，依據可驗，兩者都要**）。

## 5. §4.1 gate 之修正 —— **准**，並記其為第三例

`n_ok == 8` 於 `inputs/` 增檔後立即失效。

> **gate 要證的是「每一列都驗過且都對」，那句話裡本來就不該有一個數字。**

改為 `FAILED == 0 且 OK > 0` 正確。**本 feature 之第三例**
（`len(withheld) >= 20`、`len(LEAF_UNIVERSE) == 403`、本次），
`RUNBOOK.md` 之 R-C43 段增列之。

## 6. §1.4 第四種情形 —— **併入 A-CF23，並修其標題**

`15.1` 之 `follow the chart below` 指向**本 spec 內之圖**，而我方讀不到 ——
既非「外部文件未取得」（類 2），亦非「遍尋不著」（類 3）。

A-CF23 原記為「SYS1 export 之圖片內容不可讀」。**其標題須改**，
使本情形歸得進去：

> **A-CF23：spec 內以圖承載之內容，本 pipeline 讀不到** ——
> 含 037 之 52 處圖片標記（25 leaf）與 `15.1` 之 chart。

**其性質與外部文件缺件相反**：東西就在我方所引之 spec 裡，
**缺的是讀取能力而非文件**。此區分須明記，否則它會被誤讀為又一件缺件。

`15.1` 之 chart 一併列入 profile §5.4 之 R-C16 清單（其行為部分有 leaf，
圖表部分無 —— 56 §3 已記其形態）。
