## 0. 落檔延遲 —— **第四次**，且此次暴露了機制本身之缺陷

本包之指令於 2026-08-17 已於 chat 作成而未落檔（前為 14、82、87）。
執行層依 chat 之指令作業，其上繳包所指之本包編號於當時不存在。

**87 §6 曾為此加一列自檢**：

```
| 本輪於 chat 承諾落檔之包 | 編號 | 已落檔？ |
```

**該自檢未生效，而其原因是結構性的：那一列寫在下放包裡** ——
**若下放包本身沒被寫出來，那一列就不存在，自然也不會有人填它。**

**檢查活在它所要檢查的東西裡面。** 此形態與本 feature 反覆抓到者同族
（`--ignore-missing` 之沉默排除、`len(withheld) >= 20` 之當下規模、
`content-sha` 只覆蓋一種區塊），**而這次的犯者是我自己為防自己而設的機制**。

該自檢維持（它對「寫了包但漏落其一」仍有效），但**它不涵蓋「一包都沒寫」**。
後者之處置寫入 §5。

## 2. §4.1 `019-02`／`-03` —— **交付說明與 RD-1 皆須增句**

第四層在 `16.13`（ICE12）找到了 MAX A/C 之參數逐項清單，
而 §8.2.1 禁止跨章移植 —— **「找到而不得用」與「找不到」是兩種狀態**。

現行措辭把兩者寫成同一種。**其後果具體**：上游讀到「那份文件我們沒有」，
會去找 VF 文件；而真正該問的是**「`16.13` 所列者，是否即 VF 文件所定者」**
—— 那是一個一句話可答之問題。

指示：

- **RD-1 之該問增一段**：載明 `16.13` 逐項列出 MAX A/C 之參數，
  而本 spec 之 `2.13` 指向 VF 文件；問其是否為同一組
- **交付說明之對應句增一句**，使「有而不得用」可辨
- **兩者皆改 `docs/` 之版本**；交付夾內之副本依 90 §2 之 (b) 待下次交付一併帶入

## 3. §6.1 `some` 之形態 —— **寫入 `RUNBOOK.md`，並列 canon 候選**

> `some` 於 129 節恰出現 5 次。**三句有 TC、兩句是缺口。**
> 其分野不在 `some` 本身，而在**該句有沒有同時給出可觀察之行為**。

**該歸納使「哪些條文會變成缺口」在事前可預測**，且其判準是實質而非詞彙
（詞彙相同，分野在行為之有無）。

其形式為：**變體之宣告 ＋ 行為 → 可寫（§8.5 之條文自帶條件）；
變體之宣告而無行為 → 缺口**。

**列為 canon 候選**（91 §4.1 之「判準之寫法」群）：
下一個 feature 於 Phase 1 即可掃此形態，不必等到 TC 寫不出來才發現。

## 4. §6.2 兩種空 —— **寫入 `RUNBOOK.md`**

> **第四層之空是有依據的空，第三層之空只是空。**
> `no-counterpart` 是鏡射表自己記過的判定，其依據欄逐條寫著為何無對造；
> 而鄰節在講別的事，這是常態。

**前者可引為證據，後者不可。** 該分別直接影響 RD-1 之措辭強度 ——
可引者得寫入問句作為「我們查過且該處確實沒有」，不可引者只能不提。
