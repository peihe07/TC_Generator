## 1. R-C45 —— 外部文件得為事實之出處，不得為行為之驗證對象

執行層問：R-C1 只定 spec 之基線版本，**未定可引用哪些文件**。該缺口屬實。

```
R-C45  外部文件之可引用性

本 feature 之 TC 得引用 Comfort spec 以外之文件，惟其角色限於**事實之出處**：
配置條件、對照表、術語定義、識別符之對應。

**不得**以外部文件之內容為**行為之驗證對象** —— 該行為屬其自身之 SWE 需求
（§8.4.2、R-C17）。

三項義務：

一、**具名並釘版**：文件名 ＋ 版本 ＋ 其在客戶目錄之路徑，寫入 profile §1
    之「已認可外部文件」表。**未列表者不得引用。**
二、**引用之事實須為版本無關者**（該配置存在、該識別符對應何物）。
    **行為性陳述不得跨版本引用** —— 其行為可能於版本間改變，
    而我方之基線為 SR24 CR24879（R-C1）。
三、`specification_reference` 另列該文件之 section，**不併入 Comfort stem**
    （profile §3.5）；`reasoning` 具名其為外部出處。

**認可不等於納入基線**：外部文件不進 `BASELINE.sha256` 之 spec 項，
其變動不觸發本 feature 之重驗；但其**取得之副本**須記其 hash 於
`DATA_REQUESTS` 之該列，使日後可辨識所引者為哪一份位元組。
```

### 1.1 版本落差之逐份處置

執行層列出四份之版本落差。依 §1 之第二項義務：

| 文件 | 版本 | 所引之事實 | 判定 |
|---|---|---|---|
| CFTS043 | 25PI3.5（同基線 release）| `$Rear_HVAC_cfg$ = [Present]`、Scope、Radio | **可引** |
| Pop Up List | SR24 Post 2A (Dec 15 2023) | popup 之識別與其內容 | **可引** |
| HMI Settings List | **SR24 與 SR25 兩版** | Auto Comfort Settings 之選項 | **可引 SR24 版**；SR25 版不引，其差異登記 |
| Hard Controls | **R1L-R (2026-02)** | 「硬控型態隨配置而變」此一事實 | **可引該事實**（版本無關）；**其具體清單不得引**（跨版本之行為性內容） |
| CFTS044 | **26PI 版** | 短按之等效基準 | **餘留仍空**，本輪不引 |
| Last Mode Table | SR24 1A (2021) | COMFORT 三列之畫面回復 | **可引**（其為畫面狀態之對照，版本無關性須於引用時具名） |
| VF727 | — | 未定其身分 | **不引**，待 RD-1 |

**版本落差之記錄不因「可引」而免除** —— 每一份於 profile 表中記其版本與
其與基線 release 之關係。

## 4. 分析層之錯誤記錄

19 §4 我裁「HMI Core L&F、CFTS044 不需補入 `inputs/`」，理由為
「其內容已判 out of scope，取得反而誘使測試越界」。

**該理由有一未經檢驗之跳躍**：內容 out of scope（正確）
≠ 不需取得（不成立）。**R-C24 第四項要求「扣除委派後之餘留分析」，
而餘留分析須讀過被委派之文件方能作。** 我們是在未讀之情形下判定餘留為空的。

更早之「不再猜候選檔案」（09 §4）**本為正確**（我當時在猜），
但其後被當作「不再去找」用 —— **條文逐字具名之文件不是猜測。**

兩者合起來，使「文件不在手上」成為一個**未附搜尋範圍之陳述**，
而 R-C30 正是我立的。

`RUNBOOK.md` 記：**「不再猜」與「不再找」之別：前者禁的是無據之候選，
後者會使有據之線索一併停止。**
