## 7. 獨立自評（入 BACKLOG）—— 49 §四-5：類型之區分是否僅在 pre_conditions

**答：本批做到了把類型帶進判定對象，但那個「做到」是措辭上的，
而措辭上的區分正是 R-SU41 所要防的東西 —— 故答案是「形式上通過，實質待驗」。**

**(甲) 本批之作法。** `061`（`030`，critical）與 `006`（`180`，silent）之 Final Step：

```
061: The recorded screen content contains no download confirmation screen for this critical update
006: The recorded screen content contains no download confirmation screen
```

**遮住其餘內容，二者確實看得出驗的是不同的事** —— R-SU41(b) 形式上通過。

**(乙) 但 `for this critical update` 是一個標籤，不是一個觀測。**

測試者看著錄影，**他看到的是「有沒有確認畫面」** ——
**他無法從畫面判斷這是 critical 還是 silent 更新**。
該資訊來自 pre_conditions（他佈置了哪一種 campaign）。

**即：判定對象裡的那個子句，其真值由 pre 決定，不由觀測決定。**
**這與 R-SU41(a) 所禁之「區分只在 pre」在實質上是同一件事** ——
只是把 pre 的內容抄了一份到 Final Step。

**(丙) 而它與 `012`／`013` 之情形又不同，值得分辨。**

`036`／`037`（ROV-B）之區分為
`settings still show Wi-Fi as **enabled**` vs `show Wi-Fi as **disabled**` ——
**那是測試者在畫面上真的看得到的二個相異狀態**。
**本批之 `for this critical update` 不是。**

**(丁) 故本批之區分屬「可佈置而不可觀測」**（B-14 之族）——
測試者能佈置 critical 或 silent，**不能於畫面確認系統認定的是哪一種**。

**若上游要求該區分為可觀測**，則須有一個「當前更新類型」之外部表徵
（畫面文字、圖示、或別的彈窗），**而 037 與 CFTS 皆未載**。
**其為一個 DR 標的** —— 執行層未逕開，列待裁。

**(戊) 一項自陳**：本批十二列中，**`061`／`062`／`064`／`065` 四列之類型區分皆屬此形**。
**若上述判斷成立，該四列之 sibling 區分需要重做，而不只是加一個子句。**
**我在起草時知道這一點，仍照 §二 #1 之判準寫了** ——
因為判準是分析層給的，而「該區分須在判定對象內」我照做了；
**但我不認為照做就等於解決了。**
