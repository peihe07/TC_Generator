## 三、R-SU37（新條，抄入 RULINGS.md，逐字）

執行層 §附記之發現使本題有了具體形狀，據以立條。

```
R-SU37（統攝型需求之驗證點 —— 餘量判準）

實測（上繳包 28 §附記）：`SWE1-FOTA-313` 之自證錨集
（`4907667`–`4907672` 六個 id）**恰為其所統攝之六列
（`315`–`320`）各自錨之聯集，不多不少**。

由此，統攝列是否具「屬於自己之驗證點」（R-SU34 v3(e)）可機械地問：

(a) **餘量判準**：統攝列之驗證點 =
    其 Description 所述之行為 **減去** 其所統攝各列之驗證點。

    `313` 之餘量為其統攝語本身：
    `coordinate the handling of …` 與
    `by interacting with SWMC and the appropriate installer component`
    —— 即**協調行為本身**。

(b) **餘量為空** → 該統攝列**無屬於自己之驗證點**，
    依 R-SU34 v3(e) 處置：不產出獨立 TC，而**須經上游確認**
    其驗證併入所統攝各列（同 R-SU32(d)，分析層不逕併）。

(c) **餘量非空但不可觀測** → 第三型（R-SU32(iii)），掛 `PENDING`。
    **注意**：協調行為之典型外部表徵為「各條件皆被正確處理」，
    而那正是所統攝各列之驗證點 —— **故此類餘量極易表面非空而實質為空**。
    判別問句：**「若六列各自都通過，還有什麼情形能使統攝列失敗？」**
    答不出具體情形者，餘量為空（適用 (b)）。

(d) **餘量非空且可觀測** → 照常產出 TC，其 `specification_reference`
    仍取自證之全部 id（R-SU15(b) 不變），並於 `reasoning` 記明
    其驗證點與所統攝各列之分工。

(e) 本條適用於全部統攝型列（現為 `313`／`327`）。
```
