## 二、新分工

### 2.1 執行層之新職責 —— **起草**

依既有 **38 個 TC 之模式**自行起草，不待逐列下放。

**批量**：每批 **20–30 列**（原為 4–7）。

**其所依之模式，逐條列明**（皆已落於 repo，非本包新增）：

| 面向 | 依據 |
|---|---|
| 兩段式 `test_item`、上半逐字 | R-S4／R-4；上半須實測見於 037 |
| 錨定：**不取首選** | R-SU14 v5；前 5 候選中裁定，得多錨 |
| 可觀測面：屬性值不入 ER | R-SU25／§二 #3（下放包 44） |
| 判定核心：不斷言規格允許他值者 | R-SU43 v2（含回查範圍：同列 facet ＋兄弟列 ＋相鄰物件） |
| sibling 區分須在判定對象內 | R-SU41 |
| 否定式須載觀測窗與連續錄影 | R-SU33／R-SU36 |
| 拆分：獨立部分失效即拆 | IN §8.2.2 |
| 範圍委派：他列所轄者不涵蓋並明記 | IN §8.2.1 |
| 受控欄逐字取母本清單 | R-SU40 |
| 缺件掛 `PENDING` 並登 DR | IN §8.4.3／R-SU29／R-SU32／R-SU39 |

### 2.2 分析層之新職責 —— **三件事，其餘不做**

1. **批次前**：定該批之範圍、**難度三軸各自報數**、**範圍委派之邊界**
   （哪些行為屬他列）
2. **批次後**：審 lint、遮蔽測試、錨定之抽驗（**每批抽 5 列複核其錨與判定核心**）
3. **新型結構問題**：僅此類介入。**既有型別之套用不再逐列裁**

### 2.3 執行層之逕行範圍擴大

原凍結第 3 條之四條件**維持**，另加：

> **起草本身即為逕行** —— 其產出不需事前核可。
> **惟下列各項須列為「待裁」而不得自定**：
> (a) 一列是否拆、拆幾個
> (b) 錨之最終裁定（**得提出建議，由分析層批次後抽驗確認**）
> (c) 掛 `PENDING` 與其型別（第二／三／四型）
> (d) 範圍委派之對象列

**(a)–(d) 於上繳包以清單提出，分析層批次後一次裁。**

### 2.4 品質之保證改由抽驗承擔

分析層不再逐列讀材料，**故其錯漏之攔截改靠**：

1. **每批抽 5 列**（隨機，種子揭露）之錨與判定核心複核
2. **全簿遮蔽測試**（每批後跑全量，非僅本批）
3. **lint 全項**（含 `I-cross` 與其覆蓋揭露）
4. **執行層之自評** —— 其歷來抓出之分析層錯誤共 **17 處**，
   **本改制後其作用只會更大**

**抽驗發現錯誤時，該批全數退回重檢**（非只改那一列）——
**抽驗之效力來自「抽中即全退」，不是來自抽中之那幾列。**
