## 三、裁決條文（抄入 RULINGS.md，逐字）

```
R-SU33 v3（觀測窗法 —— (c) 之起訖點再分二級）

v1(a)(b)(d)、v2(c) 之主體維持。(c) 增分級。

(c) v3 —— 窗之起訖點須為**可觀測之事件**。不可觀測者分二級，
    **其處置不同，不得併為一類**：

    **(c1) 原理上不可觀測** —— 該事件本身無外部表徵，
      與觀測手段之有無無關。例：靜默更新之「執行開始」——
      靜默之定義即無使用者可見之表徵，故無論給什麼通道皆不可觀測。
      **永遠不得用作起訖點**，亦不構成 DR 標的（無可請求之物）。

    **(c2) 現階段無觀測手段** —— 該事件有外部後果，惟本 feature
      尚無通道可觀測之。例：「下載完成」之時點。
      **現階段不得用作起訖點，但其為正當之 DR 標的**；
      DR 有答案後即可用。

    v2 之表述把二者併為「不可作起訖點者」，會使 (c2) 被誤判為死路
    （上繳包 28 §6(戊)）。

    **判別問句**：「若上游給我一個觀測通道，這件事就看得到了嗎？」
    答是 → (c2)；答否 → (c1)。
```

```
R-SU34 v3（跨 req_id 之偽通過 —— 粒度、交集與人裁判準）

v1(a)(c)(d)、v2(b) 之主體維持。(b) 補定義，並增 (e)。

(b) v3 —— **違例類之粒度與交集語意**（v2 未定義，實作被迫決定，
    而不同決定給出不同結果，上繳包 28 §3.1）：

    1. **取最細之類**：`confirmation-screen/download` 與
       `confirmation-screen/deployment` 為二類，不併。
    2. **交集以上下位關係判**：概括式（`confirmation-screen`）
       與其任一子類**相交**；二子類**彼此不相交**。
    3. 二者缺一即失效：只取細類而以相等判交集 → TC-8 漏報；
       只取粗類 → TC-6／TC-7 誤報。**兩端皆失敗，故此二項為一組。**

    **正規化表之拘束**：窗之起訖若由裁定（而非 TC 文字）決定，
    該正規化須於腳本檔首明記其來源裁定與「改裁須同步改」之警語。
    **否則該檢查會沉默地沿用一個已失效之前提。**

(e) **命中後之人裁判準（新增）**：
    `I-cross` 命中者，人裁所問為
    **「本 TC 是否有屬於其需求單元之驗證點」**，
    **不是**「其驗證點是否被他 TC 涵蓋」。

    **覆蓋是允許的** —— 追溯性要求每一需求列有其 TC；
    一列之驗證點被另一列之較廣 TC 所涵蓋，**不使該列之 TC 失格**。

    實例（本輪人裁）：
      `TC-1 vs TC-2`（`175`／`176`A）—— **合法**。`176`A 之驗證點
        （靜默期間無進度通知）為 `175` 之真子集，但其為 `176` 之
        **專屬驗證單元**；刪之則 `176` 無 TC，追溯性斷裂。
      `TC-8`（`184`）—— **不合法**。其三類違例逐類皆有專屬 TC，
        而其獨有之宣稱（`across the three phases`）不可觀測 ——
        **本列無屬於自己之驗證點**，非僅被涵蓋。

    **二者之別**：前者「有自己的點，且該點被涵蓋」；
    後者「沒有自己的點」。
```

## 四、`newR1L-SU-003` 之處置

**起點改**：`the start of the session` → 依 R-SU33 v3(c)，
session 開始屬 **(c1) 原理上不可觀測**（靜默 session 無外部表徵），
故改為**可用性查詢**（測試者主動觸發，可觀測）。

**procedure 步驟 2**
```
2. Record the head unit screen content as continuous video capture from the availability check
```
**expected_result 第 2 行**
```
2. The head unit screen content from the availability check is recorded as continuous video capture
```

**`continuously` 一併明文化之理由**（雖其 ER 為肯定式，R-SU36(a) 不強制）：
本 TC 所驗之安全通知**其持續時間未知**（DR-SU1 未答）——
**肯定式之「有出現」同樣可能因取樣不足而漏看**。
R-SU36(a) 之射程限於否定式係就其**必要性**而言；
**肯定式之瞬時事件同受取樣影響**，故此處主動明文化，
並於 `reasoning` 記明「所驗事件之最短持續時間未知（DR-SU1）」。

> **記明**：R-SU36(a) 之射程是否應擴及「肯定式之瞬時事件」，
> 本輪**不改條文** —— 僅一例，且該例已因 DR-SU1 掛 `PENDING`。
> 待第二例出現再議。
