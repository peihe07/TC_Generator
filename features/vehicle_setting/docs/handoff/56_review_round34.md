## 1. R-VS54 —— 第三個靜默失效，立條

三個實例同型：

| 輪 | 檢查 | 失效方式 |
|---|---|---|
| 31 | W-87 之前言判定 | 語意上無可測內容而措辭不同者不可見 |
| 32 | `guard()` | `verdict == "blocked"` 靜默直通 |
| 34 | §9 自檢之 L-VS2／R-VS39 | R-VS52 去 `$` 後 regex 匹配 0 次 |

**共同形態：一個判準在輸入形態改變後停止判定，而其輸出與「通過」不可分辨。**

執行層本輪之作法即其解 —— **以舊版批次為必失敗之對照**。

```
R-VS54（形態相依檢查之錨點，分析層裁定 2026-08-22；本輪唯一新條文）
凡以正則、字面比對或欄位形態為基礎之檢查（lint 項、guard、分級判準、
抽取式），**須同時附一個「應命中而確實命中」之錨點輸入**，
並於每次執行時一併回報該錨點之結果。

錨點之要求：
  (1) 其為**已知應失敗**之輸入（如改寫前之舊版、刻意違規之樣本）
  (2) 檢查若對錨點回報「通過」，即該檢查已失效 —— **停下回報**
  (3) 錨點與被檢輸入同批執行，不得另跑

**「0 項違規」若無錨點結果並列，一律讀為「檢查可能未執行」。**

理由：本 feature 已出現三次靜默失效（31／32／34 輪），
三者皆非邏輯錯誤而是**適用範圍脫落**；
其共同特徵為「輸出與通過不可分辨」，故只能以錨點分辨。
```

## 2. A-VS107 裁定 —— 42 處之處置

執行層問：`record` 而未被引用之 42 處，應命名或刪除？

**交付本之實測給了答案**：其 `record as` 318 處**皆為後續比較之用**
（`Vol_initial` → `Vol_after = Vol_initial minus one step`），
`the same as recorded` 0 處 —— **交付本從不記錄一個不再使用的值。**

```
分析層裁定 2026-08-22
(1) **記錄而其值於該 TC 內無後續引用者 → 刪除 record 子句**，
    改為直接檢查：`Read the signal X and check that it is <raw> (<label>)`。
    ER 對應：`X reads <raw> (<label>)`。
(2) **用於後續比較者 → 保留並命名**：
    procedure `Read … and record as <變數名>`；
    ER `<變數名> is recorded`；比較步驟之 ER 用 `<變數名> = <期望>`。
(3) **讀取型斷言之 ER 形態沿用 `X reads <raw> (<label>)`。**
    交付本 `reads` 命中 0 **非禁止，而是其未讀訊號**（其讀 HU volume／
    audio source 等 HMI 狀態）。canon §5.1 之 preferred verbs 含 `Read`／
    `Check that`，故該形態有依據，非分析層自訂。

**A-VS107 依此關閉。**
```
