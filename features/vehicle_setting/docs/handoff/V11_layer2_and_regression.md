## 3. A-VF9 —— 併行線不知本線裁定之存在（治理缺口）

```
A-VF9（分析層登記 2026-08-23；來源：A-VF8 之追因）

A-VF8 之直接成因為併行線重跑 driver 而未跑後置步驟。
**其根因非併行線之疏失，而是本線之裁定（R-VF17／R-VF20）
從未以任何機制送達併行線。**

現況：兩條分析線共用 `features/vehicle_setting/` 之全部工具與資料檔，
而 `RULINGS.md` 中 `R-VF*` 與 `R-VS*` 並存、無任何跨線通知機制。

**此為 R-VF2（併入單一 feature）之結構性後果**，
與 R-VF10 所解決之命名撞號為同源之第二種表現：
**前者為「同名兩義」，後者為「異名同物而不相知」。**

處置：**不自裁**。跨線通知機制屬工作形態，須 Pei 裁（見 §7）。
本層之最小提案：`R-VF*` 中凡效果落在 Part 1 之產物者
（現為 R-VF17 一條），於 `RULINGS.md` 之 `R-VS` 區塊加一行交叉指標。
```

## 7. 分析層之發現：**提案 A 之第 8 個 Test Set 名不成立**

**量測條件**：`docs/reports/wvf25_layer2_proposal.md` §2 之命名依據欄
與 §5 之 Layer 3 對照，逐一比對名稱與其所轄章名。

提案 A 之 **#8 `Switch Power Mode`（35 leaf，9 個 spec 章）**：

```
其 Layer 3 之 9 章
  SWITCH 1–4 Power Mode                          4 章
  Suspension Default Ride Height                 1 章   ← 6 leaf
  Suspension Flash Lights With Lower             1 章   ← 5 leaf
  Suspension Sound Horn With Lower               1 章   ← 5 leaf
  Rear Guidance Lights with Cargo Lights         1 章
  4 AUX Switches                                 1 章

其族群內最大之三簇（提案自載）：Suspension Default Ride Height 6 ／
Suspension Flash Lights With Lower 5 ／ Suspension Sound Horn With Lower 5
```

→ **該 Test Set 名為 `Switch Power Mode`，而其最大之三個簇皆為 Suspension。**
名所指與其主要內容不符。依 canon §4.2「Test Set 對應能力叢集」
與 §4.1.3「同 Test Set 應蘊含共通之 setup 型態與 UI 進入路徑」，
**該名不成立，且非改名可解 —— 改名為 `Suspension …` 則 SWITCH 1–4 Power Mode
被錯置。**

**提案 B 使此問題惡化**：B 將 #8(35) 併入 `Auxiliary Switches`(131)，
`Suspension Default Ride Height` 等三章遂落入名為「輔助開關」之 Test Set，
語義更遠。**B 解決了 12 個跨界簇，卻加深了此處之名實不符。**

**根因**：037 之 11 份分報告族群為**上游之檔案切分**，
其邊界為撰寫與交付之便，非能力叢集。以其為 Layer 2 之基底，
必然出現名無法誠實描述內容之 Test Set。

**本層不改 R-VF25（粒度 D 為 Pei 之裁定），亦不擇 A／B。**
提出**提案 C** 供裁：以族群為基底，但將**語義明顯錯置之簇**移至相符之
Test Set，即

- 3 個 Suspension 章（16 leaf）自 #8 移入 #6 `Suspension and Comfort`
- 12 個跨界之 SWITCH 簇（72 leaf）整併入 `Auxiliary Switches`

其實數（Test Set 數、各 leaf 數、跨界簇數、§4.1.3 兩型態）由 W-VF31 產出。
**C 偏離 R-VF25 字面之程度大於 B，須你明示是否容許。**

## 8. 工單

### W-VF29 — 12 個跨界簇之可測代理查證

上繳 V10 §6 第 2 項具名：未查上游為何將同一功能之 6 條分置兩份，
故提案 B 之正當性只立於「跨界為害」，未立於「上游本意」。

**上游本意不可直接取得，改以可測代理**：
1. 該 12 簇之各 3/3 兩半，其 `src_ref` 之父階是否相同？
2. 其所對應之 spec 章是否為同一章（§5 之 Layer 3 顯示
   `SWITCH 1 Power Mode` 同時出現於 #4 與 #8 之對照表 —— **同章跨兩 Test Set**，
   須確認）？
3. 兩半之條文形態是否有系統性差異（如一半為 HMI 顯示、一半為訊號送出）？

**若三項皆指向「同一功能之機械切分」，則跨界為偶然，合併有據；
若第 3 項顯示系統性差異，則切分可能反映真實之關注點分離。**
**只查不判，實數回報。**

### W-VF30 — R-VF32 之機械化（**最優先**）

(b) 不涉 driver，得逕行。** 建議先落 (b) 以縮短暴露窗。

可失敗性須實測：人為重跑 driver → 檢查點須報錯並阻斷。
