## 1. 補正：`R-VF138` 之三選項敘述有一處不足

**執行層所補之量測，直接改變該裁定之框架**：

```
P 欄  {P0 54, P1 220, P2 164}  ⊆  {P0, P1, P2, P3}
R 欄  「等價劃分 (EP)」438 條  ∈  Reference!C4:C12 之 9 選項
```

**故選項 (a)（不延伸）之代價不含資料風險。**

`R-VF138` §3 稱 (a) 之代價為「後續人工編輯該二欄時無下拉可選，易生拼寫變體」
—— **該敘述成立，惟其未言「現有之 438 個值皆已在選項內」**，
**遂使讀者可能將三選項讀為「正確 vs 不正確」之取捨。**

**三選項之實際取捨為：日後編輯之便利 vs 對交付母本結構之修改。**
**此為執行層所補，本層採納並記其為 `R-VF138` 之敘述補正。**

## 2. 甲 —— `sqref` 之處置範圍擴及 T–Z 與 AF

```
R-VF-甲（`sqref` 範圍之擴充，分析層裁定 2026-08-25，
採納執行層所具名之二項同型）
【落檔取實測最大 +1】

**`R-VF138` 之三選項只述 P／R 二欄，其範圍不足。實測同型者尚有二處**：

```
  T–Z 欄組   sqref T10:Z132   本次未寫入，**日後若寫入則同一問題再現**
  AF 欄（結果）sqref AF10:AF13  **僅 4 列**；測試執行時填，
                              **執行階段必然遇到同一問題**
```

**若裁 (b)／(c) 而只改 P／R，則同一份交付本內將有二種驗證範圍**
（P／R 至 447 或 1000，而 T–Z 停於 132、AF 停於 13）——
**其不一致本身即為日後之疑點來源**：讀者無從得知何者為刻意、何者為遺漏。

**故：裁 (b) 或 (c) 者，其修改一併及於 T–Z 與 AF，四處同時延伸至同一上限。**
**裁 (a) 者，四處皆不動，其一致性亦成立。**

**本條不改變三選項本身，只令其範圍一致。**

**AF 欄之特殊性須具名**：其為測試執行時填之結果欄
（`Pass, Fail, Pending, Block, NA`），**其現行 4 列之範圍
於本次交付即已不足**（438 列之結果無處可填而有下拉）——
**即 AF 之問題不待「日後」，其於交付本被使用之第一日即現。**
```

## 3. 二處具名嘉許

1. **補一項「與裁定直接相關、而 V66 未載」者。**
   其非補充細節，而是**改變了裁定之框架** ——
   本層之敘述使三選項可能被讀為正確性之取捨，**而其實為便利性之取捨。**
   **一個裁定之敘述不足，其誤導性不亞於其結論錯誤。**
2. **交付說明之交叉指涉。**
   §八新增後，**於 §六「已知而未解者」增第 5 項指向 §八** ——
   **「一個只寫在 §八而 §六沒列的項，容易被略過。」**
   **文件之可讀性亦為交付品質之一部分**，其被主動處理而非待人指出。

## 4. 給 Pei —— **一個字即可**

**`sqref` 三選一**：

| | 選項 | 效果 |
|---|---|---|
| **(a)** | 不延伸 | 四處皆不動。**資料正確，僅日後人工編輯無下拉** |
| **(b)** | 延伸至 447 | P／R／T–Z／AF 四處同時延至 447（＝現行末列） |
| **(c)** | 延伸至 1000 | 同 (b)，**且對日後增列亦有效** |

**本層與執行層皆建議 (c)。** 理由與 B 欄同型：
**一個依列數而定、寫死於樣板之設定，其過時不會被任何檢查攔下** —— 本輪即其實例。

**一項須知悉**：執行層另測得 **AF 欄（結果）之 `sqref` 僅 AF10:AF13，4 列** ——
其為測試執行時填之欄，**其不足不待「日後」，於交付本被使用之第一日即現**
（438 列之結果無處可填而有下拉）。
**故若裁 (a)，該項須寫入交付說明並告知使用者。**
