```

逐欄非空                    D 619 / H 619 / I 619 / L 619 / M 619 / N 619
                            B（序號）= 0        ← 與 R-VS62 末項一致

**集合比對**：

```

    交集 619    tsv-only 0    xlsx-only 0        ← 逐值全等
swe_id（D 欄 ↔ tsv.swe_id）

**該 5 對為同 5 個 leaf 之空白正規化差異**，非母體差異：

```

```

### 2.3 A-VS129（新）—— `swe_id` 內嵌換行，且可能即「無對應之 3 簇」之一之成因

**量測條件**：`data/vf230_leaves.tsv` 全 619 列，逐欄掃 `\n`／`\\n`／
連續二空白／首尾空白。

```
swe_id 異常   5     皆為 SWE1-VC-RearGuidanceLightswith\nCargoLights-01[4-8]
title  異常   5     皆為 Rear Guidance Lights with\nCargo Lights
family 異常   0
相異 title    106    ← 與上繳 §4「037 Title 簇 106」相符
```

**推論（待執行層實測確認，非結論）**：上繳 §4 列為「無對應」之 3 簇之一，
逐字為 `Rear Guidance Lights with Cargo Lights`（5 leaf）——
**其 leaf 之 title 內嵌換行**。§4 之交集判準為「正規化後全等，不做子字串容錯」；
若該正規化未含換行摺疊，該簇之不匹配即為**正規化產物，而非規格缺口**。

另二簇（`E-Save` 6 leaf、`CHMSL CAMERA DYNAMIC CENTERLINE` 5 leaf）
之 title 無空白異常，其不匹配不受此解釋。

### 2.4 A-VS130（新）—— 17 個 `swe_id` 缺數字前之連字號

**量測條件**：同上，對 619 個 `swe_id` 套 `-\d+$`。

```
不符 -NNN 尾綴者   17
    SWE1-VC-TrailerBrakeType025 … 037      13 個
    SWE1-VC-MaxPowerLevel140 … 143          4 個
其餘 602 個皆符
所有 619 個皆以 SWE1-VC- 起首（0 例外）
N 欄前綴 SYS-RA-VF230_V1-  619 / 619       ← 與上繳 §3 之 745 列前綴檢查一致
```

**影響**：任何以 `^(.*)-(\d+)$` 分離 family 與序號之處理，對此 17 個會
**靜默取錯**（把整串當 family、序號空，或回退為不分離）。
上繳 §3 明言「未引入 ID 後綴啟發式」，故 W-111 未受害；
**但下游之 sibling 判定、批次排序、TC ID 指派皆有此形態之處理**。

此為上游 037 之書寫瑕疵，**不得於本層逕行補上連字號**（改值即造值）。
處置：於解析端容錯（`-?(\d+)$`），並登記；是否向上游提 DR 見 §5.3。
