## 3. R-VF38 —— 跨線通知機制

```
R-VF38（跨線通知機制，分析層裁定 2026-08-23，
依 Pei 之授權「照你覺得可以的方式」）

成因：A-VF9 —— 兩線共用 `features/vehicle_setting/` 之全部工具與資料檔，
而本線之裁定從無機制送達併行線，已致 R-VF17 被一次例行重跑抹除
並進入 git 歷史（A-VF8）。

**機制由三部分構成，缺一不可：**

**一、`features/vehicle_setting/CROSSLINE.md`（新建，兩線共用）**

  內容**只收跨線拘束項**，不複述條文全文，每項一行：
    條文編號 ｜ 受拘束之對象（檔／leaf／欄位）｜ 一句話說明 ｜
    其機械檢查之指令 ｜ 開立日期

  **短是其有效性之前提。** 超過一頁即失去被讀之可能；
  凡已解除者立即移出（移入檔末之「已解除」區，不刪）。

**二、`接手` 動作之前置**
  `<Feature>, 接手` 之讀取清單加入 `CROSSLINE.md`，
  位於 `PLAYBOOK.md` §6 與 `INDEX.md` 之前。
  **兩線皆適用**（本條非本線專用）。

**三、機械檢查為真正之保證**
  A-VF8 已證文件之可見度不足（`RUNBOOK.md`／`PLAYBOOK.md` 已載而併行線未跑）。
  故：

  **凡效果落於他線產物之條文，須同時具備 (i) `CROSSLINE.md` 之登錄
  與 (ii) 一項能失敗之檢查。二者缺一者，該條文之跨線效力視為
  「未受保護」，須於每次上繳具名，直至補齊。**

  「未受保護」非「未生效」—— 條文仍有拘束力，惟其被無聲違反之風險
  未被消除，故須持續具名而非默認安全。

**現有之跨線拘束項（首批登錄，非全集）**：
  R-VF17  `data/grade_overrides.tsv` 所列 4 leaf  `grade_overrides.py --check`
  R-VF20／R-VF32  跑 driver 後必跑後置步驟        同上
  R-VF10  `R-VF*`／`A-VF*`／`W-VF*` 命名空間      無檢查 → 未受保護
  R-VF23  handoff／upstream 之 `V{NN}_` 前綴      無檢查 → 未受保護

**全集之盤點見 W-VF32。**
```

## 4. R-VF39 —— R-VF32(a) 之授權

```
R-VF39（driver 修改之授權，Pei 裁定 2026-08-23）

逐字：「R-VF33 本來就兩線共用」。

**本層之解讀（若有誤請更正）**：R-VF33（修改既有檔前須列消費者與
解析路徑）本即拘束兩線，故 V11 §9 第 4 項所慮之「driver 為兩線共用、
須另行協調」**無須另設程序** —— 依 R-VF33 行事即為所需之協調。

據此，**R-VF32(a) 予以授權**：得修改 `scripts/writability_driver.py`，
使其於執行結束時呼叫或提示後置步驟。

**四項約束**：
1. **限於呼叫／提示之尾段**。`value_sourced()` 及任何影響分級判定之
   邏輯仍在 R-VF20 之禁令內，**不得觸及**。
2. **施行前依 R-VF33 產出消費者清單**：誰呼叫 driver、以何參數、
   其輸出被誰讀取、exit code 之現行語義為何。
   **未產出該清單即修改者，退回。**
3. **影響面須具名**：修改後併行線之重跑將使該 4 leaf 自動回復 W0
   —— **此為本裁定之意圖，非副作用**，須於 `CROSSLINE.md` 登錄。
4. 施行前實測 `git status`，確認併行線無未提交之 driver 變更；
   有者停下具名。

**W-VF30 之 (b)（不涉 driver 之檢查點）仍應先落**，以縮短暴露窗；
(a) 不因獲授權而取代 (b) —— 二者為不同層之保護。
```
