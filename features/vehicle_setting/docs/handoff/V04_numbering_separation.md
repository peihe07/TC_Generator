
## 4. 通則二條

### R-VF11 —— 判準須附錨點

```
R-VF11（判準之自我完備性，分析層裁定 2026-08-23）

任何以條文逐字所定之判準（正規化規則、掃描定義、比對條件），
其條文須同時載明：

  必命中錨點   至少一個已知應命中之實例
  必不命中錨點 至少一個已知不應命中之實例

執行層實作後須先對錨點實測，錨點不符者回報並停，不逕行套用於全集。

理由：R-VF8（原 R-VS66）之逐字正規化不足以達成其自身目的 ——
`vf230_leaves.tsv` 將換行序列化為字面兩字元 `\n`，`[\r\n\t]` 不匹配，
其後 `[^a-z0-9]+` 之摺疊將 `n` 視為英數字保留，致 `with\nCargo`
正規化為 `with ncargo`。執行層照逐字實作得 103／3（無變化），
加解序列化後方得 104／2。

**判準之不足在落筆時不可見，唯錨點可使其可見。**
本輪同型失效出現三次（A-VS135 之 (a)(b)(c)），其中二次係條文逐字所定。
此條與 canon §5a 末句（詞彙型工具之缺陷不會報錯，須以已知全集驗證）同源。
```

### A-VF1 —— `recon.py` 之證據測量恆為 0，證據力為零

```
A-VF1（分析層登記 2026-08-23；來源：上繳 62 §4 之「附帶發現」）

`scripts/recon.py:628-629` 與 `:635-636` 之
`re.search(r"-\d\d$", rid)` 要求「連字號 ＋ 恰二位數字」。

實測（上繳 62 §4）：Part 1（271 leaf）命中 0；VF230（619 leaf）命中 0。
兩 feature 之 reqid 尾綴皆為三位（`-001`），故該式**於兩 feature 恆為 0**。

該處係作為「判準之差距」之證據測量（R-C3 所禁之啟發式與判準並陳）。
**一個恆為 0 之測量不提供任何區辨力，其作為證據之力為零** ——
惟其不會報錯，故此缺陷至今未被察覺。

執行層將其列為「附帶發現，未列為 anomaly」；**分析層登記為 anomaly**
（anomaly 之登記與分類屬分析層自裁範圍）。

處置：**不改**。其修正屬 Part 1 之事（W-VF13 只查不改）。
```
