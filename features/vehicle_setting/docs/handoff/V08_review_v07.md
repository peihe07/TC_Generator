
## 3. R-VF21 —— R-VF11 之修補（錨點自身須先驗）

```
R-VF21（錨點之有效性前提，分析層裁定 2026-08-23，
採納 A-VF4 與 W-VF18 之鑑別錨點）

R-VF11／R-VF19 令「附必命中／必不命中錨點」，**未令錨點自身須先驗**。
A-VF4 實測：不存在於被掃描集合內之必不命中錨點**恆為通過**，
其「通過」與「錨點不存在」不可分辨，提供之保證為零。

**補三項要件，與 R-VF11 併行適用**：

1. **存在性先驗** —— 施行前須先確認兩個錨點**皆存在於被掃描之集合內**。
   不存在者 `raise` 並停，不得續行。
   「錨點取值為 None」與「錨點不應命中」須以不同碼路徑區分。

2. **必不命中錨點須為「存在且不應命中」** —— 不得以「不在集合內」
   充當「不命中」。前者證明判準有區辨力，後者只證明集合不含它。

3. **鑑別錨點（判準涉及兩個定義時為必要項）** —— 當一個判準是另一判準之
   代理（字串代理 layer3、族名代理 Test Set 等），須另取一個
   **實質須命中而代理須不命中**之實例為錨點。
   其存在使兩定義之差異在落筆時即可見，而非在數字對不上時才發現。

   先例：W-VF18 之 `LeftFrontHeatedSeat-004`（layer3 = `CrossZone Common`，
   實質屬 Heated Seat，字串代理漏之）—— **158 vs 160 之差額本身即最佳錨點。**

**同型先例**：A-VS106、A-VF1（`recon.py` 之 `-\d\d$` 恆為 0）、
`vf230_layer2.py:113` 之 `assert ... or True`（恆真）。
**四者同一形態：驗證機制之失效不會報錯。**
```
