## 1. 覆核結論：**核可**。並記分析層之錯二件

### 1.1 錯一 —— R-VF36 之移動規則為分析層所立，且已證不成立

Pei 之裁定為「**C**」（提案 C 之概念）。**「主題詞相交」之二條件規則
係本層於 V12 §1 自行operationalize 之產物，非 Pei 所裁。**
其失敗責任在本層，不在執行層，亦不在該裁定。

執行層以**鑑別錨點 `Power Unit`** 證其誤配（量測單位被移入
`Switch Power Mode`，僅因共用泛用詞 `power`）—— 此正是 R-VF21 第 3 項
所令之鑑別錨點首次擋下一條**本層自己寫的**規則。

### 1.2 錯二 —— V11 下放後未經上繳即續發 V12

致 R-VF32–R-VF35、A-VF9、DR-31、W-VF29–W-VF31 於本輪前全未執行。
**與 R-VF30 為對稱之另一面**：R-VF30 令成文前須讀最新上繳，
而此例為**上繳尚未存在即續發**。執行層之建議採納為 R-VF42。

### 1.3 具名嘉許三處

1. **§2.1 之自我設限** —— 執行層指出 `suspension` 亦屬泛用詞，
   故 R-VF36 起點一之 4 筆 Suspension 移動亦落入被診斷之 24 筆，
   **而該 4 筆語義正確**；遂明言「相交詞為泛用詞 ≠ 該移動錯誤」。
   **診斷只證規則之依據不足以區辨，不證每一筆皆錯** —— 此界限之自覺，
   使診斷未被誇大為全盤否定。
2. **§2.2 —— 規則之產出與其立法意圖相反。** 同一規則將 SWITCH 全族移出
   `Auxiliary Switches`，使 `Switch Power Mode`／`Switch Type and State`
   不但未消失，反成 SWITCH 專屬 Test Set，**而 V11 §7 之整個論證即為
   此二名須消去**。執行層未逕改規則（其為裁定），逐筆列出待裁 —— 處置正確。
3. **§4 之 exit code 刻意限縮並具名** —— 覆寫層失敗時不改 driver 之
   exit code，以免影響 16 個下游之判讀。**限縮本身合理，
   而其為限縮一事被寫出來，使其不至於被誤認為完備。**

### 1.4 編號登記

`docs/upstream/` 無 `V11_*`，其內容併於 `V12_layer2_final.md`。
**登記為缺號，不補不重編**（`A-VS02` 先例；同 upstream V03–V05）。

## 2. R-VF41 —— 廢止移動通則，改逐筆列舉

```
R-VF41（提案 C 之移動方式，分析層裁定 2026-08-23）

**R-VF36 之「主題詞相交」二條件規則予以廢止**，不再適用。
R-VF36 之其餘部分（Layer 2 採提案 C、合計恆為 627、逐簇不批次、
每筆須附依據）**維持**。

**廢止理由（二者皆為實測，非推論）**：
1. 該規則以單一泛用詞誤配。鑑別錨點 `Power Unit` 實測被移入
   `Switch Power Mode`；以泛用詞為唯一相交依據之移動達 24 筆
   （泛用詞之操作型定義：出現於跨 ≥3 個 Test Set 之簇章名者，本輪 18 個）。
2. 該規則之產出與其立法意圖相反：其將 SWITCH 全族移出
   `Auxiliary Switches`，使 `Switch Power Mode`(45)／
   `Switch Type and State`(12) 反成 SWITCH 專屬 Test Set，
   而 V11 §7 之論證即為此二名須消去。

**改以逐筆列舉，不設通則。**

理由：Layer 2 為一次性之框架決定，**其正確性由逐項可辯護構成，
不由一條規則之普適性構成**。設通則係本層之過度工程 ——
通則須具區辨力方有價值，而任何以詞相交為基礎者皆無足夠區辨力
（`power` 一詞即橫跨量測單位、開關電源模式、充電功率、引擎延時）。

**列舉之義務要件**，每一筆移動須附：
  簇名 ｜ leaf 數 ｜ 原 Test Set ｜ 新 Test Set ｜
  **該簇之條文主旨一句**（自其 leaf 之 desc 取，非自章名推）｜
  為何原屬不當、為何新屬適當

**不得移動者亦須列**（列於「過檢視而留置」表），附一句理由。

**種子清單（V11 §7 之診斷，非全集）**：
  (a) `Suspension Default Ride Height`／`Suspension Flash Lights With Lower`／
      `Suspension Sound Horn With Lower` → `Suspension and Comfort`
  (b) 12 個跨界之 SWITCH 簇（SWITCH 1–4 之 Power Mode／Type／
      Hold Last State）→ `Auxiliary Switches`
  (c) (a)(b) 施行後，`Switch Power Mode` 與 `Switch Type and State`
      之殘餘（預期為 `4 AUX Switches`／`Rear Guidance Lights with Cargo Lights`
      等）**須逐一定其歸屬**；二 Test Set 若清空即消失。
      **「預期」為本層之推算，非實測，以執行層之實數為準。**

**核可路徑**：列舉表產出後回報，**不逕鎖 framework**。
R-VF37(a) 之逕鎖條款於本輪**不適用** —— 其前提為「依既有規則機械產出」，
而逐筆列舉含判斷，須經覆核。**由分析層覆核；名單若仍為已核可 11 名之
子集，則不再經 Pei。**
```

## 4. R-VF43 —— 4 個 Power Mode 簇之兩半非同質，須記載

```
R-VF43（W-VF29 之發現落實，分析層裁定 2026-08-23）

W-VF29 以條文形態為可測代理，實測 12 個跨界簇：

  SWITCH 1–4 之 Type／Hold Last State（8 簇）
      兩半皆為「顯示 2 ＋ HW 通知 1」 → **形態相同**
  SWITCH 1–4 之 **Power Mode**（4 簇）
      `6 Aux Switches` 半：顯示 2 ＋ HW 通知 1
      另一半：**HMI 送出 2 ＋ 顯示 1**        → **形態不同**

該 4 簇之兩半**非同質**。其歸屬依 R-VF36 起點二整併於
`Auxiliary Switches`（不變），**惟該差異須明載，不得因整併而消失**：

1. **Layer 3 之對照表**中，該 4 簇須標註其含兩種條文形態。
2. **TC 書寫時**，該 4 簇之 leaf 不得因同屬一簇而被當作 sibling 逕行
   合併或互相套用 procedure；`reasoning` 須具名其形態
   （顯示／HW 通知／HMI 送出）。

**理由**：canon §4.1.4 第 2 項令「同 Layer 3 之 RD 為 sibling 候選之
預設訊號」。該 4 簇之兩半若被當作 sibling，其 procedure 與 ER 之
驗證對象不同（UI 顯示 vs 訊號送出），將產生 §7 之 false pass。
**整併解決索引問題，不解決同質性問題；後者須以記載處理。**
```
