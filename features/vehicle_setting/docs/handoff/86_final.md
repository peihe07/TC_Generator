## 1. R-VS6 之「逐字」以**所顯示之字元**為準 —— 27 條 WARN 收為 PASS

執行層之理由成立，且其不逕收為 PASS 而列 WARN 待裁，**正確**。

```
R-VS6 之解釋（分析層裁定 2026-08-23；非新條文）
「上半段須為來源之逐字」，其**逐字之比較基準為來源文件所顯示之字元**，
非其儲存格式之編碼。

  **屬解碼，不屬改寫**（PASS）：
      XML 實體之還原（`&lt;` → `<`、`&amp;` → `&`、`&gt;` → `>`）
      不斷行空白之正規化（`\xa0` → 空白）
      連續空白之壓縮
  **屬改寫**（FAIL）：
      字詞之替換（`HU` → `HMI`、`When` → `If`、`Softkey button` → `softkey`）
      標點之替換（彎引號 → 直引號）
      取自條文之他句、或漏其前言

理由：`&lt;&gt;` 於 docx 之 XML 中為 `<>` 之編碼，**讀者於文件中所見即 `<>`**；
回復其實體會使工作簿顯示編碼而非文字，**對讀者更差**。
而 `HU` → `HMI` 改變了主詞所指之系統，其為改寫。

**27 條 WARN 收為 PASS，不修。**
**惟彎引號 → 直引號屬 FAIL**（其已在 17 條之內，已修）——
彎引號為來源之顯示字元，非編碼。
```

## 2. R-VS78 —— 新判準首跑須先驗其所讀之欄位存在（本輪唯一新條文）

`dict.get("impl_gap")` 於欄不存在時回空字串而**不報錯** ——
「未標 `impl_gap`」恆為真，違規數即等於前半條件之命中數（28）。

```
R-VS78（分析層裁定 2026-08-23）
新寫之判準於**首跑前**，須先驗其所讀之每一個欄位／鍵**確實存在於其資料來源**：

  (1) 列出該判準所讀之全部欄位名，逐一於來源之表頭／鍵集中確認
  (2) **不存在者即停** —— 不得以 `.get()` 之預設值續行
  (3) 首跑之命中數若與預期量級不符（如全母體皆命中、或全數不命中），
      **先驗 (1) 再讀資料**

**與 A-VF1 為同一形態之兩面**：
    A-VF1 —— 測量恆為 0（條件恆為假）
    本例 —— 條件恆為真
**二者皆不報錯**，故皆須逐條驗方能發現。
`.get()`／`getattr()`／`re.search(...)` 之回退值**皆屬此類**。

實例：R-VS67′ 之判準讀 `writability.tsv` 之 `impl_gap` 欄，
**該檔無此欄**（`impl_gap` 為 TC 之欄位）→ 28 條全報不符，實為 0。
```

```
分析層裁定 2026-08-23（修訂 84 包 §4）

  `REGEN_ORDER.md` 之該 11 批，其「原生成器」欄記
      `**首版生成器未入庫；其產物以 sha256 凍結為基準**`

      （若首版檔仍在 `generated/`；不在者記其現存最早版）

**其意涵須於 `DELIVERY.md` 具名**：
  該 11 批（約 80 條）之**首版生成過程不可重放**；
  其後之每一層修正皆有腳本且順序已記，**故其變更歷程可稽核**。
  **可稽核之範圍為「自凍結點起之變更」，非「自需求起之產出」。**

理由：ASPICE 要求之追溯為**產物與其變更之可稽核**；
首版過程不可重放者，以凍結點 ＋ 有序變更鏈仍可滿足該要求，
**惟其範圍須具名，不得以「可重製」一語涵蓋。**
```
