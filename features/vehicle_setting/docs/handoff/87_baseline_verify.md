## 1. R-VS79 —— 一致性檢查之基準須具名（本輪唯一新條文）

§6-1 之判斷是本輪最重要者，且其為**交付論述之界限**：

> 「逐字以所顯示之字元為準」同時意味著 **`blocks_with_sec()` 之解析層成了逐字之
> 事實基準**。兩側都經同一個 `displayed()` ——
> **這條檢查驗的是「產物與解析結果一致」，不是「產物與文件一致」。**

```
R-VS79（分析層裁定 2026-08-24）
凡「產物與來源一致」之檢查，**須具名其比較之基準屬下列何者**：

  (L1) 產物 ↔ **解析結果**   —— 兩側皆經同一解析層；
                                 解析層之偏差**不可見**
  (L2) 產物 ↔ **原始文件**   —— 以文件之原始位元組為基準
  (L3) 解析結果 ↔ 原始文件   —— 驗解析層本身

**以 L1 為之者，其結論須逐字記為「與解析結果一致」**，
不得記為「與來源逐字相符」。

**且交付前至少一次以 L3 抽驗**：自母體抽樣，將解析所得之條文
與原始 docx 之對應段落逐字比對，**抽法與抽樣數具名**。
L3 未做者，L1 之全部結論**其有效性以解析層之正確性為前提**，該前提須具名於交付文件。

理由：R-VS6 之檢查五輪來以 L1 為之而記為「逐字」；
若解析層多吃一個空白或漏一個換行，**兩側同偏而檢查回報 PASS**。
`displayed()` 之引入使該不可見性擴大（其正規化空白）。
```
