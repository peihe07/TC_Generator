## 2. R-VF48 —— 補立「引用而無定義」之檢查

```
R-VF48（條文簿完整性之檢查，分析層裁定 2026-08-23，
採納上繳 V15 §6 第 1 項之建議）

R-VF10 之檢查驗「同一編號不得有兩個定義」，**未驗「有引用而無定義」**。
`R-VF9` 被引用 3 處逾三包而無人察覺，即該缺口之實例。

**補立檢查三（併入同一檢查點，依 R-VF40「不另立入口」）**：

  掃全庫之 `R-V[SF]\d+`／`A-V[SF]\d+`／`W-VF\d+`／`DR-\d+` 引用，
  與各簿之**條文起始行集合**比對；
  **凡被引用而無定義者即失敗**，列出該編號與其引用處。

**掃描範圍與豁免**：
  - 掃描：`RULINGS.md`／`ANOMALIES.md`／`DATA_REQUESTS.md`／`CROSSLINE.md`／
    `framework.md`／`feature.yaml`／`docs/INDEX.md`／現行腳本
    —— 即 R-VF18 所稱之「現行有效之陳述」。
  - **豁免**：`docs/handoff/`／`docs/upstream/`／`docs/reports/`
    —— 歷史包引用當時尚未落檔之條文為正常（下放包必先於落檔），
    將其納入會使檢查恆為失敗而喪失區辨力（A-VF1 之形態）。

**錨點（R-VF21／R-VF28，以內容定錨）**：
  必命中   人為於 `framework.md` 插入「依 R-VF99」→ 檢查須失敗
  必不命中 現行全庫（`R-VF9` 已補落後）→ 應通過
  鑑別錨點 `docs/handoff/V16_*.md` 對本條 `R-VF48` 之引用 ——
           其在豁免範圍內，**不得被計為「引用而無定義」**；
           一條未設豁免之規則會誤殺之

**本檢查同時封住 R-VF42 但書之洞**：純裁定包之條文若未落檔，
其一旦被 `framework.md`／`feature.yaml`／腳本引用即被本檢查攔下。
**但書之程序義務因而獲得機械後盾。**
```
