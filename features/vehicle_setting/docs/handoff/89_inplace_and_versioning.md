## 1. R-VS80 之理由段**錯了**，規範不動

R-VS80 與 A-VS162 皆載「**未更新 `revision`**，致該層不存在於任何記錄」。

**實測：五檔之 `revision` 皆被追加**（`…；D-3（48 輪）：`screen_pending` 依
R-VS69 改以 AH 之畫面層 BLOCKED 註記為判準`）。

**鏈缺該層之真因為抽取式**：

```python
m = re.match(r"(W-\d+)", rev)      # 錨於串首，只取第一個標記
```

**資訊在 repo 裡躺了十一輪，是抽取式把它丟掉的**，
而我於 88 包把該丟失報告為「不存在於任何記錄」。

```
R-VS80′（理由段之更正，分析層裁定 2026-08-24；規範不變）
R-VS80 之規範（產物一經寫出即為定版；變更一律產新版；下放包措辭亦受拘束）
**不變**。

其理由段更正為：

  就地改動使該變更**不具獨立之版本檔**，故
  (a) 其前後兩版之差**只能自 git 史取得**，`generated/` 內無可比對之兩檔
  (b) 重製鏈之重建**依賴 `revision` 之抽取式**，而該抽取式之任何缺陷
      即使記載完整亦會使該層不可見（A-VS164 即此）
  (c) 其規模不可見 —— **實測為 5 commit／26 檔次／24 檔**（A-VS163），
      而非 88 包所推之「48 輪一次、五檔、一個標記欄」

原理由段「未更新 `revision`，致該層不存在於任何記錄」**撤回** ——
`revision` 有更新。

**A-VS162 之描述依本條更正**；A-VS164 記其真因。
```
