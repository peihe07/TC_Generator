## 2. `inputs/` 之版控斷鏈 —— 與 canon G-9 明文衝突

上繳 §9-1 指出 `features/vehicle_setting/.gitignore:2` 排除整個
`inputs/`，故 `INPUTS.sha256` 不入版控。

**查既有政策**（canon §5a 第 17 條）：`FEATURE_ONBOARDING.md` §9.2 之 **G-9**
逐字為：

> **保住檔案與保住雜湊是兩件事。** 歸檔之檔案須有可執行之 `shasum -c`，
> 且**該雜湊檔本身須入版控**。

而 scaffold 之 `.gitignore` 註解逐字為 `# Customer source files - never commit`
—— 其意旨為**不提交客戶素材**，**未及於雜湊檔**。
兩者不矛盾：素材不入庫，雜湊入庫。**現況是實作未跟上政策，不是政策衝突。**

```
R-VS16（待 Pei 裁 —— 版控政策屬 Pei）
features/vehicle_setting/.gitignore 於 `inputs/` 之後增列一行例外：

    !inputs/INPUTS.sha256

理由：canon G-9 明文要求雜湊檔入版控；現行 .gitignore 之註解意旨為
「不提交客戶素材」，雜湊檔非素材。無此例外則素材落地之證據鏈在
版控中是斷的 —— 有路徑、有雜湊，但雜湊本身不可追溯。

配套：本例外僅及於 INPUTS.sha256 一檔，不及於 inputs/ 內任何其他檔案。
其餘 feature 之同一缺陷不在本裁定範圍，各自於下次開輪次時自檢
（canon R-U44 之形態）。
```

**執行層不得自行修改 `.gitignore`**（禁區正確）。裁定後由 Pei 執行。

## 3. 上繳 §10-2 之自我質疑 —— 本輪可答，且答案更強

執行層記：「已驗兩集合相等，**未驗 036 之 237 列各自對應到正確的那一個
Functional leaf**；I／H／N 之 237/237 是投影正確性之證據，非列序正確性之
證據。」

**分析層自 `inputs/` 實體檔實測，三層皆成立**（掃描條件：037
`Analysis Report` 表頭列 7、資料自列 8、`Categorization` 前綴不分大小寫；
036 資料列 10–246；文字比對先 `\s+`→單一空格再全字串相等、**區分大小寫**）：

### 3.1 逐列對應 —— 237 / 237

對每一列，以其 **D 欄之 swe_id** 取該 leaf，驗
`I 欄 == 該 leaf 之 Requirement Description` **且**
`H 欄 == 該 leaf 之 Requirement Title`：**237 / 237 成立**。
D 欄無重複值。

→ **這已經是逐列對應之證據，不只是投影**：若某列被放在錯的位置，
其 I／H 就會對不上它 D 欄所指的 leaf。

### 3.2 但 desc 並非唯一 —— 該證據之強度有界

237 個 Functional leaf 之 `Requirement Description` 正規化後：
**相異 226**，**10 組重複、涉及 21 列**。例：

- `*HW supplier shall notify the $DriverSide$ signal via the VHAL interface…` ×2
- `HW supplier shall notify the STATUS_CSWM.FR_HS_STATFailSts signal…` ×3

`Requirement Title` 之相異值僅 **20**（即四個 family 之 20 個能力叢集）。

→ **在那 21 列上，I／H 相等無法區分同組之成員。** 逐列對應之證據對
216 列為決定性，對 21 列僅為「不矛盾」。

### 3.3 列序 —— **不是 037 之檔內順序，而是 family 分塊後塊內保序**

| 量 | 結果 |
|---|---|
| 036 之 D 欄順序 == 四份 037 串接後之順序 | **否** |
| 036 之 family 分塊 | `VentedSeat 72` → `HeatedSeat 88` → `Heated_Steering_Wheel 31` → `Common_Features 46` |
| **各塊內順序 == 該 037 檔內之 Functional 列序** | **四塊全部為真** |

即：**036 是以 family 為單位重排，塊內完全保序。**
四塊之外部順序（Vented → Heated → HSW → Common）既非檔名字母序，
亦非 037 之任何自然序 —— 為 036 作者之選擇。

**此事實對 R-VS1（效力 BLANK、append from first data row）之影響**：
既有 237 列將全欄重生，寫回順序依 R-VS4 之 Test Set 與既定排序規則決定，
**不必沿用 036 現況之塊序**；但若選擇沿用，本節即其依據。
**列序之選擇本身屬 write-back 策略，於 framework 階段再定。**
