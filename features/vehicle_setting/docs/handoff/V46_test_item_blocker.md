## 1. 【阻斷】`test_item` 之括號下半不存在，**440 / 440**

**canon §4.3.1（R-S4）逐字**：

> `test_item` 分上下兩半：上半 = 需求／規格原句 verbatim；
> **下半 = 作者生成之測試目的或情境標籤，獨立成行，格式 `(...)`。**
> 同一 Requirement ID 衍生之多列，其括號下半內容不得逐字相同。
> **缺括號下半 = FAIL，不得出貨。**

**分析層實測**（預覽表 `I` 欄，與 `generated/*.json` 之 `test_item` 逐條比對）：

```
預覽表 I 欄以 `(...)` 結尾者          0 / 440
vf230_batch01.json 之 test_item        0 / 50
vf230_batch07.json 之 test_item        0 / 50
```

**即：缺漏在生成端，非在預覽端之投影。** 440 條之 `test_item` 皆為條文逐字，
**無一條有下半。**

**其未被任何一方攔下之原因**：
- 自檢 15 項無此項 —— **本層自 V19 §5.3 起所擬之升級條件與自檢清單，
  自始未含括號下半**；
- 本層前四輪之抽樣（287 條）所測九項亦未含之 ——
  **本層測的是自己列的清單，而該清單漏了一條 canon 硬規則。**

**責任在本層。** 執行層依清單自檢，其清單為本層所給。

## 2. 【併同阻斷】上半 token 逾 50 者 **197 / 440**

canon §4.3.1 逐字：「**上半 token 數上限 50（R-3）**。超限須摘句，
全文以 `specification_reference` 指回，**不得整段傾倒**。」

```
I 欄 token > 50            197 / 440   （44.8%）
最長                       117 token（B=390）
中位                        50 token
```

**且摘句之判準已由 canon 給出**：「摘句以**與括號下半之測試目的直接相關之句**為限」
—— **即摘句與括號下半為同一動作之二面**：先定測試目的（下半），
再據以摘出相關之句（上半）。**故 §1 與 §2 須一併處理，不得分兩輪。**
