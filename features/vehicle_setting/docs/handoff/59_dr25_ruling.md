# 59 下放包 — DR-25 之處置裁定（R-VS57）、36 輪修訂

分析層寫入，2026-08-22。Pei 裁定：**DR-25 先以 spec 或分析報告所載為主。**

---

## 1. R-VS57 —— L-VS2 由二值改為三分

```
R-VS57（Pei 2026-08-22）
訊號名不存在於基線 DBC 時，**不逕判不可寫**。
L-VS2 之判定由「存在／FAIL」二值改為三分：

  **PASS** —— 該 signal 名於基線 DBC 區分大小寫逐字存在
  **WARN** —— 不存在於基線 DBC，**但於 CFTS044 條文或 LID 之對應欄組
              （依 R-VS51(2) 之架構分流）有逐字來源**
              → **照常撰寫 TC**，訊號名取該來源之逐字，
                並標 `dr_dependent = DR-25`
  **FAIL** —— 不存在於基線 DBC，且無上開任一來源
              → 該 TC 不得寫出（其名將為編造）

**來源之優先序**：CFTS044 條文之逐字 > LID 對應欄組之 `Signal Name`。
二者並存而不一致時，停下回報（不自行擇一）。

**R-VS55 不變** —— 分級仍須涵蓋 lint 之否決條件，
惟 L-VS2 對 WARN 類**不再是否決條件**，故該類不因之判 W2。

**DR-25 仍送出**（57 包 §2 全文，Urgency 由 High 降 **Medium**）：
其性質由「阻塞」轉為「確認」——
覆後若為 (b)（不適用 R1LR），`dr_dependent = DR-25` 之 TC 逐條撤回；
若為 (a)（另有 DBC），則以該 DBC 複驗訊號名與值域。

理由：CFTS044 與 037 為需求之來源，基線 DBC 為實作之快照；
**來源說有而快照沒有，是快照不完整之可能大於來源錯誤**。
以快照否決來源，會使 33 個上游明列之需求無 TC 可寫。
```

執行時無法在現行 CAN 環境上跑。**其為已知且已標記之狀態**
（`dr_dependent`），非缺陷；但**交付前須向客戶揭露該 33 條之依賴**。
