
  (<該 TC 之最終驗證步驟之動作，首字小寫> -> <該步驟對應之 ER>)

```
**三項要件**：
  一、**下半之二端逐字取自該 TC 之 `test_procedure` 末步與 `expected_result` 末項**

  三、以 `(` 起、`)` 迄，**獨立成行，其前空一行**。

`features/power/sandbox/b29/pm_29.xlsx`（389／390 列具此形），
**非本層自創，亦非回退。**

**本條只及於括號下半之格式，不及於訊號記法。**
```

## 3. 乙 —— 拆題單位改為「驗證點」

```
R-VF-乙（拆題之單位，分析層裁定 2026-08-24，
依 Pei 之指示「注意拆題的部分」）
【落檔取實測最大 +2】

**VF230 現行為「一 leaf 一 TC」** —— 實測 440 條之 `D` 欄（需求 ID）
**零重複，440 / 440 唯一**。

**PM 為「一條文 N 列」** —— 175 個上半衍生 390 列，平均 2.23，最大 12。

**改採 PM 之單位：拆題之單位為「可獨立觀察之驗證點」，非 leaf。**

**其依據非僅 Pei 之指示，亦為 canon 明文**：
  §8.2.2 逐字：「**RD sub-id ≠ TC count**」「一個 RD sub-id 可能需要多條 TC
  覆蓋，當其描述綑綁了數個獨立之部分失效」
  §8.3 之壓力測試：「**若二個不同之部分失效皆經由你的 TC 落到「fail」，
  即為綑綁 —— 拆之**」

**即：VF230 現行之「一 leaf 一 TC」不是一個中立之預設，
而是一個未經 §8.2.2 檢驗之選擇。**

**拆題之判準（canon §8.3 之壓力測試，逐字可執行）**：

  對每一 leaf 之條文，逐一列出其**可獨立觀察之結果**；
  **若其 ≥ 2 且各自可獨立失效，則拆為 N 條**，各驗其一。

  **不拆之例外**（canon §5.7）：**同一觸發之數個必然後果**屬同一 TC，
  以多行 ER 涵蓋 —— 觸發為驗證之單位，同一觸發之後果為待查之事實而非另一題。

  **拆之判準為「不同之觸發／不同之輸入／不同之範圍」，非「不同之結果」。**

**其後果須先量測再執行** —— 440 條若依 PM 之 2.23 倍計為約 980 條，
**而該倍率為 PM 之實測，非 VF230 之預測**。
**W-VF80 之第一項即為 VF230 自身之倍率量測，不得以 PM 之數外推。**
```
