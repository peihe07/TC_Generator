## 1. 四處具名嘉許

1. **§二 —— 我的診斷範圍太小。** V35 §2 判 seq 295 為「實質錯誤而非僅標題重複」，
   **而實測為三條在驗錯對象**：`PowerTailgate-028`（預設值需求）／
   `EnhancedDisplaySynchronization-132`（同）／`TrailerNumber-065`（無效值處理）。
   **二種新形態與上行型之模板方向相反** —— 前者須「不送值而讀開機後之顯示」，
   後者須「送無效值而確認顯示未變」。
   **「標題重複只是它的症狀」** —— 若照 V35 只補區辨 token，三條驗錯對象之 TC 會留在交付物內。
2. **§三 —— R-VF97 乙 以實測推翻。** 以 zipfile 直讀 PROXI shared strings
   （**獨立路徑，不經 `proxi_known()`**，正合 R-VF92 一）測得四例之識別位置各不相同，
   **「別名在括號內」此一前提不成立**。照本層之令移除 `(PTGM)`，
   其參數在 PROXI 表內不存在。
3. **§三末之 `pnorm()` 陷阱** —— `pnorm("(SRT)") == pnorm("SRT")`，
   **正規化吸收括號遂掩蓋形態差異**；若候選序將原樣排前，括號會被留在標題內。
   **一個為比對而設的正規化，反使比對失去它要比的那個維度。**
4. **§四 —— `priority.py` 之歸因為 (iii)，本層所給之二選項皆非。**
   `dist['P0']`=88 自 627 列算，`pool` 之 P0 僅 82 條；**選池序是對的，錯的是斷言之切點**。
   其為既有缺陷，由 W-VF70 之 B8／B9 分級精進使 6 條 P0 掉出 W0/W1 而暴露。

## 3. 佔位式之張力裁定（上繳 §七-4 之未裁項，**本層之債**）

```
R-VF-乙（代表值之選法，分析層裁定 2026-08-24）
【落檔時取實測最大號 +2】

**R-VF91 二令「取列舉之首值為代表值」，而 R-VF81 二令
「不得以 raw 之大小為選法」。二者之字面張力上一輪已具名待裁，本層未裁，
而本輪又生成 57 條依其行事者。此為本層之債，於此清償。**

**一、「列舉首值」定義為 DBC `VAL_` 定義中之書寫順序首項**，
非 raw 值之大小排序。二者若恰同序，**須於 `reasoning` 具名其同序**，
以免日後被誤讀為依大小取值。

**二、`reasoning` 之必要句增一分句**：
```
  條文未指定所收之值；值域取自 DBC；本條驗其代表值，
  該值為 DBC VAL_ 列舉之書寫序首項，非依 raw 大小、非條文指定。
```
  **缺之即 FAIL**（自檢增項）。

**三、`SIG_VALUE_AT` 未認出 `shall be <Value>` 式為真缺陷，須修。**

  `PowerTailgate-028` 之條文明寫 `The default value … shall be Enabled`，
  而抽取式未認之，遂落入「未指名值」→ 佔位式 → 取首值 `Disabled`
  —— **與條文所令之值相反**。

  **此為 R-VF82 所述之形態：一個放寬造出的假資料缺陷，
  且偽裝成一個看似合理之佔位式 TC。** 本層之錨點未覆蓋此側。

  修訂後須依 **R-VF82** 回報：回收數／新增誤判數，
  並附一個「原應不命中而放寬後可能命中」之實例。
  **57 條佔位式須全數以修訂後之抽取式重測**，其中因此而不再屬佔位式者具名。
```
