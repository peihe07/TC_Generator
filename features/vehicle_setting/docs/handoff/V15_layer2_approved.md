## 1. 覆核結論：**核可**。分析層之錯一件

### 1.1 錯 —— V13 §1.3 誤將 W-VF13 判為「全項結案」

V13 §1.3 逐字：「W-VF13 之改名部分至此結案；其 `ANOMALIES.md` 舊制標記部分
已於上繳 V10 §4 補齊。**W-VF13 全項結案。**」

**該判斷為錯。** W-VF13 之範圍含 V04 §3.1 之**裁決條文改號**
（R-VS59–R-VS67 → R-VF1–R-VF9），該部分自始未執行。
本層僅驗了檔名與 anomaly 標記二項，**即以「全項」結案** ——
其形態正是本層自己所立之檢查表原則所禁：
**「通過條件應寫成『與參照對象在所有可讀屬性上一致』，而非『已知的幾項正確』」。**

A-VF10 因而得以在被具名三包後仍無人排入。**責任在本層。**

### 1.2 具名嘉許三處

1. **檢查二之「必不命中」錨點失敗，而執行層判其為真違反而非錨點有誤。**
   此判斷之方向正確且不易 —— 錨點失敗時，最省事之解釋永遠是「錨點選錯」，
   而本輪之正解是「現行狀態確實違反」。**A-VF10 由此浮現。**
2. **未以任何方式抑制該失敗**，並具名其副作用（其他檢查之通過會被遮蔽），
   明言「抑制即回到 A-VS106 之形態」。**知其為副作用而不掩蓋之。**
3. **W-VF36 第 3 項不以 1–4 之結果推及 5／6，實測後得反例** ——
   SWITCH 5／6 完全無「HMI 送出」需求。若當初推及，該差異永不會被發現。

  **二、歷史包不追改** —— `docs/handoff/`／`docs/upstream/`／`docs/reports/`

## 4. R-VF46 —— 檢查點須逐項報告，一項失敗不得遮蔽其餘

```
R-VF46（共用檢查點之報告形態，分析層裁定 2026-08-23）

`grade_overrides.py --check` 現含多項檢查（覆寫四欄、R-VF23 檔名、
R-VF10 編號唯一性）。A-VF10 使編號檢查恆為失敗，
**其後果為其餘各項之通過被單一 exit code 遮蔽**（上繳 V14 §5 第 1 項）。

**不得以抑制、跳過、白名單解決** —— 抑制即回到 A-VS106 之形態
（驗證機制之失效不會報錯）。

**改以報告形態解決**：
  1. **各項獨立執行並各自輸出結果**，一項失敗不中止其餘。
  2. 輸出末尾列各項之 PASS／FAIL 總表。
  3. 整體 exit code 仍為「任一失敗即非 0」——**閘不放寬**。
  4. **已知且已登記之失敗**（現為 A-VF10）於該項旁標其 anomaly 編號，
     使讀者可分辨「新失敗」與「已知未解」。**標記不改變其 FAIL 狀態。**

**理由**：檢查之價值在於區辨。一個恆為 FAIL 之總結，
與一個恆為 PASS 之總結，其區辨力同樣為零。
```

## 6. R-VF42 之結構性修補

上繳 V14 前言：V13→V14 亦未經上繳即續發，**與 V11→V12 為連續兩例**。

**成因非疏忽，是條文與另一義務相衝突**：Pei 於聊天中裁定時，
本層負有「裁定未落檔即未發生」之義務，須即刻成包；
而該包之前並無上繳可讀。**R-VF42 與落檔義務在此互斥。**

```
R-VF42 但書（分析層裁定 2026-08-23）

R-VF42 第 4 項之拘束**限於含工單之下放包**。

**純裁定落檔包**（只記 Pei 之裁定與其條文、不新增工單者）
不受其拘束 —— 其存在理由為「裁定未落檔即未發生」，
該義務優先於往返節奏。

純裁定落檔包須於首段標明「本包不含工單」；
其後之第一個含工單下放包，須依 R-VF42 第 4 項
明列該純裁定包之條文是否已落檔。
```

**V13 應為純裁定落檔包**（其記 Pei 之「一是／二 搬好了」與 R-VF40），
**惟其含 W-VF33／W-VF34 二工單，故仍屬違反。** 本層記之。
