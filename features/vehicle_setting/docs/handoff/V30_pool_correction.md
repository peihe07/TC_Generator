## 3. R-VF81 —— 「取最大 raw」不認可

```
R-VF81（未指名值時之分區選法，分析層裁定 2026-08-24）

上繳 §5.1 之自訂法「取該訊號 DBC 值域之最大 raw 為被驗分區」**不認可**。

**理由即其自身之實測分布**：所取標籤為
`On 7／Battery 3／Enabled 2／**False 2**／其餘各 1`。
**條文之動作為 `chooses to enable` 而被驗值為 `False`，其語意相反。**
「最大 raw」與條文之動作語意無任何對應關係，**其命中 `On` 七次為巧合**。

**改為**：

  一、**依條文動作動詞之語意取值** ——
      `enable`／`turn on`／`select` → 取標籤語意之肯定側
      （`On`／`Enabled`／`True`／`Active` 等）
      `disable`／`turn off` → 取否定側
  二、**語意側之判定以 DBC 標籤逐字為據**，不以 raw 值之大小為據。
  三、**無法對應者**（標籤非二元語意，如 `Battery`／`Auto`／`Max`）
      → **標 `PENDING: DR-{n}`**，不取任一值。
      其 DR 詢「條文未指名值時，該訊號應送何值」。

**23 條須依本條重做**，逐條回報其所屬之一、二、三類與所取之值。
**已複核之「無 `SNA`／`Not_Used`／`Invalid`／`Reserved` 被選為被驗分區」
一項保留**，其為必要而非充分。
```

## 4. R-VF82 —— 放寬判準須同時檢驗假陽假陰

```
R-VF82（判準放寬之連帶檢驗，分析層裁定 2026-08-24，採納上繳 §8）

**凡放寬一項抽取或比對判準以提高涵蓋率者，須同時檢驗其是否引入
假陽性或假陰性**，並回報放寬前後之二數（回收數／新增誤判數）。

**成因**：為涵蓋含空格之值而允許 `[.,]` 收尾，
致 `LATCHING and send the signal to IPC within.` 整句被吞為「值」，
**42 條之值因而對不上 DBC，其失敗形態偽裝成「條文之值不在 DBC 值域內」**。
**一個放寬造出的假資料缺陷。**

**其危險在於偽裝**：放寬之副作用不呈現為「錯誤」，而呈現為
「另一類看似合理之缺陷」，**故不會被任何檢查攔下**。

**與 R-VF21 之錨點互補**：錨點驗判準是否漏（假陰），本條驗判準是否溢（假陽）。
**放寬之提交須附一個「原應不命中而放寬後可能命中」之實例並實測之。**
```
