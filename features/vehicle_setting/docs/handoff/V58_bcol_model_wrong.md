## 3. 乙 —— 閘之保守性不因「理由不精確」而放寬

```
R-VF-乙（閘之修正界線，分析層裁定 2026-08-25，採納上繳 §三）
【落檔取實測最大 +2】

**一個閘若以不精確之理由得出正確之停手，其不得為「使理由精確」而放寬。**

**判準**：修正一個閘之前，須先問
**「修正後，本次所攔下者是否仍會被攔下？」**

438 列將寫入一個 B 欄滿是公式之工作簿，且無人會知。**

**執行層之處置（不修，並於腳本內具名此設計）正確，予以追認。**
```

## 5. 分析層本輪之錯

**V55 §2 之「VF230 用到而值域相異者 0」為誤，實測 1。**

其成因為本層之量測方式：以 `{**oB[2],**oF[2]}` 將二本 DBC 之 `VAL_` **合併為單一字典**，
**遂使同名訊號之跨匯流排歸屬被覆蓋** —— 新舊二側之合併順序若取到不同來源，
其差異即被抹平。

**執行層之方式（以 `(MSG, Signal)` 對逐條解析）正確，本層之方式有結構性缺陷。**
**`LanguageSelection` 少 `22: Slovenian` 影響 seq 546（`Language-062`）之
`input_test_data`，已於換本後之重生成中修正。**
