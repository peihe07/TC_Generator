## 1. 三處具名嘉許

1. **A-VF27 —— 錨點在為它該攔的缺陷背書。**
   `max_row=800` 之截斷使 `AUX_Switch_Types`（列 911）與
   `Blindspot_Trailer_Detection`（列 810）判為「不在表內」，
   **而該二者正是「必不命中」與「鑑別」錨點** ——
   **其每輪通過，而通過本身即缺陷之產物。**
   執行層之通則採納為 R-VF84。並自承同一錯誤本輪犯了兩次（新腳本複製了 `max_row=800`）。
2. **A-VF28 —— 自動換訊號之撤回。** 首版於值對不上時改取「同條文內值域能容納該值之

   偷換為 `Trail_Num_Req`。**其由人讀「回收者」發現，錨點射程不及。**
   **「一個放寬可以同時含二種副作用，而錨點只對得上其中一種」** —— 記之。
3. **§6-2 之句界比對 61／61 全符**、**§8 第 3 項自承 `PLUMBING` 列舉之
   「應刪而未刪」側未測** —— 二側之區分明確，未以一側之通過代表兩側。

## 2. R-VF83 —— R-VF81 修正：訊號上行型不適用第三款

```
R-VF83（R-VF81 之射程更正，分析層裁定 2026-08-24）

**R-VF81 之三款係以「訊號送出型」為模型所寫** ——
其第一款以顧客動作動詞（`enable`／`disable`）判語意側。

**訊號上行型之刺激來自 HW，顧客不執行任何動作，其條文本就無動作動詞** ——
**故第一款對該形態恆不適用，第三款遂恆成立。**
實測命中 128 條（上行型 100／送出型 28），**佔選池逾兩成，且使上行型形同停產**。
**該結果非本層之立法意圖，為條文射程未經檢驗之後果。**

**一、`R-VF81` 第三款之適用範圍限縮為「訊號送出型」。**

**二、訊號上行型之未指名值，改依 canon §8.4.1 之佔位形式處理**：

  canon §8.4.1 逐字允許 `<configured limit>`／`"value defined in spec"`
  之佔位式。**自 DBC 之既載值域中取一代表值，非造值** ——
  造值者為「宣稱條文指定了該值」，非「取用一個來源已載之值」。

  處置：
    `input_test_data`  逐字列出該訊號之 **DBC 有效值域全集**
                       （排除 `SNA`／`Not_Used`／`Invalid`／`Reserved`）
    `test_procedure`   取列舉之**首值**為代表值，逐字書寫
    `reasoning`        **具名「條文未指定所收之值；值域取自 DBC，
                       本條驗其代表值」** —— 此句為必要，缺之即為造值

  **不得**以 raw 之大小為選法（R-VF81 二之理由不變）。
  **不得**生成刺激值與斷言值皆為 PENDING 之空殼 ——
  執行層之判斷正確（「其可執行部分為零，與未生成不可分辨」）。

**三、100 條解除隔離**（送出型之 28 條**維持隔離**，其第一款適用而無語意對應）。

**四、pilot #2 之 seq 264／265 不動** —— 執行層之處置正確，
且依本條其書寫方式為適法。**R-VF81 未回頭否定任何已核可之交付物。**

**五、DR-39 維持開立** —— 其詢「條文未指名值時該送何值」仍為真問題；
本條為其覆文到達前之可執行處置，非其替代。
```

## 3. R-VF84 —— 錨點之二則補強

```
R-VF84（錨點之獨立確認與不符時之處置，分析層裁定 2026-08-24，
採納 A-VF27／A-VF28）

**一、「必不命中」錨點須獨立確認其不命中之原因。**

  一個「必不命中」錨點若其不命中之原因未被獨立確認，
  **它可能只是在複述缺陷**。須驗其不命中係「因資料如此」，
  而非「因讀不到／範圍未及／正規化吸收」。

  **確認之方式**：於**不經被驗程式之另一路徑**上證實該標的確不存在
  （直接開原始檔搜其逐字名、或以不同工具重讀全表）。

  **成因**：`AUX_Switch_Types`／`Blindspot_Trailer_Detection` 二錨點
  之「不在表內」全來自 `max_row=800` 之截斷（實在列 911／810）。
  **該二錨點每輪通過，而通過本身即缺陷之產物。**

  **推論之範圍**：本條及於**全庫所有現行之「必不命中」錨點**，
  非僅 PROXI 一處。其逐一複驗列為 W-VF71 第 5 項。

**二、比對不符時，不得改取他標的以消解不符。**

  值與值域不符、名與表不符者，**其處置為登記並回報，不得改取
  「能容納該值之另一訊號／參數」**。改取即換掉了條文明寫之驗證標的，
  **產出驗錯對象之 TC**。

  實例：`TrailerBrakeType032` 之條文明寫 `Trail_Brk_Type_Req`，
  自動換訊號機制改取 `Trail_Num_Req`（其值域含 `One`），
  **產出四條驗錯訊號之 TC**。

  **與 A-VF28 之教訓同源者亦適用**：`Greeting_Light` 與
  `GreetingLightsEnable`／`_Req` 之名近，**不得以名近推定其對應**
  （執行層本輪已依此自持，正確）。
```

## 4. R-VF85 —— 停止宣告批數與完成期

```
R-VF85（進度數之發布，分析層裁定 2026-08-24，採納上繳 §8 第 2 項）

母體之可寫數本輪為第三度變動（574 → 497 → 376），
**三次皆因本層之量測精進而非因資料變動。**

**故：在 DR-34／37／39／40 有答之前，不宣告任何批數與完成期。**

**改以逐輪回報三數**，不外推、不換算為期程：
  已生成並通過覆核之條數 ／ 現行可直接書寫之條數 ／ 隔離之條數（附其待解之 DR）

**理由**：一個每輪都在變的分母，其上之批數與排程皆不可信；
**而排程一經宣告即成為壓力來源，其壓力作用於量測之精進，方向相反。**

本條不影響批量（50 條／批）與上繳節奏（3 批一次），二者為作業參數而非承諾。
```
