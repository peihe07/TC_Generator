## 4. R-VF58 —— 理由被更正者，結論須重新檢驗

```
R-VF58（條文理由與結論之連動，分析層裁定 2026-08-23）

**凡一條條文之理由段被更正或其所依據之條文被撤回者，
須重新檢驗其結論是否仍成立** —— 不得以新理由替換舊理由而逕予保留結論，
除非新理由**本身**足以支撐該結論之處置強度。

**檢驗須明寫於更正之處**：新理由所能支撐之處置強度為何、
原結論是否落在該強度之內。

**成因（本層之實例）**：R-VF50 之閘立於「寫出不屬本 feature 之 TC」
（嚴重、不可於審查中察覺）；該前提被撤回後，本層於 V18 §2 一
改以「不易被辨識」續撐同一結論，**而未檢驗該新理由是否撐得起
『停止全部生成』**。實際上撐不起 —— 見 R-VF56。

**此形態難以自察**：更正理由時，注意力在「理由是否正確」，
而非「結論是否仍被支撐」。**故須為明寫之步驟，不倚賴自覺。**
```

## 5. W-VF53 — pilot 批生成（**本輪唯一之生成工單**）

### 5.1 範圍

依 R-VS58 之選池序（P0→P1→P2；同序內逐 Test Set 輪流 ＋ reqid 升冪），
自池首取 **10 條**。池為 621（627 − W2 6）。

**生成前先回報該 10 條之 leaf id、Test Set、Priority 預判**，
供對照；**回報後不待核可，逕行生成**（一批一上繳，覆核於上繳後）。

### 5.2 生成之約束

- **寫回仍凍結**（R-VF26）。產出落 `generated/`，**不進工作簿**。
- **B 欄續號自 238 起**（R-VF1，現以 `R-VS59` 落檔 —— **VF230 線**，
  非 Part 1 之同號條）。本輪不寫回，故該欄僅記於產出，不落工作簿。
- `not clear` 之 leaf 依 **R-VF15** 於 Remarks 逐字轉錄
  （**於 TC 書寫時履行**，非回溯編輯 —— R-VF26 二）。
- W1 之 28 leaf 標 `PENDING: DR-34`；W2 之 6 leaf 不入池。
- 值域來源依 R-VF13 之鏈序（LID → DBC → PROXI → VC/VM），
  **每條 TC 之 `reasoning` 具名其值域來源**。

### 5.3 pilot review 之升級條件（依 charter，下放包須明列）

**下列任一項出現即升 chat 覆核，不於執行層自行調和**：

1. `test_item` 缺括號下半（測試目的／區辨手足之標籤）
2. 訊號記法偏離 R-1 v2（`Send CAN: MESSAGE.Signal = 值 (DBC VAL_標籤)`／
   `PROXI $Param$ = "值"`／Input Test Data 為 `NA`）
3. 出現 `PENDING: DR-{n}` 以外之空欄或以 `NA` 充當未知
4. `specification_reference` 之格式或缺漏
5. Test Set 值不在已鎖之 9 名內（framework 已鎖，R-VF44）
6. 任一 leaf 之畫面層敘述無素材來源可指

**其餘發現依 canon §1.2 先分類**（defect／style-divergence／note），
**reviewer 之發現須通過 done-region check 方成為 defect**
—— 惟 VF230 兩本工作簿之 done region 皆為空集合（V05 §4.4 實測），
故**風格權威沿用 Part 1 已鎖者**（SWC 0708、R-1 v2），不另議。

### 5.4 不得為之

**不得生成第 2 批。** 一批一上繳，前批未覆核不得開下批。
