## 1. 三處具名嘉許

1. **§1.1 —— 錨點在為它該攔的缺陷背書。**
   `AUX_Switch_Types`（列 911）與 `Blindspot_Trailer_Detection`（列 810）
   為 PROXI 之「必不命中」與「鑑別」錨點，**二者實皆在表內，
   其「不在表內」全來自 `max_row=800` 之截斷**。
   **該二錨點每輪通過，而其通過正是缺陷之產物。** 已換錨點並具名理由。
   **且自承同一錯誤本輪犯了兩次**（新腳本一開始也複製了 `max_row=800`）。
2. **§3.1 —— 逐條人讀「回收者」而發現 A-VF28。**
   自動換訊號機制把條文明寫之 `Trail_Brk_Type_Req` 偷換為 `Trail_Num_Req`，
   **產出驗錯訊號之 TC（4 條）**。其由 leaf 名與所取訊號名之不符發現，
   **不由任何檢查發現** —— R-VF82 之錨點驗「值之邊界」，換訊號在其射程之外。
3. **§8 第 6 項 —— `Greeting_Light` 不以名近推定對應。**
   DBC 有 `GreetingLightsEnable`／`_Req` 二訊號，
   **執行層明言「二者之對應未經來源證實」而維持 W1** ——
   引 A-VF28 之教訓（以推測消解不符即為換標的）。**同輪之教訓於同輪被援用。**

## 2. R-VF83 —— 「必不命中」錨點須獨立確認其不命中之成因

```
R-VF83（錨點之成因確認，分析層裁定 2026-08-24，採納上繳 §1.1）

**一個「必不命中」錨點，若其不命中之原因未被獨立確認，
它可能只是在複述缺陷。**

**故：凡「必不命中」錨點，須另以不同路徑確認其「不命中」係因**
**資料如此，而非因讀不到、抽不出、範圍未及。**

  確認之形式：不經被測程式，直接於來源檔實測該標的之不存在
  （如逐頁掃 PROXI 全表、或以獨立腳本計其總列數並與被測程式之讀入數比對）。

**其失效不可由該錨點自身發現** —— 錨點通過，而通過即缺陷之產物。
**A-VS106 家族之第七例，且為最隱蔽者**：前六例為「檢查不會失敗」，
本例為「檢查會失敗、但其通過之理由是錯的」。

**連帶要求（讀入完整性）**：凡程式讀取外部表格者，
**須回報其實讀列數並與該表之總列數比對**，不符即停。
`max_row`／`nrows`／`head` 之類硬編上限，**一律視為缺陷候選**。

**R-VF82 之射程更正**：一個放寬可同時含二種副作用，
而錨點只對得上其中一種（A-VF28：錨點驗值之邊界，換標的在其外）。
**故放寬之提交除錨點外，須逐條人讀其「回收者」** ——
回收物之標的是否仍為條文所指者。
```

## 3. R-VF84 —— R-VF81 三維持；seq 264／265 隨 128 條隔離

```
R-VF84（R-VF81 三之射程確認，分析層裁定 2026-08-24）

R-VF81 三之實測射程為 **128 條**（訊號上行型 100／送出型 28），
遠大於其成文時所設想之 23 條。**其射程不改，條文維持。**

**理由**：R-VF81 三之立法目的為「不以任意規則造值」。
訊號上行型之條文既不含動作動詞、亦未載值，
**其被驗值於任何來源皆無據 —— 該狀態即為真實狀態**，
128 條之隔離是對它的正確描述，非條文之副作用。

**一、128 條隔離認可，不生成全欄 PENDING 之空殼。**
執行層之理由正確：「刺激值與斷言值皆為 PENDING 之 TC，
其可執行部分為零，與未生成不可分辨」。

**二、pilot #2 之 seq 264（`Susp_Tire_Jack`）／seq 265
（`Trailer_detection_blind_spot`）隨 128 條一併隔離**，
**不予保留。**

執行層之處置為「不動已核可之交付物」，**本層不採**：
  - 該二條之值係由「最大 raw」所取，**而該法已由 R-VF81 判為不認可**
  - 二條未寫回、未 tag，**依 R-VF24 不屬「已交付」**，R-VF14 之不回溯不適用
  - **保留一個已知為造值之 TC，其代價高於撤回二條 pilot 條**

pilot #2 之 verdict 不因此撤回 —— 其所驗者為書寫形式，
**形式仍成立，僅該二條之取值依據被後出之條文否定。**
pilot #2 之有效條數記為 **8／10**，於 `framework.md` 之註記處具名。

**三、訊號上行型之停產為真實狀態，不以造值掩蓋。**
124 條中 100 條上游未指明值 → 每批僅餘 1 條。
**其為上游之規格缺口，非本層之能力缺口**，故：
  - 不放寬 R-VF81 以恢復產能
  - **升級為交付範圍問題**，見 §5
```

## 5. 給 Pei —— 一項升級為交付範圍問題

**訊號上行型 124 條中 100 條，上游未指明應注入之訊號值。**

其形態：條文僅稱「HMI 評估該訊號以決定可用性」，
**未載值、亦無顧客動作可據以推其語意**。故其被驗值於 LID／DBC／PROXI／
條文四來源皆無據。

**此非技術問題，是 SWE.1 之規格缺口**，且其量級為
**可寫母體之四分之一**（100／376＋100）。

**DR-39 之送出為現階段最實質之一件** —— 其解出即回收約 100 條。
現未送出者：DR-34／35／36／37／38／39／40 **共七件**。
**DR-37（46 條）與 DR-39（100 條）二者合計 146 條**，
即現行可寫母體 376 之 39%。

**寫回解凍**（R-VF26）於量產完成後即需，現不阻塞。
