## 1. 驗收錨點 (a) —— 措辭是分析層的錯

16 包 §3 之錨點寫：

> 自 `lid_pairs.tsv` 讀回 `ESS_ENG_ST` 之 `fmt` 欄，
> **須切得 11 個鍵值**（`4 bit signal` 行 ＋ 1~9 ＋ `F = SNA`）

**括號內列舉的是 11 個「條目」，正文卻寫「11 個鍵值」——
分析層在同一句裡把兩個量混為一名。**
`4 bit signal` 是位元寬宣告，不含 `=`，不是鍵值對。

執行層之處置正確：未改解析器湊數（那會造出不存在的鍵）、
未逕行改寫錨點，**兩個數字都量出來報**（條目 11／鍵值對 10）。

```
W-27(a)′（錨點措辭更正，取代 16 包 §3 之 (a)）
自 lid_pairs.tsv 讀回 ESS_ENG_ST 之 fmt 欄，還原逸出後：
    條目數 = 11（`4 bit signal` ＋ 1~9 ＋ `F = SNA`）
    鍵值對 = 10（`4 bit signal` 不含 `=`，非鍵值對）
壓平則條目數為 1。**該錨點之實質目的為證明換行未被壓平，
以「條目數 = 11」判定；鍵值對數為附帶量，不作判準。**

通則：**驗收錨點須指明所量之量名**（條目／鍵值對／列／字元），
不得以「個」概括。同一句內出現兩種量者，以正文之量名為準，
括號內之列舉不得與正文之量名不同類。
```

## 2. §2.2 之發現 —— 分析層獨立複驗，成立且更強

執行層指出 LID `Format` 之位元寬宣告行**本身帶資訊**。
分析層自 `inputs/` 原始儲存格複驗（不正規化，按 `\n` 切）：

| LID | 條目 | 內容 |
|---|---|---|
| `HeatedSeatFL` | 10 | `ATLANTIS` / **`2 bit signal (FL_HS_STATSts)`** / `0=off` `1=low` `2=medium` `3=high` / 空行 / **`1 bit signal (FL_HS_STATFailSts)`** / `0=Fail_Not_Present` `1=Fail_Present` |
| `VentedSeatFL` | 9 | `STATFailSts` / `0=Fail_Not_Present` `1= Fail Present` / 空行 / `STATSts` / 四階 |
| `FL_HS_RQ` | **2** | `0 = Not_Pressed` / `1 = Pressed` —— **無位元寬宣告** |
| `FR_HS_RQ`／`FL_VS_RQ_TGW`／`HSW_RQ_TGW` | **2** | 同上 |

**LID 表自身內部一致**：狀態訊號 2 bit 四階、失效 1 bit 二值、
**請求訊號二值且無階**。與基線 DBC 之 `1 bit` ＋ `Not_Pressed/Pressed` 完全相符。

→ **DR-15 之性質更精確**：不是「LID 與 DBC 分歧」，
而是 **CFTS044 單方對請求訊號賦予階數**，另兩個來源一致地說它是二值。
執行層已補入 `DATA_REQUESTS.md`，正確。

**順帶登記 A-VS31**：`VentedSeatFL` 之 Format 內
`1= Fail Present`（缺空格、且 `Fail_Present` 之底線遺漏），
與 `HeatedSeatFL` 之 `1 = Fail_Present` 不一致 —— LID 表之轉錄品質問題，
**足以使字面比對誤判為不同值**。RD-1 FYI 類。

## 3. C4 之不可分辨 —— 補判準（**本包之主要產物**）

執行層 §6.2-2：

> C4 = 8 之判準為「單向子集」—— 若某來源真的漏列一值，亦為單向子集。
> **C4 與「真漏列」在現行判準下不可分辨。**

該指摘成立，且其影響大於 W-28 之三個錨點所能覆蓋者：
**W-28 驗的是「差異明顯者不被吸收」，而 C4 吸收的正是「差異不明顯者」。**

分析層實測，CFTS044 對窮舉式列舉有**固定措辭**：

| 措辭 | 全文命中 |
|---|---|
| `Valid values for the` | **49** |
| `All other states shall be considered invalid` | **48** |
| `shall be considered invalid`（含上者） | 61 |

其架構分布（逐條文區塊取 `[EE Architecture]`）：

```
CUSW 19／PowerNet 14／PowerNet, Atlantis High 5／
Atlantis High, PowerNet 4／Atlantis High 6
```

即 **in-scope（含 Atlantis High）者共 15 條**。

```
R-VS27（C4 之補判準，待 Pei 裁）
歸因類別 C4（規格引用子集）不得單以「CFTS 側為他來源之真子集」成立。
須加一項必要條件：

  C4 成立 ⟺ 單向子集 **且** 該值域所在之 CFTS044 條文
            **不含窮舉宣告**

窮舉宣告之判準（字面，區分大小寫）：條文內含
    `Valid values for the`
  或 `All other states shall be considered invalid`

若條文**含**窮舉宣告而其值集合仍為他來源之真子集 →
**不歸 C4，一律進待判**，並登記為疑似真漏列。
理由：窮舉宣告是規格作者對「這就是全部」之明示；
在其之下的子集不是引用，是矛盾。

配套：C4 之輸出須附 `exhaustive_marker` 欄（true／false／not_found），
`not_found` 者（無法定位其來源條文）**亦進待判**，不得預設為 false。

實測基數：CFTS044 全文 `Valid values for the` 49 處、
`All other states shall be considered invalid` 48 處，
其中 in-scope（含 Atlantis High）者 15 條。
```

**此條直接影響 DR-15**：`4857940`（`$HeatedSeatFL$` 三階）之條文
**含窮舉宣告**，但其架構為 CUSW，依 R-VS19 本就不取 ——
故 DR-15 不因本條改變。**但 in-scope 之 15 條須逐條檢查其值集合是否為子集。**

|---|---|---|

**W-27 兩度成為頭部並各自用掉整輪**。本輪已證 W-27 確為 W-22 之前置
（16 包 §3 之裁定正確），但代價是 W-9 又延一輪。

```
R-VS28（積壓之硬性出清，待 Pei 裁）
```

**分析層評估其代價可接受**：W-9 為 R-VS7 委派句之來源表，
且為 framework 之前置；W-22 雖為最弱一環，但其標的（三式是否窮盡）
在 R-VS27 立條後判準已變，**延一輪反而使其在新判準下執行**。
