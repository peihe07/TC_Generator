## 6. 條文增補三處

### R-VF28 —— R-VF21 增第 4 項：定錨以內容，不以行號

```
R-VF28（R-VF21 之增補，分析層裁定 2026-08-23，採納 A-VF6）

R-VF21 增列第 4 項：

  4. **判準之覆寫、例外、錨點一律以「內容」定錨，不以行號。**
     鍵為 `(檔, 內容片段)`，非 `(檔, 行號)`。

**行號是位置，內容才是識別。** 位置隨任何一次編輯而移，
而其失配**不會報錯** —— 覆寫靜默失效，該項遂由「不改」改判為「須改」。

實例（A-VF6）：R-VF22 施行使 `feature.yaml` 之 `388/619` 由 118 移至 119，
逐行覆寫鍵失配，該行靜默改判。同一次重跑中，
另一錨點因 R-VF21 第 1 項（存在性先驗）而正確停下 ——
**同一機制，一項被察覺、一項未被察覺，差別即在定錨方式。**
```

### R-VF29 —— R-VF20 增第 5、6 項：註記不累積、檢查面等於變更面

```
R-VF29（R-VF20 之增補，分析層裁定 2026-08-23，
採納上繳 V08 §4.2 與 §8 第 4 項）

R-VF20 增列：

  5. **覆寫之註記須依清單單一來源重生，不得以文字比對去重。**
     重跑 N 次後註記筆數須與 N 無關。
     （成因：新舊腳本之註記措辭不同，文字去重失效，`-030` 曾出現兩筆。）

  6. **`--check` 之涵蓋面須等於 `--apply` 之變更面。**
     `--apply` 改 `writable`／`blocker_class`／`blocker_detail` 三欄，
     而 `--check` 僅驗 `writable` —— **檢查面小於變更面即為缺口**：
     driver 重跑後 `blocker_class` 回復為 `B6-value-absent` 而 check 不察。

**通則**：凡「施行 + 檢查」成對之機制，檢查之涵蓋面須以施行之變更面
逐欄列舉並比對，不得以主要欄位代表全部。
```
