## 1. R-VS80 —— 產物之變更須產新版

48 輪之就地改動涉五檔，**未產新版、未更新 `revision`**，
致該層不存在於任何記錄，`REGEN_ORDER.md` 之鏈缺它。

**該改動係我所令**：75 包 D-3 令「`delivery_disclosure.md` 依 R-VS69 重列」，
**而我未令其變更須產新版**。產物因此正確，產生路徑因此斷了一節。

```
R-VS80（分析層裁定 2026-08-24）
`generated/` 之任何檔，其內容一經寫出即為定版。
後續之任何變更，一律產新版檔（`_v{n+1}`）並於其 `revision` 記其作業號與
所依條文；**不得就地改動已定版之檔**。

適用範圍及於**單一欄位之修正**（如 `screen_pending`、`dr_dependent` 之重標）
—— 其亦為變更。

**下放包之措辭亦受本條拘束**：凡令「依某條文重列／重標／同步」者，
須明言其產出為新版，否則執行層之就地改動即為該措辭所誘。

理由：R-VS53 令產物可自 repo 重現；就地改動使該層不存在於任何 `revision`，
鏈因而缺節而**其缺不可見** —— 本輪查得出是因 48 輪之 commit 恰留了前後兩版；
若那次未入庫，該缺口永久不可見。

A-VS162 依本條登記。
```
