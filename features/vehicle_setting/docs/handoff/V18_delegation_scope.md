## 2. R-VF53 —— R-VF50 之理由段更正；委派閘維持，範圍補足

```
R-VF53（R-VF50 之更正與委派閘之範圍，分析層裁定 2026-08-23）

**一、理由段更正。** R-VF50 之「後果不對稱」段落中，
「漏判委派 → 寫出本不屬本 feature 之 TC，違反 canon §8.2.1／§8.4.2」
**應更正為**：

  漏判委派 → **該 leaf 之畫面層內容取自錯誤之素材來源**

  誤判委派 → 該 leaf 之畫面層來源取自他 feature 而實應取自本 feature

**不對稱性因而減弱，但閘不撤銷** —— 其理由改為：
畫面層之來源錯誤**不會在生成時報錯，亦不易於 pilot review 中被辨識**
（reviewer 讀到的是一段看似合理之畫面敘述），

為 B 欄續號條（R-VF1）。**A-VF10 之撞號於本條再度生效**，

**其中已有 037 素材者方能比對**；無素材者具名為「無法比對」，
**不得以「推定無關」代替**。
```

## 4. R-VF55 —— 「不可精確化」與「成本高於收益」須分列

```
R-VF55（殘留誤報之分類，分析層裁定 2026-08-23，
採納上繳 V17 §6 第 4 項之自我判斷）

執行層自承：「『不可精確化』與『精確化之成本高』為兩件事，
本層將二者並列於同一表 —— 後者實為選擇而非限制。」**該判斷正確。**

**凡具名殘留誤報者，須分列為二類，不得混列**：

  **甲、結構性不可精確化** —— 其形態在語法上與真陽性不可分辨，
       無論投入多少成本皆無法區分。須具名其結構性理由。
       **此類為判準之已知盲區，須登錄於 `CROSSLINE.md` 或等效之可見處。**

  **乙、可精確化而未為之** —— 成本高於當下之收益。
       須具名**其精確化所需之工作**，並列入待辦清單。
       **不得以「成本高」為由使其消失於視野。**

**二者之處置不同**：甲類須被記住為盲區；乙類須被記住為待辦。
**混列使前者被誤認為可解、後者被誤認為不可解。**

本條同時適用於分析層 —— 凡本層具名「暫不處理」者，同受此分類義務。
```

## 7. 待 Pei 裁定：**P0(c) 七簇之確認**

上繳 V17 §6 第 3 項具名：P0(c) 之判定為執行層依 canon §10.2 之 `safety` 所作，
其界線採自 **R-VF51 之建議（分析層所提，非你所裁）**，
**而 P0 直接決定 pilot 批之內容**（R-VS58 令選池 P0→P1→P2，pilot 自池首取）。

**判定結果**：

| 判 | 簇 |
|---|---|
| **P0(c)** | Forward Collision Warning／Pedestrian Emergency Braking or Warning & Active Braking／Blind Spot Alert／Blind Spot with Trailer Detection／Lane Sense Warning／Park Sense／Traffic Sign Warning |
| P1 | Forward Collision Warning Sensitivity／Lane Sense Strength／Park Sense Front Volume／Park Sense Rear Volume |

**界線**：改變「警示**是否發出**」者 → P0（失效使駕駛失去一次警示，
不可回復之單次事件）；改變音量／靈敏度／樣式者 → P1（警示仍發出）。

**鑑別對**：`Forward Collision Warning`(P0) vs `…Sensitivity`(P1)
—— 二名僅差一詞而失效後果不同。

```

```

**請裁**：該界線與七簇之 P0 歸屬是否確認？
確認後 pilot 批之內容即隨之固定；不確認者請具名應調整之簇。
