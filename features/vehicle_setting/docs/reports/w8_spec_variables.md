# W-8 — `$變數$` 三來源對照（CFTS044 ／ DBC ／ LID 表）

產物：`data/spec_variables.tsv`（30 token）。

## 為何這是本 feature 唯一之跨源獨立檢驗

三個來源出自**三個不同上游作者**：CFTS044（需求作者）、
`PDT27_E2A_*.dbc`（匯流排設計）、`Logical Identifiers and CAN Mapping v1.76`（訊號對映）。
其相符不是同源自我印證。

## 掃描條件

| 來源 | 條件 |
|---|---|
| CFTS044 | 原始 docx 之 `word/document.xml` body 段落文字（788,567 字元）。**兩式並用**：<br>式一 `re.escape(token) + r"\s*(?:=\|==\|is\|shall be)?\s*\[([^\]]{1,80})\]"`<br>式二 `(?:路徑\.)?名稱 \| $var$` ＋ `==?` ＋ 引號值（**含 `$var$` 本身為左式之變體**） |
| DBC | 兩份皆掃；`^VAL_\s+(\d+)\s+(\w+)\s+…;` 之值表 |
| LID 表 | `Atlantis High` 之 `Format` 欄優先，空則取 `Atlantis(&High)`；<br>解析式 `(-?[0-9A-Fa-f#]+)\s*[=:]\s*(.*?)(?=\s+-?[0-9A-Fa-f#]+\s*[=:]\|$)` |
| 橋接 | token → LID 表之 signal 名 → DBC。**必要** —— 逐字比對僅 3 個 token 在 DBC 中存在，橋接後為 16（`$HSW_Stat$` 之匯流排名為 `HSW_STATSts`，R-VS9 之依據） |
| 值比對 | `\s+`／`_` 正規化為單一空格、**轉小寫**；剝除 `Nh: ` 編碼前綴；` / ` 切為別名 |

## 過程中修掉的兩個我方缺陷（**先報自己的錯，再報資料的錯**）

| 階段 | 無交集之來源對 | 成因 |
|---|---|---|
| 初版 | **33** | LID `Format` 以逗號切值 —— 而該欄無逗號分隔（`0 = Not Pressed 1 = Pressed`），整串被吞成一個值 |
| 修解析器後 | **7** | CFTS044 側之值帶 `0h: ` 編碼前綴與 ` / 別名` 後綴，與 DBC 之裸值不等 |
| 正規化後 | **1** | ← 真正之不一致 |

**32 / 33 是我的抽取缺陷，不是資料不一致。**
00G §7-4 曾具名警告此形態（「值域字串未解析為結構化鍵值，`0 =`／`0=`／`0 :` 有變體，
須以已知全集驗抽取」）；本輪以五個已知案例驗過解析器後才採用其輸出。

## 盲區（R-G11）

1. **CFTS044 之值域抽取仍只有兩式。** 第三種記法若存在，本報告看不見
   （00B §5-4 之同一聲明）。徵候：`$HSW_StatFailSts$` 之式二只抓到
   `Fail_Not_Present`，而 DBC 與 00B 皆載其另有 `Fail_Present`。
2. **「無交集」為不一致之判準，「有交集」不等於「一致」。**
   例：CFTS044 之 `$HeatedSeatFL$` 有 `0h: off`／`1h: low`／`3h: high` 而無 `2h: medium`，
   DBC 有四階 —— 二者有交集故未列為不一致，**但 CFTS044 側是否漏列 medium 未查**。
3. 橋接依賴 LID 表之 signal 名；**LID 表本身若對映錯誤，三來源會一致地錯**。
