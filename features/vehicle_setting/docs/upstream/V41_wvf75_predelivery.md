## 三、人讀所發現之一項機制缺口（現行後果為 0）

**句界切分 `re.split(r"(?<=\.)\s+", …)` 對「句號後無空格」無效。**

發現於 seq 407 之 `…feature availability.If $Signature_Lighting$ = [Absent]…`
—— `availability.If` 之間無空白，**二句被切分為一句**。

**其後果**：若該處之後接一管路句，`PLUMBING.match()` 只驗合併後之首字元，
**該管路句遂刪不掉**。

**量測（全 437 條）**：
```
`test_item` 含「句號後無空格」者          127 / 437
其中**因切分失效而留下管路句**者          **0**
```

**故：缺口存在而現行後果為零。** 其為**現況**而非保證 ——
條文形態一變即可能非零，**且無任何檢查在管此事**。

**本輪不改**（W-VF75 第 3 項令「不改，只報」；且改切分式將影響全部 437 條之
`test_item`，屬判準變動）。**建議下一包裁示**：
於自檢增一項「`test_item` 補空格後重切，若有句可被 `PLUMBING` 刪去則 FAIL」——
其為**零成本之守衛**（現行 0 命中），而缺之則該缺口之發生無人會知。
