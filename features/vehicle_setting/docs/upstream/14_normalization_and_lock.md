### 2.3 W-50(2) 之初測 4 筆命中，全數是我的正則造成的

初測「反向掃描命中 4 / 16」：`$FL_HS_RQ$`／`$FL_VS_RQ_TGW$`／`$FR_HS_RQ$`／`$FR_VS_RQ_TGW$`
之值中含 `HS_`／`VS_`，而其 token 被判為「無語意前綴」。

**成因**：我以 `\b(HSW|HS|VS)_` 取 token 自身之前綴。
`_` 是詞字元，故 `\bHS_` **無法**在 `FL_HS_RQ` 之中段命中 —— 判成「自身無前綴」。
改為 `(?:^|_)(HSW|HS|VS)_` 後，四者之自身前綴分別為 `HS`／`VS`／`HS`／`VS`，
**與其值中前綴完全相符**。

**真不符 0。若止於初測，會報四筆假污染。**

> 與 15 輪 §2.3 同型（大小寫敏感之過濾器），本輪為**詞界**。
> 兩次皆是「正則之邊界假設」在含底線之識別碼上失效。

## 6. 獨立判斷：本包是否仍有該驗而未驗者 —— **有，四項**

1. **`normalized_key` 欄以 `cfts044_include` 為基係本層之選擇。**
   R-VS39 只說「另增 `normalized_key` 欄」，**未指明以哪一欄為基**。
   `cfts044_exclude`／`cfts044_other_arch`／`lid_values`／`dbc` 之正規化鍵**未入檔**
   （其計數已列於 §1.3，但欄中無值）。若下游以該欄計 exclude 之基數，會取到空值。

2. **R-VS19′(d) 令 `$HSW_StatFailSts$` 之 R-VS20 階梯歸屬重查 —— 本輪未查。**
   D-5 只重算了覆蓋面之五項數字，**未重跑任何 token 之值域階梯**。
   而讀法一／讀法二之差會直接改變第一階之範圍（425 vs 695 條），
   **在 §2.1 釋義前重查也無意義。**

3. **W-51 只對照了 `1.3.1.1.3.*` 四節之**同層左右**兩對。**
   該節族之上位節 `1.3.1.1.3`（Heated/Vented Seat & HSW）本身之條文未看；
   且 `1.3.1.1.*` 其他分節（Hazard Switch、Heated Windshield Washer 等）**未掃**。

4. **W-52(1) 之檔界以「id 首次出現之檔」認定，未驗四檔之 id 集合是否互斥。**
   實測四檔相異 id 為 56／99／81／35 = **271**，恰等於 leaf 總數，
   **故互斥為真** —— 但這是事後由總數推得，**非逐 id 驗證**。
   若某 id 同時出現在兩檔且總數巧合相符，本法看不出來。
