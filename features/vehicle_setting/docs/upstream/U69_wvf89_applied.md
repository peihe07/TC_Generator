## 二、**撤回** —— `H` 非下拉，其為 conditionalFormatting；已還原

**本節之前一版稱「`H` 為 `R-VF139` 未列之第五處下拉，一併延伸」。其前提為假，撤回。**

**實測（逐字取其母元素，非只取 `sqref` 字串）**：

```xml
<conditionalFormatting sqref="H10:H132">
  <cfRule type="colorScale" priority="122">
    <colorScale><cfvo type="min"/><cfvo type="max"/>
      <color rgb="FFFFFFFF"/><color rgb="FF57BB8A"/></colorScale>
```

**其為色階（colorScale）之套用範圍，不是 `dataValidation`。**
`R-VF139` 所列之四處皆為下拉，**`H` 自始不屬同類，「未列之第五處」之說不成立。**

### 2.1 本層之錯在於「取了名而未驗其種類」

前一版之抽取方式為 **`re.findall(r'sqref="([^"]+)"')`** ——
**其取遍全檔之 `sqref` 屬性而不問其母元素為何。**
同一次抽取所得之 `L9` 實為 `<selection activeCell="L9">`（游標位置），
**若其形如區間，同樣會被誤列。**

**其為 `R-VF136` 之同型**：宣稱之範圍大於所驗之範圍 ——
**驗了「有一個 `sqref` 叫 H10:H132」，卻宣稱「有一個下拉叫 H」。**

### 2.2 已還原為 `H10:H132`

**還原之理由不是其有害** —— H 欄之值全為 `str`（相異 9），
colorScale 為 `min`／`max` 型，**文字無數值可映射，延伸與否於顯示上皆無作用**。

**其理由是：該修改之依據已不存在，且交付本 CFTS044 之 H 仍為 `H10:H132`** ——
**留之即在二本間製造一處無理由之差異。**

**還原後複驗**：XML 合法｜`x14dv` 2｜`extLst` 1｜
四處下拉維持 `AF10:AF1000`／`P10:P1000 Q10:Q11`／`T10:Z1000`／`R10:R1000`｜
資料 438 列、B 244–681｜多行而無 `wrap_text` 0。

## 三、Pei 所報之「編號前多空格」—— 根因為 `wrap_text`，非內容

**實測：儲存格之值本身無前導空格。**

```
J10 之值  '1. The HU is in the Full-Operation state'
          '2. FD-CAN8 is connected to the bus simulator…'
          '3. The "Suspension Service Mode" customer setting is set to On'
```

**其成因為 `wrap_text` 未開** —— Excel 遂將換行顯示為空白，
**視覺上即成「`2.` `3.` 前面多一個空格」。**

**修正**：補齊 `wrap_text`，**438/438**，多行而無 `wrap_text` 者 **0**。

### 3.1 樣板於列 10–246 內本身即有 7 格缺

```
L181、M179、M180、M181、M190、M191、M192   其值皆為多行
```

**非本次寫入所致** —— 首版之修法只補列 247–447（樣板容量之外），
**而該 7 格在容量之內卻仍缺**。**已一併補齊，範圍改為列 10–447 之「只補缺者」。**

### 3.2 **此為同一根源之第三處**

```
樣板容量 237 列（列 10–246）  vs  本次寫入 438 列（列 10–447）
  B 欄公式    237 格   → R-VF132 覆寫為硬值
  sqref       123 列   → 本輪延伸至 1000
  儲存格樣式   至列 246 → 本輪補齊至 447
```

**三者皆為「一個依列數而定而寫死於樣板之設定，其過時不會被任何檢查攔下」** ——
**且三者皆非本次寫入所造成，而是本次寫入使其顯現。**
