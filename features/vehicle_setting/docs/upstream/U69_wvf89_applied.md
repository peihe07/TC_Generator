## 二、`H` 為第五處，**其處置超出 `R-VF139` 之字面**

`R-VF139` 明文為 P／R／T–Z／AF **四處**。**實測尚有 `H10:H132`**
（`H` = `Test Set 測試集`，9 種已鎖之值）。

**一併延伸，其理由為該條之立法目的** ——
其逐字：「只改其一則同一份交付本內將有二種驗證範圍……
**其不一致本身即為日後之疑點來源**」。**留 `H` 停於 132 恰為該條所欲避免者。**

**本層具名此為超出字面之處置，待追認。**

### 2.1 `Q10:Q11` 未動，其為刻意

`Q` = `Estimated Test Time (mins)`，**而其被納入 Priority 之 `dataValidation`
（選項 `P0,P1,P2,P3`）** —— 一個「預估測試時間」欄之下拉為 `P0..P3`，
**為樣板之既有瑕疵**。

**延伸之則將一個錯誤之驗證自 2 列擴大至 991 列。** 故維持原狀並具名（交付說明 §六第 7 項）。

## 三、Pei 所報之「編號前多空格」—— 根因為 `wrap_text`，非內容

**實測：儲存格之值本身無前導空格。**

```
J10 之值  '1. The HU is in the Full-Operation state'
          '2. FD-CAN8 is connected to the bus simulator…'
          '3. The "Suspension Service Mode" customer setting is set to On'
```

**其成因為 `wrap_text` 未開** —— Excel 遂將換行顯示為空白，
**視覺上即成「`2.` `3.` 前面多一個空格」。**

**修正**：補齊 `wrap_text`，**438/438**，多行而無 `wrap_text` 者 **0**。

### 3.1 樣板於列 10–246 內本身即有 7 格缺

```
L181、M179、M180、M181、M190、M191、M192   其值皆為多行
```

**非本次寫入所致** —— 首版之修法只補列 247–447（樣板容量之外），
**而該 7 格在容量之內卻仍缺**。**已一併補齊，範圍改為列 10–447 之「只補缺者」。**

### 3.2 **此為同一根源之第三處**

```
樣板容量 237 列（列 10–246）  vs  本次寫入 438 列（列 10–447）
  B 欄公式    237 格   → R-VF132 覆寫為硬值
  sqref       123 列   → 本輪延伸至 1000
  儲存格樣式   至列 246 → 本輪補齊至 447
```

**三者皆為「一個依列數而定而寫死於樣板之設定，其過時不會被任何檢查攔下」** ——
**且三者皆非本次寫入所造成，而是本次寫入使其顯現。**

## 四、施行過程中之二錯，皆於副本攔下

**其一：順序錯。** `fix_styles` 以 openpyxl 存檔，**其again移除 x14 之 `extLst`**，
致其後之 `fix_sqref` 找不到 `<xm:sqref>` 而只命中 3／4。
**已改為「備份原檔 → 改樣式 → 補回 extLst → 改 sqref」**，並於補回後複驗 `x14dv`。

**其二：非冪等。** 樣式與 `sqref` 分二次施行，第二次重跑時 `sqref` 已為 1000，
**首版視其為「命中 0」而停**。**已改為冪等**：已為 `LIMIT` 之形式者記為「已為 1000，未動」。

**二者皆於 scratch 副本發現，正式檔未受影響。**
