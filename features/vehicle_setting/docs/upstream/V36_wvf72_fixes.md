## 二、Defect 1 之成因不是標題 —— 三條 TC 在驗錯對象

V35 §2 判 A 對（seq 293／295）為「實質錯誤而非僅標題重複」，**其判斷正確，
而其範圍更大**。逐條複核 procedure／ER／`reasoning` 後：

| leaf | 條文之實際需求 | 所生之 TC 在驗什麼 |
|---|---|---|
| `PowerTailgate-028` | `The default value … shall be **Enabled**` | 送 CAN 值 → 看顯示 `Disabled` |
| `EnhancedDisplaySynchronization-132` | `provide the **default value** … default as ON` | 送 CAN 值 → 看顯示 `OFF` |
| `TrailerNumber-065` | `treat the received value **as invalid**, shall **not display** … continue displaying the **previously received valid** value` | 送 CAN 值 → 看顯示 `One` |

**三者皆為未經 pilot 之新形態，而被套上「訊號上行型」之模板。**

- 「**預設值**」需求之驗法為**不送任何 CAN 值**而讀開機後之顯示；
- 「**無效值處理**」需求之驗法為**送無效值**而確認顯示**未變**。

二者與上行型（送值→看顯示）之模板**方向相反**。

**`PowerTailgate-028` 另有一重**：條文明寫 `shall be Enabled`，
而 `SIG_VALUE_AT` 未認出該式，遂落入「未指名值」→ R-VF91 二佔位式 →
取列舉首值 `Disabled` —— **與條文所令之值相反**。
**即上一輪 R-VF91 二之放寬引入了一個假陽，而其偽裝成一個看似合理之佔位式 TC**
（`R-VF82` 所述之形態，本輪之錨點未覆蓋此側）。

**處置**：依 `R-VF80` 一「不得以既有形態之書寫式套之」，
四條（另含 `PowerLiftgate/TailgateAlert-021`）**隔離並具名**，待 pilot。
**標題重複只是它的症狀 —— 若只補區辨 token，三條驗錯對象之 TC 會留在交付物內。**

**另二對之標題重複為上游條文逐字相同**（sha1 比對）：
`ParkSense-078/-080`、`AutoOnDriverComfort-103/-104`。
**未造區辨 token 消解之**（造值），保留首條、隔離次條，**開 DR-42**。

## 三、R-VF97 乙 之二例經實測皆與條文相反 —— 未施行，具名待裁

以 zipfile 直讀 `PROXI_HDCC27_R3_20250424.xlsx` 之 shared strings
（**獨立路徑，不經 `proxi_known()`** —— A-VF27 之缺陷正出於它）：

|---|---|---|---|
| `CAN node 82 (PTGM)` | `CAN node 82` ✗ | `PTGM` ✗ | **原樣逐字** |
| `SVC_SK_PRSNT (Surround_View_Camera)` | `SVC_SK_PRSNT` ✗ | — | **括號內** |
| `(SRT)` | — | `SRT` ✓ | 括號內 |
| `[ DRL_Menu_Enable ]` | — | — | 剝方括號後 |

**「別名在括號內」此一前提於本組不成立** —— 形態與識別無對應關係。
照 R-VF97 乙移除 `(PTGM)`，標題所指之參數在 PROXI 表內**不存在**。

**改以資料定之**：逐式試（剝方括號→括號外→括號內→原樣），**首個在 PROXI 表內者為準**。
`pre_conditions` 仍取條文逐字（R-VF78 二），二者不混，依據逐條記於 `reasoning`。

**V35 §3 推定 `$SRT$` 為訊號名，實測其為 PROXI 參數**（表內有 `SRT`）。
故 Defect 2 之處置非「判其為訊號或設定」，而是剝殼後取表內之名。

**另具名一個正規化掩蓋形態差異之陷阱**：候選之序若將原樣排在剝殼形態之前，
`pnorm("(SRT)") == pnorm("SRT")` 使 `(SRT)` 被判為「表內有此形態」而把括號留在標題內。
**`pnorm()` 吸收括號，遂掩蓋形態差異**（R-VF92 一）。已改為剝殼優先、原樣墊底。

## 四、`priority.py` exit 1 之歸因 —— **(i)(ii) 皆非**

V35 §8-6 令判其為 (i) 前輪 staged 內容所致、或 (ii) 選池序再度失真。**實測皆非。**

**(iii) 斷言自身之母數錯配**：

```
L128  dist = Counter(x["priority"] for x in rows)     # 母數 = 全 627 列
L141  pool = [... for x in gen ...]                   # 母數 = 574（W0+W1）
L159  head = [x["priority"] for x in pool[:dist["P0"]]]
```

`dist['P0']` = **88**（自 627 列算），而 `pool` 中之 P0 只有 **82** 條。
斷言遂取 pool 之前 88 條，其第 83–88 條為 P1 —— 即所見之 `{P0: 82, P1: 6}`。

**那 6 條之身分**：`priority = P0` 而 `writable ∉ {W0, W1}` 者，
**其被計入 `dist` 而不入 `pool`**。

**故：選池序是對的（前 82 條確為 P0），錯的是斷言的切點。**
其為斷言之既有缺陷，由 W-VF70 之分級精進（B8／B9）使 6 條 P0 掉出 W0/W1 而暴露。
**依「只查不改」未修。**
