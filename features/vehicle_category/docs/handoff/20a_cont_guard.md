## 二、二層防護

### 2.1 第一層 —— 候選偵測（解風險 1）

續行型與指涉型各有**可機械偵測之表面特徵**：

```
候選判準（對批內每 leaf 之 037 Description）：
  (a) 續行型候選 —— 去除條號前綴（如 `CO2.)`、`S8.1.)`、`VC4.1)`、
      `STN16.)`）後，首字元為小寫字母
  (b) 指涉型候選 —— 去前綴後以代名詞起首
      （It／They／This／These／That／Those）
  (c) 短句候選 —— 去前綴後 < 60 字元（profile §8 之短來源門檻共用）

檢查：候選 ∉ CONT 表 ∧ 候選 ∉ 明確排除清單 → FAIL
```

**排除清單與 CONT 表同格式同處管理**：候選經人工判定為
「表面特徵命中但實為完整可讀句」者，登記於排除清單並附一句理由 ——
使「已考慮過」與「沒看到」可區分。**默默不登記不再可能。**

**偽陰性（明文揭露）**：三特徵之外的形態
（如完整句但省略受詞、指涉以定冠詞而非代名詞承載）偵測不到。
本層之效力為「表面特徵命中者必被考慮」，非「全部此類必被發現」。

### 2.2 第二層 —— 內容驗證（解風險 2）

CONT 表每一條登記之正確性**可機械驗證**：

```
對 CONT 表每條（leaf → SYS1 節）：
  037 Description（去條號前綴、正規化）
    ⊆ substring( 該 SYS1 節之文字（正規化） )
不成立 → FAIL（登記之節指錯，或 037 片段非出自該節）
```

依據：續行型／指涉型之定義即「037 之片段出自 SYS1 之完整句」——
**片段必為其來源之子串**。指錯節則子串關係不成立。

> 正規化沿用第 7b 項之定義（首字母大小寫），另加去條號前綴 ——
> 037 之片段有時帶條號而 SYS1 之句中無（或反之）。
> 前綴樣式表沿用 2.1(a) 之同一張，二處不得分歧（承機讀行之同一原則）。

### 2.3 一次做全表，不逐批發現

候選偵測**首跑即對全 117 leaf**（非僅第 3 批）——
第 4~7 批之此類 leaf **提前現形**，登記或排除一次做完，
後續批次之勘查不再逐批撞見。

分析層之預期（依既往粗查，**不得沿用，以實測為準**）：
第 1 批之 `012-03`／`013-03`（續行）、`013-02`（037 補句號型 ——
**注意：其 Description 首字為大寫 `F`，三特徵皆不命中，屬 2.1 之偽陰性**，
但其已在 CONT 表，不受影響）、第 3 批之 `019-02`（指涉）、
`025-01`／`007-01`／`013-04`（短句，b 段）。

> `013-02` 之例證實了 2.1 之偽陰性是真的 —— 它能在表裡是因為
> 第 1 批勘查之 SYS1 對照抓到，不是特徵偵測。
> **故 SYS1 對照（勘查 (d) 項）不因本層而免除** —— 本層是底網，不是替代。
