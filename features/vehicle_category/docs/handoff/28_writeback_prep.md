## 一、A-VC20 —— R-VC12 二(a) 是用它自己所禁之方法立的

### 1.1 事實

R-VC12 二(a) 裁「§15／§10.1／§10.2 之『內容』欄一律書
『該節內容僅存於圖，SYS1 匯出未帶文字』」。**實測不成立**：

```
§10.1／§10.2 之 SYS1 Description 含
  「Refer to the HMI Settings list for settings location.」
  「All four Aux switches (Aux 1 Aux 2, Aux 3, and Aux 4) can be used simultaneously」
```

第二句是**可讀、可測的需求敘述**。

### 1.2 這件事的難看之處

R-VC12 之立條理由，是我在下放包 06 §一自認的第二次同類錯誤 ——
**「以衍生 PDF 之判讀充當實測值」**。而它的二(a)，
**正是用同一個衍生 PDF 判讀寫出來的**：我當時看到那三節在 PDF 裡只有圖，
就寫成「SYS1 匯出未帶文字」，**從未去讀 SYS1 那三格**。

**一條為了糾正該錯誤而立的條文，其本身有一款是該錯誤的產物。**
而它此後被引用了 24 個包，包括寫進表 B 草稿 —— 表 B 之用途是揭露落差，
那一列**把一句需求敘述整句藏起來**，反向作用。

執行層 §2.4 之定性精確：與 REV-14 同族，
**差別在 REV-14 是台帳寫對而沒人讀，本次是台帳本身就寫錯了**。

### 1.3 修訂（逐字抄入 `RULINGS.md`）

```
R-VC27（R-VC12 二(a) 之修訂：三節之內容欄改為逐節實測）

R-VC12 二(a) 原文「該三節之『內容』欄一律書『該節內容僅存於圖，
SYS1 匯出未帶文字』，不得寫入任何摘要文字」——**作廢**。

作廢理由：該措辭係分析層讀 Project 附件之衍生 PDF 所得，
**未讀 SYS1 之對應儲存格**；實測 §10.1／§10.2 之 SYS1 `Description`
含二句文字，其一為實質需求敘述（`All four Aux switches … can be used
simultaneously`）。R-VC12 立條之由來即為「不得以衍生物之判讀充當實測值」，
**其二(a) 本身為該錯誤之產物**。

新處置 —— 表 B 之該三列，其「內容」欄逐節依實測書寫：

  §15    —— SYS1 `Description` 僅標題句 ＋ 三個圖佔位。
             書「標題句『Electronic Park Brake Service Mode Pop-up』，
             其餘內容為三個圖佔位（image20/21/22），SYS1 匯出未帶其文字」。
  §10.1  —— 逐字引錄其 SYS1 `Description` 全文（含二句文字與圖佔位），
  §10.2     不摘要、不省略（同 R-VC12 二(c) 對 §8.3 之作法）。

**通則**：表 B 之「內容」欄，一律**逐字引錄 SYS1 `Description`**，
不以任何形式之概括代之。概括會使讀表者無從判斷該節有沒有可用之文字 ——
而那正是表 B 要回答的問題。

R-VC12 之二(b)(c)(d) 與其餘各款**不變**。
R-VC12 二(a) 之原文依 R-TM13 不刪除，加註「作廢，見 R-VC27」。

**連帶**：DR-VC6 之問法須調整 —— 其原問「§15／§10.1／§10.2 之內容
僅存於圖，請提供文字版本」之前提於後二節不成立。改問：
(一) §15 之三圖內容；(二) §10.1／§10.2 之圖內容（其文字部分已有，
不需索取）；(三) `All four Aux switches … simultaneously` 一句
是否即為該二節之完整需求，抑或圖中另有其他規則。
```
