## 一、`DECISIONS.md` 之標頭與 Sign-off —— 我的指令缺陷

### 病灶

T41 要求「複驗簽出後內容與送簽稿逐字一致（`diff -q`）」，
而送簽稿含**描述其自身狀態**之元資料（「送簽稿，尚未簽署，尚未合併」）。

**逐字複製一份含自我描述之文件，其自我描述在複製後必然說謊。**
執行層照做即得到一個內容正確、標頭自述為「尚未簽署」的已簽署檔。
這不是執行偏差，是我的指令把驗證手段與內容語意對立起來了。

執行層之處置（不擅改、不代簽、回報並提最小修正）**完全正確**。
`diff -q` 之驗證已於當時完成並通過，其效力不因事後修正而失效 ——
簽出時之逐字一致是**已發生的事實**，記於上繳包 07 §2.1。

### 裁定

**(a) 標頭 —— 改。** 此為事實更正，非內容變更。改為：

```
本檔為簽出版。內容取自 `docs/DECISIONS_signoff_draft.md`
（SHA256 `8c1abac4a46db819813396e293396bc08f6867f53c1e190c68273861483c45b2`），
經 Pei 2026-08-26 授權（下放包 07 §〇 / T41）寫入。
簽出時之逐字一致驗證見上繳包 07 §2.1（`diff -q` 無輸出）。
本檔已簽出，`recon.py` 不再覆寫（A-TM15）。
```

**(b) Sign-off 區塊 —— 改為記錄授權，不模仿紙本簽名欄。**

```
- Authorized by: PeiPYHsu — 2026-08-26（下放包 07 §〇，Tier 3 授權）
- Written by:    execution layer (Claude Code) — T41
- Verification:  diff -q vs docs/DECISIONS_signoff_draft.md → 一致（上繳包 07 §2.1）
```

原 `Reviewed by: ____ Date: ____` 之空白欄**刪除**。
理由：那是紙本表單之形制，於本流程無對應行為 ——
本流程之權威記錄是「Pei 之授權 + 執行層之寫入 + 機器驗證」三者，
不是一個簽名欄。留一個永遠空白的欄位，只會讓日後讀者以為漏簽。

**執行層不代簽之判斷正確**，本裁定亦非代簽 —— `Authorized by` 記的是
Pei 已作出之授權事實（2026-08-26「三項都準 簽出」），不是替他決定。

## 二、R-VC17 —— 成員比對義務（承 REV-12）

執行層自查所得之 REV-12 抓到 R-VC15 未涵蓋之形態：

> `docs/upstream/01_intake_recon.md:598`
> 「引用章節數 66 恰等於相異 `HMI Source ID` 數 66，一對一成立」

二數**同屬 66 section 母體**，故不觸 R-VC15（該條只拘束跨母體互援）。
但它仍以**計數相等**代替**成員比對**來主張一對一 —— 這是同一個病灶的
同母體版本，且**更隱蔽**，因為同母體看起來完全合理。

執行層已補驗成員層（一個章節號對多個全名者 = 0）並記 REV-12。
**處置正確，本包據以立條。**

```
R-VC17（一對一之主張須以成員比對為據）

凡主張二集合為「一對一」、「恰等於」、「完全對應」、「全部落在」
或任何等同性關係者，**須以成員層之比對為據**，不得以計數相等代替。
本條**不論二集合是否同母體**皆適用 —— 同母體之計數相等更具說服力
之外觀，故更易誤用。

計數相等為等同性之**必要非充分條件**。兩集合大小相同而成員不同者，
其計數比對必然通過。

書寫要求：主張等同性時，須一併載明所用之成員比對方法及其結果
（例如「逐字集合比對，差集為空」、「一對多者 0 筆」）。
僅寫「n 恰等於 n」而無成員層證據者，視為論證不足，
須補驗或改寫為較弱之陳述。

本條與 R-VC15 之分工：
  R-VC15 —— 拘束**跨母體**之數字互援（不同母體之數字不可互援）
  R-VC17 —— 拘束**等同性主張之論證形式**（不論母體是否相同）
二者可同時適用，亦可各自單獨適用。

立條由來：執行層於 T45 自查所得（REV-12）。
分析層同期之 REV-11 為 R-VC15 之由來，二者為同一病灶之跨母體版與
同母體版。
```

### 4.2 選它之四項理由

1. **含完整流程之四階段** —— 啟用（4.1, 4.2）→ 啟用錯誤（5.1, 5.2）
   → 停用（6.1, 6.2, 6.3）→ 停用錯誤（7.1）。
   pilot 之目的是驗證 TC 生成之全部形態，而非只驗 happy path；
   本組天然含正向流程、負向流程、錯誤處理與鎖定規則
   （`VC-033-01` 三次錯誤鎖 30 分鐘），足以壓測 IN §7（FP／FF）
   與 §8.3（sibling axes）。
2. **邊界清楚** —— 四章連續且各章語意單一，無跨組爭議，
   非 R-VC16(b) 所稱之單一來源弱點所在（那是 #4／#5 之界）。
3. **無待補節** —— 不受 DR-VC3 之回覆牽動，故 pilot 之結論不會因
   該 DR 回覆而需重做。#7 `Brake Service`、#8 `Cabrio Widget`
   則相反（R-VC16(c)）。
4. **規模適中** —— 12 leaf 於 117 leaf 母體中佔 10.3%，
   一批可完成，且足以暴露格式類問題（`test_item` 兩段式、
   `specification_reference` 之逐行重述、尾句號、引號規則）。
