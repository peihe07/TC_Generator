## 三、`064-03`：**拆**，第 5 批 21 筆

你們逐字施了問法：「轉到 Key On 時彈窗不消失，哪一筆會 FAIL？」——沒有。
且 Run 與 Key On 互相消耗（轉 Run 後彈窗已消失，須整輪重建才能走 Key On）。

**依 R-VC26 應拆。裁：拆 2。** `split_delta` 4 → **5**，第 5 批 **21 筆**。

未自行增筆之判斷正確 —— 授權是 20 筆而拆分清單沒有它，
**新條文之首個新適用不該由執行層單方決定其範圍**。

### 3.1 但這暴露 R-VC26 之一個邊界，須同時補上

若「or 列舉即互相消耗」，則 `057` 之
`Key Off, Timed Mode or ACC` 三態亦當拆 3 —— **而那是錯的**。

**差別在標的之性質**：

| | `064-03` | `057` |
|---|---|---|
| 標的 | **一次性事件**（彈窗消失）| **持續狀態**（tab 不可用）|
| 走完其一後 | 情境**已被消耗**，須整輪重建 | 情境仍在，切換狀態即可續驗 |
| 判 | **拆** | **不拆**，三態以各自步驟／ER 涵蓋 |

**R-VC26 之適用說明（加註，不改原文，T138）**：

```
「互相消耗」之判別，取決於**標的是一次性事件或持續狀態**：

  一次性事件（彈窗消失、畫面轉場、資料清除）—— 走完其一即消耗情境，
    另一條須整輪重建 → **互相消耗，拆**。
  持續狀態（不可用、灰化、隱藏）—— 情境不因觀察而消耗，
    切換條件即可續驗 → **不互相消耗，不拆**，以多條步驟／ER 涵蓋。

例：`064-03`（Run／Key On → 彈窗消失，一次性）拆；
    `057`（Key Off／Timed Mode／ACC → tab 不可用，持續）不拆。

本說明防的是 R-VC26 被讀成「凡 or 列舉皆拆」——
那會使狀態列舉類需求普遍爆量，且其多出來的 TC 不對應任何覆蓋洞。
```

> `064-03` 之等價性問題（Run 與 Key On 是否同一等價類）**不需另判** ——
> 互相消耗之判準已足以定拆分，等價與否不改該結論。

### 4.2 PENDING 置於 Procedure 而非 ER：**追認，並更正我的表列**

下放包 25 §三表列寫「四筆之 **ER** 帶」。**那是我套了一個未經檢視的預設。**

**那是步驟的事**。

**通則（記入 profile 之 PENDING 書寫節）**：

