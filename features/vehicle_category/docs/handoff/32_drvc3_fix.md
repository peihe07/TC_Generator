### 1.3 這件事的性質

**R-VC27 修了條文與表 B，沒修 DR。** 而 DR 是**唯一會離開這個 repo 的東西** ——
條文與表 B 錯了是內部問題，DR 錯了是對外發出。

**修訂之波及範圍檢查，其優先序應以「該處會不會被送出去」為第一judge。**
本次的順序恰好相反：先修了不出門的，漏了要出門的。

**PLAYBOOK 增一則（建議位階，T165）**：

```
條文修訂後之波及檢查，**先查對外文件**（DATA_REQUESTS、DELIVERY_NOTE、
交付本、任何會離開 repo 者），再查內部台帳。
理由：內部之錯可於下一輪修；已發出之錯須補更正函，且損及可信度。

由來：R-VC27 修了 RULINGS 與表 B，未修 DR-VC3 之「發出前須知」段，
而該段正在發送中。
```

## 三、其餘三項

### 3.1 §4.3 之「已解」更正：追認

上繳包 29 §4.3 將 §10.1／§10.2 標為「已由 R-VC27 解」——
**憑「R-VC27 已裁」推定其涵蓋範圍，未回去讀 DR-VC3。**

與 §一為同一件事之兩面：**修訂之涵蓋範圍是要查的，不是推的。**
`ledger_xref` 抓到它、而抽查時被標為已解 —— **工具做對了，讀表的人放過了。**

而它在增設該欄的同一輪就發生了。
