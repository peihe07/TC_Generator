## 二、第二層判準：裁**丁** —— 沿用第 7b 項之同一正規化

甲乙丙皆不採，第四條路更簡單：

```
第二層（修訂）：
  037 Description 與 SYS1 節之文字，**皆以第 7b 項之同一正規化處理**
  （小寫 ＋ 去標點 ＋ 壓縮空白），正規化後之子串關係不變：
    normalize(037 片段) ⊆ substring( normalize(SYS1 節) )
```

### 2.1 為何丁而非乙

**乙之「前綴」對半數登記筆有歧義**：`012-03`／`013-03` 是**續行段**，
從句中開始 —— 它們不是任何 SYS1 句之前綴。乙要成立得寫成
「前綴**或**子串」之聯合判準，二個概念疊在一起。

**丁只動正規化，判準本體（子串）不變**：

| leaf | 現行（僅首字母正規化）| 丁（去標點正規化）|
|---|---|---|
| `012-02` | ✅ | ✅ |
| `012-03` | ✅ | ✅（續行段天然為子串，不需前綴概念）|
| `013-03` | ✅ | ✅ |
| **`013-02`** | ❌（`row.` ≠ `row,`）| **✅**（`…in the same row` ⊆ `…in the same row and follow…`）|

`013-02` 之改寫（`, and` → `.`）**恰好全落在標點層** ——
去標點後其片段回復為 SYS1 之純前段，子串成立。

**且丁順帶消滅一個正規化變體**：第二層原本自帶「首字母正規化」，
與第 7b 項之定義是二套。丁之後全案只有一套正規化 ——
承機讀行與前綴樣式表之同一原則（單一來源，二處必分歧）。

### 2.2 丁之已知限制（明文，不假裝解決）

**詞級改寫仍無效** —— 若 037 刪改的是句**中段**之詞（而非標點），
去標點救不了。此限制為甲乙丙丁四案共有，目前無實例。

```
CONT 第二層之效力：驗「登記之節確為該片段之來源（至標點差異為止）」。
037 對片段之詞級改寫，本層看不到 —— 其防線仍是勘查 (d) 之 SYS1 對照。
```

（`013-02` 之「補句號刪 and」已由第 1 批勘查抓到並記於 reasoning ——
防線分工本來就是如此，本包只是把它寫明。）

### 2.3 修訂後之驗收

self-test 四斷言重跑，**全過始續**。其中斷言 4（反向：`012-03` 臨時
改指 §2.5）**必須仍 FAIL** —— 去標點不會使錯節變對（文字本身不同）。
若斷言 4 意外 PASS，即丁過鬆，停並回報。

## 三、`short` 特徵：自 CONT 候選**移除**，移位為 profile §8 之適用清單

執行層之數據成立（9/16 單靠 `short` 命中且全為完整短句；移除不影響
`reference` 之偵測力）。但**移除不是丟棄** —— 診斷指出的其實是：
**我在 20a 把二件事混進了一個偵測器。**

| 事 | 歸屬 | `short` 對它是 |
|---|---|---|
| 「上半該取 SYS1 完整句」（片段／指涉）| CONT 表 | **偽陽性**（完整短句非片段）|
| 「短來源之子串保護力弱，須人工複核」| profile §8 | **真陽性候選** |

**裁**：
- CONT 候選偵測 = `continuation` ＋ `reference` 二特徵。
- `short` 掃描保留，**輸出改為 profile §8 之適用清單**
  （`data/short_source_leaves.tsv`）——
  b 段之 `007-01`／`013-04`／`025-01` 應在其中，
  未來批次之短來源 leaf 提前列冊。
- **60 字元之耦合隨之解除**：CONT 不再用該數字，
  `short` 清單就是 §8 之清單 —— 同一個 60 是**同一個判準**，
  不再是二個判準共用一個數字。
