## 3. P-3：D-6 實際涵蓋不到兩成

R-P58 設立 D-6 之理由正是「補列之 34 個凍結欄全為新寫，不在任何雜湊範圍內」，但實作僅驗其中 6 欄（Priority / Design Method / Test Group / Test Set / Specification Reference / Requirement or Design ID）。**Test Item、Test Case Reference ID、Functional Safety 等 28 欄無任何檢查。**

> **R-P79｜D-6 擴及補列全部 34 個凍結欄**
> D-6 之驗證範圍擴及補列之全部 34 個凍結欄，逐欄逐條檢查，**每欄須有明確判準**：
>
> | 類型 | 判準 |
> |---|---|
> | **受資料驗證控制之欄** | 值 ∈ 該欄 DV 來源之值域（同 D-11） |
> | **有既有值域慣例之欄**（如 `Test Case Reference ID` = `NEW`、`Functional Safety`） | 值 ∈ 既有 558 列之相異值集合；若為新值須逐條說明依據 |
> | **自由文字欄**（如 `Test Item`、`Remarks`） | 非空（除非該欄既有列多數為空，則得為空）；`Test Item` 須符合 canon §4.3 之三種形狀與 2–14 字 |
> | **執行結果欄**（5 個 build + 結果分類） | **須為空**——補列未執行，填入任何值皆為對執行結果之陳述（同 R-P68 之理由） |
> | **公式欄**（`No.#`） | 為公式非字面值（同 W-5） |
>
> 逐欄結果須列表上繳，**不得以「其餘欄位沿用既有慣例」概括**。
>
> 本條為 R-P58 之補完——原條文陳述了理由（34 欄全為新寫）卻未據以定義範圍，實作遂只涵蓋易驗者。

## 6. A-PJ65 之通則升格 canon

執行層歸納：**抽取式比解析式更容易錯，錯了不會報錯，只會安靜地少抽或多抽。**

> **canon §5a 第十二條（新增）**
> 自來源文件抽取錨點、id 或結構時，**抽取式之缺陷不會報錯**——少抽表現為「該項不存在」，多抽表現為「多出無意義的項」，兩者皆不觸發例外。
> 因此：
> 1. 抽取式須以**已知全集**驗證（如 docx 全文 id 數 vs 索引數）
> 2. **自由文字中的數字預設不是錨點**；寧可標「未解析」也不猜
> 3. 抽取結果之總數須與來源之獨立計數比對，不得僅檢查抽取過程無例外
>
> 實例（A-PJ65）：Addendum 抽取式改三次——`R10` 被當章節號、`Table 18-11` / `line 845` / `800 x 480` 被當章節號、`Addendum` 子字串命中 MFi 另一份文件。三次皆未報錯。
