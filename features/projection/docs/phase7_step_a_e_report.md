## 1. 擋住第 F 步的唯一一項：A-PJ67

### R-P79 引 canon §4.3，與 profile §1 之風格權威相斥

R-P79 對自由文字欄的判準寫：

> `Test Item` 須符合 canon §4.3 之三種形狀與 **2–14 字**

**但 profile §1 `[OVERRIDE]` 明定本 feature 之風格權威是 base workbook 自身的
done region。** 實測：

| 項 | 值 |
|---|---|
| 既有 558 列 `Test Item` 字數 | 最小 11、中位數 **41**、最大 **143** |
| 符合 2–14 字者 | **4 / 558（0%）** |
| 超過 14 字者 | **554** |

既有列的 `Test Item` 是**需求敘述逐字**（多含 canon §4.3 明文禁止的 `shall`），
不是短標題。補列 7 條逐字取自 037，字數 9–39，其中 2 條落在 2–14 內。

### 兩種讀法都成立，結果相反

| 讀法 | 依據 | 結果 |
|---|---|---|
| **A：workbook 為風格權威** | profile §1 `[OVERRIDE]` 為明文，canon §4.3 為通則 | 補列維持逐字（**現況**），與 554 個 sibling 一致 |
| **B：canon §4.3 適用於新寫列** | 既有列違規但凍結不可改，新寫列應合規 | 7 條改寫為短標題，成為全簿唯一 7 個短標題 |

**執行層不自行擇一**，但傾向讀法 A：

1. 依 `PROFILE_INTEGRATION` 之權威鏈，**明文的 `[OVERRIDE]` 勝通則**
2. 讀法 B 會讓 7 條補列在該欄與其餘 558 列**看起來像另一份文件**，
   而 D-6 的目的正是讓補列與既有列不可區分
3. `Test Item` 不承載追溯（追溯在 `Requirement or Design ID`），改寫不增加資訊

### 為什麼停在這裡是對的

若裁為讀法 B，7 條的 `Test Item` 須重寫、D-6 重跑、複本 W 流程重跑 ——
**但交付檔仍只寫一次**，因為第 F 步尚未執行。

這正是本包 §0「交付檔只寫一次」的設計奏效之處：**衝突在寫回前被攔下，而不是在
寫回後才發現要寫第二次。** 停下的成本是一個往返；寫下去再改的成本是本包明文
要避免的兩次寫回。
