## 3. R-P90｜`pcts_ui` 之可再生性 — 兩造皆對，取證性優先

`.gitignore` 稱「re-dump 即可再生」、close-out 包稱「不可再生（需實機）」。執行層判斷正確：**兩者都對，講的是不同條件。**

> **R-P90｜取證性資料以「該次取證能否重現」判定，非以「同類資料能否再產生」判定**
> `data/pcts_ui/*.xml` **入庫**。
>
> 依據：R-P11 綁定的不是「PCTS app 的 UI 結構」這類資料，而是**取證當下之特定組合**——Pixel 10 / Android 16 / PCTS Verifier `5.1-prod.922397802`。該組合日後未必可重現（裝置汰換、OS 升級、apk 版本下架）。
> L-PJ7 之 gate 讀 `pcts_evidence.json` 之 `status` 決定 23 列能否修改；若該 status 遭質疑，原始 dump 是唯一物證。**證據之價值在於它記錄了某個時點，而非它記錄了某類事實。**
>
> 體積 297 KB，不構成負擔。
>
> **通則**：判定某資料是否為「可再生產物」時，須問「**產生它的那次觀測能否重現**」，不是問「同類資料能否再產生」。前者為否即屬證據，應入庫。

`.gitignore` 中該項之理由文字須一併更正為取證性判準。
