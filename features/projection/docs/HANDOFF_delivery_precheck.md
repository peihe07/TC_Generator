## 1. A-PJ74｜檔案大小實測有誤，且分析層未查證即接受更正

上繳包稱「R-P88 §0 寫『inputs/ 561.23 KB / 交付位置 559.25 KB』，實測兩者皆為 572,672 bytes —— 寫回後的 inputs/ 版本大小沒有變」，並將其歸為 A-PJ73／canon §5a 第十五條之第四次。

```

    574,700 bytes  (561.23 KiB)   modified 2026-08-12 16:40:59

    572,672 bytes  (559.25 KiB)   modified 2026-08-11 19:16:22

**兩者相差 2,028 bytes。原下放包之數字正確。**

> **A-PJ74**
> **(a) 執行層之量測錯誤**：「兩者皆為 572,672 bytes」不成立。`inputs/` 寫回後為 574,700 bytes。推定成因為對交付位置之路徑量測兩次。
> 補列 7 條、刪列 1 條、76 列授權例外變更、W-9 之樣式繼承後，檔案大小不變在物理上高度不可能——**該結論本身即應觸發自我懷疑**。
>
> **(b) 分析層未查證即接受更正**：分析層收到該更正後，未經任何查證即認錯並將其登記為自身缺陷之第四次。
> 這與 A-PJ73（未查證即陳述）是**同一失效模式的鏡像**：前者未查證而主張，後者未查證而讓步。**兩者的共同缺陷是「未查證」，不是「主張」或「讓步」。**
>
> 責任歸屬：執行層 (a)、分析層 (b)，各自獨立成立。

> **canon §5a 第十六條（新增）｜接受更正亦須查證**
> 收到對自身陳述之更正時，**查證義務與提出陳述時相同**。
> 未查證即接受更正，與未查證即主張，同為 §5a 之違反——認錯不是免除查證的理由，而讓步比主張更容易被誤認為謹慎。
> 實例（A-PJ74）：執行層以錯誤之實測值更正分析層之正確數字，分析層未查證即接受，致正確記載被改為錯誤記載，且被登記為分析層之第四次缺陷。
>
> **推論**：若一方之更正被無條件接受，則該方之錯誤將直接寫入記錄且無人攔截。**雙向查證是雙層檢驗（canon §7.3）在事實陳述上的對應物。**
