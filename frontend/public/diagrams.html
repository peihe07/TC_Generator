TC Generator

Architecture & workflow diagrams · 更新：2026-04-27

1運作原則

固定流程走 GUI 與 API；只有需要語意判斷或生成的地方才使用 AI。這樣使用者看得到狀態，也不會把 token 花在可以用按鈕完成的動作。

AI
生成核心
Requirement 轉 Test Case
Generate / Regenerate / Re-run 會讓模型產出 Pre-Cond、Input、Procedure、Expected Result、Method、Priority 與 AI 需求解讀。
UI
人工審查
逐列確認與修改
Review 階段顯示每筆 TC 狀態、duplicate/difference 註記、validation result，使用者可接受、刪除、編輯或重生。
$
成本邊界
可預期的 AI 呼叫
Upload 與一般 Export 不呼叫 AI；Group 是手動觸發；Spec Matching 先走 exact/fuzzy，只有有 embedding 條件時才進 semantic。

2GUI 與 API 並行 / 切換

GUI 是操作層，API 是執行層。使用者不需要知道每個 backend endpoint，但每個按鈕背後都對應明確 API；當流程需要 AI 時，API 再把必要上下文交給模型。

GUI
固定操作
把流程變成可見狀態
Upload、Configure、Review、Export 都是高重複、需要確認狀態的工作。做成 GUI 可以看到 rows、preview、validation、usage 與輸出範圍，不必在 chat 裡反覆描述要刪哪幾筆或匯出哪個版本。
API
確定執行
把副作用收斂到 endpoint
解析 Excel、儲存 job、spec matching、grouping preview、generate stream、export workbook 都由 API 執行。這讓每一步有固定輸入輸出，錯誤可重試，也能被測試覆蓋。
AI
語意判斷
只在需要理解時切入
AI 不負責操作整個系統，只負責 requirement 解讀、test case 生成、必要的分類或修正建議。GUI 決定何時呼叫 API，API 決定是否需要模型。
User Action使用者在 GUI 選檔、按 Group、Refresh Match、Generate、Delete 或 Export。
API Contract前端送出明確 payload，backend 回傳 preview、job state、SSE event 或 Excel file。
AI Boundary只有語意不足以用規則處理時，backend 才組 prompt 並呼叫模型。
GUI State結果回到畫面，使用者可審查、覆寫、刪除、重跑或匯出。
可追蹤：每一步都有狀態 可測試：API 行為固定 可省成本：AI 只處理必要內容 可人工覆寫：不被模型結果綁死

3主流程

五個主要模組對應五個決策點。Configure 不會在載入時自動 group，必須由使用者按 Group 或手動編輯。

1
Upload
建立 Job
解析 workbook、保存原檔，保留原 H 欄作為 testSetHint，但不直接當成最終 group。
< 30s$0
2
Configure
Group / Match / Options
使用者手動執行 grouping；spec matching 可 refresh preview；model 與 batch size 在這裡設定。
手動觸發可預覽
3
Generate
SSE 逐筆產生
批次生成、即時回傳進度，處理 auto split、duplicate sibling 與 validation retry。
2-5 min計 usage
4
Review
審查與修正
Accept / Edit / Delete / Regenerate。刪除後前端會清除失效 duplicate reference 並重排 TC ID。
人工確認本地重排
5
Export
寫回 Excel
依 scope 輸出，移除已刪除的原 workbook rows，重編 TC ID，最後欄輸出 AI 需求解讀。
< 10s$0

4Configure 決策圖

這裡是目前最容易誤會的區塊：載入頁面只顯示現有資料，真正分類要按 Group；Spec Matching 則有明確的 exact → fuzzy → semantic 順序。

Grouping

Load讀取 rows 與 testSetHint，不自動產生 group。
Group用現有 Test Set 與 hint 當參考，重新分類全部 rows。
Review檢查 preview；需要時在 Manual Override 直接改 row。
Apply寫回 job rows，test set label 會縮短為可讀名稱。
HVAC Popup Status Bar Touchscreen & Hard Controls Hard Control LEDs Unclassified

Spec Matching

Exact Code先抓 C1、C6.1、CR、ICE、LS、PDM code。
Fuzzy Text沒有前綴時，改用 H/I/L/M 欄與 hint 做文字比對。
Semantic只有 spec cache 有 embedding 且環境可用時才跑。
Preview使用者可 refresh 與檢查 unmatched / low confidence。
無前綴也可比對 Exact 不需 embedding Refresh 會重載 preview

5Generate / Review 邏輯

生成階段負責結構化產出；Review 階段負責把不該交付的 rows 排除，並維持後續 export 的資料一致性。

GEN
AI pipeline
Decompose → Generate → Validate
同一 Requirement ID 的 sibling rows 會被放進 prompt context。模型需判斷 duplicate 或差異軸，validation 失敗時走 retry / escalation。
REV
Local state
Delete 後立即整理
刪除 row 後會重算 split sibling metadata、清掉指向已刪除 row 的 duplicate note，並依 group bucket 重排 TC ID。

6Export 寫回規則

Export 使用 Review 後的最終 rows，不把已刪除的原 workbook row 帶回輸出檔。

ScopeAccepted Only 或 All Generated 決定輸出集合。
Prune原 workbook 中被刪掉的 rows 會從輸出移除。
Resequence依 (project, group_abbr) 重新 001/002/003 編號。
WriteExcel 寫入 TC 欄位、Framework sheet 與最後欄 AI 需求解讀。
刪除重複項後不再輸出兩條 TC ID gap 會閉合 R 欄：AI 需求解讀

7Quick Generate

替代路徑：單筆 requirement 直接生成 TC，不載入 workbook，也不寫回原 Excel。
